# Linux 0.15.42 对齐计划（对应 macOS 0.15.39–0.15.41）

日期：2026-11-26

## 1. 上游变更审计（`790dcd9c..65807ebe`，macOS `v0.15.39`–`v0.15.41`）

1. **顶部会话列表与侧栏「会话」页统一采用总览卡片（`0.15.39` + `0.15.40`）**
   - `gui/lib/ui/session_block.dart`、`gui/lib/ui/session_switcher.dart`、`gui/lib/ui/sessions_tab.dart`、`gui/lib/ui/overview.dart`：
     - 顶部会话切换列表、侧栏「会话」标签页与总览统一使用 `SessionBlock`，显示标题、窗口数、流量速率或程序状态（推断状态标「推断」）、断开原因，文字终端第二行前缀统一带 `CLI`（按应用/项目分组时显示 `CLI · <设备> · …`）。
     - 侧栏「会话」页的「常用」项改用与总览同源的 `FavoriteBlock`（第二行显示设备名，右侧显示「打开」/「新建」，点按调用 `openFavorite` 支持首次恢复存量文字终端、再次点按新建终端）。
2. **`rapp update` CLI 命令与服务升级协调（`0.15.40` `feat/cli-update`）**
   - `rust/cli/`：新增 `rapp update [--yes] [--timeout 秒] [--json]`、`rapp update check`、`rapp update status`、`rapp update rollback`，统一退出码（如服务未运行退出码 `3`，需手动安装包退出码 `7` / `not_launchd`）。
   - `rust/service/`、`rust/term/src/serve.rs`、`gui/lib/main.dart`、`gui/lib/service_client.dart`、`gui/lib/update.dart`：
     - 服务记录远程活动（`activity`）与非文字终端远程窗口数（`gui_windows`），支持通过 `update_status.quit_gui` 请求主窗口与 `--cm` 小窗无确认干净退出（Linux `--cm` 走 `MethodChannel('rapp/linux').invokeMethod('close_window')`）。
     - 根据 `docs/superpowers/specs/2026-11-26-rapp-cli-update-design.md` §3 非目标，Linux 服务不由 `launchd` 管理（安装包由 `pacman` 管理），不启用自动替换安装包，`rapp update` 按规范返回 `not_launchd`（退出码 `7`）。
3. **总览设备列系统图标与 Omarchy 实机识别（`0.15.41` `feat/device-os-marks`）**
   - `rust/service/src/workers.rs`、`rust/service/src/peer.rs`、`rust/hub/`、`gui/lib/ui/device_os.dart`、`gui/lib/ui/os_mark.dart`、`gui/lib/ui/overview.dart`：
     - 服务端 `list_apps` 回报设备系统 `os`（Linux 下检测 `/usr/share/omarchy/shell` 存在则报 `omarchy`，否则报 `linux`），`rapp-hub` 持久化至 `hosts.json` 并透传给 GUI；
     - 总览每个设备列状态灯左侧绘制单色系统图标（`macOS`、`Windows`、`Omarchy`、`Linux`、`iPad`、`iPhone`、`Android 平板`、`Android 手机`、`系统未知`）；
     - 已在本机 Omarchy 4.5.0 实机核对 `/usr/share/omarchy/shell` 存在，本机列与被控端 `list_apps` 均准确识别为 `omarchy`。
4. **Linux 端发现并补齐的关键缺口**
   - `scripts/linux/rapp`：原打包启动脚本仅将 `share|unshare|hosts|pipe|-h|--help|--version` 转发给 `rapp-cli`，导致在 Linux 执行 `rapp update ...` 会误拉起 `rapp-gui` 图形窗口；已补齐 `update` 分发并扩展 `scripts/test-linux-launcher.py`。
   - `rust/cli/src/update.rs` & `rust/cli/tests/update.rs`：
     - Linux 上 `state == "off"` 时：将默认的 `/releases/latest`（指向 macOS 自动更新入口）映射为包含 Linux 安装包的 `https://github.com/wizlijun/rapp/releases`；
     - `rapp update status [--json]` 在 Linux 上回填编译期版本号 `env!("CARGO_PKG_VERSION")` 并准确提示「Linux 上还不能在线升级（请从发布页面下载安装包）」，避免误报「不是从安装包装的」或当前版本为空；
     - 修复 `rust/cli/tests/update.rs` 的 `not_launchd_exits_7` 在 Linux 目标下的退出码与输出断言，并在 `scripts/test-linux-bundle.py` 中对真实打包服务验证 `rapp update status --json`（退出码 `0`）、`rapp update --json`（退出码 `7` / `not_launchd`）及 `apps.os`（`omarchy` / `linux`）。
   - 协议保持 **v16**，与 macOS `0.15.35–0.15.41` 互通。
