## 1. 差异审计（`0.15.47`–`0.15.50`）

1. **Linux 打包入口脚本 `scripts/linux/rapp` 缺少 `state` 与 `load` 分发（必须修复）**：
   - `0.15.47` 新增 `rapp load [设备…] [--top] [--json]` 与 `rapp load pick [--json]`；`0.15.48` 新增 `rapp state [on|off]`。
   - 此前 `scripts/linux/rapp` 未包含 `state` 与 `load`（连同 `0.15.45` 补齐的 `term`），在 Linux 下直接运行 `rapp load` 或 `rapp state` 会误入 `rapp-gui` 分支。
   - 修复：将 `scripts/linux/rapp` 的 CLI 匹配更新为 `share|unshare|hosts|pipe|term|update|state|load|-h|--help|--version)`，并在 `scripts/test-linux-launcher.py` 与 `scripts/test-linux-bundle.py` 增加命令路由及真实服务进程下的 `rapp state on/off`、`rapp load --json`、`rapp load pick --json` 端到端校验。
2. **Linux 设备负载采集（`0.15.47`，`rust/service/src/load/linux.rs` + `disks.rs`）**：
   - `LinuxSampler` 读取 `/proc/stat`、`/proc/loadavg`、`/proc/meminfo`（`MemAvailable`、`SwapTotal - SwapFree`）与 `/sys/class/thermal/thermal_zone*/temp`（自动忽略不可读传感器如 `EIO`），`DiskReader` 按 `st_dev` 聚合工作路径（支持 Omarchy Btrfs 子卷 `/home` 去重与 2 秒单盘超时隔离）。
3. **伴随状态服务 `rapp-state`（`0.15.48`，`services/state` + `rust/service/src/companion.rs`）**：
   - `scripts/build-linux.sh` 与 `scripts/package-linux.sh` 已包含 `rapp-state` 编译、Staging 与 `/usr/bin/rapp-state` 符号链接（打包文件总数为 42 个、ELF 共 15 个）。
4. **输入法意图切换与本机列折叠（`0.15.49`）及远端 Mac 终端授权提示（`0.15.50`）**：
   - `LinuxLocalIme` 通过 `fcitx5-remote`（`-o`/`-c`）或 `ibus engine` 在进入写作框时切中文、回到画面时切英文；Linux 画面按键前由 `rapp-session` 按需触发远端 `auto_english`；`rust/host-linux/src/select_wait.rs` 为被控 Linux 端输入源切换提供有界排队与稳定等待。
   - 总览「本机」列仅在无本机服务（如 iOS）时默认折叠；Linux 有 `ServiceMonitor` 时保持展开并显示本机余力。
   - `rust/term/src/pty/consent.rs` 在非 macOS 平台恒返回 `false`，Linux 客户端遥控未授权的 Mac 时可正常接收授权提示并保持当前正在查看的远端屏幕。
