## 1. 差异审计

审查 `796f4e90..7681dea4`（`feat/term-restore`）的全部 58 个变更文件：

1. **Linux 打包入口脚本 `scripts/linux/rapp` 缺少 `term` 分发（必须修复）**：
   - `2b03fb99 feat(cli): rapp term restore` 在 `rapp-cli` 新增了顶层 `term` 子命令（`rapp term restore [--list|--forget|<序号|名字>...]`）。
   - `scripts/linux/rapp` 仍只匹配 `share|unshare|hosts|pipe|update|-h|--help|--version)`，导致在 Linux 上运行 `rapp term restore` 会误启动 `rapp-gui` 而非转发给 `rapp-cli`。
   - 修复：在 `scripts/linux/rapp` 的 CLI 分支加入 `term`，并在 `scripts/test-linux-launcher.py` 与 `scripts/test-linux-bundle.py` 增加命令路由及端到端快照列表/清理/日志脱敏校验。
2. **`rapp-term` Linux 端快照、开机时间与环境读取（已就绪，需跑全量实机测试验证）**：
   - `rust/term/src/pty/saved.rs`：`#[cfg(not(target_os = "macos"))] boot_time()` 从 `/proc/stat` 的 `btime` 读取本机启动秒数，用于区分重启前（`boot: true`）与本次开机后关闭的快照；`held()` 结合 `libc::kill(pid, 0)`、socket 存活与 `boot_time` 防止忙时误清理或跨重启 PID 复用。
   - `rust/term/src/pty/fg.rs`：`#[cfg(target_os = "linux")] launch_info(pid)` 读取 `/proc/<pid>/cmdline` 与 `/proc/<pid>/environ`（白名单仅保留 `VIRTUAL_ENV`、`CONDA_PREFIX`、`CONDA_DEFAULT_ENV`）。
   - `rust/term/src/pty/shell.rs` 及 `hook/{zshenv,rapp.zsh,rapp.bash,rapp.fish}`：POSIX/各 shell 通用 OSC 7502 状态与命令上报钩子（`0700`/`0600` 原子安装至 `<term_dir>/shell/`），支持恢复时激活 `venv`/`conda` 并在首轮提示符后仅预填命令、不自动回车。
   - `rust/term/src/pty/launch.rs` 与 `serve.rs`：`command_file` 生成带 `--restore '<key>'` 与 `--cwd '<cwd>'` 的启动脚本，Linux 下经 `systemd-run --user` 拉起已安装的终端程序（如 `ghostty`、`foot`、`kitty`、`alacritty`）。
3. **GUI 跨平台行为与 `TargetPlatform.linux` 覆盖**：
   - 总览与侧栏「常用 · 终端」在无存活终端且存在重启前快照（`boot: true`）时显示「恢复」，点击弹出 `TermRestoreDialog`（「恢复上次的终端」）；设备页显示「上次没关的 N 个终端」与「恢复…」；「新建」与 `Ctrl+Shift+T` 传入当前或最近使用的终端 `from`（无存活终端时回退至最新快照目录）。
   - 在 `gui/test/ui/term_restore_test.dart` 增加 `TargetPlatform.linux` + Omarchy 终端启动器（`ghostty`）回归测试。
4. **版本号跟随约束**：
   - 保持 `rust/Cargo.toml`（`0.15.45`）与 `gui/pubspec.yaml`（`0.15.45+101`）不变，不改动 macOS 代码路径（遵循 `CLAUDE.md` 中仅影响 Linux 的改动不触发 macOS 发版的边界），将构建出的 3 个 Linux `0.15.45` 产物直接上传至现有 `v0.15.45` Release，并同步 `website/releases.json`、`website/README.md` 与 `tasks/todo.md`。
