# Linux 0.12.2 parity implementation

Approved scope: Linux controls the current macOS app/desktop/text-terminal sessions;
Linux supplies text terminals and shared ports. Linux graphical hosting and a Windows
implementation are separate work. Preserve existing macOS behavior and platform guards.

- Every agent has its own branch/worktree. Shared files have one owner. Do not format

## Contracts and gates

1. App-session protocol and clipboard side requests use protocol 12. Preserve every
   compressed delta; only complete decoded canvases may be replaced under backpressure.
2. Worker JSON already carries focus/input_source/screen_locked/weak/rtt/stalled.
   New commands/events require both producer and consumer tests.
3. ComposerEditor owns live text. Draft capture/detach must await IME/FIFO reads.
   A native Send reaches ComposerModel once; a late result must not complete a later send.
4. In-app Flutter, detached GTK3 and standalone GTK4 are separately verified.
5. Text-terminal Ctrl keys retain terminal semantics; graphical Mac-session keys keep
   their existing mapping. Super remains local; Ctrl+Enter belongs to the writing panel.
6. Linux graphical hosting is unavailable; terminals and port sharing remain usable
   without rapp-host. Do not label missing host binaries as missing macOS permissions.
7. No-argument `rapp` starts the GUI; explicit CLI commands reach rapp-cli. Bundles carry
   all workers. System package management owns Linux installation.
8. Linux updates select stable Linux assets across releases, use validated repository
   URLs, and never offer an older Linux package as an upgrade to a newer installed build.

## Firewall follow-up (package revision 2)

- Device ingress is the configured QUIC UDP listener (default 22028). The code
  binds IPC TCP 22029 and mapped TCP 28000–28999 to loopback only; they must not
  be advertised as LAN firewall exceptions. UDP 22026 belongs to a separate relay.
- Status now includes the actual bound UDP port. Old services are supported by
  reading the explicit port from LAN IDs, otherwise using the default 22028.
- Linux Local shows UDP guidance and UFW configuration state. Passive diagnostics
  never elevate. An explicit user action reads recent kernel UFW records through
  polkit with bounded execution; it does not change rules. Evidence must match
  time, direction, UDP, local destination and listener port. Empty/inaccessible
  logs are not interpreted as an open port. Copyable commands accept one numeric
  peer address and the actual port, never broad port ranges.
- Add-device and disconnected-session timeouts provide connection-specific
  guidance; relay failures retain their own configured-port guidance. Upload and
  command timeouts, authentication messages and retry classification are preserved.
- Targeted integrated Flutter regression: 76 passed; analyzer clean. GUI-agent
  regression including stage/device tests: 160 passed (overlapping tests, not
  additive). Rust `reports_status` passed for the actual dynamically bound port.
  Independent review found and resolved an unbounded post-timeout process wait;
  the final bounded implementation passed re-review and a real sleep-process test.
- Revised archives use `PKGREL=2` and a separate output directory. Validation of
  the revised artifacts is recorded in that directory's `LINUX-VALIDATION.txt`.
