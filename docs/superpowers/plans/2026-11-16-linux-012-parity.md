# Linux 0.12.2 parity implementation

Approved scope: Linux controls the current macOS app/desktop/text-terminal sessions;
Linux supplies text terminals and shared ports. Linux graphical hosting and a Windows
implementation are separate work. Preserve existing macOS behavior and platform guards.

## Source and ownership

- Main reference: `a5e130a0dff9782f1cdbcc7c566e6a9c6324707f` (0.12.2).
- Existing Linux reference: `f393bc4` (0.5.2 native windows and transfers).
- Integration branch: `linux/0.12.2`, structural merge `5bb7a72`.
- That merge is a development baseline, not a tested release. Semantic adaptation and
  tests are required before packaging.
- Protocol agent: `rust/client-core`, `rust/client-gtk`, independent client fixtures.
- GUI agent: Flutter and GTK3 runner, GUI tests, desktop smoke test.
- Backend agent: terminal/service/CLI, build and package scripts, backend tests.
- Integrator: release asset selection, shared-contract review, staged integration,
  regression tests, documentation and package verification.
- Every agent has its own branch/worktree. Shared files have one owner. Do not format
  the whole Rust workspace or change user desktop/service configuration during tests.

## Contracts and gates

1. App-session protocol and clipboard side requests use protocol 12. Preserve every
   compressed delta; only complete decoded canvases may be replaced under backpressure.
2. Worker JSON already carries focus/input_source/screen_locked/weak/rtt/stalled.
   New commands/events require both producer and consumer tests.
3. ComposerEditor owns live text. Draft capture/detach must await IME/FIFO reads.
   A native Send reaches ComposerModel once; a late result must not complete a later send.
4. In-app Flutter, detached GTK3 and standalone GTK4 are separately verified.
5. Text-terminal Ctrl keys retain terminal semantics; graphical Mac-session keys keep
   their existing mapping. Super remains local; Ctrl+Enter belongs to the writing panel.
6. Linux graphical hosting is unavailable; terminals and port sharing remain usable
   without rapp-host. Do not label missing host binaries as missing macOS permissions.
7. No-argument `rapp` starts the GUI; explicit CLI commands reach rapp-cli. Bundles carry
   all workers. System package management owns Linux installation.
8. Linux updates select stable Linux assets across releases, use validated repository
   URLs, and never offer an older Linux package as an upgrade to a newer installed build.

## Acceptance matrix

Automated coverage below is not a substitute for a real macOS peer or a physical
Wayland/X11 desktop. Real-device acceptance remains open for every applicable row.

| Area | In-app | Detached GTK3 | Standalone GTK4 |
| --- | --- | --- | --- |
| Frames, window table, input, stream settings | Flutter/worker tests | Native/worker tests | Protocol/runtime fixtures |
| Native popups, mixed scale and window lifetimes | Flutter tests | Private GTK3 Broadway smoke | Private GTK4 Broadway fixtures |
| Clipboard, files, cancellation/resume | Flutter/worker tests | Shared worker/model tests | Protocol/worker tests |
| Focus-pane rendering and lock state | Flutter tests | Native/worker tests | Focus geometry/worker tests |
| Disconnect/reconnect, retained frame/draft | Lifecycle tests | Handoff/race tests | Runtime disconnect/takeover fixtures |
| IME and writing controls | Editor/epoch tests | IME filter/draft tests | Native input path; real IME pending |

Additional gates: Linux terminal launch/discovery/rename and survival after service
restart; localhost port maps/access control/concurrent forward and session; data migration
from client-only 0.5.2; package inventory/entry points; isolated Wayland/X11 smoke tests.
