# 删掉旧 relay、新 relay 改名 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 仓库里不再有旧 relay（`rapp-relay/1`）的代码、协议、脚本和界面；新 relay 改叫 `rapp-relay`（目录 `rust/relay`）。

**Architecture:** 先删旧 relay 的使用方（hub、service、GUI、脚本），每一步都能编译、测试全过；再删旧 crate 和 `rapp-net` 里只给它用的消息；最后 `git mv rust/relay2 rust/relay` 并改包名。B 连 A 只剩一条路：按 `hosts.json` 里保存的地址直连，用密码认证（A 只接受私有网段来的密码认证，这条不改）。

**Tech Stack:** Rust 2021（tokio、quinn 0.11），Flutter/Dart（gui/），bash、python3（scripts/）。

**Spec:** `docs/superpowers/specs/2026-11-14-drop-relay1-design.md`（已确认）。背景：`docs/superpowers/specs/2026-11-13-rapp-relay-design.md`。

## Global Constraints

- 只删、改名，不加新功能。不写设备连新 relay 的连接层（第 2 步）。
- 保留：设备 ID、密码、`ID@IP` 直连（ALPN `rapp/1`）、`Op::Auth { password, name }`、`ListApps`、`Ping`、`Open`，以及"密码认证只接受私有网段"（`rapp_net::addr::is_private`）。
- `hosts.json` 格式不变；`service.json` 里旧的 `relay`、`key`、`secret` 字段读的时候忽略（serde 默认忽略未知字段，不加 `deny_unknown_fields`），下次保存时自然消失。
- 新包名 `rapp-relay`，二进制 `rapp-relay`，目录 `rust/relay`，库名 `rapp_relay`。Docker 镜像名 `ghcr.io/wizlijun/rapp-relay` 不变。
- 不发版，不改版本号。
- 用户同时在改仓库：在分支 `feat/drop-relay1` 上做；不碰 `README.md`、`docs/archives/`、未跟踪的 spec / plan 文件、`tasks/`（那里是历史记录）。按文件名 `git add`，不用 `git add -u/-A/.`、`git stash/checkout/restore/reset`。
- 不跑 `cargo fmt`；只对改过的文件跑 `rustfmt --edition 2021 --config max_width=120,use_small_heuristics=Max <file>`。
- `flutter test` 会改 `gui/pubspec.lock`：测完 `git diff gui/pubspec.lock` 若有变化，不要提交它（告诉主会话，由它恢复）。Flutter 在 `~/development/flutter/bin/flutter`，cargo 在 `~/.cargo/bin`。
- 每个 Rust 任务结束：`cd rust && cargo test --workspace` 全过，`cargo clippy --workspace --all-targets -- -D warnings` 无警告。GUI 任务结束：`cd gui && flutter test` 全过、`flutter analyze` 无问题。
- 提交信息沿用仓库写法（`refactor(hub): …`、`refactor(service): …`、`refactor(gui): …`、`chore(scripts): …`、`refactor(relay): …`），结尾加 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。

## Review Focus

1. 升级前经旧 relay 加的主机（`hosts.json` 里有 `lan` 地址列表）升级后仍在局域网里连得上，路径显示 `lan`。
2. `hosts.json` 里 `lan` 为空的老主机（只填过 ID）：`apps` / `open` 立刻失败，错误是 `no address: add the host again as id@ip`；presence 照常报离线，不卡、不刷日志。GUI 显示"没有地址，请用 ID@IP 重新添加"。
3. 带旧字段（`relay`、`key`、`secret`）的 `service.json`：service 正常启动，ID / 密码 / 名称不变。
4. 老版本 B（0.5.5 的 hub）发来 `{"op":"auth","token":"…"}`（不带密码）：A 回 `auth required`，记一条 `auth_fail`，不崩。
5. 新 GUI 连到还带 `relay` 字段的老 service（升级过程中）：本机卡片照常显示，不报错。

每条的测试写在负责那块代码的任务里（任务 1：1、2；任务 2：3、4；任务 3：2、5）。
