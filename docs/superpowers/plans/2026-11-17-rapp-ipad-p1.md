# rapp iPad P1 可用版 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 按 spec §15 P1 做出能在 iPad 上日常用的 rapp：接入、看设备、开 app 会话和终端会话、触摸 / 触控板 / 外接键盘 / 输入板都能用，切后台回来自己恢复。只做常规档。

**Architecture：** 在 `gui/` 里加 iOS 目标，和桌面共用同一份 Dart 代码。hub 编成静态库 `rust/hub-ffi`，在进程里跑，Dart 用 `dart:ffi` 接，接口同 P0 探查，另外补上评审时提的几处修改。画面层用 `RappSession`：`KeyRouting` 去掉对 AppKit 的依赖；`SessionPlugin.swift` 改成 macOS 和 iOS 共用一份，平台差别用 `#if` 隔开。iOS 的引导入口在 `main_ios.dart`，不碰托盘和窗口管理。哪个平台能做什么，统一查一张"平台能力表"（`PlatformCaps`）。iOS 上 `service.json` 由 hub 写（新加 `access` / `set_access` 两条命令）。

**Tech Stack：** Rust 1.99（目标 `aarch64-apple-ios`、`aarch64-apple-ios-sim`）、Xcode 27.2、Flutter 3.44.1（`~/development/flutter/bin`）、Swift 6 / SwiftPM、iOS 17。

**Spec：** `docs/superpowers/specs/2026-11-17-rapp-ipad-duo-design.md`（§6、§7.2、§7.4 的 Z1、§8、§9、§10、§11、§12、§14.1、§15 P1）。P0 的结论在 `docs/superpowers/measurements/2026-11-17-rapp-ipad-p0.md`，探查代码在分支 `probe/ipad-p0`，只作参考，不合入。

## Global Constraints

- 桌面三个平台的行为不能因为这次改动而变（spec §2）。有两处例外，是 spec §16.2 第 4 条定的"分档规则对桌面也生效"：§7.2 里左侧面板的宽度、全景换行。`swift test`、`cargo test --workspace`、`flutter test`、`flutter analyze` 都要全过。
- 线路协议、relay、A 端都不改（spec §2）。hub 只加选项和命令，这些只在 hub-ffi 打开时才生效。
- key 和 relay 地址只能在运行时由用户填进 App，不写进任何提交、构建文件或 `--dart-define`。日志里 key 必须遮住。
- iOS 最低版本 17.0，包标识 `com.rapphub.rapp`，iPhone 和 iPad 通用，模拟器只编 arm64（`ARCHS[sdk=iphonesimulator*] = arm64`）。iPad 支持四个方向，`UIRequiresFullScreen` 设为 NO，使用 UIScene 生命周期（spec §14.1）。
- 签名团队 `T5G56DH47L`，用 Xcode 自动签名（`-allowProvisioningUpdates`）。
- iOS 入口不能调用 `tray_manager`、`window_manager`、`screen_retriever` 的任何方法（spec §6.4）。
- 面向用户的文字用中文，措辞照 spec 原文（如「正在重连…」「切到后台」「连接同一网络里你自己的电脑」）。
- 所有可点控件不小于 48×48（spec §7.2）。
- 每次跑完 Flutter 测试都要把 `gui/pubspec.lock` 还原（`git checkout gui/pubspec.lock`）。如果是有意加了依赖，就提交新的 lock。
- 不提交到 main。本计划的分支是 `feat/ipad-p1`，做完把分支名交给 rapp-49 合入。

## Review Focus

1. **hub 自己退出了**（panic、`run` 报错）：Dart 侧所有在等的请求要立刻失败，界面显示 hub 出错，不能卡在转圈。Task 3 测 C 层的 `on_line(NULL)`，Task 7 测 Dart 侧未完成的请求都失败。
2. **回前台时有会话正在打开，或者草稿只写了一半**：草稿要还在，命令不能发到已经关掉的 sid 上，也不能开出两个会话。Task 10 测。
3. **`set_access` 给了坏的 key 或空的接入点**：返回错误，原来的 `service.json` 不能被改，界面上能看到原因。Task 1 测 hub，Task 7 测引导页。
4. **外接键盘的键按住时焦点离开画面，或 App 进了后台**：A 上不能留下按住的键。Task 6 测 `KeyTracker` 和 iOS 的松键规则。
5. **iPad 分屏、侧拉把窗口压窄**（834、744、600、507 宽）：P1 只有常规档，但窄窗口也不能溢出，会话切换、需要你、流量标签三样要一直在。Task 11 在这几个宽度上测。

**Interfaces:**
- `enum LatchState { off, once, locked }`
- `class ModifierLatch extends ChangeNotifier`
  - `LatchState of(int bit)`、`int get flags`（once 和 locked 的位 OR 起来）
  - `void tap(int bit, {Duration? sinceLast})`：
    - off 时点一下变 once；
    - once 时，距上次点击不到 350 ms 就变 locked，否则变 off；
    - locked 时点一下变 off。
  - `void used()`：把所有 once 清掉，locked 留着。
  - 位值：⌘ `1048576`、⌥ `524288`、⌃ `262144`、⇧ `131072`。

  - `void keyEvent(Object sid, int keyCode, int modifiers, {required bool down})`，发 `key_event`；
  - `void latch(Object sid, int modifiers)`，发 `latch`。
  - 每次 latch 状态变了，把 `flags` 告诉原生，外接键盘的下一个键就会带上。收到原生发来的 `latch_used` 事件时调 `used()`。
- `AppKeyRow({required MainState state, required Object sid, required ModifierLatch latch})`：
  - 键：Esc 53、Tab 48、⌘、⌥、⌃、⇧、← 123、↑ 126、↓ 125、→ 124、删除 51、回车 36；每个键不小于 48。
  - 普通键：`port.key(sid, code, latch.flags)`，然后 `latch.used()`。
  - 修饰键的颜色：once 是主题强调色描边，locked 是强调色实底。
