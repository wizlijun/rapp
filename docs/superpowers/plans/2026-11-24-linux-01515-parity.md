# Linux 0.15.15：对齐 macOS 0.15.14

基线 main `b8469482`。用户要求补齐 Linux 版并发布。

## 差异与修复

上游已将共享录音时限、Linux worker 音频缓冲与 worker 等待时限改为 5 分钟，但 `LinuxSpeechChannel.finishWait` 仍为 80 秒。长录音最终识别可能在 UI 的 5 分钟等待结束前被适配层杀死。

- 适配层最终识别等待改为 5 分钟；MainState 与适配层共用同一常量，避免两层再次偏离。
- 修正 Linux 语音规格中残留的 80/90 秒描述及按钮注释，补充发行包说明。
- 回归验证默认适配层在 299 秒时仍不报错，300 秒时终止卡住的 worker；继续覆盖子进程最终文字、取消、启动超时和失焦。
- 真实 Whisper 模型使用公开 JFK PCM：短语音、静音、放在录音第 299 秒结束的语音、5 分钟以后出现的语音；前者应识别，超出时限应排除。测试不访问用户麦克风，不下载模型。
- PCM 读取使用已在项目使用的固定数组切片 API，消除当前 Clippy 的常量 chunks_exact 警告；已有符号采样/EOF 测试覆盖行为。

## 发布与边界

Linux 发布号 0.15.15（Flutter 0.15.15+71），协议仍为 v15，与 macOS 0.15.14 兼容。使用 `--latest=false` 保留 macOS Latest。输出 Omarchy/Arch x86_64 包、便携包和 SHA256SUMS，不自动安装。

Linux 仍用本地 Whisper CPU 后端；本轮对齐录音上限与等待策略，不承诺识别准确率和速度与 Apple 后端相同。真实麦克风、多语言准确率需设备验收。
