目标：严格跟随已发布的 macOS `v0.15.56` 版本号（不抢先递增版本号、不新建 tag），对齐快捷区第二行 `⌘C ⌘V ⌘T ⌘ ⌃ ← →` 与终端 `⌘`+字母快捷键，同时在 `#[cfg(target_os = "linux")]` 下修复 `tasks/todo.md` 交接指出的 Linux 被控端 `applications` 能力字段漏传问题，构建并向现有 GitHub Release `v0.15.56` 上传 Omarchy / Arch `x86_64` 双格式包。

## 1. 差异审计与修复

审查 `838cdc6b..1adea012` 的 Linux 侧行为：

1. **快捷区第二行重排与终端 `⌘` 快捷键（`feat/bar-cmd`）**：
   - 快捷区第一行调整为 `Tab ⇧Tab Esc ⌃C ↑ ↓ ⌫ ⏎ ⋯ ⌄`（`⌃` 移入第二行），第二行调整为 `⌘C ⌘V ⌘T ⌘ ⌃ ← →`（移除 `⌥` 及 `⌃O`/`⌃R`/`⌃T`/`⌃B`/`⌃L`，工具命令统一保留在常用语条）。
   - `KeyBar` 的 `⌘T` 在文本终端上直接触发 `TermStage` 新建相邻终端（带 `WaitCard`），在应用会话上发送 `⌘T`；粘滞 `⌘` 在文本终端上配合实体键盘或写作板字母触发 rApp 快捷键（`c`/`v`/`t`/`w`，长按不重复触发，无关字母消费 `⌘` 且不写入 PTY）；再次点击 `⋯` 收起第二行时自动松开亮着的 `⌃` 与 `⌘`。
   - Linux 桌面端 `KeyBar` 继续包裹在 `TextFieldTapRegion` 内，鼠标点击不丢失写作板光标与输入法选区。
2. **修复 Linux 被控端 `applications` 能力透传（`rust/service/src/workers.rs`，`#[cfg(target_os = "linux")]`）**：
   - 响应 `tasks/todo.md` 给 Linux session 的发现：`rapp-host-linux` 在 `check` / `list-apps` 中已返回 `"applications": desktop.application_capture_supported()`，且 `workers::capabilities()` 已读取 `state.permissions["applications"] == true`，但 `workers::permissions(v)` 此前漏拷了 `v["applications"]`，导致 Hyprland / X11 被控端对外恒报 `applications: false`。
   - 在 `workers::permissions` 的 `platform == "linux"` 分支中以 `#[cfg(target_os = "linux")]` 保留 `applications` 布尔值（对 macOS / Windows 零字节影响），同步更新 `scripts/test-linux-bundle.py` 断言并补充单元测试。
3. **Windows A / B 段草稿目录（`rust/host-core`、`rust/host-windows`、`rust/svc-windows`）**：
   - 均未接入 `rust/Cargo.toml` workspace 成员表，对 Linux 构建与打包零影响。
