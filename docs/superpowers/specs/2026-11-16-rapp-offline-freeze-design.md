# 断网时冻结画面，不弹对话框（短设计）

日期：2026-11-16

## 为什么

现在会话一断开，舞台就整块换成 `DisconnectedStage`：上一帧盖斜条纹，正中是「重连／停止」「结束会话」。
断网（在车上、电梯里）是最常见的断开，这样做太粗暴：画面没了，输入板没了，写到一半的字看不见。
用户要的是：画面停在上一画面，文本终端也停在最后的内容，输入板照常能写，只是提示发不出去；离线能做的事都不受影响。

## 目标

- 网络原因的断开（`autoReconnects(reason)` 为真：网络断了、连接超时、中继连不上、对方离线）时，舞台**不换**：
  - app 会话：`Picture` 继续显示最后一帧，不盖条纹。
  - 文本终端：`TermStage` 继续显示最后的内容，能滚动、选中、复制。
  - 输入板照常挂着：能用「输入」按钮或 Ctrl+Enter 打开，能打字、编辑、用输入历史。
    在画面上直接打字唤出输入板（type-to-compose）冻结时不做：那要远端 runner 把按键交回来，链路已断（我定的，写计划时发现）。
  - **发送键变灰**；会发送的回车（含「直接回车」）什么也不发，内容留在输入板里。
  - 舞台顶部一条细提示：文字用现有的 `waitWordOf(rec)`，没有就用 `disconnectWord(reason)`，自动重试中再带「正在重连…」；右边一个按钮：在自动重试时是「停止」，停了以后是「重连」（hub 不可用时灰掉）。
- 网恢复、新会话换进来后，草稿照现有的 `ComposerModel.adoptFrom` 搬过去，发送键自动恢复。

## 不做

- 不做排队发送（用户选的：发送键变灰、内容留着，网通后手动发）。
- 非网络原因的断开（被接管「拿回来」、远端关闭 app、密码不对、你断开了等）照旧用 `DisconnectedStage`。
- 「结束会话」不放在提示条上，从顶栏菜单、会话列表结束。
- 不改已拆出去的单独窗口（detached）在断开时的行为。
- hub 本身有问题（`hubProblem`）时照旧显示那段文字。

## 不能出现

- 冻结期间任何输入、尺寸变化发到 A（原 R25：断开后不输入、不改尺寸）。舞台尺寸变了也不发 resize。
- 断网或恢复时舞台组件被换掉，导致输入板焦点、光标、终端滚动位置跳动。
- 输入板里写的字因断开或重连丢失。

## 办法（用户选了 A）

- **A. 舞台不换，加"冻结"**（选用）：网络原因断开时，`stage.dart` 照常走 `Picture`／`TermStage`／`composerLayer` 那几支，只是标成冻结；所有送往 A 的路径在冻结时不发；输入板发送看冻结状态变灰；顶部加提示条。画面、终端、输入板是同一套组件，焦点不跳。代价：几条输入路径都要加判断、都要测。
- B. 改造 `DisconnectedStage`，在里面另渲染终端、塞进输入板。等于另造一份，断开/恢复时组件一换，焦点和滚动会跳，不合"停在上一画面"。不选。

## 已定的做法

- 冻结的判定：当前记录 `phase == disconnected` 或 `lastSid != null`（在重连、新画面还没换进来），并且 `autoReconnects(rec.reason)` 为真。重连中（`connecting`）同样冻结，提示条写「正在重连…」。
- 舞台看到的会话照旧是 `_stageRemote(r)`（`lastSid ?? sid`）。终端断开后 `TermSessionPort` 只标 `disconnected`，模型还在，`TermStage` 可以照常画。
- 送往 A 的输入以 `MainState._liveSid` 为闸门（已经挡住 resize、selectWindow、回车、点击等）；`Picture`、`TermStage`、输入板里不经过这个闸门直接调 port 的路径要逐条找出来补上。
- 提示条和现有的锁屏横幅（`lockBanner`）一起放在顶部那一列里，不遮输入板。

## 留给实现者

- 提示条的具体样式（用现有 tokens 和 `RappButton`，跟锁屏横幅一个量级）。
- 冻结标记怎么传给 `Picture`／`TermStage`／`ComposerPanel`（参数还是从 `state` 读）。
- 发送键变灰时要不要加一个 tooltip。
