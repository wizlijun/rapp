# rapp 输入记录

状态：设计稿，待用户确认。

和《输入区：写作面板》（`2026-11-14-rapp-composer-writing-panel-design.md`，下称「写作面板」）是一对：那一份管怎么写，这一份管写过的东西去哪里。

标了【我定的】的是我做的决定，用户没有逐条确认过，可以否掉。

## 1. 为什么做

用户的话（2026-11-14）：

- 「输入历史的记录，需要持续记录，全局统一，每条输入记录，都应该有时间、主机-会话-窗口标题等有用的元数据信息，以为后续给 agent 分析时做上下文；也可以当做输入意外丢失后的召回。」
- 「已发送记录要 git 同步。」

现状：草稿只在内存里（`ComposerModel`），每个会话一份，rapp 退出、崩溃或会话结束就没了。发出去的文字不留任何记录。日志按可观测性规格不记键入的文字。

## 2. 目标、不做的、不能出现的

目标：

- G1 写作面板发出去的每一段都留下，带上时间和「发给了谁」。
- G2 全局统一：所有主机、所有会话、所有主控台的记录在一处，按时间能合成一条线。
- G3 写了没发的也不丢：崩溃、误关、会话结束之后能找回来。
- G4 是普通的文本文件，Agent 直接能读。

这次不做：

- 点着画面直接敲的键、按键排上的键：不记（§3）。
- 图片和文件的内容：只记描述。
- 同步前过滤密码和密钥（决策文件待定清单第 5 条是同一个问题，一起定）。
- 给 Agent 的专门接口；和画面记录合成一条时间线（路线图 D1 做，这里只保证对得上）。
- 加密。

不能出现的：

- 输入的文字出现在日志里。
- 记录写不进去，导致发送被挡住。
- 发送中途 rapp 崩溃，这段文字既没发出去也找不回来。

## 3. 记什么

| 来源 | 记不记 | 理由 |
|---|---|---|
| 写作面板发出去的每一段 | 记，`kind: "sent"` | 成段的、有意写下的话 |
| 写了没发的草稿 | 记，先在本机（§5.2），会话结束时变成 `kind: "draft"` | 这就是「意外丢失后的召回」 |
| 点着画面直接敲的键 | 不记【我定的】 | 是逐键的，里面会有密码；记了就成了键盘记录器 |
| 按键排的 Esc、回车等，空着按 Enter 发的回车 | 不记【我定的】 | 没有文字内容 |
| 终端会话的写作面板 | 记，和 app 会话一样 | 同一个面板 |

## 4. 一条记录

一条一行 JSON：

```json
{"v":1,"id":"01JCM7Z3K8…","ts":"2026-11-14T21:37:05+09:00","kind":"sent",
 "from":{"id":"b7f2…","name":"bruce-tablet"},
 "host":{"id":"3a91…","name":"bruce-mac"},
 "app":{"id":"com.apple.Terminal","name":"终端"},
 "session":"3a91…/com.apple.Terminal","run":"…",
 "window":{"id":4123,"title":"agent — zsh"},
 "projects":["rapp"],
 "text":"可以，继续改。这一轮只做三件事：…",
 "blocks":[{"kind":"image","label":"图片 #1 1440×900","bytes":182044}],
 "result":"sent","after":"none","source":"typed"}
```

| 字段 | 是什么 |
|---|---|
| `v` | 格式版本，现在是 1。读的一方遇到不认识的字段就跳过 |
| `id` | 按时间排序的唯一标识（ULID 那一类）；同一毫秒内也不重复 |
| `ts` | 这台主控台的本机时间，带时区 |
| `kind` | `sent` 或 `draft` |
| `from` | 从哪台主控台写的：设备 id 和名字 |
| `host` | 发给哪台主机：设备 id 和名字 |
| `app` | 哪个 app：标识和名字。终端会话是 `term:` 开头的那个标识 |
| `session` | 会话的键，就是现有的 `<主机 id>/<app 标识>` |
| `run` | 这个会话这一次打开的标识。同一个 app 先后承载过很多段不同的对话，光靠 `session` 分不开；`run` 加窗口标题能分开（评审 A5）|
| `window` | 发送那一刻当前标签的窗口 id 和标题 |
| `projects` | 这个会话当时属于哪些项目，可以是空的 |
| `text` | 文字全文 |
| `blocks` | 块：种类、标签、大小、文件名。粘贴成块的长文字带全文（`text`）；图片和文件不带内容 |
| `result` | `sent`、`partial`（带 `sentPieces`：发出了前几块）、`failed` |
| `after` | 发完有没有补回车：`return` 或 `none` |
| `source` | 现在都是 `typed`；留给以后的语音输入 |

`kind: "draft"` 的记录没有 `result` 和 `after`。

## 5. 存在哪里

### 5.1 已发送的

```
$ROOT/devices/<这台设备 id>/inputs/2026-11-14.jsonl      进 git
$ROOT/local/inputs-pending.jsonl                          不进 git
```

- **一天一个文件**，按这台设备的本机日期；只在末尾加行。
- 放在 `devices/<id>/` 下面，沿用它的规则：每台设备一份，只由这台设备写。几台主控台同步时各写各的文件，不会冲突。「全局统一」就是把所有设备的 `inputs/` 按 `id` 合起来。
- **先在本机放 10 分钟，再进同步的文件**（评审 U4）【我定的】：新记录先写进 `local/inputs-pending.jsonl`，满 10 分钟后挪到当天的文件里。这 10 分钟里删掉一条是真的删掉；挪过去之后 git 历史里就一直有了。读记录的一方把两处合起来看。
- GUI 来写（写作面板在它里面）；git 的提交和推拉仍然只由 rapp-service 做，不用改。
- 一直留着，不自动删。我估计一年在几十 MB 以内（没有实测）。
- 写不进去时不挡发送，在写作面板的提示行说一次「输入记录没写进去」和原因。

### 5.2 草稿

```
$ROOT/local/drafts/<会话的键>.json      不进 git，0600
```

- 停笔 1 秒后存一次；先写临时文件再改名，不会留下写了一半的文件。
- **发送时不马上删**：等这一段的记录写进了 5.1 的文件，才删草稿（评审 A6）。这样发送中途崩溃，文字还在草稿里。
- 草稿空了就删文件。
- 会话「结束」时还有草稿：变成一条 `kind: "draft"` 的记录，草稿文件删掉。会话只是「断开」时，草稿留着。
- 启动时发现 7 天以上没动过的草稿文件：同样变成 `draft` 记录【我定的】。

## 6. 召回

R1. 重开 rapp、重连会话：草稿自己回到写作面板里。

R2. 编辑区空着时按 ↑：取这个会话的上一条（`sent` 和 `draft` 都算）；再按 ↑ 更早一条；↓ 往回；回到最新之后再按 ↓ 变回空的。取出来的内容一旦改过，↑↓ 就恢复成移动光标。

R3. 编辑区空着时的灰字带一句提示：「写给 <app 名> · ↑ 上一条」。

R4. 「输入历史」列表，两个入口：写作面板的「＋」，和左侧面板「资源」标签里剪贴板旁边的一节（评审 U3：它和全局剪贴板是同一类东西，一个是复制过的，一个是写过的）。
  - 顶上一个搜索框，三个范围：这个会话、这台主机、全部。
  - 每条显示：时间、`主机 · app · 窗口标题`、文字的第一行；草稿标「没发出」。
  - 每条三个动作：放进输入框、复制到本机、删除。
  - 别的主控台写的记录也在列表里，但不能从这里删（那个文件不归这台设备写）。

R5. 删除的说法要老实：还在本机的 10 分钟里，按钮写「删除」；已经同步的，按钮写「从记录里去掉」，旁边注明「git 历史里还在」。

## 7. 给 Agent 用

- 就是 `$ROOT/devices/*/inputs/*.jsonl`。数据目录的 `README.md` 里加一段说明格式和位置。
- 它和沟通机制规格的消息层是同一条时间线的两半：远端说了什么要靠看画面，用户说了什么在这里是原文。两边用 `ts`、`host`、`session` 对上【我的分析】。
- 以后（不在这一版）：终端会话的记录可以带上发送那一刻屏幕最后几行文字，Agent 就知道这句话是在回答什么（评审 U6）。会多存不少内容，也多一分带出密钥的可能，到时候再定。

## 8. 开关和隐私

- 只记写作面板里的内容，从不记直接敲的键。
- **总开关**：`gui.json` 里 `inputHistory`，默认开【我定的】。
- **按 app 关**：app 配置里加 `recordInput`，默认 `true`；密码管理器、网银这类 app 可以设成 `false`（评审 U4）【我定的】。关着的会话，草稿照样在本机保存和恢复，只是不产生记录。
- 《配置规范总览》里有一条「`devices/` 里不写口令、key、secret」。输入记录是用户自己写的话，rapp 保证不了里面没有密钥。这一条要改写成：rapp 自己不往那里写机密；`inputs/` 里是用户的原话，可能含私事（和钉住的剪贴板同样对待）。
- 日志照旧，一个字都不记。可观测性规格里「绝不记键入的文字」要注明：说的是日志；输入记录是用户自己的数据，在数据目录里。

## 9. 做法的选择

存在哪里：

| 做法 | 取舍 |
|---|---|
| 只放本机（`local/`） | 最安全；但不统一，换一台主控台就看不到 |
| **进 git，按设备分目录的文本文件（用户已选，U127）** | 多台设备统一，和「画面文字用 git 同步」一致，Agent 直接读；代价是 git 历史删不掉，所以加了 10 分钟的缓冲和按 app 的开关 |
| 数据库文件 | 查得快；但不是文本，git 看不出改了什么，Agent 不能直接读 |

格式：一天一个 JSONL，而不是像钉住的剪贴板那样一条一个 `.md`。一天几十上百条，一条一个文件太碎；多行文字和元数据放在 JSON 里不会有歧义【我定的】。

在哪一头记：在主控台（B），不在被控端（A）。文字是在 B 写的，B 手里就是原文；A 可能是一台没有界面的服务器【我定的】。沟通机制规格里「记录在被控端做」说的是画面，不是这个。

## 10. 分步

| 步 | 做什么 | 验收 |
|---|---|---|
| H1 记下来 | 记录和草稿的读写；写作面板发送和草稿接上（在写作面板 S1 之后）；两个开关；README 和几份规格的文字 | 发三段话到两个会话，文件里有三行，字段都对；发送中强杀 rapp，重开后文字在输入框里；关掉开关后不再产生记录；日志里搜不到任何一段正文 |
| H2 找回来 | ↑ 取上一条；「输入历史」列表、搜索、放进输入框、删除 | 空着按 ↑ 取到刚才那一条；在列表里搜一个词找到三天前的一条并放回输入框；10 分钟内删除后，两处文件里都没有它 |
