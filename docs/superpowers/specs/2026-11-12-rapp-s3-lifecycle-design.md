## 1. 目标与非目标

目标：
- 会话断了不消失，留着条目、设置和最后一帧，一键重连。
- 每个会话的状态和流量看得见：顶栏、会话列表、面板底部总览。
- 顶栏「需要你」把断开的会话和掉线的设备数出来，点开直接处理。

非目标：
- "Agent 等你"信号（S8）。设计语言里的"等你"灯保留，S3 不产生它。
- 自动重连。S3 只做手动「重连」（§6 第 1 条）。
- 断开的会话跨重启保留。退出 rapp 后全部清掉（§6 第 2 条）。
- 全景（S4）。

## 2. 用户看到的行为

### 2.1 状态怎么变

| 从 | 到 | 什么时候 |
|---|---|---|
| — | 连接中 | 打开、重连 |
| 连接中 | 活动 | 收到第一帧 |
| 连接中 | 已断开 | 连不上（离线、密码错、超时）；提示写原因 |
| 活动 | 空闲 | 连续 10 秒没有新帧（A 上画面没变时 host 不发数据） |
| 空闲 | 活动 | 来了新帧 |
| 活动、空闲 | 已断开 | 用户点「断开」；网络断；A 端关了 app 或 host 退出 |
| 已断开 | 连接中 | 用户点「重连」，或再次打开同一（设备, app） |
| 任何 | 已结束 | 用户点「结束会话」（点两次）；条目从所有列表消失 |

- 关掉分离出去的独立窗口仍然是"结束会话"（S2 §6 第 2 条）。
- 断开原因用中文短语：「你断开了」「网络断了」「A 端关闭了 app」「对方离线」「密码不对」「连接超时」，其余原样显示在冒号后面。

### 2.2 已断开的会话

- 条目留在会话列表里，状态灯是"已断开"，第二行写原因。
- 选中它时，舞台显示最后一帧（S2 的纹理不释放，停在最后一帧），上面盖斜条纹，居中一个「重连」按钮，按钮下一行写原因。分离中的会话断开时，独立窗口自动放回舞台再显示这一屏。
- 「重连」：同一（设备, app），沿用断开前的串流设置（档位、密度、帧率）和当前窗口；条目、位置、所属分组都不变。重连成功后换成新画面。
- 已断开的会话不占流量，不计入总流量。

### 2.3 流量

- 每个会话每秒上报一次收到的字节数（A→B 画面和侧通道合计）。
- 顶栏流量标签：五格电平和数字（例：`48 KB/s`），按当前会话显示；没有选中会话时不显示（主界面规格 §3.1）。电平按 1、8、32、128、512 KB/s 五档点亮。
- 会话列表每行在状态文字的位置显示流量数字；空闲显示「空闲」，已断开显示原因。
- 面板底部总览的「总流量」是所有活动会话之和（S1 里一直是「—」）。

### 2.4 需要你

- 顶栏在流量标签左边加「需要你」：一盏灯和一个数字。数字 = 已断开的会话数 + 掉线的设备数。为 0 时显示活动灯，不显示数字。
- "掉线的设备"：这次启动以来见过在线、现在离线的设备。从没在线过的设备不算，避免常年不开的机器一直占着数字。
- 点开从右上角浮出，最多列 3 件，按发生时间新的在前；超过 3 件在末行写「还有 N 件」：
  - 某会话已断开：「<app> @ <设备> 已断开：<原因>」·「重连」
  - 某设备掉线：「<设备> 离线」·「查看」（打开设备面板并选中它）
- 没有时显示活动灯和「没有需要你处理的事」。
- 和串流菜单互斥：开一个就关另一个（主界面规格 §5 第 2 条）。点浮层外或按 Esc（焦点不在画面上时）关闭。

### 2.5 设备在线

- hub 每 30 秒探一次所有设备是否在线（复用现有探测，失败不报错，只改在线状态），设备面板和需要你都用这份结果。
- 打开设备面板仍会立刻探一次（S1 行为不变）。

### 2.6 断开按钮

- 串流菜单第 6 组「会话」：路径和状态、「断开」、「结束会话」（点两次）。已断开时「断开」换成「重连」。
- 会话列表每行不加按钮，保持 S1 的样子（选中后在舞台和串流菜单里操作）。

## 3. 接口改动（细节在计划里定）

- 嵌入会话（macOS）：S2 的 runner 侧会话对象上报 `traffic`（每秒字节数）、`frame`（已有）和 `disconnected`（原因）；GUI 据此算空闲和流量。断开时不释放最后一帧的纹理，结束时才释放。
- 主动断开：GUI 关闭到 A 的连接但保留会话条目；hub 收到 `close` 照常释放流，`closed` 事件里带原因 `user`。
- 重连：GUI 用同一（设备, app）重新 `open`（嵌入选项），新 sid 换到同一个条目上。
- hub：加一个定时探测（30 秒，一次一个设备，串行），探测结果用现有 `hosts` 事件里的在线字段，或新事件 `presence {id, online}`，计划里二选一。
- 日志：断开、重连各记一行（原因、设备、app），不记内容。

## 4. 拆分建议

1. 会话状态机和断开原因（纯 Dart，MainState 里），含空闲判定。
2. runner/hub 上报流量和断开原因；主动断开、重连。
3. 已断开的舞台（最后一帧 + 斜条纹 + 重连）和分离会话断开时自动放回。
4. 顶栏流量标签电平、会话列表流量、总流量。
5. 需要你计数、浮层、和串流菜单互斥；hub 30 秒在线探测。

## 5. 验收

- 打开一个 app，状态从连接中到活动；A 上画面不动 10 秒后变空闲，动一下回到活动。
- 串流菜单点「断开」：条目留着，舞台显示最后一帧加斜条纹和「重连」；需要你 +1；点「重连」回到活动，设置和窗口不变。
- 在 A 上关掉被串流的 app（用自己拉起的 Calculator）：会话变已断开，原因「A 端关闭了 app」。
- 停掉自己起的 host：会话变已断开；设备在 30 秒内变离线，需要你出现"离线"一件。
- 顶栏流量随画面变化跳动；总流量等于各活动会话之和。
- 「结束会话」点两次后条目消失，需要你相应减少。
- 测试只用自己起的 host、client 和自己拉起的 app，按 PID 操作。

## 6. 我做的假设（按默认执行，验收时可改）

1. **不自动重连。** 网络抖一下也要手动点「重连」。另一种：断开后自动重试几次（省事，但 A 端关了 app 时会反复把它拉起来）。
2. **断开的会话不跨重启保留。**
3. **空闲阈值 10 秒。**
4. **"掉线的设备"只算这次启动后见过在线的。**
5. **在线探测 30 秒一次。**
6. **流量电平五档：1、8、32、128、512 KB/s。**
