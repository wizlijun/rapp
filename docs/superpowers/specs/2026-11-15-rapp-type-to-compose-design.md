# 按字母键打开写作面板（设计稿，短）

状态：用户已确认（2026-11-15），已实现（feat/type-to-compose）；待真机确认 §5 拼音检查和 Figma 关开关后 V/R。补《写作面板》（`2026-11-14-rapp-composer-writing-panel-design.md`）和《写作面板浮动》（`2026-11-15-rapp-floating-composer-design.md`）。

## 1. 要什么、为什么

用户原话（2026-11-15）：「在app上一旦输入字母按键，说明有意图输入。则直接激活输入框，显示并输入文字。 其他按键不做激活输入框。 打开输入框时应先把远程输入法改为英文。」

- 画面有焦点时按下字母键，就打开写作面板，光标放进编辑框，这个字母作为第一笔写进去，接着打下去。
- 其他键（数字、标点、空格、回车、方向键、Tab、Esc、F 键、带 ⌘⌃⌥ 的组合键）照旧发给远端，不打开面板。
- 不管用哪种方式打开面板，打开时都先把远端输入法切到英文（现在只在发送前切）。

### 1.1 输入法原则：中文输入交给本机

用户原话（2026-11-15）：「这种设置远端输入法为英文的做法，相当于是强制把中文输入的活接管到本机。方便用户一致的输入法体验。」

这是整个写作面板在输入法上的原则，不只管这一个功能：

- 组字、选候选都在本机完成，用的是本机的输入法、本机的词库和习惯。不管远端是哪台机器、装了什么输入法，用户打中文的体验都一样。
- 远端只收组好的文字。远端的输入法一律切到英文，这样它不会吃掉或改动发过去的字。
- 所以，凡是要往远端送文字的时刻都先切英文：打开面板时（本稿新增）、发送前（`prepareInput`，已有）、提示行上的「点一下切到英文」（W11，已有）。串流菜单里的「切回 拼音」照样保留，给偶尔要在远端直接用输入法的时候。
- 本稿 §2 第 2 条（第一个字母也交给本机输入法），就是这条原则在「按字母键打开面板」上的落实。

## 2. 用户定下的两件

1. 直接往远端打字（输密码、Figma 按 V/R、游戏）靠每个 app 自己的开关：app 设置里加一项「按字母键打开写作面板」，默认开，记在 apps.json，字段名 `typeToCompose`（`false` 才写入，和 `recordInput` 一样）。关掉的 app，字母照旧直接发给远端。内置的终端模拟器（终端、iTerm2、Ghostty、Warp）默认关：串流的终端里 vim、less、y/n 提示都靠字母键，sudo 密码也不该进草稿（终审补，2026-11-15）。
2. 本机在用中文输入法时，第一个字母也交给本机输入法，打 nihao 就是「你好」，不是「n爱好」。Mac 上的做法：先把焦点移到面板，再把原来那一下按键重新交给窗口。这一步先做小试验（见 §5）；试验不通，就退回「把这个字母原样放进面板」。Linux 先按原样放进面板做。

## 3. 怎么做（思路已确认）

判定在原生层，按键重放回窗口。

- **什么键算字母（我的判断）：** 按下（不是松开，不是自动重复）；不带 ⌘、⌃、⌥，带 Shift 或大写锁定都可以；按当前键盘布局，这个键只出一个字符，并且这个字符是字母（Unicode 字母类，所以 AZERTY、俄文布局也对）。按字符判断，不按键位。
- **什么时候生效（我的判断）：** 主窗口里的画面有焦点；这个会话是 app 窗口，不是终端（终端的 vim、shell 都靠字母键）；这个窗口允许出写作面板（没被「不要输入区」规则挡掉）；这个 app 的 `typeToCompose` 不是 `false`。面板已经开着但焦点在画面上时，也一样：焦点回到面板，字母写进去。拆出去的独立窗口不参与，那里没有写作面板。
- **Mac：**
  1. Dart 在 `picture_focus` 里多带一个 `compose`（布尔），表示这个会话是否生效（上面四条都满足）。条件变了就重发。
  2. `KeyRouting.swift` 的分流多一个去向 `compose`：画面有焦点、`compose` 为真、是字母键时走这里。原生层不把这一下发给远端，先存下这个 NSEvent，再给 Dart 发 `compose_key {sid}` 事件。这个键之后的松开也不发给远端：按下没发出去，松开也不该发。
  3. Dart 收到后打开面板（打开时远端切英文，见下条），焦点进编辑框。等编辑框真拿到焦点，下一帧调 `compose_replay {sid}`。
  4. 原生层把存下的那一下重新交给窗口。这时画面已经不是焦点，按键走本机，经本机输入法进编辑框。约 1.5 秒内没等到重放就丢掉，不会晚到乱插（原定 500ms；面板第一次打开可能慢过半秒，开头的字母会丢，实现时放宽）。
- **Linux：** `linux_session_port.dart` 的 `handleKeyEvent` 用同样的条件判断（用 `event.character`）。命中就吞掉这一下，打开面板，把这个字母写进草稿，光标放到末尾。
- **打开时远端切英文：** 放在一个地方做：会话里写作面板从关到开的那一刻，如果远端报过输入法而且不是英文，就调一次 `selectInput('')`。按钮、快捷键、剪贴「插入」、按字母键，四种打开方式都经过这里。发送前的 `prepareInput` 照旧保留，作为兜底。
- **app 设置页：** 在「记下发给这个 app 的话」下面加一个开关「在画面上按字母键时打开写作面板」，说明写「关掉后字母直接发给这个 app，适合 Figma、游戏、密码管理器」。

## 4. 不做什么

- 不记录触发的那一下：日志里永远不出现打的字。字母进了草稿，就和手打进草稿的字一样处理，发送时按 `recordInput` 决定记不记。
- 不改终端，不改拆出去的窗口。
- 不在远端判断：远端看不到本机输入法，开关也不在那边。
- 不让 Flutter 先看每一下按键再决定：每个键都要多走一趟，打字和游戏都会变慢。

## 5. 先做的小试验

Mac 上，焦点移进 Flutter 编辑框后，用 `NSApp.postEvent(_:atStart:)` 或 `window.sendEvent(_:)` 把存下的 keyDown 重新送出，看本机拼音能不能接住第一个字母。要在真机上用简体拼音确认：在画面上打 `nihao` 再按空格，面板里得到「你好」。不通就按 §2 第 2 条退回。

## 6. 测试

- Swift：分流单测，覆盖字母、Shift 加字母、⌘ 加字母、数字、空格、`compose` 为假、画面无焦点，以及松开不外发。
- Dart：`compose_key` 打开面板、焦点进编辑框、调 `compose_replay`；面板打开时远端非英文就调 `selectInput('')`，已经是英文就不调；终端会话里 `compose` 为假；`typeToCompose: false` 让 `compose` 为假；Linux 字母进草稿，数字照旧发出；设置页开关写进 apps.json。
- 真机：§5 的拼音检查；Figma 关掉开关后 V/R 照旧可用。
