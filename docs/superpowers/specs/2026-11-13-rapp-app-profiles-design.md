# rapp：按 app 的配置（app 配置）设计

日期：2026-11-13。状态：**已确认**（用户 2026-11-13：「可以，浏览器里加一个 Edge」）。

来源：
- U23（需求反馈 §0.9）：要针对常用 app 做优化，作为产品的一项可配置能力，发布时给常用 app 带默认配置，没适配的用默认配置。
- 用户 2026-11-13：「现在有特殊要求隐藏一些 app 的子窗口或不显示子窗口的输入框，这些需要有地方配置。」

需求反馈 §4 第 18–20 条的待定项按推荐定（用户的默认：全部按推荐），见 D2、D5、D8。

## 0. 决定

| # | 决定 | 理由 |
|---|---|---|
| D1 | 配置只放在 **B**（操作端）这一侧，由 GUI 读写；A 不用改，协议也不变 | 第一版的各项都是 B 自己的事（显示哪些窗口、开不开输入区、开流时用什么档位）。放在 B，macOS、Windows、Omarchy 三种 A 都能马上用 |
| D2 | 第一版做四类：**窗口**（隐藏子窗口）、**输入区**（某些窗口不显示）、**画面**（默认档位、密度、帧率）、**发送后**（补不补回车）。标题栏裁剪、按键映射、「在等你」的判断放第二版（§7） | 用户这次提的是前两类；画面和文字输入是 §4 第 18 条推荐先做的 |
| D3 | 一份配置用 **app 标识列表** 来认 app：`com.google.Chrome`、`chrome.exe`、`google-chrome` 写在同一份里，哪个对上都算。比较时不分大小写 | 三种系统的 app 标识不一样（主机与客户端规格 §3.3：macOS 用 bundle id，Windows 用 exe 文件名，Omarchy 用窗口 class）。用列表的话，B 不必知道 A 是什么系统 |
| D4 | 两层：**内置配置**随 GUI 一起发布，只读；**我的配置**放在 B 的配置目录里，写在 `apps.json`。同一个 app 两层都有时，按字段合并，我的配置优先；两层都没有的字段用通用默认 | 用户改过的最优先，其次内置，最后通用默认（§0.9 推荐的先后） |
| D5 | 第一版不做导入、分享和市场。`apps.json` 是普通 JSON，高级用户可以自己改；页面上有「打开配置文件夹」 | YAGNI；文件格式先定下来，以后要分享也不用改格式 |
| D6 | 隐藏窗口**只在 B 上不显示**：A 上的窗口照常存在，画面照常传。被隐藏的窗口不出标签、不进舞台、不能分离，B 的点击和按键也到不了它 | 不改协议。代价是流量不省（§6 风险 1），第二版可以让 A 不采集它 |
| D7 | 隐藏的窗口**永远找得回来**：标签栏末尾显示「已隐藏 N 个」，点开可以「这次显示」。如果 app 只剩被隐藏的窗口，就照常显示，舞台不会黑着 | 被隐藏的可能是模态对话框，A 的 app 在等它，B 却看不见；不给出口就会卡住（§6 风险 2） |
| D8 | 首批内置先做 macOS，名单见 §9（16 个，按用途分 6 组，另带本机常用的 2 个）。内置配置只填画面一类；隐藏规则和输入区规则内置一条都不带，由用户自己加。每条内置配置都标「未实测」，用户在真机上试过才去掉 | 默认值都是猜的（§0.9）；隐藏窗口这类规则猜错了会让人找不到窗口，不能替用户猜 |
| D9 | 日志里不写窗口标题、不写规则内容，只写「命中了哪份配置」（配置名）和「隐藏了几个窗口」 | 窗口标题里可能有文件名、网页标题这类私事；可观测性规格只记事件不记内容 |

## 1. 用语

- **app 配置**：对一个 app 的一组设置，有名字（如「Chrome」）。
- **窗口规则**：一份 app 配置里的一条，说明「哪种子窗口」→「怎么处理」。
- **子窗口**：A 的窗口表里除主窗口以外的窗口。主窗口是 app 最早出现、且没有父窗口（`parent == 0`）的那个普通窗口。

## 2. 配置的内容

```json
{
  "version": 1,
  "apps": [
    {
      "name": "Chrome",
      "ids": ["com.google.Chrome", "chrome.exe", "google-chrome"],
      "stream": {"mode": "color16", "density": "adaptive", "fps": 15},
      "afterSend": "none",
      "composer": true,
      "windows": [
        {"kind": "floating", "title": "*下载*", "action": "hide"},
        {"kind": "dialog", "action": "noComposer"}
      ]
    }
  ]
}
```

| 字段 | 取值 | 没写时 |
|---|---|---|
| `name` | 显示用的名字，1–40 字 | 用 `ids` 的第一个 |
| `ids` | 至少一个 app 标识；不分大小写 | 必填，没有就整条不用 |
| `stream.mode` / `density` / `fps` | 和串流菜单里的选项一一对应（`StreamChoice` 的取值） | 通用默认 |
| `afterSend` | `none`：只贴，不按回车（现在的做法）；`return`：输入区发完最后一块后补一个回车 | `none` |
| `composer` | `false`：这个 app 的所有窗口都不显示「输入」按钮和输入区 | `true` |
| `windows[]` | 窗口规则，按顺序比，**第一条对上的生效** | 空 |

窗口规则：

| 字段 | 含义 |
|---|---|
| `kind` | 可选。`normal`、`dialog`、`floating`、`sheet`、`popover`、`menu`、`tooltip` 之一（协议里的 `WindowKind`） |
| `title` | 可选。窗口标题的通配：`*` 配任意多个字，其余按原样比，不分大小写。不写就不看标题 |
| `child` | 可选。`true` 只配子窗口；不写时默认就是 `true`——主窗口不会被规则隐藏 |
| `action` | `hide`：隐藏；`noComposer`：这个窗口是当前标签时，不显示「输入」按钮和输入区 |

`kind` 和 `title` 都不写的规则会配上所有子窗口，编辑页要提示「这条会作用于这个 app 的所有子窗口」。

**为什么不用正则：** 通配一般人能看懂，标题里常见的括号、点不用转义；第二版真要再加。

## 3. 生效的地方

只改 GUI 的嵌入会话（舞台和分离出来的窗口）。

1. **打开 app 时**：按 `ids` 找配置（我的配置优先），开流用 `stream` 里的档位。用户在串流菜单里临时改的只对这次会话有效（重连时沿用，和 S3 一样），不写回配置。
2. **窗口表来时**（`WindowTabs.update`）：先过窗口规则。`hide` 的窗口从标签、舞台和弹层里去掉，也不能分离；如果只剩被隐藏的窗口，就当没有规则（D7）。
3. **输入区**：`composer: false`，或者当前标签对上了 `noComposer` 规则时，「输入」按钮和输入区都不显示；已经打开的输入区收起来，草稿留着（R18：草稿跟着会话走），切到别的标签再出现。
4. **发送后**：`afterSend: return` 时，输入区把最后一块贴完、A 回了 `pasted` 且没出错，再发一次回车。中间出错就不补。
5. **被隐藏窗口的点击和按键**：B 看不见它就点不到它；如果 A 把焦点给了被隐藏的窗口，按键照常发到 A（由 A 决定落在哪），标签栏的「已隐藏 N 个」要亮起来提示。

独立的 `rapp-client` 和 Omarchy 上的 GTK 客户端第一版不读配置，第二版再接（§7）。

## 4. 在哪里配置

| 入口 | 做什么 |
|---|---|
| 窗口标签右键 →「隐藏这类窗口」 | 用这个窗口的种类和完整标题生成一条 `hide` 规则，写进我的配置，弹出提示「已隐藏，可在 app 配置里改」，带「撤销」 |
| 窗口标签右键 →「这个窗口不要输入区」 | 同上，生成一条 `noComposer` 规则 |
| 标签栏「已隐藏 N 个」 | 列出被隐藏的窗口：「这次显示」（只对这次会话有效）、「不再隐藏」（删掉对上的那条规则） |
| 串流菜单 →「记为这个 app 的默认」 | 把当前的档位、密度、帧率写进这个 app 的 `stream` |
| 串流菜单 →「app 配置…」，以及设备页每个 app 那一行的 ⋯ | 打开这个 app 的配置页 |
| 本机页新增一节「app 配置」 | 列出所有配置：名字、标识、来源（内置 / 我的 / 内置 + 我改过）。可以新建、删除我的配置、「恢复内置」；还有「打开配置文件夹」 |

**配置页**是表单，不是 JSON 编辑器。四块：画面（三个下拉）、发送后（两个选项）、输入区（一个开关）、窗口规则（列表，每条：种类下拉、标题通配输入框、动作下拉；可上下移、可删）。内置的项灰着显示，改了就变成我的配置。保存后对已打开的会话**马上生效**，不用重连。

文案照设计语言：按钮用动词，提示句子短，不出现「profile」「regex」这类词。

## 5. 文件和读写

- 内置配置：`gui/assets/app_profiles.json`，随 GUI 打包。
- 我的配置：B 的 GUI 配置目录（和 `workspace.json` 同一个目录）下的 `apps.json`，写法照 `workspace_store.dart`：先写临时文件再改名；读不出来就从空白开始，原文件改名为 `apps.json.bad`，页面提示「app 配置没有读到，已从空白开始」。
- 文件里没有密码、token、剪贴板内容；只有 app 标识、名字、档位，以及用户写的标题通配。
- 内置文件格式不对时 GUI 照常启动，只是没有内置配置；测试里要有一条覆盖这种情况。

## 6. 风险

1. **隐藏不省流量。** 被隐藏的窗口在 A 上照常采集、照常传。第二版让 B 告诉 A「这些不要采」，需要协议 v7 和三种 host 都改。
2. **藏掉的是模态对话框。** A 的 app 在等它，B 看起来像卡住了。靠 D7 的「已隐藏 N 个」兜底；规则编辑页对 `dialog`、`sheet` 加一句提醒「它可能在等你回应」。
3. **标题会变。** 网页、文档的标题随内容变，通配写得太死会对不上，写得太宽会多藏。「隐藏这类窗口」生成的是完整标题，提示里写明可以改成带 `*` 的。
4. **同一个标识对上了两份配置**（我的配置里重复了）：用列表里排在前面的那份，配置页标出「和 〈名〉 重复」。
5. **内置默认是猜的**（D8）：每条都标「未实测」，用户试过一个去掉一个。

## 7. 第二版（这次不做）

- A 不采集被隐藏的窗口（协议 v7）。
- 标题栏裁不裁（按 app 改 A 的判断；原型规格风险 5）。
- 按键：修饰键映射、哪些快捷键留给本机。
- 「在等你」的判断：配置里写这个 app 出现什么迹象就是在等你，只观察、不替用户点（需求反馈 §0.6 的界线）。
- 独立 `rapp-client`、Omarchy GTK 客户端读同一份配置。
- 配置的导入、分享。

## 8. 验收

单元测试：
- 合并：内置 + 我的配置按字段合并；我的优先；标识不分大小写；重复标识用排在前面的那份。
- 规则：第一条对上的生效；`child` 不写默认只配子窗口；主窗口不会被隐藏；只剩被隐藏的窗口时照常显示。
- 输入区：`composer: false` 和 `noComposer` 都会让按钮和输入区消失；草稿留着；切到别的标签再出现。
- `afterSend: return`：只在最后一块成功贴上之后补回车；出错不补。
- 文件：写坏的 `apps.json` → `.bad` + 提示；内置文件坏了 GUI 照常启动；日志里没有窗口标题和通配内容。

实机（要用户安排）：Chrome 里打开「下载」或设置这类子窗口，从标签右键隐藏，「已隐藏 1 个」出现，「这次显示」能找回；某个对话框设成不要输入区，切过去输入区消失、切回来出现。

## 9. 首批适配的 app（先做 macOS）

用户 2026-11-13：「一般情况下，用户经常使用的 app 不会很多，请列出最著名最常用的生产力有关的 app 和 ai app、terminal 等，整理一个第一批适配的 app，先做 macos 的。」

**怎么选的：** 用户 2026-11-13 定的过滤：「请以最有可能远程访问的方式作为过滤」。只收**东西只在 A 上**的 app：A 上跑着的任务（终端、写代码、本地 AI 任务）、A 上的文件、只能在一台电脑登录的账号（微信、企业微信）、A 上浏览器里的登录和内网。**云端同步、在 B 上直接打开就能用的不收**（Notion、Obsidian、备忘录、Slack、飞书、Perplexity、Grok、邮件、日历等）——这类 app 不需要远程。很少远程用的（视频会议）也不收。剩下的按用途分组，这台 Mac 上已经装了的优先。

**标识一栏：** 标 ✓ 的是 2026-11-13 从这台 Mac 上已装 app 的 `Info.plist` 读出来的；没有 ✓ 的按公开资料填，第一次在装了它的机器上打开时要核对，标「待核对」的连公开资料都没把握。

**画面一栏：** 档位 / 密度 / 帧率，取值就是串流菜单里的那几个（帧率只有 1、5、15、30）。全部是猜的，标「未实测」（D8）。发送后一律 `none`、输入区一律开着、窗口规则一条不带。

### 以后加 Windows、Omarchy 时

同一份配置的 `ids` 里补上 exe 文件名和窗口 class（D3），不另起一份。例如 Chrome 补 `chrome.exe`、`google-chrome`。
