# rapp 终端会话设计：评审记录（Linux 远程工作的视角）

日期：2026-11-14。状态：**评审意见，待用户取舍**。本文不改代码，也没有改被评审的那份规格。

被评审的：`2026-11-14-rapp-terminal-sessions-design.md` 第 1 稿（下称“规格”）。
用户的要求（2026-11-14，原话）：“你是个 linus 这样的资深 linux 开发者，请根据你最专业的远程工作方式。评审一下这个方案”。这句话还没有记进反馈文档（原因见提交说明：那份文档在另一个分支上也有改动，等合并后再补）。
标“实测”的是这次在一台 Linux 机器上用 tmux 3.4 跑过的；标“未实测”的是凭经验和文档说的。

## 0. 结论

方向对，可以做。**但第 1 稿做得太多**：它在 Unix 上重造了一部分 tmux，往服务器上加了一个带 shell 的新守护进程，并且在第二个后端出现之前就把接口设计完了。砍掉这三样，剩下的东西更小、更稳，而且一样满足 TR1–TR8。

有两处是错的或者不成立的，要改（R5、R6）；有一处漏了（R9 的选中复制）。

## 1. 这次实测了什么

环境：Linux，tmux 3.4，独立的 tmux 服务，没有碰任何真实会话。没有用 Claude Code、Codex 实测，也没有测 SSH。

| # | 测的事 | 结果 | 对规格的意义 |
|---|---|---|---|

| E2 | 再接一个 200×60 的普通客户端 | 窗口被改成 200×59；它走了、原来的客户端一动，又变回来 | 证明“不能用普通方式接上去看”，规格的担心是对的 |

## 2. 做对了的

- **问 tmux 要屏幕，不再仿真一遍。** tmux 已经把输出解析成网格了，再跑一个仿真器去解析它的重画是多余的。E4、E7 说明这条路又准又便宜。
- **只送最新状态，带确认。** 这是 mosh 的思路，用在网格上。弱网下它是对的。
- **SSH 用系统的 `ssh` 和 `~/.ssh/config`，rapp 不保管凭据，不交互。** 这是唯一正确的做法。
- **不改别人的尺寸、不挤掉别人。** E1、E2 说明这不是多虑。
- **状态用未读，不猜“在等你”。**

## 3. 要改的

按要紧程度排。

### R1 Unix 上不要自己做伪终端的持有进程

规格 §7.2 说自带后端用在“Windows，以及没有 tmux 的 macOS、Linux”，还要一个“独立的小进程持有伪终端，服务重启后重新接上”。

这就是在写一个更差的 tmux。让一个进程脱离启动它的服务活下去，在 systemd 和 launchd 下各有各的坑（R6），tmux 花了十几年把这些踩平了。

建议：**Unix 上会话的容器只有 tmux**。`rapp-term run -- claude` 在 Unix 上就是替你执行一次 `tmux new-session`。机器上没有 tmux，就提示装一个，各发行版和 Homebrew 都有。自带的伪终端加仿真器只留给 Windows，那里没有 tmux，TR4 也正是这么定的。

砍掉的：Unix 上的持有进程、Unix 上对 `alacritty_terminal` 的依赖、Unix 上的两条取屏路径。

### R2 砍掉 T6：服务器上不装新的守护进程

T6 要在没有桌面的 Linux 上装 `rapp-service`。那是一个常驻的、从网络上可达的、能给出 shell 的新程序。服务器上已经有一个干这件事的程序，叫 sshd，它被审查了二十多年。

规格 §8 自己已经说明 SSH 这条路能覆盖 TR1。那就不要再留 T6 当“之后的事”，把它写进“不做”。只有一种情况值得重新考虑：服务器在 NAT 后面，你任何一台设备都 SSH 不到它。真遇到了再说。

### R3 接口不要先设计完

规格 §4 给了一个六个方法加一个能力表的后端接口。这时候一个后端都还没写。接口长什么样，要等有了两个真的实现才知道，现在写下来的都是猜的。

TR7 要的是“底层能换”，这个要求是对的，办法是留一道缝，不是先把缝的形状画死：

- 执行器（本机或 SSH）留着。它很小，而且第一天就有两个实现。
- 后端先只有 tmux 一个，直接写，不套接口。核心只认三样东西：会话列表、某个面板现在的屏幕、把输入送进去。
- 等写 Windows 那一个的时候，把两边共同的部分提成接口。那时提出来的才是真的。

`caps`、`create`、`history` 这些先不进接口。往上翻在 tmux 上就是一次 `capture-pane`，用到再加。

### R4 屏幕每一行就用带颜色转义的文字

规格 §6 说每行是若干段“文字 + 前景 + 背景 + 粗体等”的结构。E4 里 `capture-pane -e` 吐出来的本来就是带标准颜色转义的文字行。

建议线上直接传这种文字行。被控端对 tmux 完全不用解析，比较两次的行是不是同一个字符串就行；主控台写一个只认颜色转义的小解析器，不是完整的仿真器。Windows 那个后端把网格写成同样的文字行。这个格式所有做终端的人都认得，不用再发明一种。

### R5 尺寸的规则要改

规格 §7.1：“默认不设。主控台按面板原来的行列数缩放字号显示。”

这条在有人同时接着时是对的（E1）。但 TR1 说的是没有桌面的服务器，那上面多半**没有别的客户端接着**。这时面板的尺寸是上一个离开的人留下的，可能是 250 列，在平板上缩得看不清。

改成 tmux 自己的做法：

- 这个会话没有别的客户端接着：按主控台的屏幕设尺寸。没有人会受影响（E8）。
- 有别的客户端接着：不动，缩放显示；用户明确点了才改。

### R6 “rapp 新开的 tmux 不受服务重启影响”在 Linux 上不成立

规格 §7.1、§15 第 7 条都这么说。但如果这台机器上还没有 tmux 服务，rapp 的服务执行 `tmux new-session` 时起出来的 tmux 服务，是 rapp 服务的子孙。systemd 默认在停止一个服务时杀掉它控制组里的全部进程，tmux 也在里面。重启 rapp 的服务就会把刚才新开的会话全杀掉。这是 systemd 的已知行为，在本项目里未实测。

要做的：在 Linux 上经 `systemd-run --user --scope` 起 tmux 服务，让它不在 rapp 服务的控制组里。macOS 的 launchd 怎么对待这种脱离出去的子进程，我不确定，列进探查。经 SSH 起的不受影响，那是 sshd 的会话。

这一条同时是 R1 的理由：连“起一个 tmux”都有这种坑，自己持有伪终端只会更多。

### R7 不动用户的 tmux

规格没有写清 rapp 可以对用户的 tmux 做什么。写成规则：

- rapp 只发四类命令：读（列表、取屏、查值）、送输入（`send-keys`、`paste-buffer`）、新开会话（用户点了才做）、设尺寸（按 R5）。
- **不执行 `set-option`，不改键位，不动用户的配置。**
- 粘贴用自己命名的缓冲区，贴完就删，不占用户的粘贴缓冲区。
- 控制客户端**只在有人正在看这个会话时接着**。没人看时用一次性的命令每 2 秒问一次列表（E7：3 毫秒）。这样 `tmux ls` 里的 “attached” 说的是真话：有人正通过 rapp 在看。规格 §7.1 的“一条常驻的控制连接”改成“看的时候才有”。

### R8 安全：§16 第 3 条是个假问题

规格问“SSH 目标从主控台远程加，还是只能在代管设备本机加”。两个答案没有区别：能在代管设备上打开终端会话的人，已经有了那个用户的 shell，可以自己敲 `ssh` 去任何地方。限制“谁能加目标”拦不住任何人。

真正的边界只有两道，都已经在别的规格里：relay 的 key（加上 relay 规格 §7.3 的两个开关），和每台设备的“允许终端会话”开关。规格应该直说这一点，把第 3 条删掉，远程加就行。

另外在使用说明里给一条建议，不是功能：给 rapp 用的那把 SSH 密钥，在服务器的 `authorized_keys` 里限制成只能执行 tmux。这样即使这把密钥被拿走，对方得到的也只是你的 tmux 会话，不是任意命令。

### R9 漏掉的

- **选中和复制。** 这是文字网格相对像素最实在的好处：报错信息能直接选中复制到本机。规格没有提，应该在第一版里。
- **远程主机上找不到 tmux。** 不交互的 SSH 用的是精简的 PATH。远程主机是 Mac 而 tmux 装在 Homebrew 里时，`ssh 主机 tmux` 会报找不到命令。目标的配置里要能写 tmux 的路径（已知的坑，未实测）。
- **会话的名字。** tmux 会把会话名里的冒号和句点改成下划线；名字里也可能有空格。规格用冒号做 `term:` 标识的分隔符，解析只能在一个地方做，别处都当不透明的字符串。给 tmux 发命令时用它的面板编号，不用名字。

### R10 第一版再小一点

把上面的都算上，建议的第一版是：

1. tmux，本机和 SSH 一起做（执行器只有几十行，分成两步没有意义）。
2. 看、选中复制、输入区发一段、按键、往上翻。
3. 未读和全景里的最后几行。

Windows 的自带后端是第二版。Linux 无界面安装包不做（R2）。
