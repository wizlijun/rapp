# 按住说话，和单手好按的舞台按钮（iPad / Duo）

日期：2026-11-18。状态：设计已确认，待实现。5.1 在 2026-11-18 按微信的同心圆环带重写（用户确认）。

## 1. 为什么做

用户在 Duo 和 iPad 上给 A 的程序发字，现在得先点「输入」打开输入板，再用软键盘或听写键。用户要的是（2026-11-18 原话的意思）：

- 「输入」左边加一个识别按钮，**长按说话，松手就提交上去**。
- **提交过的统一进入历史**，和输入板发出的一样。
- 用 **iOS 自带的语音能力**，不接第三方服务。
- **风格和主题保持一致**。
- 用户追加：Duo 和 iPad 上语音按钮和输入按钮要放到**更易于单手按住的地方**。用户选的是：竖排贴在屏幕边上，整组可以拖到另一边（2026-11-18 选择题）。

本规格改掉 iPad 规格（`2026-11-17-rapp-ipad-duo-design.md`）里两句："语音：第一版就是系统键盘上的听写键，专门的按住说话不在本文范围"，以及"rapp 不要麦克风权限"。

## 2. 目标、非目标、反目标

目标：

- 按住语音按钮说话，边说边在气泡里看到识别出的字；松手后把这段字发给 A，和在输入板里按发送的效果一样：走同一条发送路径，按这个 App 的「直接回车」设置决定补不补回车，进输入历史。
- 舞台右下角那一排按钮（还原、输入）在 iOS 上改成竖排贴边的大方按钮，加上语音按钮；整组可以拖到左边缘，按设备记住。

非目标：

- macOS、Linux 客户端不加语音按钮，那一排按钮也不改。
- 不接云端识别（火山等），不做标点或口语整理，不做离线模型下载管理之外的事。
- 不做上下位置的拖动，整组固定在底部。

反目标（做了也算失败）：

- 语音发出去的东西不进历史，或者和输入板发出的记录长得不一样。
- 说话时手一抖就把半句话发出去了，或者想取消却取消不了。
- 新按钮和舞台上现有按钮样式不一致，深浅主题里看着突兀。
- 语音按钮在冻结（断网、正在移动）时还能发，内容丢了。
- 弄乱输入板里正在写的草稿。

## 3. 方案

考虑过的三种：

1. **SpeechAnalyzer（iOS 26+），更早系统退回 SFSpeechRecognizer**（选这个）。全是系统框架，不用新依赖；新接口在本机识别、无时长限制；老接口能在本机识别就在本机，否则走 Apple 服务器，单次最长约 1 分钟。
2. 只用 SFSpeechRecognizer：代码少一半，但在 iOS 26 上用的是老模型，长句和中英混说差一些。
3. 接火山等云端识别：要密钥和网络，用户明确要 iOS 自带能力，排除。

部署目标仍是 iOS 17.0，SpeechAnalyzer 用 `if #available(iOS 26, *)` 隔开。本机 Xcode 27.2、iOS SDK 27.2，新接口能编译。

## 4. 舞台按钮组（iOS）

### 4.1 布局

```
┌──────────────────────────────┐
│                         (↙)  │  还原，只在放大时出现
│                         (⌨)  │  输入
│  ┌──────────────────┐  (🎤)  │  语音，最靠下；三个都是 56
│  │ 帮我把这个函数重命名… │        │  录音时的样子见 5.1
│  └──────────────────┘        │
└──────────────────────────────┘
```

- 竖排，从下到上：语音、输入、还原（只在当前窗口放大时出现）。三个一样大，直径都是 56（用户 2026-11-18：「按键能否改成一样大」；原来是 64 / 56 / 48）。按钮间距 12。整组外沿离屏幕边 80，底部离屏幕底 88，语音按钮的圆心约在离边 108、离底 116 处，是单手握持时大拇指最容易按到的地方，不用伸到角上（用户 2026-11-18：「放在大拇指最容易单手按到的位置」；原来是离边 12、离底 12）。数字在 Duo 上试过再调。
- **竖屏**（舞台高大于宽，按舞台本身算，不算键盘让出的部分）改成横排（用户 2026-11-18：「竖屏时，键盘在语音按钮靠中间的横排就行了」）：语音在最外侧，位置不变（离边 80、离底 88）；「输入」在它靠屏幕中间的一侧，间距 12，两个圆心在同一水平线上；「还原」接在「输入」再往里。横屏仍是上面的竖排。
- 只有图标没有文字：语音 `Icons.mic_none`（录音中 `Icons.mic`），输入 `Icons.keyboard_outlined`，还原 `Icons.zoom_in_map`。读屏标签分别是「语音」「输入」「还原」。各自保留现在的 Key：`composer-open`、`zoom-reset`；语音按钮 Key `voice-hold`。
- 样式**极简**（用户 2026-11-18）：圆形，只有图标；底色沿用 `RappButton.secondary(onPicture: true)` 在画面上的那套底（`Color.alphaBlend(t.raise.first, t.float.first)`），1 px `t.line` 描边，图标 `t.text`。没有阴影、发光、渐变，也没有按下以外的状态色。颜色全部取 `RappTokens`，深浅主题都对。实现上给 `RappButton` 加一个圆形图标变体；不要另起一套颜色。
- **方的，和 Mac 一样**（用户 2026-11-18：「能不能和 macos 版本一样都改为方的。统一一下设计风格」）：三个按钮是方块，角用主题的圆角（和 Mac 那排按钮、输入板的 ＋ 和发送同一个角），底色、边线照旧。
- **没按时半透明**（用户 2026-11-18：「未按时半透明显示」）：三个按钮平时 30% 透明（不透明度 0.7；用户 2026-11-18：「修改为30%透明吧」，原来是 0.5），少挡画面；手指按上去那一刻变成不透明，手指离开（松手或取消）后 80 ms 回到 0.7。其他端同样的按钮一样（用户：「其他端同样的按钮透明度都修改 一致」）：macOS、Linux 画面右下角那排的还原、输入和 macOS 的按住说话也是平时 0.7，鼠标移上去或按下时不透明；传输的「取消」和断线时的「重连」「停止」不算这类按钮，不变。语音按钮按住后照旧变成发送圆盘，圆盘本身不透明。
- 按住说话时语音按钮本身隐藏，变成发送圆盘（见 5.1 的动画），松手后再变回来。
- 显示条件：输入板没开时，现在「输入」什么时候出现，语音就什么时候出现（`session.composerAllowed` 为真）；还原的条件不变。都不出现时整组不画。输入板打开时见 4.4。
- 上传、下载进度那一行（`transferStatus` 文字 + 取消）放在按钮组内侧，和语音按钮同一高度；竖屏横排时改放在按钮行上方 12，靠外侧对齐。录音时它和「输入」「还原」一起淡出。

### 4.2 换边

- 按住「输入」或「还原」往屏幕另一侧拖：手指移动超过 10 点才算拖，轻点仍是原功能。拖动中整组跟着手指水平移动；松手时手指越过屏幕中线就吸到另一边，否则回原边。吸附有一个短动画（约 200 ms）。
- 语音按钮不参与拖动。
- 在左边时整组镜像：贴左边缘，进度行和提示气泡放在右侧，录音画面也整组镜像。
- 边存在本机界面设置 `gui.json`（`UiPrefs`）里，键名 `stage_buttons_side`，值 `left` / `right`，默认 `right`。每台设备各记各的，不跨设备同步。

### 4.3 让位

- 软键盘弹出时，整组站在键盘上：底部在键盘上沿上方 12；有终端按键行时在按键行上方 8。
- 终端按键行显示、键盘没弹出时，按键行顶部离底 57，整组的 88 已经在它上方，位置不变。
- macOS、Linux 上的那一排按钮保持原样（横排、带文字、在右下角）。
### 4.4 输入板打开时（用户 2026-11-18）

- 「输入」「还原」照旧收起；语音按钮留下，还是同一个 56 方按钮，放在输入板外、输入板上方：横向和整组同一条线（离边 80，跟着整组在左还是右），底部在输入板顶部（含拖动条；终端里按键行排在输入板上方时，算按键行顶部）上方 8。
- 输入板跟着键盘或拖动换位置时，按钮跟着走（晚一帧）。输入板很高时按钮不出舞台顶。
- 按住说话、滑到「取消」「编辑」都和平时一样。发送只发这一句，不动输入板里的草稿；输入板保持打开。「编辑」把这句接到输入板文字末尾。
- 按语音按钮时不应该让输入板里的编辑器丢掉焦点（真机检查，见 8 第 14 条）。

- 「iOS」指所有 iOS 设备（`Platform.isIOS`）：Duo 本身就是 iPhone 机型，没有单独的 iPad 判断。按钮尺寸在 Duo 的小屏上也合适。

## 5. 按住说话

### 5.1 交互

结构照微信 iPad 的按住说话（用户给的截图，2026-11-18 逐像素量过）：底部一个大**发送圆盘**，外面一圈和它**同心的环带**在弧顶附近断开成两段，就是「编辑」和「取消」两个选项。和微信唯一的不同：微信的圆心在屏幕正中，这里放在**拇指正下方**，断口往屏幕内侧转过去，让两段都落在拇指扫得到的那一侧（用户要的是单手，不是居中）。

```
┌────────────────────────────────┐
│        ┌────────────────────┐  │  气泡：贴拇指这侧，主色底
│        │ 帮我把这个函数重命名… │  │
│        └──────────────────▽─┘  │
│                    松手 发送    │  提示
│                  ╭─编辑─╮       │  环带：编辑（靠边、靠上）
│         ╭─取消─╮  ╰──────╯      │         取消（靠里、靠下）
│          ╲   ╭──────────────── │  发送圆盘的弧
│           ╲ ╱        ●（拇指）  │  语音按钮已隐藏
└────────────────────────────────┘
```

**几何**（舞台宽 W、高 H；拇指点 = 语音按钮圆心；全部在按钮所在一侧镜像）：

- 圆盘半径 `R = min(1.1·W, 0.9·H)`（Duo 竖屏约 410，iPad 横屏约 735）。
- 弧顶在语音按钮圆心正上方 `max(0.23·R − 44, 84)` 处；圆心在弧顶正下方 R 处（在屏幕外）。
- 环带与圆盘同心：内边离圆盘 `0.033·R`，带宽 `max(0.113·R, 48)`。
- 断口轴：从圆心竖直向上的方向往舞台内侧转 22.5°。断口两边各一段：
  - 两段的头尖沿中线相距 `0.059·R`；头不是半圆，是压扁的圆头（头的深度 = 0.36 倍带宽）。
  - 每段长 19°（从头的根部量），往外渐淡：前 55% 实色，到末端剩约 8%。
  - 离竖直方向近（靠屏幕边、偏上）的一段是「编辑」，另一段（靠里、偏下）是「取消」。
  - 每段一个图标加两个字（「编辑」用笔，「取消」用叉），顺着切线斜放，在离断口轴 12° 处。
- 气泡：贴拇指这侧，离屏幕边 16，宽 `min(W − 32, 600)`；气泡加提示行的底部比两段环带（按整段长度算）的最高点再高 12（「编辑」段比断口轴处的外沿高，按轴算会让提示压在亮起的「编辑」段上）。最多 4 行，超了只显示末尾。气泡尾巴在拇指这侧，提示（「松手 发送」等）在气泡下面、同一侧。
- 气泡里右下角（拇指侧）一排 24 根音量条，跟着麦克风音量动（5.4 的 `level`）。
- 全屏压暗：`t.bg` 60% 不透明度盖在舞台上。

**手指在哪儿就是哪个选项**（用户：按钮在同心圆边缘，手指挪上去就选中）：

- 手指离圆心的距离 ≤ R：**发送**。
- 出了圆盘：看手指在断口轴哪一边——靠竖直一侧是**编辑**，另一侧是**取消**。只要出了圆盘就算，不必压在带子上。
- 选项每变一次轻震一下（`HapticFeedback.selectionClick`）。

**样式**（极简：平涂、1 px 线，没有发光、阴影；颜色全取 `RappTokens`）：

| 状态 | 圆盘 | 被选中的那段 | 气泡 | 提示 |
|---|---|---|---|---|
| 发送 | `t.raise` 底，1.5 px `t.text` 边 | —（两段都是 `t.raise` 底、`t.text` 字） | `t.text` 底、`t.bg` 字 | 「松手 发送」 |
| 取消 | 1 px `t.line` 边 | `t.accent` 底、`t.accentInk` 字 | `t.raise` 底、`t.muted` 字、`t.line` 边，音量条停 | 「松手 取消」 |
| 编辑 | 1 px `t.line` 边 | `t.accent` 底、`t.accentInk` 字 | `t.float` 底、`t.text` 字、1 px `t.text` 虚线边、末尾光标 | 「松手 改一改再发」 |

还没有字时气泡显示「正在听…」。

**动画**（用户：按下后语音按钮隐藏，做好转换动画）：

- 按下（共 240 ms，`Curves.easeOutCubic`）：
  - 0 ms：中等轻震（`HapticFeedback.mediumImpact`），开始识别。需要权限时先走 5.3，这时不出圆盘。
  - 语音按钮**长成圆盘**：一个圆角方块从按钮的位置、大小和形状（中心 = 按钮中心，边长 56，主题圆角）连续变到圆盘的位置和大小（圆心、R），边长的一半和圆角一起长到 R，最后成圆，240 ms。按钮的图标在前 80 ms 淡出，按钮本身不再画。
  - 「输入」「还原」和进度行 120 ms 淡出。压暗 160 ms 淡入。
  - 气泡和提示从 80 ms 开始，160 ms 内淡入并上移 8。
  - 两段环带从 120 ms 开始，160 ms 内从头尖往外长出（扫过 0→19°）并淡入。
- 松手（共 200 ms，`Curves.easeInCubic`）：
  - 环带 100 ms 淡出；圆盘缩回语音按钮的位置和大小（倒放按下的变形），最后 80 ms 按钮图标淡入，按钮回来；「输入」「还原」淡入。
  - 发送：气泡淡出时上移 8（像被送走）。取消：气泡原地淡出。编辑：气泡原地淡出，同时输入板打开。
- 「减少动态效果」打开时（`MediaQuery.disableAnimations`）：没有变形和位移，直接出现和消失。

**松手、限时、中断**：

- 在发送区松手：停止录音，等识别给出最终结果，最多等 1 秒（超时就用已有的结果），然后发送（5.2）。动画不等结果，松手就开始收。
- 在「取消」松手：丢掉结果，什么都不发。
- 在「编辑」松手：停止录音，同样最多等 1 秒拿结果，把字放进输入板草稿末尾并打开输入板（5.2），不发送。
- **没听清**：结果去掉首尾空白后为空，不发送也不放进草稿，显示「没听清」约 1.5 秒。
- **最长 60 秒**：到 60 秒按手指当时所在的选项松手处理。
- **中断**：来电、切到后台、录音被系统打断、手势被系统抢走（pointer cancel）时，按取消处理。
- 同一时间只有一次录音；录音时其他按钮都已隐藏。

**松手后的提示**（没听清、放回草稿、权限、准备中）：不再有圆盘和压暗，只在按钮组内侧、语音按钮上方显示一个小气泡（`t.raise` 底、`t.text` 字、1 px `t.line` 边，同样贴拇指这侧），按各自的时长消失；权限提示带「去设置」。

### 5.2 发送

- 发送和输入板走同一条路：通过 `ComposerModel`（这样 `InputRecorder` 的 `onSubmitted` / `onFinished` 钩子照常触发，记录、密码框不记录、失败重试、「直接回车」都和输入板一致）。新加一个入口，例如 `ComposerModel.submitText(String text)`：不碰编辑框和草稿，用这段文字组一个 `Outgoing`，其余和 `submit()` 的发送分支相同（`onSubmitted`、`_inFlight`、`sending`），返回 `SubmitPieces`。
- 调用方和 `_submit` 一样：被挡住（`isDetaching` / `sendBlocked`）就不发，提示「连接已断开或正在移动，内容尚未发送」，这段文字放进输入板草稿末尾，不丢；否则 `session.prepareInput()` 然后 `port.composerSend(sid, pieces)`。
- 上一轮还在发（`sending` 或 `_inFlight` 不空）时，这段文字同样放进草稿末尾，提示「上一段还在发送，已放进输入板」。
- 两种放回都不打开输入板，只显示提示约 2 秒（我定的）。
- **编辑**：这段文字放进草稿末尾（和放回同一个 `keep`），然后打开输入板，光标在末尾；不发送，不进历史（用户在输入板里发出去时才进）。
- 输入板里正在写的草稿不受影响（除了上面放回和编辑是追加）。
- 「直接回车」后的 `composer.collapse()` 对语音无害（输入板本来就关着）。

### 5.3 权限

- `Info.plist` 加 `NSMicrophoneUsageDescription`（「按住语音按钮说话时录音，转成文字发给远程程序」）和 `NSSpeechRecognitionUsageDescription`（「把你按住语音按钮时说的话转成文字」）。
- 第一次按下时依次申请语音识别和麦克风权限；申请期间不录音，这一次按住不算（用户授权后再按一次）。
- 被拒绝或受限：提示气泡显示「需要麦克风和语音识别权限」和一个「去设置」按钮（调用现有的 `openSettings`），约 4 秒后消失。

### 5.4 识别（原生）

- 新建 `gui/ios/Runner/SpeechPlugin.swift`，通道 `rapp/speech`，在 `AppDelegate` 里和 `IosPlugin` 一样注册。
- 方法：`start`（参数无；返回 `ok` / `asked`（首次弹了授权框）/ `denied` / `preparing`（资源还在下载）/ `unavailable` / `cancelled`（还没开始就被 `cancel` 或中断抢先，Dart 侧静默））、`stop`（结束录音，等最终结果）、`cancel`（丢弃）。事件经同一通道回调到 Dart：`partial {text}`、`final {text}`、`error {code}`、`level {value}`。`level` 是麦克风音量，0–1（每块音频的 RMS 换成分贝，−50 dB 到 0 dB 线性映射，夹在 0–1），每秒最多 20 次，只在录音时发。
- 还按着时原生先给了 `final`（例如老接口到了 1 分钟）：Dart 侧记下这段字，松手时直接用，不再等 1 秒。
- 语言（2026-11-18 起改为只用系统首选语言的第一项，见 `2026-11-18-rapp-macos-voice-design.md` §4.1；下面是原来的做法）：取设备的语言列表（`Locale.preferredLanguages`），中文项排前，其余按设备顺序，最后退回 `zh-CN`；逐个试到识别器支持的为止。不用 `Locale.current`：应用包只声明了英文，中文手机上它是 `en_CN`，中文会被当英文识别（0.14.8 实机发现）。
- iOS 26+：`SpeechAnalyzer` + `SpeechTranscriber`（开启实时结果），需要的语言资源由系统 `AssetInventory` 准备；资源还没下好时本次返回 `preparing` 并触发下载，提示「正在准备语音识别，请稍后再试」。
- iOS 17–25：`SFSpeechRecognizer` + `SFSpeechAudioBufferRecognitionRequest`，`shouldReportPartialResults = true`，`supportsOnDeviceRecognition` 为真时设 `requiresOnDeviceRecognition = true`。
- 录音：App 里别处没有用 `AVAudioSession`（2026-11-18 查过 `gui/ios/Runner` 和 Dart 依赖），语音插件独占它。`AVAudioEngine` 输入节点；`AVAudioSession` 用 `.record`（不加 `.duckOthers`：SDK 说它只配别的类别），结束时 `setActive(false, options: .notifyOthersOnDeactivation)`。监听中断通知，中断时发 `error {code: interrupted}`。
- Dart 侧一个小类（例如 `gui/lib/embed/voice_input.dart` 的 `VoiceInput`）包装通道，暴露状态（空闲 / 听 / 等结果）和当前文字，供按钮和气泡使用；测试里用假通道。

## 6. 不变的东西

- 协议不变，A 端和 relay 都不用改。
- 输入历史的格式不变；语音发出的记录和输入板发出的完全一样（不加"来自语音"标记，我定的：用户说的是"统一进入历史"）。
- macOS、Linux 界面不变。

## 7. 留给实现者

- 圆形按钮是给 `RappButton` 加变体还是新组件，看现有代码哪种改动小。
- 拖动换边用 `GestureDetector` 的水平拖动还是 `Listener`，以不影响「输入」「还原」的轻点为准。
- 圆盘、环带、气泡用一个 `CustomPainter` 画还是拆成几个组件，看哪种动画好写；几何和选中判断要能脱离界面单独测。

## 8. 验收（真机，Duo 和 iPad）

1. 按住语音按钮说一句中文：按钮长成圆盘、环带长出、气泡边说边出字、音量条跟着声音动；松手后圆盘缩回按钮，A 上的程序收到这句话，并按设置补了回车。
2. 输入板里上翻历史能看到这句话。
3. 按住后拇指滑出圆盘到「取消」段：那段亮起、轻震、提示「松手 取消」，松手后 A 上什么都没收到。滑回圆盘又变回「松手 发送」。
3b. 滑到「编辑」段松手：输入板打开，草稿末尾是这句话，A 上什么都没收到。
4. 按住不说话就松手，显示「没听清」，什么都没发。
5. 第一次按下弹出两个授权框；在设置里关掉麦克风权限后再按，显示「需要麦克风和语音识别权限」和「去设置」。
6. 拖「输入」到左边，整组吸到左边缘；杀掉 App 再开，还在左边。轻点「输入」仍能打开输入板。
7. 软键盘弹出时按钮组让开；文本终端里按键行出现时，按钮组在按键行上方。
8. 断开 Wi-Fi 让会话冻结，按住说话再松手，提示内容未发送，文字在输入板草稿里。
9. 深色和浅色主题下，三个按钮、圆盘、环带和气泡都和舞台上其它控件一致，没有发光和阴影。
10. 按钮组在左边时，圆盘、环带、气泡全部镜像，「编辑」仍在靠屏幕边、偏上的那段。
11. 打开「减少动态效果」，按下和松手都没有变形动画，直接出现和消失。
12. 单手握 Duo，大拇指不用伸到角上就能按住语音按钮；竖屏时「输入」在它靠中间的一侧（横排），横屏时在它正上方，都够得着。按钮组在左边时一样。
13. 打开输入板：语音按钮还在，在输入板外右上方（整组在左时在左上方）。弹出键盘、拖动输入板时按钮跟着输入板走，不压在输入板上。
14. 输入板打开、键盘弹出时按住语音说话再松手：A 收到这句话，输入板还开着，草稿没变，键盘没收起（编辑器没丢焦点）。
