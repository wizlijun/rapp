# rapp 触摸屏双指滚动（P3）

状态：设计（用户需求 2026-11-12：「需要支持触摸屏双指上滑下滑的操作」；按用户「全部按推荐」默认采用）。
已实现（b8b7361，`gui/lib/embed/picture.dart`）；实机检查待做（需要触摸屏 B）。

## 1. 要什么

B 是触摸屏（平板、触屏电脑）时，在 GUI 舞台的远程画面上双指上下滑动 = A 上手指所在位置滚动。
内容跟着手指走（和 Mac 触控板「自然滚动」一样）：手指往上推，A 的内容往上走。左右滑也照样转给 A，不另做限制。

## 2. 范围

- 只改 Flutter GUI 的嵌入画面（`gui/lib/embed/picture.dart`）。detach 后的原生窗口、rapp-client 跑在 Mac 上，没有触摸屏，不改。
- 鼠标、触控板、滚轮的行为一律不变。
- 不做捏合缩放、不做惯性滚动、不做单指滚动（单指仍然是按下 / 拖选 / 松开）。
- A 侧和线路协议不变：仍用已有的 `scroll(sid, window, x, y, dx, dy)`。

## 3. 规则（只对 `PointerDeviceKind.touch`）

T1. 第一根手指落下时先不发「按下」，挂起。以下先发生哪个就按哪个处理：
  - 第二根手指落下 → 进入「滚动」，挂起的按下作废，A 上什么也没发生；
  - 手指移动超过 8 逻辑像素 → 补发按下（落点位置），然后照常拖；
  - 手指抬起 → 补发按下 + 松开（一次点击，双击计数照旧）；
  - 过了 150 ms → 补发按下（按住不动的长按照常工作）。
T2. 按下已经发出后再来第二根手指：忽略它（和现在一样），不打断拖选。
T3. 滚动中：任一手指移动，按两指中心点的位移（单指位移的一半）发 `scroll`，位置 = 两指中心点，目标窗口 = 中心点下的窗口或弹出层；中心点不在画面上就不发。
T4. 滚动中抬起一根手指，剩下那根不变回点击，直到所有手指都抬起才结束滚动。
T5. 第三根及更多手指：滚动中忽略；挂起时同第二根（进入滚动）。
T6. 手指取消（`PointerCancel`）：挂起的按下作废；已发出的按下照现在一样发松开。
T7. 滚动的第一下照样让画面拿到键盘焦点（同按下）。

## 4. 测试（widget 测试，假 port）

- 双指上滑：只出现 `scroll`，dy 为负、位置在两指中心；没有 `mouse`。
- 单指轻点：`down` + `up`，坐标是落点。
- 单指拖：超过 8 像素后 `down` 在落点，随后 `drag`、`up`。
- 单指按住 200 ms：`down` 已发出；再落第二根手指不出现 `scroll`。
- 滚动中抬起一指再移动另一指：没有 `mouse`。
- 鼠标按下立刻发 `down`（不受 150 ms 影响）。

## 5. 代价

触摸的单指按下晚到 A 最多 150 ms；只影响触摸屏，鼠标不受影响。
