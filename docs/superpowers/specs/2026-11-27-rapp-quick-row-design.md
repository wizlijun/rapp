## 1. 一句话

常用语条变成“第一行”：前面是打了星的常用语、命令和按键动作（没打过星就按使用次数排），末尾固定「按键▾」「常用语▾」两个菜单；下面的快捷键盘（第二块）由用户自己排。这五样设置存成一个单独的本机文件，网里有 rapp-state 时和它同步。

```
┌ 继续  搜历史  进度  跑下测试 …→            │按键▾│常用语▾│ ┐  ← 第一行（常用语条）
┌ Tab ⇧Tab Esc ⌃C ⌫ ⏎ ↑ ⋯                               ┐  ← 键盘布局 第 1 行
┌ ⌘C ⌘V ⌘T ⌘ ⌃ PgUp PgDn ← ↓ →                          ┐  ← 键盘布局 第 2 行（⋯ 展开）
```

## 3. 目标、不做、反目标

**目标**

- T1 第一行末尾两个菜单，点开能看到并直接用这一类的全部项；菜单里能打星；菜单底部「设置…」进这一类的独立设置页（U1、U2）。
- T2 第一行前面：有星标时放打星的项，按打星的先后；一个星都没有时按使用次数排（U2）。
- T3 按键动作：带名字的键或组合键，可加、改、删（U7）。
- T4 键盘布局可以自己排：两行各放哪些键、什么顺序（U3、U6）。
- T5 常用语、按键动作、键盘布局、星标、使用次数在 Mac、iPad、Duo、Linux 上读到同一份（U4、U8）。
- T6 网里没有 rapp-state 时，一切照常，只是不同步。

**不做**

- 同步其他设置（主题、语音、输入法、窗口位置……）（U8）。服务的格式不挡以后加。
- 每台设备一份不同的布局。所有设备用同一份【我定的】。
- 同一份列表里两边同时改时逐条合并。整份以改动时间晚的为准（§10.3）。
- 和别的用户共享。

**反目标**（做出来也算失败）

- 第一行在手指底下自己换位置：按次数排的顺序只在第一行出现时算一次，用着的时候不动（§5.3）。
- 同步悄悄吃掉刚改的东西：本机改了还没交上去的，不会被服务上更旧的那份覆盖（§10.3）。
- 没有 rapp-state 的用户多了任何步骤或提示。

## 5. 第一行（常用语条）

### 5.1 摆法

- 前面一段横滑，放“显示项”（§5.2）；末尾固定两个按钮「按键▾」「常用语▾」，取代「全部 ›」。两个按钮和小块同高（`phraseStripChip`），不随横滑移动。
- 显示条件改为：`phrase_strip` 开，且是文字终端或 App 配置开了常用语条。**不再要求有能显示的项**：前面空着时只剩两个菜单，菜单仍然有用【我定的】。
- 小块的点和长按照旧（常用语 spec §4、§5）。按键动作的小块点一下发出它的键（§6.3），长按菜单是：编辑 / 取消星标或打星 / 删除。常用语和命令的长按菜单里「移到最前」改成「打星」或「取消星标」；已经打星的再多一项「移到最前」（改的是星标的先后）【我定的】。

### 5.2 显示什么

- **有星标**（星标列表非空）：只显示打了星的项，按星标列表的先后。不能在这个会话用的跳过（命令前面没有认得的 AI 工具，同今天；按键动作在 App 会话里要有键码，§6.3）。
- **没有星标**：显示全部项（常用语、命令、按键动作），按最近 30 天的使用次数从多到少；次数一样的按它在自己菜单里的先后，常用语菜单的排在按键菜单的前面【我定的】。新装机所有次数都是 0，看到的就是今天常用语条的样子，后面再接上按键动作。

### 5.3 顺序什么时候算

- 按次数排的顺序在第一行出现时算一次（换会话、快捷区展开、第一行重新显示），之后用着不重排。星标改了立刻重排（那是用户自己的动作）。

### 5.4 两个菜单

- 点「按键▾」或「常用语▾」：底部升起这一类的完整列表，沿用今天「全部 ›」那个弹出层（`phrase_strip.dart` 的 `_all`）。
- 每行：名字（按键动作再带上键的写法，如 `⌃R`；命令带 `/clear` 这类本会话会发的东西，今天已有），右边一颗星 ☆/★。
- 点一行：用它，然后收起（同今天）。点星：只切换星标，不收起，不发送。
- 这个会话用不了的项变灰，点了说明原因（沿用今天的提示文字），星照样能点。
- 列表最后一行「设置…」：收起弹出层，进这一类的设置页（§6.4、§7）。
- 两个菜单在 iOS 和 macOS/Linux 一样【我定的】。

## 6. 按键动作（「按键▾」）

### 6.1 一项是什么

```
KeyAction { id, label, chord, per? }
```

- `id`：稳定标识。内置的是固定字符串，用户加的是随机 8 位。
- `label`：名字，如「搜历史」。
- `chord`：默认发什么。修饰键 ⌃ ⌥ ⇧ ⌘ 的组合加一个键：字母 a–z、数字 0–9，或 `barKeys` 里有 wire 名的键（Tab、Esc、Enter、方向、PgUp……）。
- `per`：可选，按 AI 工具改写：`{ 工具 id: chord 或 null }`。缺这个工具就用 `chord`，有值就用它，null 表示这个工具没有这个动作（在它前面变灰）。**只能是键**，不能是文字：发文字的是常用语菜单里的命令（`StripCmd`）。设置页第一版**不**提供编辑 `per`，只有内置项带；数据里留着这个字段【我定的】。
- 常用语菜单里的命令（`StripCmd`）照旧可以在某个工具上发一个键（`CmdKey`），今天的编辑功能不变：按键动作是“到处发同一个键”的，命令是“同一个意思、各工具写法不同”的。

### 6.2 内置的（新装机和“恢复默认”）

| id | 名字 | 键 | 说明 |
|---|---|---|---|
| `search` | 搜历史 | ⌃R | 从内置命令里搬过来（今天是 `builtinCmds['search']`），id 不变，星标和次数跟着走 |
| `mode` | 切模式 | ⇧Tab | |
| `expand` | 展开输出 | ⌃O | |
| `bg` | 转后台 | ⌃B | |
| `clear` | 清屏 | ⌃L | |
| `newtab` | 新标签 | ⌘T | 终端上是 rApp 自己的 ⌘T（同 `cmdt` 键） |

这几个的名字是按 Claude Code 的含义起的【我定的】；实现时照各工具文档核一遍，某个工具上含义不同的，用 `per` 标成 null 或改键（同常用语条命令 spec §7 的做法）。

**文档核对结果（2026-11-27，Task 1）**：标准是“在这个工具上会做坏事才记 null，只是没反应不算”。结论：四个都不做坏事，`per` 里只有 `search` 的 `agy`、`opencode` 是 null（沿用命令表）。

| 键 | Claude Code | Codex | Gemini CLI |
|---|---|---|---|
| ⇧Tab 切模式 | 轮换权限模式 | 文档里没写，按“没反应”处理 | 轮换批准模式（agent 忙时跳过） |
| ⌃O 展开输出 | 开关记录视图，展开折叠行 | 复制最近一条完成的回复（不破坏数据） | 展开/折叠内容块 |
| ⌃B 转后台 | 把运行中的 Bash 和 agent 转后台 | 文档里没写 | 开关当前后台 shell 的显示 |
| ⌃L 清屏 | 只重绘屏幕，对话保留 | 只清终端画面，对话保留，任务进行中禁用 | 清屏并重绘 |

Antigravity（agy）和 opencode 没查到公开的按键文档，沿用不特别处理（没反应也不算坏）。

### 6.3 怎么发

- 终端：`chord` 转成 wire 名（`Ctrl-Alt-x`、`Shift-Tab`），和快捷键盘一样发。⌘ 组合在终端上走 rApp 自己的快捷键（今天 sticky ⌘ 加字母那条路，`termCommand`）；不是 rApp 认得的 ⌘ 组合在终端上不能用（变灰）。
- App 会话：`chord` 转成 macOS 键码加修饰位，和快捷键盘一样发。字母和数字的键码表补全数字（`macLetterCodes` 今天只有字母）。
- 发出时不碰输入框、不抢焦点，和按键一样；发出后不加回车。sticky 修饰键（`ModifierLatch`）不叠加到按键动作上，发完不清 latch【我定的】。

## 8. 键盘布局（第二块）

### 8.1 一份布局是什么

```
Layout { rows: [[id…], [id…]] }
```

- 两行。第 1 行总显示；第 2 行由 `⋯` 展开（`key_bar_more` 照旧是本机的，不同步）。第 2 行为空时第 1 行不放 `⋯`。
- 每格是 `barKeys` 的 id，或按键动作的 id（显示它的名字，太长截断）【我定的】。
- 每行最多 10 格（`keyBarColumns`），`⋯` 也占一格：`⋯` 不进布局数据，第 2 行非空时自动排在第 1 行末尾，这时第 1 行最多 9 格。
- 倒 T 照旧由 `keyBarTail` 认出来：一行末尾正好是 ↑（下一行末尾是 ← ↓ →）时那几个键占一列一格，否则所有格平分。
- 默认就是今天的两行。数据坏了、空了、有不认得的 id 时：丢掉不认得的格；两行都空就用默认。

### 8.2 编辑

- 设置页里画出两行的样子（和真的一样宽）。点一格选中，再点下面的键盘里的一个键替换；选中后有「删除」；拖动换位置；行末「＋」加一格。
- 可选的键：`barKeys` 全部（除 `more`）+ 所有按键动作。
- 改了立刻生效，无“保存”按钮，和今天的设置页一样。

## 9. 使用次数

- 每台设备记自己的（设备 id 用数据目录的设备 id，即 `devices/<id>/` 的那个）：`{ 项的 id: { 日期(yyyy-mm-dd，本地时区): 次数 } }`，只保留最近 30 天。
- 记的是第一行和两个菜单里“点了用了”的：常用语、命令、按键动作。键盘布局里的按键不记（不参与第一行排序）。
- 排序用的是所有设备合起来的 30 天总数（同步上的话，§10.2）。
- 常用语今天没有 id：给 `Phrase` 加一个 `id` 字段，读到没 id 的就生成一个随机 8 位写回【我定的】。

## 10. 存储和同步

### 10.1 本机文件

两个文件【我定的】：

- **`devices/<设备id>/quick.json`**（和 `gui.json` 同目录，进 git，和今天的常用语一样有 git 备份）：五份“文档”，每份 `{ "at": 毫秒时间, "data": … }`：

| 名字 | data |
|---|---|
| `phrases` | 常用语和命令（今天的 `phrases` 列表，`Phrase` 带 id） |
| `keys` | 按键动作列表 |
| `layout` | `{ rows }` |
| `stars` | 项 id 的列表，按打星先后 |
| `usage` | 只有这台设备自己的次数 `{ 项 id: { 日期: 次数 } }` |

- **`local/quick-sync.json`**（不进 git）：同步的记账：连的是哪个中心服务（它所在设备的 id），每份文档的 `synced`（上次和**这个**服务一致时的 `at`，没同步过是 0），以及从服务上抄来的别的设备的次数。这样别的设备的次数和同步时间不会每分钟进 git。
- 数据目录里已有的 `shared/` 也是靠 git 在设备间共用的，但只有配了 git 远端才同步、而且是分钟级；这五样走 rapp-state（U9），不放 `shared/`，免得两套同步打架。
- **迁移**：`quick.json` 不存在时，从 `gui.json` 的 `phrases` 建：
  - `StripCmd('search')`：它的 `per` 里没有任何改成文字的（今天用户可以改），就拿出来变成按键动作 `search`（`per` 里的 `CmdKey` 换成对应的 chord）；有改成文字的就留在常用语里当命令，按键动作里照样放一个内置 `search`。
  - 用户自己加的命令（不管发文字还是发键）都留在常用语里。
  - 其余照搬，常用语补 id；`keys` 是内置 6 个（`search` 已在就不重复）；`layout` 是默认；`stars`、`usage` 空。
  - 迁移出来的五份 `at` 记成 0：表示“还是出厂/升级时的样子，没有被这台改过”，第一次接上服务时让位给服务上已有的（§10.3）。
  - `gui.json` 里的 `phrases` 留着不删（旧版本还读它），以后只读 `quick.json`【我定的】。
- `phrase_strip`（开关）、`key_bar_more`、`phrase_cmds_seeded` 留在 `gui.json`，不同步。

### 10.2 中心服务的内置能力 `prefs`

rapp-state 已改名中心服务 rapp-center（`services/center/`，见 `2026-11-27-rapp-center-design.md`）。用户 2026-11-27 定：这五样做成中心服务的内置能力 `prefs`（实现 `Builtin`，在 `builtin::table` 登记一行），**并掉中心服务规格里的 G3**（那边只同步常用语、整份覆盖；以这里为准）。

| 接口 | 做什么 |
|---|---|
| `GET /v1/routes` | 入口自己的，自动多一项 `{"name":"prefs","kind":"builtin","v":1}`；app 靠它知道这个服务支持设置（没有这项、或 `/v1/routes` 404 的旧服务就不同步） |
| `GET /prefs/v1/all` | `{ "store": "<16 位十六进制>", "phrases": {at, data}, "keys": …, "layout": …, "stars": …, "usage": { 设备 id: {at, data} } }`，没有的文档不带 |
| `GET /prefs/v1/<名字>` | 一份：`{at, data}`；没有时 `{"at":0,"data":null}` |
| `PUT /prefs/v1/<名字>` | `{at, base, data}`，`名字` 是 `phrases` `keys` `layout` `stars` 之一。`base` 是客户端以为服务上现在的 `at`（没有就 0）。服务上的 `at`（没有算 0）等于 `base` 就收下，回 204；否则回 409 和服务上的那份 |
| `PUT /prefs/v1/usage/<设备 id>` | `{at, data}`：整份替换这台设备的次数，总是收下，回 204 |
| `GET /v1/watch` | 入口那一条，多两种推送：`{"what":"prefs.<名字>","doc":{at,data}}`；`{"what":"prefs.usage","device":…,"doc":{at,data}}`。旧 app 遇到不认的 `what` 忽略（`state_sync.dart` 的 `_apply` 默认分支） |

- `store`：服务的身份（§10.3 “第一次接上”靠它认），第一次建时随机生成，存进 `prefs.json`；没有数据目录（只放内存）时每次启动新生成。`health` 不动（它归入口）。
- 存盘：数据目录下自己的 `prefs.json`（入口的 saver：0600、原子写、读坏了挪开只丢这一块、记 `load_failed`），没有数据目录时只放内存。文档不过期；某台设备的 `usage` 按**服务收到的时间** 90 天没更新就清掉【我定的】。
- 每份 `data` 序列化后最大 256 KB，超了回 413；体不是 `{at, base, data}` 回 400；不认的名字回 404；方法不对 405。服务不检查 `data` 的内容（app 自己验，坏的当没有）。
- 写进 `services/center/api/prefs.md`，`routes.md` 的例子加上 `prefs`，样本放 `services/center/api/samples/prefs.ndjson`。

### 10.3 合并规则

一份文档（`phrases` `keys` `layout` `stars`）只有三种情况：

| 本机 | 服务上 | 做法 |
|---|---|---|
| 没改过（`at == synced`） | 比 `synced` 新 | 用服务上的，`synced = at = 服务的 at` |
| 改过（`at > synced`） | 还是 `synced` | `PUT`（`base = synced`），成功后 `synced = at` |
| 改过 | 也比 `synced` 新（两边都改了） | `at` 晚的赢。本机晚：`PUT` 带服务的 `at` 当 `base` 再交；服务晚：用服务的，本机这次的改动丢掉，日志记一行 |

- `PUT` 回 409 时，拿回来的那份当“服务上的”，再走一遍上表。
- 本机写的 `at` 取 `max(现在, 服务上的 at + 1)`，免得两台钟差把新改动当成旧的【我定的】。
- 服务上没有这份：把本机的交上去（第一次接上的那台，内容成为大家的）。
- **第一次接上这个服务**（`quick-sync.json` 里记的服务不是它，或者 `synced` 是 0），服务上已经有这份：
  - 本机这份 `at` 是 0（没改过）：直接用服务上的。
  - 本机改过：`phrases` 和 `keys` **合并**：服务上的在前，本机有而服务上没有的接在后面（常用语和命令按文字 / id 认同一条，按键动作按 id，用户加的按“名字 + 键”认）；合并后本机的 `stars` 里指向被认成同一条的 id 换成服务上的 id；`stars` 取并集，服务上的在前；`layout` 用服务上的，除非服务上那份是默认、本机不是。合并结果当作本机的新改动交上去。谁也不丢东西【我定的】。
  - 合并完记下这个服务，`synced` 按它记。
- **服务上这份比 `synced` 旧，或者没了**（服务重装、换成了只放内存）：当作第一次接上处理。
- 网里只该有一个中心服务（中心服务规格 §3）；有两个时 app 用设备 id 最小的那个，它掉线换到另一个时，也走“第一次接上”。
- `usage` 不走这张表：每台只写自己那格，读的时候加起来。本机的次数变了，最多 1 分钟交一次【我定的】。

### 10.4 什么时候同步

- 和中心服务连着的时候（`StateSync` 是 connected、`/v1/routes` 里有 `prefs`）：连上时 `GET /prefs/v1/all` 走一遍 §10.3；之后靠 watch 的 `prefs.*` 推送；本机一改（间隔 1 秒合并）就交。
- 连不上、或中心服务关了：只用本机文件，改动记着（`at > synced`），连上后按 §10.3 交。
- 回到前台时重取一次（同状态的做法）。

### 10.5 用户看得到的

- 两个设置页底部一行灰字：「已和 <设备名> 上的中心服务同步」/「只存在本机（没有中心服务）」/「连不上中心服务，改动会在连上后同步」。
- 别处改了、这台收到时，第一行和设置页直接换成新的，不提示。
