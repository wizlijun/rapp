日期：2026-11-25。状态：**已定**。用户说“全部做完，中途不用问我”，下面标【我定的】的都是我替你做的选择，可以改。

## 1. 做什么

1. **总览（Q1）**：已打开的终端块，第二行写程序自己报的状态，五种都写：「在干活 · 42%」「等确认 · approve Bash: …」「出错 · …」「完成」「空闲」。有程序状态时它代替流量数字。断开、连接中仍写原来的字。
2. **设备页跟着统一【我定的】**：终端那一行的 `done` / `idle` 也写「完成」「空闲」，不再落回「未读」「N 分钟没动静」。有没有看过由灯表示（没看过是等待灯），规则不变。
3. **状态队列（Q2）**：顶部提示右边 ▾ 打开的列表【我定的：用户说的“状态菜单”就是它，它是顶栏上唯一按时间排的列表】，改成一个队列：
   - rApp 自己说的话（原来的提示历史），和程序状态的变化，按时间排在一起，新的在上，共 50 条。
   - 程序状态的变化：一个终端的状态换了（开始干活、等你、完成、出错、空闲），或者等你时换了一个新问题（`seq` 变了），记一条：`<终端名> @ <设备>：<状态>`，前面一盏灯。进度数字变化不记。
   - 刚连上设备时它已有的状态不记【我定的】，免得开机刷一屏；之后新出现的终端照记。
   - 程序状态的变化只进队列，不占顶栏那一行字【我定的】：那一行留给 rApp 刚做的事。
   - 跟会话有关的一行可以点：点了切到（或打开）那个会话，菜单关上。
   - 每条记录可以带来源（`source`）、设备、会话和灯，以后 GUI 客户端状态（规则引擎）认出来的变化用同一个格式进来，标“推断”。这次**不做**规则引擎：它的规格还是待确认的第 2 稿，被控端也还没有识别画面的代码。
4. **需要你直达（Q3）**：每一行整行可点：
   - 等你处理的终端 → 切到（或打开）那个会话；
   - 断开的会话 → 切到那个会话（舞台上有重连按钮）；
   - 离线的设备 → 设备页。
   - 原来行尾的按钮（打开 / 重连 / 查看）保留。
   - 不再只列 3 条加“还有 N 件”，全部列出，列表可以滚【我定的】。
5. **顺手修**（S1 遗留，todo 第 11 条）：设备离线时，已打开终端的“等待”灯和程序状态都不算。

## 2. 不做

- 不自动点、不自动输入；队列只读。
- GUI 客户端（Claude、ChatGPT、Antigravity）状态识别：等那份规格确认后另做，接进本文第 3 条的格式。
- 队列不存盘，重开 rApp 从空开始（和原来的提示历史一样）。
- 连着状态服务时，程序状态行从服务来；没连上时仍是本机从设备终端列表里读。

## 3. 办法（考虑过的）

- **A 并进提示历史（选这个）**：一个列表、一个入口，正合“统一到一个队列”；改动小。
- B 顶栏另开一个“状态”菜单：多一个按钮挤顶栏，而且 rApp 的提示和程序状态还是两处。
- C 放进“需要你”：那里只放要你动手的事，干活中、完成这些不该进去。

## 4. 验收

- 总览：五种状态各一种字，断开时写断开。
- 队列：终端状态变一次记一条；同一状态只换进度不记；刚连上时已有的不记；点一条切到那个会话。
- 需要你：点终端行、断开会话行、离线设备行，各到对应的地方；多于 3 条全列。
- 设备离线：已打开终端不再亮等待灯。
