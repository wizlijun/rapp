## 0. 一句话

**项目是"工作域"在 rapp 里的对应。** 人本来就在十来件事之间来回切换，每件事牵着一组工具。rapp 不创造这个结构，也不规定它；rapp 做三件事：让切过去更省，让切回来更快，让不相关的不来打扰。

## 1. 理念：工作域研究说了什么

"工作域"（working sphere）是 Gloria Mark 和 Victor González 在 2004 年提出的。他们跟着知识工作者一整天，记下每一次切换。定义是：**一组相互关联的事，有共同的目的，牵涉一组特定的人，用到特定的资源，有自己的时间安排。**

下面每一行是研究的发现，和它在 rapp 里的含义。

| # | 研究的发现 | 出处 | 对 rapp 的含义 |
|---|---|---|---|
| W1 | 人切换的单位是工作域，不是单个动作或单个 app。一个人一天在约 10 个工作域之间切换 | Mark 2004 | 项目这一层是真实存在的，值得有对应的手段 |
| W2 | 在一个工具或文件上平均停留 2 分多钟；在一件小事上 3 分多钟；在一个工作域里连续工作约 11 分半就会切走 | Mark 2004 | 切换非常频繁。切换必须是一个动作，不能有任何准备步骤 |
| W3 | 57% 的工作片段被打断。其中约一半是自己打断自己 | Mark 2005 | 打断是常态，不是例外。设计要假定用户随时会离开 |
| W4 | 被打断的工作，77% 当天会回来；回来平均要 25 分钟，中间隔着 2 个多别的工作域 | Mark 2005 | 回来是关键时刻。回来时要一眼知道"上次停在哪、这期间发生了什么" |
| W5 | 中间隔的事越多，回来时需要保留的信息越多。被打断的工作要容易恢复：保留现场，给出重新进入的线索 | Mark 2005 | 现场要原样留着；项目要记住上次停在哪 |
| W6 | 打断如果来自当前的工作域，是有帮助的；来自别的工作域，才是干扰 | Mark 2005 | "需要你"要区分是不是当前项目的 |
| W7 | 工作域分中心的和外围的。中心的每天占约 47 分钟，外围的约 15 分钟 | Mark 2004 | 项目不是平等的。少数几个是主要的，要一直看得见 |
| W8 | 人自己会做"容器"让中心的工作域一直在眼前：专门的邮件夹、一摞打印件、计划本、贴在显示器上的便利贴（有人最多贴七张）。这些容器放在看得见的地方，不表示优先级，事情做完就清掉 | Mark 2004 | 便签（PD7"只放少数最重要的大块记事"）和全景里的项目灯，就是这种容器 |
| W9 | 邮件、日程这类工具被多个工作域共用 | Mark 2004 | 同一个 app 可以在多个项目里，也可以哪个都不在 |
| W10 | 人要花时间管理这些工作域本身（研究里单列为一类） | Mark 2004 | 管理项目花的功夫要压到最低 |
| W11 | 研究给信息技术的建议：围绕工作域而不是单个 app 来设计；让人能把文件和应用归组；保存每个工作域的现场以便快速回来；提供一直在、扫一眼就懂的状态显示 | Mark 2004 | 归组（已有）、保存现场、状态灯和全景、外部小屏 |

相邻研究里用得上的几条：

| # | 发现 | 出处 | 对 rapp 的含义 |
|---|---|---|---|
| W12 | 用户的窗口天然成组，每组对应一件事。Rooms 让每件事一个"房间"；同一个窗口可以在几个房间里；有"口袋"（不管在哪个房间都带着的窗口）和"后门"（一步回到上一个房间） | Henderson 和 Card 1986 | 成员可以共用；"常用"相当于口袋；要有"回到上一个项目" |
| W13 | 以活动为中心的计算：暂停一件事、之后恢复，它用到的东西原样回来；在一台电脑上暂停，可以在另一台上恢复 | Bardram 2006 | 项目跟着人走：平板和电脑上看到的是同一批项目 |
| W14 | 任务情境：激活一个任务，界面只显示和它有关的东西，其余隐藏 | Kersten 和 Murphy 2006 | 切到一个项目，就只看这个项目的东西。这也是专注（PD10）的依据 |
| W15 | 注意力残留：从一件没做完的事切走，上一件事还占着一部分注意力，下一件事做得更差 | Leroy 2009 | 少切、切得干净。离开时现场留着，人才放得下 |
| W16 | 情境依赖记忆：在什么环境里记的，回到那个环境更容易想起来 | 见文末说明 | 东西的位置要稳定。这是"固定位置比 git 更容易回忆"（U35）的依据 |

W2 的数字要说明一下：它们来自 2004 年对一家公司 14 个人的观察，是那个环境下的数字，不是普遍的常数。本文用的是它的量级和方向，不是具体的秒数。

## 2. 原则：用户定的

这些是 2026-11-14 上午用户逐条说的，和 §1 的研究是一致的：研究说工作域是人自己形成的，用户说 rapp 不该规定它。

| # | 原则 | 出处 | 对应的研究 |
|---|---|---|---|
| P1 | **两个层级。** 设备和会话是物理层面的记忆；项目是概念层面的。当工具用时前者容易理解；深入使用以后，概念层面才和脑子里的分组对应上 | U92 | W16、W1 |
| P2 | **项目只是对应的手段。** 各个工具里都有自己的 workspace、project，互不相通。rapp 不同步它们，也不规定用户必须怎么记 | U93 | — |
| P3 | **概念层面经常调整。** 所以改起来不能有代价 | U93 | W10 |
| P4 | **探索期边界是模糊的。** 还没长成项目的东西不需要持续投入；一开始不能要求用户先有结构，要适应各种用法 | U94 | — |
| P5 | **物理层本身就是自留地。** 东西在成为项目之前就待在那里，不需要另做一个功能 | U95 | — |
| P6 | **项目在前还是设备在前，由用户选，不是强制项** | U96 | — |

由此得到一条检验办法（我提的，用户没有反对，也没有单独确认）：**用户一个决定都不做，这个功能还能不能用？** 能，结构就是提供的；不能，结构就是要求的。rapp 里只该有前一种。

## 4. 概念

| 词 | 是什么 | 层 |
|---|---|---|
| 设备 | 一台机器 | 物理 |
| 会话 | 一次到（设备, app）的连接 | 物理 |
| 常用 | 用户标出来的（设备, app），没打开时也看得到 | 物理 |
| 项目 | 一个名字，加一组指向（设备, app）的引用 | 概念 |

项目本身没有状态。它的样子全部来自成员：成员的灯是什么，项目的那一排灯就是什么。

项目里可以存的东西只有四样：名字；成员；每个成员的一行备注；是不是固定的（§6.3）。没有描述、截止日期、负责人、进度。rapp 不做任务模型（主界面规格的非目标，不变）。

**每个成员的一行备注**：S5 里叫"Agent 任务标签"。按 P2，它的用处是记下"这件事对应这个工具里的哪一个"，比如"Claude 里的 rapp 项目"。rapp 没法替用户在那个工具里切过去（不侵入 app），它只是帮用户记着。界面上的叫法改成"备注"。（我定的）

## 5. 项目怎么长出来

按 P4、P5，从零散使用到成为项目，中间没有门槛，也没有人催。

```
零散地开着用  →  有几个总在用，标成常用  →  觉得这几样是一件事，起个名字  →  调整  →  不是一件事了，散掉
   物理层              物理层                      概念层                 概念层        回到物理层
```

每一步都是可选的，停在哪一步都是完整的用法。

| 时刻 | rapp 做什么 | rapp 不做什么 |
|---|---|---|
| 还没有项目 | 按设备、按 app 列出会话；"常用"和最近的在手边 | 不提示"还没有项目"；不显示空的项目页催人去建 |
| 开着几样东西，想存下来 | 一个动作："把现在开着的存成项目"，只要起个名字 | 不问别的；不要求选哪些，默认是全部开着的，之后可以移出 |
| 用着用着想加一样 | 在会话上一个动作："加入项目" | 不要求先打开项目页 |
| 这样东西不属于这里了 | "移出"。会话照常开着 | 不问"确定吗" |
| 这件事结束了 | 删掉项目。会话、常用都不受影响。删后几秒内可以撤销 | 不要求先结束会话；不做归档 |

**没归到任何项目是正常状态。** 按项目分组时，这些会话照常列出，不标数字，不叫"未分类"。

**rapp 不提议分组。** 它可以把最近用的、常用的排在前面（这是物理和时间上的顺序），但不说"这几样看起来是一件事"。

## 6. 切换和回来

这是 §1 里研究最着力的地方（W2–W5、W15），也是现有功能最薄的地方。

### 6.1 切到一个项目

一个动作。切过去以后：

- 看到的是这个项目的成员，以及各自的灯。
- 停在**上次在这个项目里用的那个会话**上，不是第一个成员。（W5）
- 成员里没打开的不自动打开。要全部打开，仍然用"全部打开"。（我定的：切换要快，打开远程 app 有代价，由用户决定）

### 6.2 回来的线索

切到一个项目时，在项目名旁边给一行线索，几秒后淡掉：

```
25 分钟前离开 · 这期间 1 个等你
```

- "多久前离开"来自上次离开这个项目的时间。
- "这期间"只说和这个项目有关的变化：有几个成员进入了"等你"或"已断开"。没有变化就只写时间。
- 这一行不用强调色，不闪。它是线索，不是提醒。

### 6.3 固定的项目

少数几个主要的项目可以"固定"（W7、W8）。固定的项目：

- 排在前面。
- 在全景里一直占一格（现有的全景已经是每个项目一格、一个成员一盏灯）。
- 以后外部小屏要显示项目状态时，显示的是固定的这几个。

固定不表示优先级，只表示"一直看得见"。数量不设上限，但界面按"不多"来设计：研究里的人最多贴七张便利贴。

### 6.4 回到上一个项目

一个动作回到上一个项目（W12 的"后门"）。在两个项目之间来回是最常见的切换。

### 6.5 现场

"保存现场"在 rapp 里大部分已经成立，不用另做：会话断开以后条目还在、可以重连（S3）；远程 app 自己的状态留在被控端。本文只新增一样：每个项目记住上次停在哪个会话。

## 7. 打扰

W6：来自当前工作域的打断有帮助，来自别的才是干扰。

| "需要你"来自 | 平时 | 专注时 |
|---|---|---|
| 当前项目的成员 | 照现在的做法：顶栏计数，灯闪 | 同左。它就是这件事的一部分 |
| 别的项目，或者不在任何项目里 | 照现在的做法 | 只计入顶栏的数字，不弹横幅。退出专注后照常 |

"专注时"那一列是我的提议。它回答了决策文件里专注那一条的一个待定项（专注时"需要你"还打不打断）；写专注的规格时以这里为准，或者由用户改。

没有项目的用户（P4）：专注的范围退回到物理层，也就是当前这个会话。别的会话的"需要你"按"别的项目"那一行处理。

## 8. 排列：项目在前还是设备在前（P6）

一个偏好，两个取值。它只改变顺序和默认值，不隐藏任何东西：

| 受影响的地方 | 设备在前 | 项目在前 |
|---|---|---|
| 会话列表默认的分组 | 按设备 | 按项目 |
| 左侧面板标签的顺序 | 会话、设备、项目、资源 | 会话、项目、设备、资源 |
| 全景里两排的顺序 | 设备墙在上，项目在下 | 项目在上，设备墙在下 |

- 默认是设备在前（我定的：P1 说当工具用时前者容易理解，新用户还没有项目）。
- 这是界面偏好，每台操作设备各存各的：平板和电脑可以不一样。
- 用户临时切换会话列表的分组方式，和现在一样，不改这个偏好。

## 9. 跨设备

项目存在数据目录的 `shared/workspace.json` 里，随 git 同步（数据目录规格 D2）。所以在平板和电脑上看到的是同一批项目（W13）。

每台操作设备各自记的（不同步）：排列的偏好；每个项目上次停在哪个会话；上次离开的时间。这些是"我在这台设备上的位置"，不是项目本身。

## 10. 不做

- 自动归纳项目、提议分组（P2）。
- 项目嵌套、项目模板、项目归档。
- 同步各个工具自己的 workspace 或 project（P2）。
- 在别的工具里替用户切到对应的 workspace（不侵入 app）。
- 任务、进度、截止日期（主界面规格的非目标；任务状态在 NEXT 里管，PD7）。
- 项目级的打扰设置（研究建议过"让用户为每个工作域声明能接受哪些打断"，第一版用 §7 的固定规则）。
- 多人共享项目。

**范围**

- 只动界面这一侧（`gui/`）。hub、service、relay 都不改。
- §7 专注时的规则**不做**：rapp 还没有专注模式，等专注的规格。
- 外部小屏显示固定的项目不做。

**数据放在哪里**

| 数据 | 文件 | 同步吗 |
|---|---|---|
| 项目：名字、成员、备注、是否固定 | `shared/workspace.json`。每个项目多一个可省略的 `pinned`（缺了当 false）。`version` 仍是 1。备注在文件里的键仍是 `task` | 同步 |
| 排列偏好 | 每台设备自己的 `gui.json`，新增 `"first": "device"` 或 `"project"`，不认识的值当 `device` | 每台设备各存各的 |
| 每个项目上次停在哪个会话、何时离开 | `local/project_positions.json`：`{"version":1,"projects":{"<项目 id>":{"last":"<设备>/<bundle>","left_at":"<UTC 的 ISO 8601>"}}}` | 不同步。它每次切换都会变，放进 git 会让数据目录每分钟提交一次 |

**切到项目（§6.1）**

- 切过去以后：会话列表改成按项目分组；这个项目那一组排在最前；停在上次用的会话上。
- 上次用的会话已经不在项目里或者没开着：退到第一个开着的成员。一个都没开：不选任何会话，仍然算切到了这个项目。
- 有当前项目时，顶栏的前后切换只在这个项目开着的会话里循环。
- 选了一个不属于当前项目的会话，等于离开这个项目（回到"没有当前项目"）。
- "何时离开"在这两个时刻记：切到别的项目；选了项目外的会话。

**回来的线索（§6.2）**

- 显示 5 秒，位置是顶栏当前会话的第二行，文字用次要文字的颜色，不加粗、不闪。
- 文字的规则：不到 60 分钟写"N 分钟前离开"；不到 24 小时写"N 小时前离开"；否则"N 天前离开"，都向下取整。有变化时接" · 这期间 A 个等你""B 个已断开"，两个都有时用顿号隔开。
- 不显示的情况：第一次切到这个项目；离开不到 1 分钟；记下的离开时间在将来（时钟往回走过）。
- "这期间"只数在离开之后才变成等你或已断开的成员；离开之前就已经在等你的不算。

**入口**

| 动作 | 在哪里 |
|---|---|
| 存成项目 | 项目页顶部，「新建项目」旁边；流量菜单"会话"一组里「加入项目」展开的列表最后一项。什么都没开着时不可用，不建空项目 |
| 加入项目 | 流量菜单"会话"一组，「结束会话」上面。展开后列出还不包含当前会话的项目 |
| 切到 | 项目页每张卡的标题行；会话列表按项目分组时点组名 |
| 固定、取消固定 | 项目页每张卡的标题行 |
| 上一个项目 | 顶栏，前后切换按钮旁边。没有上一个项目时不出现 |
| 排列 | 左侧面板底部，主题下拉旁边，两项：设备在前、项目在前 |

不做快捷键。

**删后撤销（G8）**

- 删项目点一次就删。项目页顶部出现一行"已删除「名字」"和「撤销」，5 秒后消失。
- 只能撤销最后删的那一个；撤销后放回原来的位置，并且已经存盘。
- 删的是当前项目或上一个项目时，对应的记录一并清掉。

**排列偏好（§8）**

- 改偏好不改当前的分组方式；它只决定下次启动时的默认分组、面板标签的顺序、全景里两排的顺序。
- 固定的项目在项目页和全景里都排在前面，各自保持原来的先后。

**界面上的词**（只用这些，不换说法）：存成项目、切到、固定、取消固定、加入项目、撤销、备注、未归项目的、设备在前、项目在前、上一个项目。

**规格没有明说、实现时要处理并测试的五种情况**

1. 位置记录里的项目已经不存在（在别的设备上删了，同步过来）：启动时丢掉这条记录；它是当前项目时退回到没有当前项目，不报错。
2. 停在的那个会话已经结束：按上面"切到项目"的第二条处理。
3. 时钟往回走，或者记下的离开时间在将来：不显示线索，不显示负数。
4. 什么都没开着时点"存成项目"：按钮不可用，不建空项目。
5. 连删两个项目再撤销：只恢复最后删的那个；5 秒后不能撤销。

**验收**

- 没有任何项目、没有任何偏好文件时，现有的测试全部照常通过，界面上不多出任何提示。
- `flutter analyze` 无问题，`flutter test` 全过。
- 新控件的高度都不小于 48px。
- 平板上的实机检查（触控大小、线索是否挡住别的东西）单列为未验证项。
