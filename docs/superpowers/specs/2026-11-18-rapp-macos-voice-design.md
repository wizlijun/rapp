# macOS 上的按住说话：鼠标按钮和长按右 Option

日期：2026-11-18。状态：设计已确认，待实现。

## 1. 为什么做

iOS 上已经有按住说话了（`2026-11-18-rapp-voice-input-design.md`，下称「iOS 规格」）。用户在 2026-11-18 提出，macOS 版也要有同样的体验，原话的意思是：

- 「语音输入的体验，macOS 版也实现一下，只是按钮布局和大小要调整一下，适合鼠标操作。」
- 「以及响应用户的键盘自定义快捷键。默认快捷键设定为右 Alt 长按。」

用户在选择题里定了三件事：

1. 快捷键只在 rapp 是前台窗口时生效，不做全局快捷键，也不申请辅助功能或输入监控权限。
2. 录音时画面是一个小气泡加两个目标，不照搬 iOS 的大圆盘，也不压暗舞台。
3. 快捷键是按住说话、松开发送。按住期间按 Esc 是取消，按 Tab 是编辑。可以自定义成别的修饰键或组合键。

实现方案 A 也是用户选的：识别用的原生代码和 iOS 共用一份。

审阅时用户又定了一件：**文字终端也要支持**，鼠标按钮和快捷键都要有（见 §6.3）。

之后用户又提出：「请考虑支持英文、欧洲语种、中文、日文、韩文这些国家」。后来说明了意思：「使用 Apple ASR 中支持多国的能力，使用系统默认的，如果用户第一次用不满意，则引导用户去那里设置。现阶段无需加那么多多国语言。」接着又说：「减少不必要的语言判断逻辑等。保持极简能力，跟随系统」。所以 rapp 自己不做任何语言选择，识别语言就用系统的，只告诉用户去哪里改（见 §4.1）。这条 iOS 和 macOS 共用。

本规格改掉 iOS 规格里的两句：§2 的「macOS、Linux 客户端不加语音按钮，那一排按钮也不改」，以及 §6 的「macOS、Linux 界面不变」。Linux 仍然不做。

## 2. 目标、非目标、反目标

### 目标

- 舞台右下角那排按钮里加一个「按住说话」：
  - 用鼠标按住就开始听，气泡里边说边出字。
  - 松开就发送，和 iOS 一样：走 `sendVoice`，进历史，遵守这个 App 的「直接回车」设置，冻结时把字放回草稿。
  - 按住时把指针拖到「编辑」或「取消」上松开，就选中那一项。
- 在 rapp 的主窗口里，长按右 Option（默认快捷键）也一样能说话：松开发送，按住期间 Esc 取消、Tab 编辑。
- 快捷键可以在侧栏的设置里改，也可以关掉。

### 非目标

- 不做全局快捷键（rapp 不在前台时不响应）。
- 不在单独拿出去的窗口（detached window）里加按钮或快捷键。那里的右 Option 和现在一样，直接发给 A。
- Linux 不做。iOS 的交互不变。
- 不接云端识别，不做标点整理（同 iOS 规格）。

### 反目标（做了也算失败）

- 平时用右 Option 打组合键（例如 ⌥←、⌥字母），A 收到的按键少了或者顺序乱了。
- 轻点一下右 Option，A 收不到这次按键。
- 语音开始后 A 收到一个按下却没松开的 Option，结果卡住。
- 语音发出去的东西不进历史，或者和输入板发出的记录不一样。
- 新按钮、气泡和舞台上现有的控件样式不一致，深浅主题里看着突兀。

## 3. 方案

考虑过两种（用户选了 A）：

1. **两端共用识别代码，快捷键在原生层判断**（选这个）。
   - `SpeechPlugin.swift` 和 `SpeechLocales.swift` 改成 iOS 和 macOS 两个工程共用一份。iOS 工程已经用这种方式引用了 `../macos/Runner/SessionPlugin.swift`。
   - app 画面上，右 Option 在 `SessionPlugin.route` 里判断。发给 A 上 app 的按键都是在这里截下来的，Dart 根本收不到，所以只能放在这里。文字终端的按键不经过这里，由 Flutter 舞台自己处理（`main_state.dart` 里「A terminal's keys are the stage's own」），所以终端要在 Dart 侧另做一份同样规则的判断（§6.3）。
   - Dart 侧复用 `VoiceInput`、`VoiceHold`（逻辑部分）和 `sendVoice`。
2. **给 macOS 另外复制一份识别插件**：不用动 iOS 工程，但同样约 400 行代码要维护两份，iOS 上刚修过的中文识别问题以后得两边各修一次。

在 Dart 里用 `HardwareKeyboard` 判断快捷键这条路走不通：按键在原生层已经发给 A 并被吞掉了。

## 4. 识别（原生，两端共用）

- 把 `gui/ios/Runner/SpeechPlugin.swift` 和 `SpeechLocales.swift` 移到 `gui/macos/Runner/`，iOS 工程改成引用这两个路径，和 `SessionPlugin.swift` 的做法一样。通道还叫 `rapp/speech`，方法和事件不变（iOS 规格 §5.4）。
- 只有 iOS 才有的东西用 `#if os(iOS)` 隔开：`AVAudioSession` 的类别、激活和停用，中断通知，`UIApplication.willResignActiveNotification`。
- macOS 上，当 rapp 的主窗口不再是 key window（`NSWindow.didResignKeyNotification`）时，按中断处理（`error {code: interrupted}`），Dart 侧按取消处理。注意不是整个 App 失去前台时才算。
- macOS 26 及以上用 `SpeechAnalyzer` + `SpeechTranscriber`，14–25 用 `SFSpeechRecognizer`（部署目标是 macOS 14.0），`preparing` 和本机识别优先都照 iOS 规格 §5.4。用哪种语言识别改按 §4.1，iOS 也一样。
- 在 macOS 的 `AppDelegate` / `MainFlutterWindow` 里注册插件，位置和其它插件一样。
- 权限：
  - 在 `gui/macos/Runner/Info.plist` 里加 `NSMicrophoneUsageDescription` 和 `NSSpeechRecognitionUsageDescription`，文案和 iOS 一样。
  - 在 `DebugProfile.entitlements` 和 `Release.entitlements` 里加 `com.apple.security.device.audio-input = true`。Developer ID 包是带 hardened runtime 签名的（`scripts/lib/sign-check.sh`），不加这一项的话，麦克风会被系统直接拒掉，而且不会弹授权框。
  - 被拒绝时，提示气泡显示「需要麦克风和语音识别权限」和「去设置」。macOS 上「去设置」打开系统设置的「隐私与安全性 → 麦克风」（用 `open` 打开 `x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone`，做法同 `openSettingsPane`）。
- `MainState.voice` 在 macOS 上也要创建（现在只有 iOS 才创建）。

### 4.1 识别语言：跟随系统（用户定的，极简，iOS 和 macOS 都适用）

- 只用系统「首选语言」列表的**第一项**（`Locale.preferredLanguages.first`），经现有的 `SpeechLocales.normalise` 转成识别器认识的写法。苹果的识别器本身支持英文、欧洲语言、中文、日文、韩文等，rapp 不加任何语言判断。
- 去掉现有 `SpeechLocales.candidates` 里的多余逻辑：不再把中文排到最前，不再逐项往下试，也不再退回 zh-CN。`normalise` 保留，因为它解决的是 `zh-Hans-CN` 这类写法识别器不认的问题，不是在选语言。
- **iOS 例外（用户 2026-11-18 在 0.14.12 发布后定的）**：首选语言列表里有中文时，用排在最前的那一项中文，没有中文才用第一项。iPad 和 iPhone 上常见系统界面用英文、键盘用中文，只看第一项会把中文听成英文单词。不恢复逐项往下试，也不退回 zh-CN。
- **macOS 也一样（用户 2026-11-25 定的）**：和 iOS 同样中文优先。起因是一台 Mac 的首选语言是 English (UK) 在前、中文在后，按住说中文被当成英文听。
- 不用 `Locale.current`，原因见 iOS 规格（应用包只声明了英文，中文系统上它是 `en_CN`）。
- 这种语言这台设备识别不了：照现有的 `unavailable` 处理，提示文字改为「这种系统语言暂不支持语音识别，可以在系统设置里换一种」。
- 引导：**第一次用完以后**提示一次「识别语言跟随系统。要换语言：系统设置 → 通用 → 语言与地区」。macOS 上带「去设置」按钮，打开「语言与地区」（`x-apple.systempreferences:com.apple.Localization-Settings.extension`）；iOS 不能直接跳到那一页，只显示文字。只显示一次，记在 `gui.json` 里（`voice_language_hint_shown`）。
- 不做：rapp 自己的语言设置、语言列表、跟着输入法切换、在气泡上显示或切换语言。

## 5. 鼠标：按钮和气泡

### 5.1 按钮

```
舞台右下角（横排，和现在一样）：
                 [⟲ 还原] [⌨ 输入] [🎤 按住说话]
```

- 在现有那排横向按钮（`composer_panel.dart` 里非 iOS 的那支）**最右边**加一个 `RappButton.secondary`：图标 `Icons.mic_none`（录音中是 `Icons.mic`），文字「按住说话」，`onPicture: true`，Key 为 `voice-hold`，读屏标签「语音」。大小和「输入」一样，不用 iOS 的大圆按钮。
- 只在 macOS 上出现，出现条件和「输入」一样（`session.composerAllowed`，输入板没开（2026-11-24 输入块起，文本区开着也算，见 2026-11-24-rapp-input-dock-design.md §5.6），也只在 `state.voice` 不为空时出现。
- 鼠标左键一按下就开始（和 iOS 一样不等），不需要长按阈值。
- 录音时，这排里的其它按钮和进度行淡出（120 ms），「按住说话」留在原位、显示为按下的样子。

### 5.2 气泡和两个目标

```
舞台右下角：

          ┌────────────────────────┐
          │ 帮我把这个函数重命名… ▮▮▮▯ │   气泡
          └────────────────────────┘
            [✎ 编辑 Tab]  [✕ 取消 Esc]   两个目标
                            松手 发送   提示
                                [🎤 按住说话]
```

- 气泡右对齐在按钮排的右边上，底边比按钮排高 8。宽度是 `min(舞台宽 − 32, 480)`，最多 4 行，超出时只显示末尾。气泡里右下角有一排音量条，和 iOS 一样跟着 `level` 跳。还没有字时显示「正在听…」。
- 目标排在气泡下面，从右往左依次是「取消」和「编辑」，最右边和气泡右边对齐。两个都是 `RappButton.secondary` 的样子（图标 + 文字），文字后面用 `t.muted` 小字标出键名：「编辑 Tab」「取消 Esc」。
- 提示行（「松手 发送」「松手 取消」「松手 改一改再发」）在目标下面，右对齐。
- 样式和颜色全部取 `RappTokens`，三种状态对应 iOS 规格 §5.1 的表格：
  - 发送：气泡是 `t.text` 底、`t.bg` 字。
  - 取消：被选中的目标是 `t.accent` 底、`t.accentInk` 字；气泡变灰，音量条停。
  - 编辑：被选中的目标同样亮起；气泡是 `t.float` 底，虚线边，末尾有光标。
  - 舞台**不压暗**，也没有圆盘和环带。
- 动画：
  - 按下：气泡和目标用 160 ms 淡入并上移 8。
  - 松开：发送时气泡上移淡出，取消和编辑时原地淡出。
  - 打开「减少动态效果」时直接出现和消失。

### 5.3 选项判断

- 鼠标按住期间，指针在「编辑」或「取消」目标的范围里（每边各放宽 6 点）时选中那一项。其余任何地方，包括舞台外，都算「发送」。
- 在哪里松开，就按松开时所在的选项处理（同 iOS 规格 §5.1 的「松手、限时、中断」）：
  - 发送：最多等 1 秒拿最终结果，然后 `sendVoice`。
  - 取消：丢掉结果。
  - 编辑：最多等 1 秒拿结果，放进草稿末尾，打开输入板。
- 「没听清」、最长 5 分钟（2026-11-22 从 60 秒放宽）、同一时间只能有一次录音，都和 iOS 一样。
- 鼠标按下后又被系统抢走（pointer cancel），按取消处理。
- 用鼠标按住时也可以按 Esc 或 Tab，效果和快捷键一样（见 6.2）。
- 没有轻震（Mac 没有）。
- 按下按钮时，现有的 `holdForPanel` 会让画面失去焦点，所以按住期间 Esc 和 Tab 能被 Flutter 收到。**（我定的）**发送或取消以后，焦点还给画面（app 画面或终端），这样接着打字、再按快捷键都能直接用，不用先点一下画面；选「编辑」时焦点留在输入板。

### 5.4 松开后的提示

- 没听清、放回草稿、权限、准备中这几种提示，用一个小气泡显示，样式同 iOS 规格 §5.1（`t.raise` 底、`t.text` 字、1 px `t.line` 边）。位置在按钮排正上方、右对齐，显示时长和 iOS 一样。

## 6. 快捷键

### 6.1 默认：长按右 Option

- 判断放在 `SessionPlugin.route` 的 `.main` 分支，在「打字就打开输入板」（`composeStart`）之前。只有这次按键本来就要发给 A 时（`targetSid` 不为空，即舞台上的画面有焦点）才算，并且要求这个会话 `composerAllowed`、输入板没开（2026-11-24 输入块起，文本区开着也算，见 2026-11-24-rapp-input-dock-design.md §5.6）、Dart 侧说「能说话」。Dart 用一个通道方法把这些条件告诉原生，例如 `set_voice_ready {sid, ready}`。条件不满足时，右 Option 和现在完全一样。
- 右 Option（keyCode 61）按下，而且此刻**没有别的键按着**时，先扣住，不发给 A：
  - **0.3 秒内松开**：把按下和松开一起补发给 A，等于轻点了一下，和现在一样。
  - **0.3 秒内按了别的键**（包括另一个修饰键）：先把扣住的右 Option 按下补发给 A，再按原来的路线发那个键。之后就当普通的组合键处理，这次不会再触发语音。
  - **按满 0.3 秒**，期间没有别的键：开始说话。这次右 Option 的按下和松开都不发给 A。
- 按上面的规则，扣住的永远只有这一个右 Option 按下：别的键一来就补发。这套判断要放在「打字就打开输入板」的扣字逻辑（`ComposeHold.add`，在 `composeStart` 之前就会运行）**前面**，两者互不干扰：右 Option 补发之后，后面的字母照常走那套逻辑。
- **（我定的）鼠标也算「别的键」**：发给 A 的鼠标消息不带修饰键，A 只能从按键里知道 Option 有没有按着。所以扣住期间，只要在画面上按下鼠标或滚动，就先把右 Option 按下补发给 A，再发鼠标消息，这次不会再触发语音。这样 ⌥点击、⌥拖动、⌥滚动都和现在一样。录音期间在画面上按下鼠标：取消录音，鼠标消息照常发给 A（A 没见过这个 Option，不用补发）。录音期间的滚动照常发给 A，不影响录音。
- **（我定的）松开的规则**：一个键的按下如果发给了 A，它的松开也发给 A；按下被吞掉的，松开也吞掉。录音期间也一样，这样 A 上不会有卡住的键。
- 录音期间：
  - 松开右 Option：发送（等最终结果，同 5.3）。
  - 按 Esc：立刻取消，气泡消失。之后松开右 Option 什么也不做，也不发给 A。
  - 按 Tab：立刻进入编辑（等结果，放进草稿，打开输入板）。之后松开右 Option 什么也不做，也不发给 A。
  - 其它任何键：吞掉，不发给 A，也不影响录音。
  - 按 Esc 或 Tab 之后、松开右 Option 之前，其它按键照样吞掉。
- 录音期间，主窗口不再是 key window：按取消处理（见 §4）。这时 A 没有收到过右 Option，所以不用补发松开。
- 原生通过 `rapp/session` 通道通知 Dart，例如 `voice_key {sid, phase}`，`phase` 取 `start`、`release`、`cancel`、`edit`。Dart 用同一个 `VoiceHold` 把它转成对应的动作，画面和鼠标完全一样（5.2），只是没有指针，也就不会悬停选中。
- 鼠标正在按住说话时，快捷键不再触发；快捷键正在说话时，鼠标按下「按住说话」也无效。

### 6.2 自定义

- 侧栏的设置里加一行「语音快捷键」，只在 macOS 上显示，位置在「记下写作面板发出去的话」附近。这一行显示当前设置，例如「长按 右 ⌥」「按住 ⌃⌥Space」「关」，旁边有一个「改」按钮。
- 点「改」以后，这一行变成「请按下快捷键…（Esc 取消）」，下一次按键决定新的快捷键：
  - **只按了一个修饰键就松开**（左右分开算：左/右 ⌥、左/右 ⌃、左/右 ⇧、左/右 ⌘，以及 Fn）：设为「长按这个修饰键」，规则同 6.1，阈值也是 0.3 秒。
  - **修饰键 + 普通键**（至少有 ⌘、⌃、⌥ 中的一个）：设为「按住这个组合键」。按下组合键就立刻开始，没有阈值。松开那个普通键就发送。录音期间 Esc 和 Tab 的规则和 6.1 一样。
    - **（我定的）修饰键照常发给 A**：用户先按下 ⌃⌥ 时还看不出是不是快捷键，这时它们已经发给 A 了，所以录音期间 A 会认为 ⌃⌥ 按着。只有那个普通键（例如 Space）的按下和松开不发给 A。修饰键的松开照常发给 A（按 6.1 的松开规则）。
    - 如果修饰键先松开、普通键还按着：继续录音，松开普通键时发送。
  - 不接受的情况：单独的普通键、只加了 ⇧ 的普通键、Esc、Tab、rapp 在舞台上自己留着的组合键（`KeyRouting.swift` 里 `routeKey` 留在本机的那些：任何 ⌃⌘ 组合、⌘Q、⌃↩）。遇到这些就提示「这个键不能用」，保持在录入状态。
  - Esc：退出录入状态，什么都不改。
- 旁边还有「关」（关掉快捷键，鼠标按钮仍然可以用）和「恢复默认」（长按右 ⌥）。
- 存在本机界面设置 `gui.json`（`UiPrefs`）里，键名 `voice_hotkey`：
  - 值为 `{"kind": "hold_modifier", "key_code": 61}`，或 `{"kind": "hold_combo", "key_code": <n>, "modifiers": <NSEvent 修饰键位>}`，或 `"off"`。
  - 没有这一项或者值不对，都当默认值（长按右 ⌥）。
  - 每台设备各存各的。
- Dart 在启动时和每次修改后，都通过 `rapp/session` 通道把设置告诉原生，例如 `set_voice_hotkey`。终端那一份判断（§6.3）直接读同一个设置。

### 6.3 文字终端（用户定的：按钮和快捷键都要有）

- 鼠标按钮：终端舞台右下角那排按钮里同样有「按住说话」，行为和 §5 完全一样，发送走同一个 `sendVoice`。
- 快捷键：终端的按键由 Flutter 舞台自己处理，不经过 `SessionPlugin.route`，所以在 Dart 侧另写一个纯 Dart 的判断类，放在终端按键路径（`term_keys` / `term_stage`）的最前面。规则和 §6.1、§6.2 一字不差：0.3 秒阈值、轻点补发、别的键或鼠标按下就补发、录音期间 Esc/Tab/吞键、松开规则、组合键快捷键。
- 「补发」在终端里的意思是：把扣住的右 Option 按下事件交给终端原来的按键处理（例如「Option 当 Meta」的设置照常生效），然后再处理后来的键。
- 只在终端舞台有焦点、输入板没开的时候生效（2026-11-24 输入块起，文本区开着也算，见 2026-11-24-rapp-input-dock-design.md §5.6）。
- 原生 Swift 和 Dart 两份判断共用同一张测试用例表（按键序列和时间 → 发出去的事件 + 语音动作），两边各跑一遍，保证规则一致。

## 7. 不变的东西

- 协议不变，A 端和 relay 都不用改。
- 输入历史的格式不变。
- iOS 的交互不变。iOS 工程改成引用共用的 Swift 文件；行为上只多两点：识别语言按 §4.1（列表里有中文时仍用中文，否则用第一项），第一次用完提示一次去哪里改。
- Linux 界面不变。
- 单独拿出去的窗口不变。

## 8. 留给实现者

- 桌面版气泡用新组件写，还是从 `voice_overlay.dart` 里拆出可共用的部分（气泡、音量条），看哪种改动小。圆盘和环带是 iOS 独有的。
- `VoiceHold` 现在以 iOS 的几何为准判断选项。鼠标版本可以给它加一个「由外部给出选项」的入口，也可以另写一个小的判断类。两种做法都要能脱离界面单独测试。
- 扣住右 Option 的那段逻辑写成纯 Swift 的小类型，单独测试：按顺序收进按键事件和时间，输出「发给 A 的事件」和「语音动作」。现有的 `KeyDecision` 和 `hold` 也是这样测的。
- 判断「此刻没有别的键按着」时，用现有的 `keys` 状态，或者按下时的 `modifierFlags`，选更简单的那个。

## 9. 验收（真机，Mac）

1. 鼠标按住「按住说话」说一句中文：气泡里边说边出字，音量条在动。松开后 A 上的程序收到这句话，并按设置补了回车。上翻输入历史能看到这句话。
2. 按住后把指针拖到「取消」上：目标亮起，提示变成「松手 取消」，松开后 A 什么都没收到。拖回别处，提示又变回「松手 发送」。
3. 拖到「编辑」上松开：输入板打开，草稿末尾是这句话，A 什么都没收到。
4. 舞台有焦点时长按右 Option 说话，松开后发送成功。说话过程中 A 上没有任何 Option 按下的效果（例如菜单栏没有出现 Option 状态）。
5. 长按右 Option 说话时按 Esc：气泡消失，什么都没发；再松开 Option，A 也没收到任何键。按 Tab：输入板打开，字在草稿里。
6. 在 A 上用右 Option 打组合键：⌥← 按词移动、⌥ 加字母打特殊字符，都和以前一样。轻点一下右 Option，A 能收到这次按键。
7. 在设置里把快捷键改成 ⌃⌥Space：按住说话，松开发送。改成「关」以后，长按右 Option 没有反应，鼠标按钮仍然能用。重启 App 后设置还在。
8. 第一次使用时弹出麦克风和语音识别的授权框，而且是用 Developer ID 签名的安装包测。在系统设置里关掉麦克风后再按，显示提示和「去设置」，点「去设置」打开麦克风那一页。
9. 断开网络让会话冻结，按住说话再松开：提示内容没发出去，字在输入板草稿里。
10. 说话过程中用 ⌘Tab 切到别的 App：录音取消，什么都没发，回来以后 A 上也没有卡住的 Option。
11. 深色和浅色主题下，按钮、气泡和目标都和舞台上其它控件一致。
12. iOS 版（Duo）按住说话照常可用（检查共用 Swift 文件后没有回归）。
13. 在文字终端里（例如跑着 Claude Code）：鼠标按住说话和长按右 Option 都能发送；轻点右 Option、⌥ 组合键和以前一样。
14. 长按右 Option 不到 0.3 秒就在画面上 ⌥点击：A 收到的是带 Option 的点击。说话过程中点画面：录音取消，点击照常生效。
15. 用鼠标说完一句发出去以后，不点画面直接打字，字能到 A。
16. 系统首选语言第一项是简体中文时，说中文能识别；第一次用完弹出一次「识别语言跟随系统…」，第二次不再弹。Mac 上点「去设置」打开「语言与地区」。
17. 在系统里把 English 排到首选语言第一项，回到 rapp 后：Mac 上说英文能识别；Duo 上列表里还有中文时说中文能识别，把中文从列表里删掉后说英文能识别。
18. 某种语言第一次用、资源还没下载时，提示「正在准备语音识别」，下载完后再按就能识别。
