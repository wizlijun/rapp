## 1. 一句话和边界

**文本终端：rapp 在被控端开一个真的终端窗口，在里面用伪终端跑程序，再用屏幕状态同步把画面送到主控台。被控端的窗口照常能看能用，主控台是第二个观众。**

名字【我定的】：

| 界面上 | 全称 | 专业叫法 |
|---|---|---|
| 文本（默认） | 文本终端 | 屏幕状态同步（screen-state synchronization）：被控端维护字符网格，只同步最新状态。mosh 的 SSP 和 hurryvc 是同一类 |
| 画面 | 画面串流 | 像素串流（pixel streaming），就是现有的 app 会话 |

目标：

- 主控台点一下，被控端出现一个终端窗口，程序在里面跑；主控台上是清楚的文字，可以选中复制，可以发一段话、按 Esc 打断。
- 主控台关掉会话、断线，或者 rapp 的服务重启、升级，被控端的窗口和程序都照样在。重新打开，接上的是同一个，看到的是现在的屏幕。
- 被控端坐着的人在那个窗口里照常打字，和没有 rapp 一样。
- 一个入口：设备下的“终端”，排在“桌面”后面。

不做：

- **接管不是 rapp 开的终端窗口。** hurryvc 也做不到：它只能管经它启动的程序（`src/producer.rs:359-378`）。另一个程序的伪终端归终端 app 所有，macOS 上没有别的进程插得进去的办法。这些窗口只能用画面看（§2.3）。以后也不做接管（用户 2026-11-25 定的）：要在 rapp 里用 Claude Code、Codex 这类 TUI，引导用户从 rapp 的“终端”入口打开。
- 关了窗口还能活着。被控端有人关掉那个窗口，就是“用户主动退出”。要关了窗口还活着，用同一个入口里的 tmux 会话。
- 主控台上一个“结束程序”的按钮。结束会话只是不再看它（终端规格 §12）；想退出，就在终端里敲 `exit` 或退出程序。
- 按主控台的屏幕改尺寸（§6）。
- 鼠标转发、图片、把记录写盘（同终端规格）。
- Windows 被控端（另起设计，§9）和 Windows 当主控台（X6）。

不能出现的结果（做成了也算失败）：

- 主控台断线、关闭会话、rapp 服务重启或升级，让 rapp 开的窗口或里面的程序退出。hurryvc 和服务端的连接一断就杀掉程序（`src/producer.rs:313-318`），这一点**不照搬**。
- 被控端窗口里显示的东西和直接跑这个程序不一样，或者本机键盘不好用了。
- 远程的操作改了被控端窗口的尺寸，让本机显示错位。
- 线协议、舞台出现只有文本终端才有的分支（能复用的都复用；没有的能力就灰掉）。
- relay 的代码里出现“终端”这个概念。

## 3. 做法的选择（Approaches）

关键是**伪终端由谁持有**。

| 做法 | 是什么 | 取舍 |
|---|---|---|
| **A. 由被控端窗口里的 `rapp-term run` 持有（已选）** | rapp 开一个终端窗口，窗口里跑 `rapp-term run -- <命令>`；`run` 开伪终端、起程序、把输出同时写回窗口和自己的仿真器。这就是 hurryvc 的结构 | 和 hurryvc 一致，也最小。`run` 是终端 app 的子孙，不是 rapp 服务的子孙，服务重启、升级都碰不到它；主控台怎么样也碰不到它。代价：被控端关掉窗口，程序就结束（X8 把这算作用户主动退出） |
| B. 另起一个后台进程持有伪终端，窗口只是它的一个观众 | 一个自己写的、类似 tmux 的小服务 | 关掉窗口程序还在。但这是在重写 tmux：在 launchd 下怎么活过服务重启、窗口怎么重新接上，正是评审 R1、R6 说的那些坑；而且 Mac 上 tmux 已经能管这件事了 |
| C. Mac 上的“文本”底下悄悄用 tmux 实现 | 新开文本终端就是开一个 tmux 会话，再开一个窗口 `tmux attach` | 不是 hurryvc 的方法（X1）；用户也会在 tmux 的规矩里撞上它的配置、前缀键。排除 |

用户选了 A（2026-11-16，“请跟串流应用关闭后不关闭 host 应用一样的体验”，A 正好给出这个体验，见 §5）。

### 4.1 `rapp-term run`（新含义，X5）

照 hurryvc 的生产端重写（X7），三件事：

1. **开伪终端，起程序。** Mac 上用 `portable-pty` 的 `openpty` 加 `spawn_command`；目录、环境照命令行；没给命令就起用户的登录 shell。伪终端的初始尺寸取所在窗口的尺寸。
2. **输出分两份。** 从伪终端读到的字节，一份原样写到自己的标准输出（就是那个窗口），一份喂给 `alacritty_terminal`，得到字符网格和滚出去的历史。
3. **本机键盘。** 把所在窗口切到 raw 模式，读标准输入，原样写进伪终端；窗口改了尺寸（SIGWINCH），就改伪终端和仿真器的尺寸。退出时把窗口的模式还原。

另外三件是 rapp 要加的：

4. **本机 socket。** `run` 自己开一个 unix socket 等别人来连，路径 `$ROOT/local/term/pty/<pid>.sock`，目录 0700【我定的】。用 pid 不用名字：macOS 的 unix socket 路径最多 104 字节，名字可能很长，改名、重名也不用动文件；名字放在状态里。路径超长就报错退出，写明路径。谁来连都先给一个 token，对不上就断开。现成的两个 token 都不能用：`serve` 的 token 每次启动随机生成、只放在环境变量里（`rust/service/src/workers.rs:231`），`local/ipc.token` 每次服务启动也会重新生成（`rust/service/src/lib.rs:120`），而 `run` 要活过服务重启。所以新建一个固定的 `$ROOT/local/term/pty.token`（0600），第一次用到时生成，之后不换；`run` 和 `serve` 都读它【我定的】。`serve` 是来连的那一方，所以 `serve` 重启后重新扫这个目录就能接上，`run` 不用知道 `serve` 在不在、什么时候重启（§5）。
5. **对终端查询的应答。** 程序发来的查询（光标位置、设备属性这类）由被控端的那个窗口回答，`run` 不另外回，不然会回两次。hurryvc 也是这么分的：有本机终端时让它回答，没有时才自己回（`src/producer.rs:113-114`、`TerminalResponder`）。rapp 开的文本终端总有一个窗口，所以 `run` 只需要“不回”这一种【我定的】。

   **例外：程序状态的探测（OSC 7501）。** 这一条 `run` 自己回，回答固定是 `ESC ] 7501 ; ? ESC \`（10 字节），一块输出里最多答 64 次，回答排进程序的输入队列，排在这一块输出送到窗口之前，所以程序先读到它，再读到窗口对设备属性查询的回答。`term.json` 的 `programStatus` 为 `false` 时不答。见《程序状态规格》（`2026-11-25-rapp-program-status-design.md`） §5.3。
6. **程序状态。** `run` 同时从输出里解析程序报的状态（OSC 7501，Claude Code、Codex 等），记在状态和会话行的 `ps` 里（`TermRow.ps`），随列表送到主控台；有 `ps` 时未读跟着程序状态走，`blocked` 进“需要你”。扫描不改伪终端两个方向的字节。见《程序状态规格》（`2026-11-25-rapp-program-status-design.md`） §5。

`run` 什么时候结束：程序退出，或者所在窗口没了（伪终端另一头收到 SIGHUP）。**不因为任何连进来的观众断开而结束。**

在被控端任意一个终端里手敲 `rapp-term run -- claude` 也是同一件事，只是窗口是自己开的。它同样出现在主控台的列表里。

### 4.3 `rapp-term serve` 的改动

- **一个新后端 `pty`**：会话标识 `term:pty:<名字>`（`id.rs` 不用改格式，后端名本来就是参数）。
  - 列出会话：扫 `$ROOT/local/term/pty/`，每个 socket 连一下问状态（名字、命令、尺寸、最后输出时间、观众数、pid、ticket）；连不上的 socket 是死掉的 `run` 留下的，删掉（还在忙、状态半秒没回的不删）。`run` 自己拿 `pty/.lock` 的文件锁，挑没人用的名字（`名字`、`名字-2`…）。
  - 看：连上那个 socket，后面照 §7 的会话协议，消息格式和 tmux 那边一模一样（`Hello` 的 `backend` 写 `pty`）。
- **新请求 `open`**（主控台的“新开文本终端”）：带目录、命令、名字、用哪个终端 app。`serve` 打开窗口的做法见 §4.4，然后每 100 毫秒扫一次状态，等 `ticket` 对上的那个 `run` 出现（最多等 10 秒【我定的】），回给主控台会话标识，主控台直接打开它。
- **抽出后端这一层**（评审 R3 说的时候到了）：现在 `serve.rs`、`session.rs` 里的列会话、取屏、送输入都直接写着 tmux。计划的第一步是把这三样提成一个两边都能实现的接口，tmux 后端的行为和测试不变。具体怎么切由计划定，但要守住一条：线协议（`proto.rs`）一个字段都不为 `pty` 加。
- `TermRow` 对 `pty` 会话的填法：`panes` 是 1，`attached` 是观众数（被控端那个窗口不算），`activity` 是最后输出时间，`dead` 总是 false（程序一退出，`run` 给观众发 `session ended`、删掉 socket，这一行就从列表里消失；正在看的主控台留着最后一屏），`unread` 照 `Unread` 的规则。主控台据此在列表里写“文本”，不写“几个面板”。

### 4.4 在被控端打开窗口（macOS）

- `serve` 在 `$ROOT/local/term/launch/` 写一个 `.command` 文件（0700），内容是 `#!/bin/sh` 加一行：`exec '<rapp-term 的绝对路径>' run --dir '<term 目录>' --ticket '<t>' [--name '<名字>'] [--cwd '<目录>'] [-- <命令>]`（路径、名字、目录用单引号转义，`'` 写成 `'\''`；命令原样放在 `--` 后面，由 shell 去拆；没有命令就不写 `--`）。`ticket` 是 `serve` 生成的随机串，`serve` 靠它认出自己开的那个 `run`。然后执行 `open -a Terminal <这个文件>`。Terminal 打开 `.command` 不需要“自动化”权限【我定的】。
  - iTerm：`open -a iTerm <文件>`，未实测，T0 要验证。
  - `run` 出现了，`serve` 就删掉这个文件；10 秒到了还没出现，文件先留着（冷启动的 Terminal 加上慢的 shell 配置可能更久才读它，删早了窗口里会报找不到文件）。每次 `open` 写新文件前，`serve` 先删掉 `launch/` 里修改时间超过 5 分钟的 `.command`。`run` 不知道这个文件。
  - 能用哪些终端 app：`serve` 起来时查一次，macOS 上 Terminal 总有，`open -Ra iTerm` 成功就有 iTerm；结果放在本机那条 `HostRow` 的 `launchers` 里，主控台只在它非空时显示“新开文本终端…”。
- 这样起来的 `run` 是 Terminal 的子孙，不在 rapp-service 的 launchd 任务里。T0 要实测这一点：停掉服务，看 `run` 和程序还在不在（§11）。
- `rapp-term` 的绝对路径取 `serve` 自己所在的目录（`.app/Contents/MacOS/`）。

### 4.5 主控台

- `TermSessionPort`、`TermStage` 不改，靠 `backend` 字段决定 §2.4 那两样灰不灰。
- 设备面板：合成“终端”这一项，排序（X4），合并原来的终端组，“打开方式”，“新开文本终端”对话框。
- hub：`terms` 列表、监视流都不用改格式；新增转发 `open` 请求。

## 5. 生命周期（X8）

| 发生了什么 | 被控端的窗口和程序 | 主控台 |
|---|---|---|
| 主控台关闭会话 | 照样跑 | 不再看 |
| 主控台断线、网络切换 | 照样跑 | 重连后接上，先收一整屏（S3 重连） |
| rapp-service 或 `serve` 重启 | 照样跑 | 列表短暂空一下；`serve` 起来后扫目录，会话回来 |
| rapp 升级（换了 `.app`） | 照样跑（跑着的旧 `rapp-term` 不受文件替换影响，未实测） | 新 `serve` 要能和旧 `run` 说话，见下 |
| 被控端的人在窗口里退出程序 | 程序结束；窗口照 Terminal 自己的设置留着或关掉 | 会话标“已结束”，最后一屏留着 |
| 被控端的人关掉窗口 | 程序结束 | 同上 |
| 被控端注销或关机 | 结束 | 同上 |

**升级时的版本差**：`run` 和 `serve` 之间的本机协议带一个版本号。`serve` 至少要能列出和看旧一个版本的 `run`；实在说不了话，就在列表里写“旧版本开的窗口，重开后才能用文本看”，不要让它消失，更不能去结束它【我定的】。

## 6. 尺寸

> 2026-11-17 起：勾着「跟着我的窗口」时被控端窗口跟着主控台走，见 2026-11-17-rapp-term-fit-design.md。

> 2026-11-16 起改了，见 `2026-11-16-rapp-term-entry-design.md` §2.6：“只缩不放”改了，舞台放大缩小都行；下面提到的 tmux 会话已不存在。

- 伪终端的尺寸只跟被控端窗口走：被控端的人改窗口大小，`run` 跟着改。
- 主控台不改它，按它的行列数缩放字号显示，这和 tmux 会话“有别的客户端接着”的情况一样（终端规格 §8.3）。
- “按我的屏幕重排”在这种会话里灰掉（§2.4）。hurryvc 是让远程直接改伪终端的尺寸，调研里已经指出那会让本机显示错位，这里不照搬。

## 7. 输入

| 主控台发来的 | `run` 做什么 |
|---|---|
| 一段文字（`Text`，可能分几条） | 拼完以后，程序开了括号粘贴模式（仿真器的 `BRACKETED_PASTE`），就包上 `ESC[200~` … `ESC[201~` 写进去；没开就原样写。`enter` 为真时再写一个回车。回一条 `Pasted` |
| 按键（`Keys`） | 按 `keys.rs` 现在认得的那套键名翻成字节；方向键要看仿真器是不是在“应用光标键”模式，换成相应的序列 |
| 逐键打字（`Type`） | 原样写 |
| 往上翻（`History`） | 从仿真器的历史里取。历史至少留 10000 行【我定的】，hurryvc 只留 1000 行 |

程序状态探测（OSC 7501）的回答也走这条输入队列，和这张表里的输入谁先到谁先进（§4.1 第 5 条）。

本机键盘和主控台的输入写进同一个伪终端，谁先到谁先进，和 hurryvc 一样，也和 tmux 会话里“输入谁发都进去”一样（终端规格 §15）。

## 8. 取屏

- 每次有输出就把网格标脏；合并、限速和“只留最新”照现在 `session.rs` 的规则：确认到了才发下一屏，发的是“主控台已确认的那一版”和“现在”的差。hurryvc 是来一块输出就发一次，这一点不照搬。
- 每一行写成和 `capture-pane -e` 一样的文字：字符加 SGR 颜色、粗体等转义，宽字符占两列，超链接写成 OSC 8。这样 `TermStage` 不用改。从 `alacritty_terminal` 的网格转成这种行，是这个后端里最要测的一块。
- 光标位置、形状、是否备用屏幕、`wrapped`（哪些行是折行接下来的）都从仿真器读，填进现有的 `Screen` 字段。
- 不在看的时候不取屏，只更新状态（最后输出时间、是否退出），给列表和未读用。

## 9. Windows（另起设计，X6）

Windows 被控端不在本文里做，等 Mac 做完另起一份设计（用户 2026-11-16 定的）。原因：Rust 代码里还没有一处 Windows 适配（2026-11-16 查过）；被控端的 ID、密码、relay 地址现在都靠 Flutter 的「本机」区设置和显示，而 Windows 版 Flutter 不做，那份设计得先解决“没有界面怎么配置、怎么看 ID 和密码”。这一块比伪终端本身的工作量还大。

本文给那份设计留下的约定：

- `run` ⇄ `serve` 的本机协议不写死 unix socket，Windows 上换成命名管道就能用。
- 伪终端照 hurryvc，用随包带的新版 ConPTY（`cpp/ptyrun.cpp:143,191`）；`portable-pty` 在 Windows 上也走 ConPTY，选版本时留意它能不能指定用随包的那份。
- 开窗口用 `wt.exe`。

## 10. 配置、日志、安全

- `term.json` 不加字段。`allow` 为假时，文本终端和 tmux 一样都关掉，“终端”这一项也不出现。
- 主控台 `gui.json` 加 `term_open`（§2.2），写进《配置规范总览》§2.4。
- 新目录 `$ROOT/local/term/`（`pty/` 放 socket，`launch/` 放临时的 `.command`，固定的 token 在 `pty.token`），0700，属于“程序自管的状态”，写进总览 §3。
- 日志照终端规格 §14：记谁什么时候开了、看了哪个文本终端，发了几次输入；不记屏幕内容、输入内容和命令。
- 安全边界不变（终端规格 §15）：relay 的 key，加上每台设备的“允许终端会话”开关。本机 socket 用 0700 目录加 token，只防同机的其他用户，不当成新的一道门（安全取向：relay 是唯一的门）。

## 12. 留给计划和实现的

- 后端接口具体怎么切、放在哪个文件。
- 本机协议（`run` ⇄ `serve`）的消息细节：只要能实现 §4.3 的“问状态”和 §7 的会话协议，并带版本号。
- `alacritty_terminal`、`portable-pty` 选哪个版本，许可证用之前核对。
- 合成“终端”这一项在主控台代码里怎么实现（参考 `desktop:` 的做法）。
- 文本终端在全景、项目、常用里的样子：和 tmux 会话一样，没有新的设计。
