# 常用语条里的命令：按工具发不同的指令（设计）

日期：2026-11-26。状态：设计稿，待用户审。
标「原话」的是用户的话，标【我定的】的是写规格时的判断，用户可以改。

相关：常用语条（`2026-11-22-rapp-ios-phrases-design.md`）、PC 按键区（`2026-11-24-rapp-pc-key-bar-design.md`）、快捷区按键梳理（`2026-11-25-rapp-key-bar-keys-research.md`）、程序状态（`2026-11-25-rapp-program-status-design.md`）、终端标题（`2026-11-25-rapp-term-title-design.md`）。

## 1. 为什么

原话：「像 /new /model 选择模型清理筛选这种常见的命令操作，应该放到快捷栏里；要根据不同的客户端发送不同的指令。」

在手机上遥控 Claude Code、Codex 这类 AI 编程工具时，开新对话、换模型、压缩上下文、搜历史这些操作每次会话都要用几次。现在得打开写作框，手打 `/clear`，还得记住这个工具叫 `/clear`、那个叫 `/new`。目标是**点一下就做成这件事，不用记各家的写法**。

## 2. 用户定下来的（2026-11-26）

1. **按意图，不按命令。** 按钮上写「新对话」「换模型」这种意图，rApp 看前台是哪个工具，翻成它的命令再发出去。换工具时按钮位置不变；这个工具没有的意图，按钮灰掉。
2. **合进常用语条，不另加一排。** 原话：「我觉得应该融合到第一排的快捷语音那一块，请把那块功能融合一下，做到可调整、可配置。」（一开始选的是放进 ⋯ 第二排下面，后来改成这个。）
3. **一张混合列表。** 常用语和命令在同一张列表里，一起拖动排序，管理页只有一个。
4. **「筛选」是搜以前发过的话**，也就是各家的 ⌃R。所以列表里除了「发一串字」的命令，还要有「按一个键」的命令。

## 3. 目标 / 非目标 / 反目标

目标：
- 常用语条上同时有常用语和命令，顺序由用户定。
- 命令按前台工具翻成对应的写法：发一串字加回车，或者按一个键。
- 管理页里能增、删、改、排序；能改内置命令在某个工具上的写法；能加自己的命令。
- iOS、macOS、Linux 三端一致：PC 端也是同一条常用语条（PC 按键区规格）。

非目标（这一版不做）：
- **App 会话里的命令**：远程画面里的 iTerm2、Ghostty、Claude 桌面版，rApp 看不出前台在跑什么，命令一律不出现。已定的路线是让用户通过 rApp 的文字终端来开 TUI（「不接管终端」，2026-11-25）。
- 用户自己加新的工具（比如没内置的某个 CLI）。内置的工具表随版本更新。
- 根据工具状态（在干活、在等确认）改变按钮。
- 设备之间同步配置。

反目标（这样做出来就算失败，哪怕技术上能用）：
- 把命令发进 shell。前台是 zsh 时如果发了 `/clear`，会被当成普通文字敲进命令行。
- 命令一出现，常用语就被挤得找不到。
- 管理页变成一张要填满每个工具、每种写法的大表格。

## 4. 条上怎么显示

- 条和现在一样：可以左右滑动，最右边固定一个「全部 ›」。列表里的项按用户排的顺序摆。
- 命令按钮的颜色和常用语不同（比如边框用强调色），键面只写意图，比如「新对话」，不写 `/clear`【我定的】。读屏念「命令：新对话」。
- **前台是认得的工具**：命令按钮正常显示。这个工具没有的意图就灰掉，点了在条上提示「Codex 没有这个命令」，显示 2 秒，提示的出法和现在的「连接已断开」一样。
- **前台认不出**（zsh、vim，或者终端列表还没到）：命令按钮**整个隐藏**，条上只剩常用语，不占位置【我定的：灰着的一排按钮占了位置却点不了，把常用语也挤远了；隐藏后看起来和今天一模一样】。前台在 zsh 和 claude 之间切换时，条上的命令跟着出现和消失。
- 「全部 ›」的列表也一样：显示常用语和命令，认不出工具时不列命令。
- 命令按钮的长按菜单：「编辑」「移到最前」「删除」。没有「放进输入框再改」，命令不会放进草稿。

## 5. 怎么认出前台是哪个工具

- 只认文字终端会话（`rapp-term`）。
- **先看前台是不是 shell。** 终端列表行的 `shell` 为 true（前台就是会话起的那个 shell），命令一律隐藏，不管别的信号怎么说【我定的：程序退出后，程序状态里 `done`、`error` 那几条还会留着（`rust/term/src/pty/ps.rs` 的 `drop_transient` 只清 idle、working、blocked），`app` 可能还写着 `claude-code`。只看它就会往 zsh 里发 `/clear`】。`shell` 为 null（旧设备）时按下面两条认。
- 前台不是 shell 时，依据有两个，先看前一个：
  1. 程序状态里的 `app`（OSC 7501 报的，比如 `claude-code`、`codex`）；
  2. 终端列表行里的 `fg`（前台进程名，比如 `claude`、`codex`、`agy`），通过 `MainState.termFg` 读取。
- 内置一张工具表：工具 id、显示名、匹配哪些 `app` 值和 `fg` 值。第一版列这五个：Claude Code、Codex、Gemini CLI、Antigravity（agy）、opencode【我定的；Gemini 和 opencode 是 node 程序，`fg` 可能是 `node`，那就只能靠 7501 的 `app` 认，认不出就按第 4 节隐藏】。
- tmux 后端和 App 会话认不出，命令隐藏。

## 6. 列表里的三种项

| 种类 | 存什么 | 点一下 |
|---|---|---|
| 常用语 | 文字、「点了之后」（发送或放进输入框） | 和现在一样（常用语规格第 4 节） |
| 命令（发字） | 意图 id、键面文字、每个工具的写法 | 按前台工具取出写法，比如 `/clear`，再加回车，走常用语发送的同一条路 |
| 命令（按键） | 同上，但写法是一个键（id 取自 `barKeys`，比如 `cr`） | 走按键区发送键的同一条路（`port.sendKeys` / `termWire`） |

- 命令「发字」还是「按键」是**按工具分的**：一个意图在 Claude Code 上可以是按键，在另一个工具上可以是发字。所以每个工具各存一条写法：`{text}` 或 `{key}`。没有写法就是这个工具没有这个意图，按第 4 节灰掉。
- 常用语的发送规则基本都适用于命令：1 秒内不能连发、断网时不发、上一条还在发时不发、不碰草稿、不改面板状态、⌃⌥⌘ 粘滞不作用在它上面。有两条不同：
  - 命令**完全不记进输入历史**，历史列表里也没有【我定的：历史里出现 `/clear` 没用】。常用语现在会记进历史，只是标了 `phrase`、↑ 翻不到；命令连记都不记，所以不能原样复用 `submitText(phrase: true)`；
  - 命令不经过 AI 整理（常用语本来也不经过）。

## 7. 默认内置的命令

默认列表 = 下面 6 条命令排在前面，后面接精简后的 7 条常用语：继续 · 按你推荐来 · 进度 · 全做完别问我 · 先写方案别改代码 · 跑下测试 · 提交并推送（用户随后又要求「最大程度减少快捷语句长度」，字是用户逐条定的）。用户 2026-11-26 要求精简（原话：「听你的和按你推荐来是重复的。请减少以方便默认空间能承载最多的快捷能力」），选了「留 7 条」：去掉「确认」「听你的」「总结一下改了什么」。只改默认值，已经存过列表的用户不动，点「恢复默认」才换成新默认【我定的：用户点名的就是这几个。「清理」和 `/new` 算同一个意图「新对话」，Claude Code 的 `/clear` 就是开一段新对话；如果你说的「清理」是别的意思，再单独加一条】。

| 意图 | Claude Code | Codex | Gemini CLI | agy | opencode |
|---|---|---|---|---|---|
| 新对话 | `/clear`（别名 `/new`、`/reset`） | `/new`（`/clear` 也开新对话，但先清屏） | `/clear` | `/clear`（别名 `/new`） | `/new` |

## 8. 发出去之前要实测的

- **粘贴进去的斜杠命令能不能执行。** 文字终端发文字用的是括号粘贴，回车另外发（文本终端设计）。要在 Claude Code、Codex 上实测：粘贴的 `/clear` 加回车，是真的执行了命令，还是被当成一句普通的话发给了模型；回车会不会被自动补全菜单吃掉。如果不行，命令就改成逐字按键发，不走粘贴【留给实现者实测后决定，结果写回这一节】。
- 打开选择器的命令，比如 `/model`、`/resume`：发出去后工具会弹出一个列表，接下来用户用第一排的 ↑ ↓ ⏎ 选。这是预期的行为，不需要再做什么。
- **实测结果（2026-11-26，macOS，pty 40x120，空目录）：粘贴可行。** 做法：写 `ESC[200~/help ESC[201~`，等 300 ms，再单独写 `\r`。三个工具都在启动时发了 `ESC[?2004h`（开了括号粘贴）。
  - Claude Code 2.1.332：粘贴 `/help` 加回车，打开了帮助面板；粘贴 `/model` 加回车，弹出「Select model」选择器。粘贴后补全菜单已经显示，但回车执行的是输入的命令，没有被菜单吃掉或补成别的。首次启动要先过「信任此文件夹」。
  - Codex（codex-cli 0.172.0）：粘贴 `/model` 加回车，弹出「Select Model and Effort」；粘贴 `/status` 加回车，直接打印了会话状态（没有发给模型）；粘贴 `/help` 得到「Unrecognized command '/help'」，说明也是按命令解析的（只是 Codex 没有 `/help`）。
  - agy 1.5.17：先过「信任此文件夹」；粘贴 `/help` 加回车，打开帮助面板；粘贴 `/model` 加回车，弹出「Switch Model」选择器。
  - Gemini CLI、opencode：本机没装，**未测**。
  - 所以第一版命令走和常用语相同的括号粘贴加另发回车，不用逐字按键。实现仍要保留「命令发字」这一层，以后遇到不行的工具可单独改成逐字。

## 9. 管理页（可调整、可配置）

就在现有的「常用语」管理页上扩展，不另开新页。原来的管理页在 iOS 的全局设置里，PC 端在 ＋ 菜单的「编辑常用语…」里，入口都不变。

- 列表混排，每行前面用一个小标记区分常用语和命令（见第 4 节的颜色），可以拖动排序、左滑删除、点一下进入编辑。
- 底部的按钮：「＋ 新增常用语」「＋ 新增命令」「恢复默认」。
- **编辑命令**：
  - 键面文字（必填）。
  - 一张每个工具一行的小表：工具名，右边是写法。写法可以是一串字（比如 `/clear`），也可以选「按键」，再从现有的按键里挑一个（⌃R、⌃O、⌃T、⌃L、⇧Tab、Esc 等）；留空就表示这个工具没有。
  - 内置的命令改过以后，每一行旁边有一个「恢复这一项」【我定的】。
- 新增命令时，键面文字和写法全部由用户填。内置的意图之外，用户也可以做自己的，比如「审查」：Codex 是 `/review`，Claude Code 是 `/review`。
- 管理页底部那句关于菜单的提醒照留，再加一句：「命令只在文字终端里认出 Claude Code、Codex 等工具时出现。」

## 10. 存储与兼容

- 仍然存在 `gui.json` 的 `phrases` 列表里。新增的命令项带 `kind: "cmd"`；没有 `kind` 的项照旧当常用语读，旧数据原样能用。
- 命令项的样子：`{kind: "cmd", id: "new", label: "新对话", per: {"claude-code": {text: "/clear"}, "codex": {text: "/new"}, ...}}`。内置命令可以只存 `id` 加用户改过的部分，没改过的部分跟着内置表走，以后的版本修正对照表时用户能自动拿到【我定的；具体存法留给实现者】。
- **升级时**：老用户的 `phrases` 已经有内容。第一次升级到这一版时，把 6 条默认命令插到最前面一次，用一个标记（比如 `phrase_cmds_seeded`）记下来，以后不再插。用户删掉的命令不会再回来，「恢复默认」除外【我定的】。
- 旧版 rApp 读到新格式的 `phrases`：带 `kind: "cmd"` 的项没有 `text`，会被 `Phrase.fromJson` 跳过，不会崩。但旧版保存时会把这些命令项丢掉。这是可以接受的：同一台机器上很少同时用新旧两个版本。
- 协议不用改：`fg` 和 `ps.app` 都已经在终端列表里了。

## 11. 方案比较（记录）

用户在对话里选的：

| | 做法 | 取舍 | 结果 |
|---|---|---|---|
| 按意图 vs 按工具 | 键面写意图，按工具翻译；还是每个工具一套写死的命令按钮 | 按意图位置不变，靠肌肉记忆点；按工具更直观，但一换工具整排都变 | **按意图** |
| 放在哪 | 常用语条 / 单独加一条 / ⋯ 第二排下面 | 单独一条要把画面顶高 36 点；⋯ 要多点一下 | 先选了 ⋯，**后来改成合进常用语条** |
| 怎么组织 | 一张混合列表 / 两张列表拼一条 / 每个工具一套 | 混合列表最灵活，配置页只有一个；两张列表顺序死板；每个工具一套和「按意图」相反 | **一张混合列表** |
| 「筛选」 | 搜历史 / 挑旧会话 / 筛选界面上的内容 | 决定要不要支持「按键」这种命令 | **搜历史（⌃R）**，所以命令里有按键 |
