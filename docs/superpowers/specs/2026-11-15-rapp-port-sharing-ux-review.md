# rapp 端口分享设计：第二轮评审（用户操作极简）

日期：2026-11-15。状态：**已并入规格第 2 稿，用户已确认（U141），含 §5 的前三条。** 本文不改代码。

被评审的：`2026-11-15-rapp-port-sharing-design.md` 第 1 稿（下称"规格"），加上第一轮评审 `2026-11-15-rapp-port-sharing-review.md`（下称"安全评审"）§5.1 建议加的 6 处。

用户的要求（2026-11-15，原话，反馈文档 U139）："再review一遍，保持用户操作的极简"。

评审的办法：把用户会做的每一件事从头走一遍，数他要动几次手、要懂几个词。凡是系统自己能定的，不问用户；凡是只有少数人用得到的，不出现在正常的路上。

## 0. 结论

规格在"安全"和"能用"上是成立的，但**让用户做的事多了**。四件最常见的事，现在一共要十来步，可以减到三步：

| 用户要做的事 | 现在 | 改完 |
|---|---|---|
| 在一台桌面机上分享一个服务 | 2 步（起名字、注册端口） | **1 步**（注册端口） |
| 在一台桌面机上第一次用域名访问 | 2 到 3 步（点"启用域名"、输管理员密码、回答要不要加 SSH 配置） | **0 步**（装 rapp 的时候已经做了） |
| 加一台无界面的服务器 | 6 步左右（去桌面机找服务器 key 并复制、在服务器上安装、填接入点、填 key、起名字、注册端口） | **1 到 2 步**（复制一行到服务器上运行；端口可以写在这一行里） |
| 日常访问 | 0 步 | 0 步，并且在设备面板里点一下端口就打开，不用记端口号 |

另外两件偶尔发生的事，从"要用户处理"改成"系统自己处理并告诉用户"：机器名重名、服务器重装后换了设备密钥。

安全评审建议的 6 处里，有 2 处会给个人用户增加操作，改掉；其余 4 处在个人使用时本来就不出现。

**不能再减的只有三处**（§3）：注册端口那一下、新设备填一次 key、服务器上那一行。每一处背后都是一条安全上的决定。

## 1. 逐条：减掉和合并的

### M1 "启用 `.rapp` 域名"并进安装，不单独做

规格 §9.2 让用户装好以后再点一次"启用"，输一次管理员密码。

macOS 的安装包本来就带安装脚本，以管理员身份运行（仓库里：`scripts/package-macos.sh` 用 `pkgbuild --scripts scripts/pkg`）。把"告诉系统 `.rapp` 去问本机"和"开机加回环地址"放进这个脚本，用户装完就能用，一步都不多。Linux 和 Windows 的安装包同理。

只有一种人还要点一次：从老版本自动升级上来的用户（自动升级不经过安装包，没有管理员权限）。界面上给他们留那个按钮。

### M2 SSH 不用配置

规格 §9.4 让用户在 `~/.ssh/config` 里加两行，启用域名时还要问一句"要不要加"。

改成：入口在 22 端口上也监听，`ssh gpu1.rapp` 像访问别的端口一样直接通，什么都不用配。1024 以下端口的监听权限，在安装那一次里一并解决（规格 §16 第 2 条本来就要验证这一点）。

`rapp pipe` 和那两行配置留在文档里，作为"22 端口监听不了时"的后备，不出现在正常的路上，也不问用户。

### M3 加服务器：复制一行

规格 §11 要用户分别填接入点、服务器 key、短名，还要先懂"服务器 key"是什么、去哪找。

改成：桌面机的设备面板上有一个"添加服务器"。点开是一行命令，带一个复制按钮：

```
curl -fsSL https://rapphub.com/install.sh | sh -s -- <入网串>
```

- **入网串**把接入点和服务器 key 打包在一起。用户不需要知道里面是什么，也不需要知道"服务器 key"这个词。
- 名字不用填：用服务器的机器名（M4）。服务器的机器名通常本来就起得像样。
- 想一步到位，可以在这一行后面写上要分享的端口：`… <入网串> --share 22,8000`。
- 命令行上对应 `rapp add-server`，打印同一行。

**这一条和规格 §11 我定的"key 不从命令行参数传"相抵**，要用户定（§5 第 1 条）。入网串写在命令里，会留在那台服务器的 shell 历史里。我的看法：它留下的地方和 rapp 自己存 key 的地方是同一台机器、同一个用户；而服务器 key 本来就是为"丢了损失也有限"设计的。所以我倾向于一行带上。更稳的做法是命令里不带，安装脚本运行后问一句"粘贴入网串"，多一次粘贴。

### M4 名字不用起

规格 §7.2：机器名重名时，后来的那台"请起一个短名"，在那之前只能用 ID。

改成：**重名时自动加序号**，`ubuntu` 被占了就是 `ubuntu-2`，登记以后不再变，并告诉用户它叫什么。短名仍然可以起，但那是"想要更好记的名字"时才做的事，不是必须的一步。

这样规格 §2 里 `rapp name gpu1` 从第一步变成可选。

### M5 分享完直接给地址；界面上不用输端口号

- `rapp share 8000` 执行完直接打印 `http://gpu1.rapp:8000`，用户复制走就行，不用再去查名字。
- 桌面机的"本机"面板里，列出**这台机器上正在监听的端口**（带上是哪个程序），每行一个开关。分享就是拨一下开关，不用输数字，也不会输错。
- 设备面板里别的设备分享的端口，点一下就打开（桌面上用系统浏览器，平板上用内置浏览器）；长按或右键复制地址。

### M6 命令从 8 个减到 4 个

规格 §17 列了 8 个命令。日常用得到的只有一个。

| 留下的 | 做什么 |
|---|---|
| `rapp share [端口…]` | 分享。不带端口时列出本机的分享、名字、和 relay 连没连上（合并了 `shares`、`status`） |
| `rapp unshare <端口>` | 取消 |
| `rapp hosts` | 别的设备、它们的域名和分享的端口 |
| `rapp add-server` | 打印 M3 的那一行（取代 `server-key`） |

`rapp name`、`rapp pipe` 还在，写在文档的"进阶"一节里。

### M7 名字换了设备：自动接受并提示

规格 §7.3 我定的是"拒绝并提示，用户确认一次"。服务器重装一次，每一台访问过它的设备上都要确认一次。

改成和 relay 规格 §7.2 一致：对方能给出对的证明，就自动重新认识，界面上留一条提示。代价是规格 §7.3 防的那种情况不再防（relay 被攻破，同时有人拿到了服务器 key）。SSH 自己的 `known_hosts` 检查不受影响，照样会报。

严格的做法（必须确认）留给组织模式。

### M8 安全评审的 6 处：2 处改掉，4 处不动

| 安全评审的建议 | 会不会给个人用户加操作 | 处理 |
|---|---|---|
| L1 每个分享带"允许谁" | 不会，默认所有设备 | 不动 |
| L2 托管策略文件 | 不会，没有这个文件就不生效 | 不动 |
| L3 访问记录可以每条一行 | 不会，默认不开 | 不动 |
| L4 敏感端口要二次确认 | **会** | 改成只打印一句提醒，不拦、不问。"分享 22 等于把这台机器能到的网络也交出去"说一次就够 |
| L5 key 放进钥匙串；显示 key 前本机验证 | 前一半不会；**后一半会** | 只留前一半。有了 M3，用户平时根本不用看 key |
| L6 macOS 解析先实测 | 不会 | 不动 |

### M9 出错时一句话说清下一步

操作少，还要求出了岔子时不用查文档。规格 §9.3 的几种冲突，每一种的提示都要带上"现在该做什么"：

| 情况 | 提示 |
|---|---|
| 对方没分享这个端口 | "gpu1 没有分享 8000。在 gpu1 上运行 rapp share 8000" |
| 对方不在线 | "gpu1 不在线" |
| 本机同一个端口被占 | "本机的 8000 被 xxx 占着，gpu1.rapp:8000 接不了。可以用 rapp pipe gpu1 8000" |
| 域名没启用（老用户） | "还没有启用 .rapp 域名。点这里启用（需要管理员密码）" |
| 网页服务拒绝了请求 | 浏览器里显示一页说明，而不是一个空白的错误 |

### M10 顺带的一条建议（不属于这份规格）

新设备接入现在要填两样：接入点和 key（relay 规格 §2）。可以像 M3 那样合成一串，一个输入框。这动的是 relay 规格，这里只记一笔，要不要做由用户定。

## 2. 减完以后，用户的全部操作

**分享**（在有服务的机器上）：

```
$ rapp share 8000
已分享：http://gpu1.rapp:8000
```

或者在"本机"面板里拨一下 8000 那一行的开关。

**访问**（在任何一台装了 rapp 的桌面机上）：直接用。

```
http://gpu1.rapp:8000/        浏览器、curl、MCP 客户端
ssh gpu1.rapp
```

或者在设备面板里点 gpu1 的 8000。平板上只有后一种。

**加一台服务器**：桌面机上点"添加服务器"，复制那一行，到服务器上粘贴运行。

用户要懂的词只有两个：**分享**、**名字**。回环地址、指纹、角色、HTTP 适配、服务器 key，都不出现在界面的正常路径上。

## 3. 不能再减的

| 留下的操作 | 为什么不减 |
|---|---|
| 注册端口那一下 | 用户定的（S9），也是"默认什么都不交出"的全部内容。自动分享所有在听的端口，就回到了最初讨论里被否掉的"全开放" |
| 新设备填一次 key | relay 规格 R10、R11：有 key 才是自己人 |
| 服务器上运行一行 | 服务器上总得有一个程序、有一把凭据 |
| 安装时的管理员授权 | 系统层的域名没有不要管理员权限的做法（规格 §9.2）。并进安装以后，它不是额外的一步 |

## 5. 要用户定的

1. **服务器那一行里带不带入网串**（M3）。带：真正的一步，入网串留在那台服务器的 shell 历史里。不带：多粘贴一次，不留痕迹。我倾向于带。
2. **机器名重名自动加序号**（M4），而不是让用户起短名。
3. **名字换了设备自动接受并提示**（M7），放弃规格 §7.3 的"必须确认"。
4. 以上三条定了以后，我把两轮评审里采纳的部分并进规格，出第 2 稿。

第一轮评审问的"企业使用具体指谁"还没有回答。这一轮的改动都是按"个人和小团队优先，组织模式另立规格"做的；如果那个前提不对，请告诉我。
