# 输入法跟着意图走：直接打字 = 英文，写作版 = 中文

状态：草稿，待用户批准（2026-11-26）
相关规格：`2026-11-15-rapp-type-to-compose-design.md`（§1.1 中文交给本机、远端一律英文；§2.1 内置终端默认关字母开面板）、`2026-11-14-rapp-composer-writing-panel-design.md`、`2026-11-14-rapp-terminal-gui-design.md` K5、`2026-11-14-rapp-terminal-gui-review.md` R9、`2026-11-20-rapp-ios-rime-ime-design.md`。

## 1. 为什么做

用户原话：「现在中英文切换反复浪费我时间。我希望能识别到我的意图，如果我想在远程输入时，一定是输入英文。要调用输入法时，一定是使用写作版，且切换到中文输入法上来输入。」

现在的情况（2026-11-26 调查，代码为准）：

- **远端**：rApp 只在「写作版从关到开」和「发送前」把远端切英文（`remote_session.dart` `_composerChanged`、`prepareInput`）。直接在画面上打的键从不检查远端输入法：新连上的会话、A 上被人改回拼音、或点过串流菜单「切回 拼音」后，直接打字会被 A 的拼音组字。
- **本机**：rApp 从不按写作版切本机输入法。全工程唯一切本机输入源的是 macOS 密码框（`SecureInputPlugin.swift`）。本机停在 ABC 时开了写作版打出来是英文，要手动 ⌃空格——这是"来回切"的主因。
- **终端**：串流的 终端 / iTerm2 / Ghostty / Warp 默认「按字母键开写作版」（`777adf33` 去掉了静态关闭，改成自适应 `composeArmed`），在里面跑 Claude Code 时按 `y`、`n`、vim 键会先弹写作版。

## 2. 目标、非目标、反目标

目标（用户 2026-11-26 批准的三条）：

1. **写作版 = 中文**：光标进入写作版时，本机切到中文输入法；光标离开写作版回到画面时，本机切回英文。
2. **直接打字 = 英文**：在画面上直接打的键发给远端之前，远端不是英文就先切英文。
3. **终端默认不因字母开写作版**：串流的 终端、iTerm2、Ghostty、Warp 默认关闭「按字母键打开写作面板」。

非目标：

- 不接管、不改远端 app 里的输入法以外的任何状态。
- 不做「按内容猜中英文」（比如看到 `/` 就切英文）。意图只由「在哪儿打字」决定。
- iOS 系统键盘（「系」模式）：iOS 不给 app 切系统键盘的公开接口，不做。
- 不改协议：`input_source` / `select_input`（v8）已够用，协议号不变。

反目标（做出来但等于失败）：

- 用户在写作版里自己按 ⌃空格 切成英文，下一秒被 rApp 切回中文（只在**进入**写作版那一刻切一次，之后不抢）。
- 打 `y` 回答 Claude Code 时被拼音吞掉，或弹出写作版。
- 每个按键都多一来一回、打字变慢（远端已是英文时不发任何额外消息）。

## 3. 设计

### 3.1 第 1 条：写作版 = 中文（本机）

**唯一信号**：Dart 侧每个会话的 `composer.editorFocused`（`composer_model.dart:176`，`main_state.dart:788` 写入）。它从假变真 = 光标进入写作版，从真变假 = 离开。macOS 原生编辑区、Flutter 编辑区、浮动输入块、文字终端的写作版都写这同一个字段，所以触发逻辑只在 Dart 写一处；原生只提供切换能力，不自己判断。

**触发时机**（只在边沿切一次）：

| 事件 | 本机输入法 |
|---|---|
| 光标进入某个会话的写作版（按钮、⌃⏎、按字母开、剪贴「插入」、语音整理落到写作版……任何打开方式；也包括 rApp 自己文字终端的写作版） | 切到「中文输入法」（见下） |
| 光标从写作版回到画面（Esc、收起、⌃⏎ 回画面、发送后自动收起） | 切到英文：系统的 ASCII 键盘布局（`TISCopyCurrentASCIICapableKeyboardLayoutInputSource`，和 macOS 被控端处理 `select_input("")` 一样，用 Dvorak 的人得到 Dvorak）；本来就是 ASCII 就不动 |
| rApp 回到前台，且光标在写作版里 | 再切一次中文（用户可能在别的 app 里切成了英文） |
| rApp 退到后台 | 不动（用户在别的 app 里的输入法是系统全局状态，rApp 不管） |
| rApp 自己的密码框获得焦点 | 照旧由 `SecureInputPlugin` 切 ASCII 并在离开时还原；这期间不做本条的切换 |

**「中文输入法」是哪个**：最后一次在写作版里用过的非 ASCII 输入源（光标离开写作版时，如果当时本机是非 ASCII 输入源，就记下它的 id，存 `gui.json`）。从没记过时，取系统已启用、可选、语言含 `zh` 的第一个输入法（`kTISPropertyInputSourceLanguages`）。都没有就不切。

**按字母开写作版**：被截下的那个字母必须在切到中文**之后**才重放，这样第一个字母就进拼音组字（「nihao」→「你好」，而不是「n你好」）。Dart 先等 `toChinese` 返回，再发 `compose_replay`；原生在下一轮 runloop 才重放（第三方输入法切换生效可能晚一拍）。鼠须管、搜狗是尽力支持：切换没生效时照样重放，第一个字母按当时的输入法上屏（等于现状），不丢字。这一点要实机确认。远端在这一刻只有原来 `_composerChanged` 那一次切英文，不加别的。

**设置**：全局设置加一个开关「打开写作版时切到中文，回到画面时切回英文」，默认开。关掉 = 现在的行为。

**各平台**：

- macOS：新原生能力（可以和 `SecureInputPlugin` 的 TIS 代码放在一起）：`toChinese(preferredId)` → 返回实际选中的 id；`toEnglish()`；`current()` → `{id, ascii}`。
- iOS：内置 Rime（「内」）时，光标进入写作版把 Rime 的 `ascii_mode` 设为 0（中）；离开时不动（画面上的实体键不经过 Rime）。「系」模式不做（见非目标）。
- iOS 补充：iPad 实体键盘打在画面上时键走根 VC 的 `pressesBegan` 直发 A，不经过 Rime，所以离开写作版时 Rime 停在「中」不影响直接打字。从常用语条、语音落到写作版时同样以 `editorFocused` 变真为准。
- Linux 客户端：本机 fcitx5 时进入 `fcitx5-remote -o`、离开 `fcitx5-remote -c`；ibus 时进入切到记下的 engine、离开切 `xkb:us::eng`；都没有就不切。异步执行，不阻塞界面。命令不存在或失败：不提示用户，只写一行日志（日志页能看到）。

### 3.2 第 2 条：直接打字 = 英文（远端，客户端做——用户 2026-11-26 选定）

**规则**：会话层在把一个**按下**的按键发给 A 之前看一眼 A 最近报告的输入源：

- 报告过且 `ascii == false`，且本会话没有暂停自动切 → 先发 `select_input("")`，紧接着发这个键，并把本地记的状态先当作英文（避免每个键都重发；A 切完会再报一次，以报告为准）。
- 没报告过（老 A、rApp 文字终端的 pty）→ 什么都不做。
- 只按修饰键、带 ⌘ 的组合键 → 不触发（拼音不吃这些键）。
- A 已是英文 → 不发任何额外消息。

**放在哪**：

- macOS / iOS：共用的 Swift 会话层 `Sources/RappSession/EmbeddedSession.swift` 的发送路径。画面上的按键（macOS `SessionPlugin.sendKey`、iOS `pressesBegan`）和按键区、常用语条发的键都走这里，一处覆盖。
- Linux 客户端：`gui/lib/embed/linux_session_port.dart` 的 `_remoteKey` 发送前（按键区的键也要走到同一个检查）。

**状态**：「A 最近报告的是不是英文」和「本会话是否暂停」都存在会话层（Swift `EmbeddedSession` 每个实例一份；Linux 在 port 的每个会话里一份），重连 = 新实例 = 不暂停。Dart 通过会话通道上的一个新方法（如 `auto_english {sid, on}`）写暂停状态：点「切回」时关，`editorFocused` 变真时开。暂停对所有走这条路的键都生效（画面、按键区、常用语条发的键）。

**报告不准时**：发了切英文后先当作英文。macOS 被控端切完总会再报一次（`Server.swift:1132-1148`），失败时报回的仍是非英文，下一个键会再试一次；不另加超时。A 被人手动切回拼音时，macOS 被控端靠系统通知立刻报、每秒兜底一次，Linux 被控端 750 ms 轮询一次，所以手动切回后的头一两个键可能来不及，接受。

**老的被控端**：macOS 被控端早就是同步切换，没问题。没升级的 Linux 被控端仍是异步，切英文后紧跟的头几个字可能被吃掉；不为它在客户端加延时（Linux 被控端随这次一起升级）。

**暂停自动切**（用户 2026-11-26 选定）：用户在串流菜单点「切回 ‹输入法›」= 想直接在 A 上打中文。本会话暂停自动切，直到下次打开写作版或重新连接。暂停期间串流菜单「远端输入法」组多一行说明「直接打字不会自动切英文，打开写作版后恢复」。

**Linux 被控端改成同步**：现在 `select` 只把请求丢给后台线程就继续处理后面的输入（`rust/host-linux/src/server.rs:714` → `input_source.rs:129-133`），开头几个字可能被 fcitx 吃掉。改成和 macOS 被控端一样：切换完成（或最多等 300 ms）再等 50 ms，然后才处理这个客户端的下一条输入；后台线程忙时排队等待，不再直接报 "input source helper busy"。

### 3.3 第 3 条：终端默认不因字母开写作版

`gui/assets/app_profiles.json` 里 终端、iTerm2、Ghostty、Warp 四项加 `"typeToCompose": false`。用户自己在 app 配置页改过这个开关的，以用户的为准（配置只保存改过的字段，`app_profile.dart:218`）。`composeArmed` 的自适应保留，管其他 app。type-to-compose 规格 §2.1 那句「内置终端默认关」于是又和代码一致。

rApp 自己的文字终端本来就从不因字母开写作版，不变。

### 3.4 K5 / R9 的结论

终端 GUI 规格 K5（舞台检测组字、提示去写作版）和评审 R9（本机不是英文时舞台上的可见字符开写作版）都没实现。按本规格，回到画面时本机已切回英文，舞台打字本来就是英文意图，**R9 作废**；K5 降级为：本机仍是非 ASCII 输入源时在舞台上打字，不提示、照发英文字符（现状）。在终端 GUI 规格里注明被本规格取代。

## 4. 做法对比（第 2 条）

| 做法 | 好处 | 代价 | 结论 |
|---|---|---|---|
| 客户端做：B 发键前检查 A 报的输入源 | 老 A 也能用；能配合「切回」暂停；协议不变 | Mac/iOS 共用层和 Linux 客户端各改一处 | **选这个**（用户选定） |
| 被控端做：A 注入按键前自己切 | 所有客户端一次生效 | A 不知道 B 的意图，没法暂停；A 要升级 | 不选 |
| 每次画面获得焦点就切远端英文 | 简单 | 管不到"焦点没变、A 被别人改回拼音"的情况，焦点切换时多余地切 | 不选 |

第 1 条的触发点对比：「写作版打开/关闭」vs「光标进出写作版」。选后者：⌃⏎ 可以在写作版和画面之间来回而不关写作版，用打开/关闭会漏掉。

## 5. 测试

- Dart：本机切换的触发逻辑用一个假的本机输入法端口测（进入切中文、离开切英文、只在边沿切、开关关掉不切、记住上次的 id、密码框期间不切、rApp 回前台再切一次）。
- Dart：Linux 客户端 `_remoteKey` 的自动切英文（非 ASCII 先发 select、ASCII 不发、修饰键和 Ctrl 组合不发、暂停期间不发、开写作版后恢复）。
- Swift：`EmbeddedSession` 自动切英文同上几条；`swift test`。
- Rust：Linux 被控端 select 之后的下一条输入要等切换完成；忙时排队不报错。
- 内置配置：`builtin_profiles_test.dart` 改成四个终端 `typeToCompose == false`。
- 实机检查写进 `tasks/todo.md`（本机 ABC 下开写作版直接出中文、按字母开写作版第一个字母进拼音、鼠须管/搜狗、A 在拼音时直接打 `ls` 得到 `ls`、「切回 拼音」后直接打中文、Linux 被控端开头几个字不丢、iOS「内」开写作版回到「中」）。

## 6. 留给实现的

- Linux 客户端 ibus 的 engine 记录方式。
- 会话通道新方法的名字。

## 7. 我替用户定的（可改）

- 只在边沿切一次，不抢用户在写作版里的手动切换。
- rApp 退到后台不动本机输入法；回到前台且光标在写作版里时再切一次中文。
- 带 ⌘ 的组合键和单独的修饰键不触发远端切英文。
- 全局开关默认开。
- R9 作废，K5 维持现状不提示。
- 「英文」= 系统的 ASCII 键盘布局，不强制 ABC。
- 鼠须管、搜狗尽力支持，切不过去时第一个字母照现状上屏。
- 不为没升级的 Linux 被控端加客户端延时。
- 本机切换失败只写日志，不弹提示。
- 第 3 条只影响没在配置页改过这个开关的人：配置只存改过的字段（`app_profile.dart:218`），从来没有整份写入默认值。
