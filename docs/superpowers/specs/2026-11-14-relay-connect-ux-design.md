# 连接方式：ID 显示、自动切局域网、强制走中继

日期：2026-11-14。这是设备连新 relay 那一步（`2026-11-13-rapp-relay-design.md` §5、§7、§10.3，下称"relay 规格"）的补充，和它一起实现。

## 0. 用户的要求

> 当用户设置了 relay 后，提供的 连接ID 第一个应该只是数字，带 ip 的请折叠，用户点开后可以复制带 ip 的。 另外如果同一局域网内的机器通过 relay 走，应该先尝试他们的局域网是否能联通，能联通应该自动切到局域网直连上，在设备、会话上应该能 看到连接的方式是通过 relay 还是直连，并在对应菜单里允许用户强制通过 relay连接。请理解需求合理设计。先写变更的 spec 再做实现。

已经开着、走中继的会话，发现局域网能通时：**自动切过去**（用户选 A）。窗口会闪一下。

## 1. 前提

- 设备连新 relay 以后，B 只填 A 的 ID 就能连；选路顺序是局域网 → 直连（打洞）→ 中继（relay 规格 §5.3）。relay 的 `connect` 回复里带着 A 的局域网地址和公网地址。
- 信不信对方只看设备密钥（relay 规格 §7）。所以"局域网连通"的意思是：在局域网地址上握手成功，**并且对方的指纹就是这台主机的**。别的网络里恰好用了同一个 IP 的另一台机器不算。
- 没设 relay 时，`ID@IP` 仍是局域网里直连的写法（relay 规格 §7.2 末尾）。

## 2. 本机的 ID 怎么显示（A 那一侧）

**设置了 relay**（填了接入点，连没连上都算）：

```
ID      123456789                    [复制]
        ▸ 局域网地址（2 个）
```

点开以后：

```
ID      123456789                    [复制]
        ▾ 局域网地址（2 个）
          123456789@192.168.1.5      [复制]
          123456789@10.0.0.7         [复制]
```

- 第一行永远是纯数字 ID，这是给别人的那个。
- 折叠的一行写出有几个地址。每次打开设置页都是折叠的，不记住展开状态（我定的：它是偶尔用的东西）。
- 没有局域网地址时，不显示折叠的那一行。

**没设 relay**：和现在一样，直接列出每个 `ID@IP`，各带复制按钮。没有局域网地址时显示纯数字 ID。理由：没有 relay，纯数字 ID 别人连不上。

## 3. 自动切到局域网（B 那一侧）

**新连接**：照 relay 规格 §5.3 的顺序，先试局域网。地址来自两处：`hosts.json` 里存着的，和 `connect` 回复里的。每个地址等 500 ms，一起试，先通的那个用。

**已经不在局域网上的连接**（走中继，或者打洞直连）：B 隔一段时间试一次局域网。

| 什么时候试 | |
|---|---|
| 连接刚建立在中继或直连上 | 2 秒后试一次（第一次可能只是局域网慢了一点） |
| 之后 | 每 30 秒一次 |
| B 的网络变了（本机地址变了） | 马上试 |
| 上一次切换失败 | 5 分钟内不再试 |

试成功以后（握手成功、指纹对上）：

1. 这台主机的连接换到局域网。之后的请求（列 app、在线探测、新开的会话）都走局域网。
2. 每个开着的会话用现有的"重连打开"在局域网上重开一次。窗口闪一下，状态、位置照旧。一个一个来，不一起断。
3. 某个会话在局域网上重开失败：它留在原来的路上，不报错，这台主机 5 分钟内不再试。
4. 设备行和会话上的连接方式随之更新（§4）。
5. B 的日志记一行 `path relay→lan`。A 的访问记录照常（重开的会话会记为一条新的、路径是局域网的记录）。

**局域网断了**：走现有的重连，按局域网 → 直连 → 中继的顺序重新选。不另加逻辑。

**只往局域网切**。从中继往打洞直连切不做（§6）。

**用户强制走中继的主机不试**（§5）。

## 4. 看得到连接方式

文字沿用现有的：`局域网`、`直连`、`中继`。强制走中继时写 `中继（强制）`。

| 在哪 | 现在 | 要改的 |
|---|---|---|
| B 的设备行（名字、ID、在线状态后面） | 已经显示 | 切换后马上更新，不等下一次在线探测 |
| B 的会话列表 | 已经显示 | 同上 |
| 流菜单"会话"一组的第一行 `路径 … · 状态` | 已经显示 | 同上 |
| A 的本机连接列表（`对方 · 路径`） | 已经显示 | 不用改：重开的会话本来就带新路径 |

要做的是让 hub 在路径变化时通知界面，而不是界面只在打开、探测时读一次。

## 5. 强制走中继

**是每台主机的设置**，存在 `hosts.json` 那台主机的项里：`"route": "relay"`。不写就是自动。老版本读到这个字段会忽略它。

同一台主机的所有会话共用一条连接，所以设置跟着主机走，不跟着会话走（我定的）。

**在哪改**：

| 在哪 | 显示 |
|---|---|
| B 的设备行 | 连接方式后面一个按钮：自动时是"强制走中继"，强制时是"恢复自动" |
| 流菜单"会话"一组 | 一项：自动时是"改走中继"，强制时是"恢复自动选路" |

两处改的是同一个设置。B 没设 relay 时两处都不显示。

**改了以后马上生效**：

- 打开强制：这台主机的连接改走中继，开着的会话各重开一次（窗口闪一下）。
- 恢复自动：马上试一次局域网，按 §3 切过去。

**强制时 relay 连不上**：这台主机显示离线，错误写"中继连不上"。不自动退回局域网，那就不叫强制了。

## 6. 不做

- 从中继往打洞直连的自动切换。
- "强制局域网""强制直连"。
- 切换时窗口不闪（同一条端到端连接无缝换路）。这要 relay 规格 §3 的做法乙，已经排除。
- 记住"局域网地址"折叠的展开状态。

## 7. 做法

| | 做法 | 结果 |
|---|---|---|
| 甲 | B 定时试局域网，通了就把会话在局域网上重开 | 选这个。复用现有的重连打开，窗口闪一下 |
| 乙 | 会话不重开，底下的连接无缝换路 | 不行。经中继时会话是在 relay 接好的流里再握一次 TLS（relay 规格 §3 甲），没法把它挪到另一条连接上 |
| 丙 | 只有新连接走局域网 | 用户没选（B） |

## 8. 留给实现计划的

- 试局域网用的连接和正式连接是不是同一条：我倾向于试通了就直接留着用，不再握第二次手。
- hub 通知界面路径变化用哪种消息。
- 设备行上那个按钮的样式（和"删除设备""用屏幕共享打开"一排）。
- 原来测试里用的 `RAPP_FORCE_PATH` 已经随旧 relay 删掉。测试要强制某条路时，用这里的 `route` 设置，或者在测试环境里挡住局域网地址。

## 9. 测试

- 一开始局域网就通：路径是局域网，没有经过中继。
- 一开始挡住局域网，走中继；放开以后 35 秒内会话都在局域网上，每个窗口只重开一次，界面上没有错误；B 的日志里有 `path relay→lan`。
- 局域网地址上回应的是另一台设备（指纹不对）：留在中继上，不切。
- 某个会话在局域网上重开失败：它留在中继上，不报错；5 分钟内不再试。
- 强制走中继，局域网是通的：一直走中继，标签是 `中继（强制）`；恢复自动后切到局域网。
- 会话在局域网上时打开强制：会话重开到中继上。
- 强制走中继、relay 停了：主机显示离线，"中继连不上"，不退回局域网。
- 没有 `route` 字段的 `hosts.json` 当作自动；老版本读带 `route` 的 `hosts.json` 不出错。
- 界面：设了 relay 时第一行是纯数字 ID，局域网地址折叠，展开后每个都能复制；没设 relay 时直接列出 `ID@IP`；没有局域网地址时没有折叠行；B 没设 relay 时看不到强制走中继的按钮和菜单项。
