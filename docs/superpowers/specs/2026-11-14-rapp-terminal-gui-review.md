# rapp 终端会话界面设计：评审记录（macOS 开发者、命令行重度用户的视角）

日期：2026-11-14。状态：**评审意见，待用户取舍。** 本文不改代码，也没有改被评审的那份设计。

被评审的：`2026-11-14-rapp-terminal-gui-design.md` 第 1 稿（下称“设计”）和它的原型。
用户的要求（2026-11-14，原话）：“你是macos的开发者，熟练使用terminal 和 专业的cli 交互经验，请评审下现在的方案。给出修改建议”。

标“实测”的是这次在一台 Linux 机器上用 tmux 3.4 跑过的（独立的 tmux 服务，没有碰任何真实会话）。**没有在 Mac 上跑，也没有用 Claude Code、Codex 实测。** 标“凭经验”的是 macOS 上各家终端的习惯做法，这次没有核对。

## 0. 结论

方向对：照 iTerm2 的 tmux 集成来做（标签、滚动、查找、复制都在本机），输入区和 app 会话共用写作面板，这两条不用动。

问题集中在**键盘**上。设计把“键都到终端”写成了一句话，但 macOS 上一款终端好不好用，一半取决于 Option、Shift+回车、⌘ 加方向键这些键到底发了什么。第 1 稿在这里有三处会出错（R1、R2、R9），另有四处是照做会出事或做不准的（R3–R8）。其余是手感上的补齐。

| # | 测的事 | 结果 | 对设计的意义 |
|---|---|---|---|
| M1 | tmux 给不给光标形状、“程序开没开括号粘贴” | 3.4 里两个都没有（取出来是空的） | D5 的光标形状这一版做不了；K4 没法按“开没开括号粘贴”来分（R7） |

## 2. 做对了的

- 标尺选对了。iTerm2 的 tmux 集成证明这条路走得通，而且 rapp 的传法（只送最新一屏）比它更适合弱网。
- 不进 tmux 的复制模式，选中复制在本机做。程序开了鼠标模式时，别的终端里拖选要按住修饰键；rapp 不转发点击，拖选永远是本机的，反而简单。
- 按键排做成开关、默认关。接着键盘的人不需要它。
- 画面按格子画、框线自己画。这是中日文对齐的唯一办法。
- 写作面板上移一行、不改尺寸。

## 3. 要改的

### 会出错的

**R1 Option 不能一刀切当 Meta（改 K3），并补上 macOS 的“自然文字编辑”**

设计 K3 说 Option 一律当 Meta。两个问题：

- 有些键盘布局靠 Option 打字符。JIS 键盘上反斜杠是 Option+¥；美式布局上 Option 也打 `–`、`≠` 这些。一刀切就打不出来了（凭经验）。
- 只说了“当 Meta”，没说 macOS 用户天天按的那几个键。

建议：

- **左 Option 当 Meta，右 Option 照系统**，可以在设置里改成两个都当、两个都不当（凭经验：iTerm2 里常见的设法）。
- JIS 键盘的 ¥ 键在终端舞台上发反斜杠，可关（凭经验：终端里几乎用不到 ¥，系统输入法里也有同样的开关）。
- 默认带一组映射，M7 实测都发得出来：

| 按 | 发 | 作用 |
|---|---|---|
| ⌥← / ⌥→ | Alt+b / Alt+f | 按词移动 |
| ⌥⌫ | Alt+退格 | 删一个词 |
| ⌘← / ⌘→ | Ctrl+A / Ctrl+E | 行首、行尾 |
| ⌘⌫ | Ctrl+U | 删到行首 |

Claude Code 的文档也写了：它的 Option 快捷键（Option+回车换行、Option+P 换模型）要终端把 Option 当 Meta 才有用。

**R2 Shift+回车发换行符，不指望 tmux 的扩展键（改 §6 第一行）**

- M5：默认配置下，`S-Enter` 会被 tmux 当成文字“S-Enter”打进程序里。这是 `send-keys` 的行为：编不出来的键名退回成字面文字。**被控端的键名表里只要多放一个这样的名字，用户按一下，Agent 的输入框里就多七个字母。**
- Claude Code 的文档说：在 tmux 里 Shift+回车默认是提交而不是换行，要用户自己在 tmux 配置里开扩展键；rapp 不能替用户改那个配置（规格 §8.1）。同一份文档说 Ctrl+J 在任何终端里都是换行，不用设置。

建议：

- Shift+回车、Option+回车在舞台上都发一个换行符（`0a`，就是 Ctrl+J）。M8 实测原始字节发得进去。
- 被控端的规则：键名表里只放“任何模式下都编得出来”的键（M7 那几个）；其余一律用原始字节发。加一条测试：未知的键名必须被拒绝，不能落到字面文字。

**R9 输入法在舞台上的失败方式（改 K5）**

K5 只写了“检测到组字时提示”。实际会发生的是：本机输入法停在日文或中文上，点了一下终端就开始打字。结果要么是一串罗马字被逐键发给了 Agent，要么是没反应。两种都糟，而且第一种收不回来。

建议：**本机的输入源不是英文时，在舞台上敲可见字符，等于打开写作面板并把这个键交给它。** 英文直接进终端，中文、日文自动进面板，用户不用想“现在该在哪里打”。macOS 上外壳读得到当前输入源；写作面板的 S0 探查里加这一件。

### 照做会出事、或者做不准的

**R3 “响铃算等你”要加一道门槛（改 N2）**

交互着用终端时铃到处响：补全失败、退格到头、`less` 翻到底。照 N2 原样做，“等你”会被刷成噪音。

M3、M4 说明 tmux 自己的规则正好合用：没人接着的会话才立标志；有人接上去看，标志就清掉。建议写成：

- 没有任何客户端接着的会话，响铃标志是 1 → 等你。
- rapp 正接着看的那个会话里的铃不算（人就在眼前）。
- 用户在 tmux 里关了响铃监视就没有这个信号。不去改它，使用说明里提一句。

**R4 一个字占几格，以 tmux 为准（补 D1）**

D1 说“位置由列号决定”，但线上给的是一行字符串，列号要主控台自己算。按码点逐个算会把 M13 里带变体选择符的、带肤色的、连起来的、国旗全算错，后面整行错位。

建议：

- 主控台按“字素簇”算：一簇里有全角字或 emoji 呈现的算 2 格，否则 1 格；歧义宽度的字算 1 格。和 M13 一致。
- G0 探查加 M13 这一组字做对照；G1 的验收里加一行这样的混排。不同版本的 tmux 结果可能不同，探查时至少对一下 3.2 和最新版。
- Nerd Font 的图标占 1 格，但字体里要有它，不然 starship、p10k 这类提示符是一排方框。随包带一份只含符号的字体做回落（许可证用之前核对）；powerline 的三角和框线一样自己画。

**R5 解析器不止认颜色（改规格 §7、设计 §7）**

M12：取屏里有超链接、带冒号的下划线样式、下划线颜色。只认颜色的解析器会把它们当成乱码画出来。

建议：认得的画出来；不认得的转义整段吞掉，不显示。超链接直接用作 L1 的链接，比用正则猜网址准。

**R6 查找放到被控端做（改 F2）**

F2 要把全部历史取到本机再找。M14：5 万行是 5.3 MB，弱网下是分钟级的事，而且只是为了找一个词；在那台机器上直接搜只要 70 毫秒。

建议：线上加一个“查找”请求，被控端取全历史、在本地搜，只回命中的行号和那一行。主控台跳过去时再取那一段上下文。往上翻仍然分批取。

另外 M15：tmux 默认只留 2000 行。使用说明里写一句“想翻得更远，自己调 tmux 的历史行数”，rapp 不改。

**R7 多行粘贴按程序分，不一律绕到写作面板（改 K4）**

K4 的担心是对的（M9），但把所有多行粘贴都绕到写作面板，会让最常见的动作多一步：往 Claude Code 里贴一段日志。而 M1 说明 tmux 3.4 读不到“程序开没开括号粘贴”，没法自动判断。

建议：app 配置里加一项 `paste`（`direct` 或 `review`）。随包的配置里 claude、codex、zsh、fish、vim、nvim 是 `direct`（凭经验：它们都开括号粘贴，没有逐个实测）；别的命令是 `review`，多行内容先进写作面板。

**R8 按键排常开时，不能一直切掉顶上三行（改 Z2、W3）**

Z2 用“画面上移”给按键排腾地方。写作面板是临时的，上移没问题；按键排在平板上是常开的，vim 的标签行、htop 的表头、lazygit 的顶栏就永远看不见了。

建议：没有别的终端接着时，按键排占的那一行从行数里扣掉，开关时重排一次；有别的终端接着时才上移。

### macOS 手感上的补齐

**R10 滚动的键位说清楚（改 H1）**

“PageUp（焦点不在终端程序上时）”判断不了。建议照 macOS 终端的习惯（凭经验）：

| 键 | 做什么 |
|---|---|
| PageUp、PageDown、Home、End | 一律发给程序 |
| ⌘↑ / ⌘↓ | 本机滚一行 |
| ⌘PageUp / ⌘PageDown，或 Shift+PageUp / Shift+PageDown | 本机滚一页 |
| ⌘Home / ⌘End | 到最早、回到最新 |

**R11 补齐 macOS 的标准快捷键（改 K2）**

⌘ 组合本来就到不了终端，加这些不占程序的键：

| 键 | 做什么 |
|---|---|
| ⌘T | 新标签（就是「＋」） |
| ⌘1–⌘9、⌘⇧[ / ⌘⇧] | 选标签、前后标签 |
| ⌘G / ⌘⇧G | 下一处、上一处 |
| ⌘E | 用选中的字查找 |
| ⌘K | 发 Ctrl+L，并把本机视图的历史起点记在这里：之前的本机不再显示、不再搜，那边原样不动 |
| ⌘W | 要写明：不做事，或者“断开”。不能落到结束会话或关主窗口上 |

**R12 程序开了鼠标模式，滚轮发滚轮事件（改 H5，从“以后”提到 G3）**

H5 在备用屏幕里一律发方向键。nvim 默认开鼠标，方向键是移光标，不是滚屏。M2、M8 说明读得到鼠标模式、原始字节发得进去。

建议：程序开了鼠标模式就发滚轮事件，没开才发方向键。点击转发仍然放以后。

**R13 「本机」页也要有“终端”一组（补原型和设计 §3）**

规格 §9 说最简单的用法是在主控台上加 SSH 目标、由本机的服务去连。原型的「本机」页只有一个开关。对 macOS 开发者这是第一天就用的入口：本机的 tmux，加自己的几台服务器。

建议：「本机」页和别的设备页一样，列终端、SSH 主机、新开、添加。

**R14 「＋」对用户叫“新标签”（改 T3）**

界面上一个标签是一个面板；“窗口”在 rapp 里指 app 的窗口，在 tmux 里又是另一个意思。实现是 tmux 的新窗口，对用户只说“新标签”。

**R15 去掉光标后面的省略号（改 K6）**

多出来的字符会被当成屏幕内容，选中和截图都带着。建议改成光标变淡，或者不做；顶栏已经有网络标记。

**R16 颜色定为原色（设计 §10 第 4 条）**

diff、测试结果、`ls` 的颜色是信息。单色只作为 MATRIX 主题下的一个选项。另外 16 色里的“亮黑”（很多提示符和补全建议用它）在每套主题下要单独验对比度。

**R17 终端里像在要口令时，写作面板提醒一句、这一次不进输入记录**

《输入记录》里，终端会话的写作面板照记、进 git。而终端正是最常被要口令的地方（sudo、ssh、各种登录）。

建议：屏幕最后一行像口令提示时，写作面板的灰字改成“这里像在要口令：请直接在终端里打”，这一次发送不写输入记录。只提醒、少记一条，不拦。

### 放到以后，但要记一笔

**R18 附件。** 给 Agent 一张截图是 Claude Code 用户常做的事，终端会话现在做不了。以后做成：文件传到那边的临时目录，把路径贴进去。排在“以后”的第一位。

**R19 tmux 的前缀键。** 老用户会下意识按前缀键加 c、d。键是直接送进面板的，程序会收到一个 Ctrl+B。不拦；检测到“前缀键后面紧跟 c、n、p、d、[”时，在顶栏提示一次“这里不用前缀键”。

## 4. 对设计 §10 五条确认项的看法

| 确认项 | 看法 |
|---|---|
| 1 按键排默认关 | 同意，加上 R8 |
| 2 响铃算“等你” | 同意，加上 R3 的门槛 |

- §4.2：Z2 分成“临时的上移、常开的扣行”（R8）。
