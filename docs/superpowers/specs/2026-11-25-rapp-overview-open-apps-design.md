# 总览「打开应用」菜单 — 设计（短）

日期：2026-11-25 · 分支：feat/overview-open-apps · 效果图：选定 A（下拉菜单）

## 为什么

在总览里想打开某台设备上的应用，现在要先进侧栏「设备」页、选中设备、再找到那一行，步骤太多。用户希望在总览的设备列里一步打开。

## 要做什么

每台**远程**设备列的最底部一行：左边是版本号（已有），右边右对齐一个链接「打开应用 ▾」。点开后贴着链接弹出一个下拉菜单，列出这台设备现在能打开的所有项，点一下就打开或切过去。

## 目标 / 不做 / 反目标

- 目标：从总览两次点击打开任意一个正在运行的应用；常用的设置也能在菜单里改。
- 不做：列出装了但没在运行的应用（要改主机端和协议，以后单独做）；本机列不放链接（本机没有应用列表）。
- 反目标：菜单不能把总览布局挤乱，也不能变成第二个设备页。终端会话、端口分享、权限这些仍然在设备页里处理。

## 方案（已选 A）

- **A 下拉菜单（已选）**：最快，不改动布局，用法和现有的 RappDropdown 菜单一样。
- B 列内展开：列会被拉长，页面要往下滚；没选。
- C 居中面板：会遮住总览，太重；没选。

## 设计

1. **链接**：只出现在有 id 的设备列，放在版本号同一行右侧（没有版本号时这一行只有链接）。设备离线或 hub 不可用时链接变灰、点不了。空列里原来那个「打开 app」按钮（`open-app-$id`）去掉，统一走这个链接。
2. **打开菜单**：贴着链接弹出，右边缘对齐链接，宽约 290，默认往下展开，下方空间不够时往上翻。菜单有最大高度，超出部分在列表内部滚动，筛选框和底部那行固定不动。打开菜单时如果这台设备还没有探测结果，就调一次 `probe(id)`。等结果期间显示「正在读取…」；探测出错时显示 `disconnectWord(error)`。
3. **内容与顺序**，和设备页一致（复用 `orderApps` / `showsTermsEntry` / `terminalAppsOf`）：
   - 「屏幕」：桌面（`desktop:`），有才显示。
   - 「终端」：终端入口（`termsEntry`），终端列表可用时才显示；后面跟着正在运行的终端程序（Terminal.app 等，设备页里它们也收在终端下面，不跟进来就在菜单里打不开了）。终端会话不展开。
   - 「应用（N）」：其余正在运行的应用。设备只支持文本（`graphical == false`）时，这一组换成设备页里同样的提示文字。
4. **每一行**：状态灯（有会话就用会话的灯，否则用 `Lamp.notOpened`）、名字、右侧状态字（「已打开」；鼠标悬停或键盘选中的未打开项显示「打开」），最右边是 ☆/★。点行调用 `openOrSwitch(id, app, name)` 然后关闭菜单；点星调用 `toggleFavorite`，菜单保持打开。桌面行也有星（设备页的桌面行有「设为常用」，保持一致）。
5. **筛选和键盘**：菜单打开后焦点就在筛选框里，直接打字就按名字筛选（包含匹配，不分大小写）。↑↓ 移动选中，回车打开，Esc 关闭。筛选后一项都没有时显示「没有匹配的应用」。
6. **底部**：设备支持应用（`applications`）时，显示一行包名输入框加「打开」，行为和设备页的 `_openBundle` 一样。最下面是右对齐的「设备详情 ›」，点了调用 `showDevice(id)` 并关闭菜单。
7. **无障碍**：链接朗读为「打开应用，<设备名>」；每行朗读为「<名字>，已打开/没打开，常用」。
8. **平台**：macOS、Linux、iOS 共用同一套代码。iOS 上没有悬停，点一下行就直接打开。

## 留给实现的

- 菜单具体用 `showRappMenu` 改造，还是新做一个 overlay（它要带输入框和行内星标，现有菜单项可能放不下）。
- 「打开」字样的悬停效果细节、行高（参考值 32）。
- 抽出的公共函数放在哪个文件（例如把排序和分组逻辑放进 `terms_entry.dart`，或新建 `device_apps.dart`）。

## 测试

在 `overview_test` 里加 widget 测试，至少覆盖：链接出现在远程列、不出现在本机列；离线时变灰；点开后的分组和顺序；点行会调用打开并关闭菜单；点星切换常用且菜单不关；筛选和键盘；「设备详情 ›」会跳到设备页；空列不再出现「打开 app」按钮。
