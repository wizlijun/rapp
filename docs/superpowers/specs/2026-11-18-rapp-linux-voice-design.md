# Linux 按住说话（0.14.13）

用户要求 Linux 对齐最新版本的功能与修复。本文扩展 macOS 语音规格；该规格中“Linux 不做”和“Linux 界面不变”不再适用于 0.14.13。Apple 识别实现和移动端布局保持各自的平台实现。

## 用户行为

- 主窗口的应用画面和文字终端都有“按住说话”。默认长按右 Alt 0.3 秒开始，松开发送；Esc 取消，Tab 编辑。鼠标按钮沿用桌面气泡、编辑和取消目标。
- 侧栏可以修改、关闭、恢复快捷键。标签使用 Alt/Ctrl/Shift。Super、F11 和 rapp 的 Ctrl+O、Ctrl+[、Ctrl+]、Ctrl+Enter 不接受为新录入的语音快捷键。
- 普通 Alt 组合键和轻点按键照常发送。输入板打开、密码焦点、独立拆窗不启用画面语音快捷键。切走主窗口、失焦、断开、切会话取消录音。
- 发送复用 `sendVoice`，遵循直接回车、冻结/断线回草稿和输入历史规则。
- 识别语言跟随系统首选语言。提示使用 Linux 文案，不打开 Apple 设置。

## 本地识别

- CPU worker `rapp-speech` 使用固定版本 whisper-rs 0.16.0 / whisper.cpp，采集由 `libpulse` 的 `parec` 完成，兼容 PulseAudio 和 PipeWire PulseAudio 服务。打包禁用本机 CPU 和 AVX 指令优化，当前 CPU 后端要求 SSE4.2。
- 初次按下时下载官方多语言 `ggml-base.bin`，提示准备中；下载完成后再次按住即可使用。模型为 147951465 字节，SHA256 为 `60ed5bc3dd14eea856493d334349b405782ddcaf0028d4b5df4088345fba2efe`。
- 模型存储在 `$XDG_CACHE_HOME/rapp/speech` 或 `~/.cache/rapp/speech`，不进入 rapp 的同步数据目录。下载经过长度与摘要校验，再原子替换；失败和退出会清理本次临时文件，可重试。离线且已有有效缓存时直接识别。
- 每次录音最多 5 分钟（2026-11-22 从 60 秒放宽；松手后等识别结果最多 5 分钟）、16kHz 单声道。音频仅在内存中，不保存、不上传；只有识别文字按既有输入历史设置记录。下载模型是唯一新增的网络操作。
- worker 加载模型后才启动录音，每两秒尝试更新部分结果；CPU 忙时会跳过中间更新。松手立即停采集，进程适配层和 UI 的最终识别等待上限统一为 5 分钟。实际延迟和准确率取决于 CPU、语言和声音，不能视为与 Apple 模型相同。
- 取消会终止 worker。录音子进程设置父进程死亡信号，worker 意外退出也不会留下采集。GUI 只接受当前 worker 的事件，旧结果不能进入下一次录音。
- 0.15.16 起，每次录音读取共享热词缓存，将词表传给 Whisper 的 initial prompt 作为拼写上下文；“记住改法”或删除学习条目成功后，沿用共享缓存刷新机制。最多传 100 条、每条 64 个 Unicode 字符，worker 的上下文限 1024 UTF-8 字节；空词和控制字符被过滤。缺少热词照常识别，静音不会输出热词。上下文只作识别提示，不保证输出或准确率与 Apple 相同。

## 验证边界

自动化用本地 HTTP 服务器检查模型下载、错误摘要、缓存和取消；用真实子进程检查文本/音量/最终结果、取消、超时和失焦；复用终端 gate 用例并增加 Linux 画面键盘测试。真实 Whisper 测试使用公开 JFK 样本和静音 PCM，麦克风生命周期使用假的 `parec`，不采集用户麦克风。真实麦克风、中文/多语言准确率和 macOS/iOS 对端交互需要人工设备验收。
