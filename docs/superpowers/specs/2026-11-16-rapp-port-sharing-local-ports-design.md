# rapp 端口分享：用本机端口访问（`localhost:<端口>`）

日期：2026-11-16。状态：**已实现，已并进 `main`**（用户 2026-11-16："合并到 main 里"，反馈文档 U152；分支 `feat/port-map`）。界面的测试和真机检查这时还没有做（§7）。

这是端口分享规格 `2026-11-15-rapp-port-sharing-design.md`（下称"主规格"）和设备面板增补 `2026-11-15-rapp-port-sharing-panel-design.md`（下称"面板增补"）之上的一次变更。它换掉的只有一件事：**访问方用什么地址**。分享、授权、转发、远程设置都不变。

## 1. 一句话

本机的 `rapp-service` 给别的设备分享给它的每个端口各开一个本机端口。连 `localhost:<本机端口>`，就是连那台设备的那个端口。

```
浏览器 / curl / ssh ──> localhost:28000（本机 rapp-service 监听）
                              │  已有的转发：局域网直连，或经 relay（端到端加密）
                              ▼
                        对方的 rapp-service ──> 它本机的 127.0.0.1:8000
```

rapp 之外什么都不设：不加解析器、不改 hosts 文件、不给网卡加地址、不要管理员权限。

## 2. 用户看到的

面板里每台设备的"端口"那一段：

```
端口                                                                [刷新]
● 8000    jupyter   http://localhost:28000      所有设备          [打开] [复制] [取消分享]
● 11434             http://localhost:28001      只给 本机、mini   [打开] [复制] [取消分享]
○ 22                ssh -p 28002 localhost      所有设备                 [复制] [取消分享]
● 9000                                          只给 mini（不含本机）    [打开][复制] 是灰的
[ 端口号 ]  [ 备注，可不填 ]  [分享]
```

- "打开"现在直接可用。面板增补 §6.3 那一行"这台电脑还没有启用 .rapp 域名"去掉了。
- 不给本机的分享没有地址，"打开"和"复制"是灰的。
- "本机"那一段里，自己分享的端口显示 `http://localhost:<原端口>`（22 显示 `ssh localhost`）：在本机上它本来就在那里。

命令行：

```
$ rapp hosts
gpu1  123456789.rapp  8000  http://localhost:28000
                      22    ssh -p 28002 localhost
mini  987654321.rapp  不在线

$ rapp share 8000
已分享：8000
在别的设备上用：打开 rapp 的设备面板，或运行 rapp hosts，看那台设备上的地址
```

`rapp share` 不再打印地址：地址是每台访问的设备上各自的本机端口，分享的这一方说不出来。

## 3. 做法

### 3.1 本机端口从哪来

- 范围 **28000–28999**，1000 个。它在各系统给对外连接自动挑端口的范围之下（Linux 从 32768 起，macOS 和 Windows 从 49152 起），别的程序的连接不会碰巧占到。
- 给（设备，端口）一个本机端口：已经有就用原来的；没有就取范围里最小的空闲端口。
- 挑的时候先问一下那个端口上有没有别的程序在答应，再在 `127.0.0.1` 和 `::1` 上各监听一个（`localhost` 两个都可能指）。有一个被占就换下一个。
- **只监听回环地址**，局域网里的别的机器连不到。
- 范围用完时那个分享没有地址，面板显示"没有本机端口可用"。

### 3.2 什么时候有，什么时候没有

| 什么时候 | 做什么 |
|---|---|
| 面板读一台设备的分享表（选中、设置后、按刷新），或运行 `rapp hosts` | 给这台设备能用的每个分享一个本机端口；对方不再分享的、不再给本机的，收回并停止监听 |
| 服务启动 | 按存下的表重新监听，**不用先打开面板**。书签、MCP 客户端里写的地址重启后照用 |
| 存下的端口在停机期间被别的程序占了 | 那一项先不监听，日志记一行；下次面板读表时换一个新端口 |
| 设备从设备列表里删掉了 | 运行 `rapp hosts` 或服务重启时收回它的本机端口。设备列表读不出来时一个都不收回 |

### 3.3 连进来以后

本机端口上每进来一条连接，服务就向那台设备发一个 `forward`（主规格 §5.1），和 `rapp pipe` 走同一段代码：授权检查点、"只给谁"、局域网直连和 relay 的选择、经 relay 时的复用通道和让路，全部照旧。

对方拒绝或连不上时（没分享了、不给本机、离线），这条连接被直接关掉，本机日志记一行原因。浏览器里看到的是"连接被重置"，没有说明页（§6）。

### 3.4 存在哪

`local/maps.json`（0600，不进 git），一个数组：

```json
[{"id": "123456789", "port": 8000, "local": 28000}]
```

它只记"哪个本机端口给了谁"。读不懂时当作空的，下次写的时候直接盖掉；后果只是地址会重新分配。

### 3.5 代码

- 新文件 `rust/service/src/maps.rs`：分配、监听、收回、存取。
- `rust/service/src/share_cmds.rs`、`ipc.rs`：`shares`（带 `to`）和 `hosts` 的回复里，每个分享带 `local`（本机端口）和 `addr`（照着输入或打开的那一串）；`url` 字段去掉了。
- `rust/cli/src/say.rs`：`rapp hosts`、`rapp share` 的输出（§2）。
- `gui/lib/ui/shares_section.dart`、`gui/lib/shares.dart`、`gui/lib/service_client.dart`：地址照服务给的显示；去掉"启用 .rapp 域名"的开关和那一行字。

## 4. 换来了什么，丢了什么

**换来的**

1. 不动系统设置，不要管理员权限，装完就能用（M3）。主规格 §16 第 1 到 7 条那些没验证的风险（解析器、浏览器的加密 DNS、1024 以下端口、回环地址）这条路上都不存在。
2. 浏览器把 `http://localhost` 当作安全来源，剪贴板、麦克风、后台缓存这些功能可用。主规格要到第 6 步（https）才解决这件事。
3. 被分享的服务看到的 `Host` 是 `localhost:<端口>`。很多开发服务器只认 `localhost`，这样大概不用改它们的配置。**这一条我没有拿 Ollama、Jupyter、Vite 实测**，主规格第 5 步（HTTP 适配）还要不要做，等真机试过再定。
4. 主规格 §4.2 的 T9（把 `.rapp` 解析到别处）在这条路上没有了。

**丢掉的**

1. **地址不好记，也不通用。** 同一个服务在每台访问的设备上是不同的端口号，不能把地址发给另一台设备用。这和最初"用容易记住的方式访问"（U129、U132）的要求相反。缓解：同一台设备上端口重启后不变；面板和 `rapp hosts` 随时能看。
2. **不是原来的端口。** 写死了端口的客户端（比如默认连 11434 的工具）要改成本机端口。
3. `ssh` 要写端口：`ssh -p 28002 localhost`。想写 `ssh 123456789.rapp` 仍然可以用 `rapp pipe`（主规格 §9.4），那条路没有动。

## 5. 安全

和主规格比，变的是访问方这一侧：

| 事情 | 现在 |
|---|---|
| 访问方机器上的其他本机用户和程序 | 都能连本机端口，也就能用别的设备分享的端口。**本机端口上没有 token**（`rapp pipe` 走的 IPC 有）。和主规格 T7 对桌面入口的结论相同：只该用在自己一个人用的机器上 |
| 访问方浏览器里的恶意网页 | 能向 `localhost:<端口>` 发请求，和它能向本机任何开发服务器发请求一样。主规格 §10.3 的两条检查（看 `Host`、看来源）**没有做**；被分享的服务自己不检查的话就没有人检查 |
| 浏览器的 cookie | cookie 不分端口，所有 `localhost:<端口>` 共用一份。两台设备上的两个服务会互相看到对方的 cookie。页面脚本之间仍然按端口隔离 |
| 局域网里的其他机器 | 连不到：只监听回环地址 |
| 分享方 | 不变。它看到的仍然是一台按 key 互信的设备发来的 `forward` |

第二、三条是这次变更新增的缺口。要补的话，做法是在本机端口上认出 HTTP、只放行 `Host` 是 `localhost:<端口>` 的请求（挡住"把别的域名解析到 127.0.0.1"这一类），这一轮没有做。

## 6. 没做的

- 主规格第 4 步的桌面入口（让系统认识 `.rapp`）：**搁置**，没有删。`.rapp` 的名字在 rapp 内部照旧作数（`rapp pipe 123456789.rapp 22`）。
- 本机端口上的 HTTP 检查（§5）。
- 转发失败时给浏览器一个说明页。现在是直接断开。
- 让用户自己指定本机端口，或者尽量用和对方相同的端口号。
- 平板和手机：没有本机服务，仍然要等内置浏览器（主规格第 7 步）。

## 7. 验证过的，和没验证的

在一台 Linux（arm64）上跑过：

- `rapp-service` 单元测试：`maps` 12 条（分配、重启后同一端口、端口被占时跳过或换、收回、范围用完、文件读不懂）。
- 端到端 `rust/testkit/tests/maps.rs` 10 条：经本机端口到对方的回显服务（局域网直连一条，经 relay 一条，后者 300 KB 往返）；不给本机的分享没有地址，原来的本机端口停止监听；取消分享后收回；访问方重启后不问就能连、端口不变；对方已经取消时连接被关掉并记日志；`hosts` 带地址；设备删掉后收回。
- `rapp-cli`、`share_set`、`forward` 里受影响的测试改过，都过。

没有验证的：

- **界面这边的改动和测试没有跑过**（这台机器上装不了 Flutter）。要在 Mac 上跑 `cd gui && flutter test test/shares_test.dart test/ui/shares_section_test.dart test/ui/allow_dialog_test.dart`。
- macOS 上的真机行为：别的程序监听"所有地址"的同一端口时能不能认出来（代码里先连一下再监听，Linux 上测了，macOS 没测）；浏览器、curl 对 `localhost` 先连 `::1` 还是 `127.0.0.1`。
- Windows。
- 真实的服务（Jupyter、Ollama、Vite、MCP 服务器、sshd）经本机端口用起来怎么样。
