# PC 端按键区 + 常用语条对齐 iOS（短设计）

日期：2026-11-24　分支：feat/pc-key-bar

## 要什么、为什么

用户原话：「请把ios上快捷键和快捷短语的代码都对齐到pc端，只是在那一排快捷键可以在有键盘输入时隐藏」。

- macOS / Linux 改用 iOS 的那套按键区（`KeyBar`）和常用语条（`PhraseStrip`），代码只留一份。
- PC 上唯一不同的地方：用过实体键盘以后，按键区自动收成 ⊙ 窄条。

## 做法（用户选了 A）

| 做法 | 取舍 | 结论 |
|---|---|---|
| A 同一部件贴底 | `KeyBar` 和常用语条整宽贴在画面底部，替换 PC 原来的六颗键。写作框、「输入」、语音按钮还是 PC 现在的样子，浮在按键区上面。 | **选中** |
| B 整个 iOS 底部区搬过来 | `IosDock` 整套用到 PC 上。共用的代码最多，但会连带改掉 PC 的按钮排和开合动画，动得太多。 | 不选 |
| C 只换六颗键里的内容 | 仍是角落摆法，改动最小。但摆法还是两套，常用语条也没地方放。 | 不选 |

## 定下来的行为

1. **什么时候有按键区。**
   - 终端会话和终端类 App（`keyBarWhenClosed`）一直有。
   - 其他 App 会话只在写作框打开时有。
   - 这条规则和 iOS 完全相同。
2. **怎么排。** 键的排法、粘滞的 ⌃⌥⌘、长按连发、上滑换键（Home / PgUp / PgDn / End）、⋯ 更多、⊙ 收起，都和 iOS 一样（`keyBarRows`）。
   - PC 上始终显示 ⊙，因为 `hardwareKeyboard()` 在 PC 上恒为真。
3. **用过键盘就收起（PC 独有）。**
   - 会话显示在台上时，只要按下一个非修饰键（键盘事件经过 `HardwareKeyboard`，不管在画面里还是写作框里），按键区就收成 ⊙ 窄条。
   - 点 ⊙ 展开。下一次按键又会收起。
   - 只按 ⇧⌃⌥⌘ 这类修饰键不算，避免 ⌘Tab 切应用时把它收起来。
   - 收起状态存在偏好 `keyBarSlim` 里，重启后仍是收着的。
4. **常用语条。**
   - 跟 iOS 一样放在按键区上方，同一套规则：开关在、有常用语、终端或 profile 开了常用语。
   - PC 上窄条时常用语条**照常显示**；iOS 窄条时仍然隐藏，不变。
5. **画面让位。** 跟 iOS 一样，画面上移一个按键区的高度（`_lifted(..., bar:)`），A 那边看到的尺寸不变。写作框和「输入」按钮排也抬高同样的距离，站在按键区上面。
6. **去掉旧的东西。**
   - 删掉 `TermKeyRow`（六颗键）和它的测试。
   - 删掉 stream_menu 和 top_bar 里的「按键排」菜单项。
   - prefs 里还留着的 `term_key_row` 字段读到就忽略。
7. **设置。** 全局设置里的「常用语」那一行在 PC 上也显示，进的是同一个 `PhrasesPage`。

## 不做

- 不改 iOS 的任何行为，只把 `phraseStripShown` 的 iOS 限制拿掉，并给 PC 加上"窄条照显"这一条。
- 不改协议，也不动 Rust。
- Windows 不专门处理，照 PC 的逻辑走。

## 留给实现者判断

- 按键区和写作框、按钮排之间的具体间距：照 iOS 取 8。
- `PhrasesPage` 用鼠标左滑删除是否顺手：先照原样，放进实机检查。

## 实机检查（写进 tasks/todo.md）

1. macOS 终端会话：按键区贴底，画面上移，键都能用（⌃ 粘滞、↑ 长按连发、上滑出 PgUp）。
2. 在终端里打一个字：按键区收成 ⊙，常用语条还在；点 ⊙ 展开，再打字又收起。
3. 只按 ⌘ 或 ⌘Tab：按键区不收。
4. App 会话：写作框打开时才有按键区，⌘C / ⌘V 键能用。
5. 设置 → 常用语：增、改、删、排序都能用。
6. Linux 同 1–3。
