# rapp 端口分享：一个分享一个端口，到处一样；分享时定协议

日期：2026-11-16。上游：`2026-11-15-rapp-port-sharing-design.md`（主规格），`2026-11-16-rapp-port-sharing-local-ports-design.md`（本机端口，下称"本机端口设计"）。这份改本机端口设计 §3.1 的分配方式，加协议；本机端口设计的其余部分（只监听回环、按需建一直保留、`maps.json`、连进来走 `pipe::open`）照旧。

## 0. 用户的要求

- "端口映射后有些匪夷所思，搞混了。例如 M5 设备 8007 映射为 8007，则在其他机器上被映射为 28000 了。用户分不清哪个为准。能否全部映射为统一分配的端口 28000，这样一个 url 哪里都能访问。"
- "相当于有一个全局的端口区 28000-，只由映射来分配。各个终端都是一致端口。"
- "默认不一定是 http 协议，有可能是 tcp、udp 协议，请允许用户指定和复制协议层。"
- "还有那种 mcp 常见的长连接支持。"（SSE / Streamable HTTP，见 §6）
- 用户定的三件（2026-11-16）：
  1. 撞号：**分享方挑号时避开它看得到的，少数情况访问方退让并标明**。
  2. UDP：**分两步**。第一步统一端口 + 协议；第二步加 UDP 转发。
  3. 没指定协议时：**分享时自动探测**，用户可以改。
  4. 两台分享方还是撞了号：**发现就让一台换号**（设备 ID 大的那台换）。

## 1. 一句话

分享方分享一个端口时，从 28000–28999 里给它定一个号（"分享号"），写进分享表；分享方自己和所有访问方都在 `localhost:<分享号>` 上提供这个分享，地址带协议，复制出来哪里都能用。

## 2. 目标、不做、反目标

**目标**
- 同一个分享，在分享方和每台访问方上地址相同，例如 `http://localhost:28000`。面板、`rapp share`、`rapp hosts` 只显示这一个地址。
- 分享时可以指定协议：`http`、`https`、`tcp`、`ssh`；第二步加 `udp`。没指定时自动探测。复制的是带协议的地址。
- SSE、Streamable HTTP、WebSocket 这类长连接在 `http`/`https`/`tcp` 下照常工作。

**不做**
- 改转发路径、授权、"只给谁"、让路（照旧）。
- 回环以外的监听。
- 访问方替分享方改号；分享号只由分享方定。
- 用户手填分享号（以后需要再加）。

**反目标（做到了也算失败）**
- 一个号在两台访问方上指向不同的分享（访问方退让时必须明说"这台上是别的号"）。
- 已经能用的地址在没人动分享的情况下变了。例外只有三种：升级到这一版时变一次（§5.4）；两台分享方撞号时 ID 大的那台换号（§3.1.1）；访问方退让后换回分享号（§3.2）。
- 探测给正在跑的服务造成副作用（例如往 sshd 或数据库里写了东西、留下报错日志刷屏）。

## 3. 做法

考虑过的：

| 做法 | 结论 |
|---|---|
| **分享方挑号，避开自己看得到的；访问方撞了才退让** | 采用（用户定） |
| 按设备 ID + 端口算号 | 不用。不用通信，但撞的机会一样，撞了避不开 |
| 每台设备分一段号 | 不用。设备多了段会撞，每台能分享的数量有上限 |

### 3.1 分享号怎么挑（分享方）

- 范围仍是 28000–28999。这一段只给 rapp 分配，rapp 自己不会把别的东西放进去。
- 已分享的端口改备注、改"只给谁"、改协议，号不变。取消分享再分享，号可以变。
- 新分享挑号：取范围里最小的、同时满足下面几条的号：
  1. 这台的分享表里没人用；
  2. 这台 `maps.json` 里没人用（它访问别的设备用的号，含退让号）；
  3. 分享方最近一次读到的别的设备的分享表里没人用（§3.4 的"见过的号"）；
  4. 本机 `127.0.0.1` 和 `::1` 上都没有别的程序在答应（和现在 `maps::taken` 一样）。
- 分享方自己在 `127.0.0.1:<分享号>` 和 `[::1]:<分享号>` 上监听，连进来的直接连本机 `<端口>`（先 `127.0.0.1` 后 `::1`，和 `forward.rs` 的 `LOCAL_CONNECT_WAIT` 一样）。不经 rapp 的连接，也不过授权检查点：本机的程序本来就能直接连 `<端口>`。
- 范围用完：分享照样成功，没有分享号，地址为空，面板写"没有空的号"；访问方按 §3.2 自己找号。
- 分享号在**分享方自己**上被别的程序占了（比如 rapp 停着时别的程序拿了 28000）：号不换，免得所有访问方的地址都变。分享方自己那个监听先不开，每次列表时再试一次；分享方面板这一行写「本机上 28000 被别的程序占着，本机请用 localhost:8007」，日志记一行。别的设备照常用 28000。（我定的）

#### 3.1.1 两台分享方撞号（用户定：发现就让一台换号）

- 分享方每次读到别的设备的分享表，看有没有一项的分享号和自己某个分享的号相同。
- 有的话，**设备 ID 大的那台**（按数字比）给自己那个分享换一个号（按上面的规则挑），写回 `shares.json`，日志记 `share_renumbered`（带旧号、新号、撞的是哪台）。ID 小的那台不动。
- 换号的那台的面板在这一行写「28000 和 Mini 撞了，换成 28003」，直到用户在面板上点掉或下次服务重启。
- 访问方下一次读表就跟上新号（§3.2），旧号上的监听收回。

### 3.2 访问方怎么用

- 分享表里带 `local`（分享号）时，访问方给（设备，端口）用这个号：
  - 本机这个号空着（没被别的映射用、没有别的程序在答应）→ 用它。
  - 被本机另一项映射占着，而那一项用的不是它自己的分享号（是它退让来的，或者是升级前的旧号）→ 先把那一项挪走（它按本条规则重新找号），再用这个号。这样升级时两项互相占着对方的号也能解开。
  - 被别的程序占了，或者被另一项**用着自己分享号**的映射占了（两台分享方撞号、还没换开）→ 退让：取范围里最小的、本机没人用、也不在"见过的号"里的号。这一行的回复里 `wanted` 写分享号，面板和 `rapp hosts` 在这一行写「这台上是 28005（28000 被占）」。
  - 退让后，原来占着分享号的东西没了（下一次读表时发现分享号空了），换回分享号。这是唯一允许"没人动分享，地址也变"的情况，而且是变回大家一致的号。
- 分享表里没有 `local`（对方是旧版本）→ 照本机端口设计的老办法自己挑号，不标"退让"。
- 本机自己的分享不进 `maps.json`。

### 3.3 协议

- 分享表每一项多一个 `proto`：`http` | `https` | `tcp` | `ssh`（第二步加 `udp`），和一个 `proto_auto`（是不是探测出来的）。
- `rapp share 8007 --proto tcp`、面板每行一个协议选择，改的时候 `proto_auto` 变 false。
- 没指定时探测（§3.5）。
- 地址怎么写：

| proto | 地址（复制的就是它） | 面板"打开" |
|---|---|---|
| http | `http://localhost:28000` | 有 |
| https | `https://localhost:28000` | 有 |
| tcp | `tcp://localhost:28000` | 没有 |
| ssh | `ssh -p 28000 localhost` | 没有 |
| udp（第二步） | `udp://localhost:28000` | 没有 |

- 原来的 `web` 字段（访问方自己按 `port != 22` 算，设备之间不传）改成由 `proto` 算：`http`/`https` 为 true。旧访问方不认 `proto`，会把 tcp 的分享也显示成 `http://` 并给"打开"，升级后就对了；这是接受的。
- `proto` 和已有的 `raw`、`open_web` 互不影响。（我定的）
- 原来的 `(22, 22) => "ssh localhost"` 去掉：分享号永远在 28000 段里。

### 3.4 见过的号

- 每台设备（不管是分享方还是访问方）每次读到别的设备的分享表（面板、`rapp hosts`、§3.2 的访问），把表里每项的 `local` 记进内存里的"见过的号"，按设备分开，这台设备的表下次读到时整份替换。挑分享号（§3.1 第 3 条）和访问方退让（§3.2）都避开它。
- 不落盘。服务刚启动、还没读过别的表时挑号，靠 §3.1 的第 2 条（`maps.json` 里有别的设备的号）兜底；真撞了由 §3.1.1 解开。
- 挑号前**不**专门去问一遍所有在线设备（慢，离线的也问不到）。（我定的）

### 3.5 探测

分享时、以及 `proto_auto` 为 true 且上次探测时没有服务在听、这次列表时发现有服务在听了，各探测一次。按顺序，每步一条新连接，任何一步超时（300 ms）就算这步不像：

1. 连上后什么都不发，等对方先说话：读到 `SSH-` 开头 → `ssh`。
2. 发一个 TLS ClientHello（用已有的 rustls，不校验证书，不发 SNI 以外的东西），收到 ServerHello → `https`。握手不完成就关。
3. 发 `HEAD / HTTP/1.0\r\nHost: localhost\r\n\r\n`，回复以 `HTTP/` 开头 → `http`。
4. 都不是 → `tcp`。
5. 连不上（没有服务在听）→ `tcp`，记"没探到"，等有服务时再探。

副作用说明：第 1 步不发任何字节；第 2 步只握手不发数据；第 3 步是只读的 `HEAD /`。数据库这类服务会在第 2、3 步收到看不懂的字节然后断开，可能留一行日志，这是接受的。

### 3.6 长连接（SSE / Streamable HTTP / WebSocket）

转发是原样搬字节，不缓冲、不按空闲掐断，所以不用单独支持。要保证并测试：
- 分享方自己的监听（§3.1）同样是原样搬字节，写完即刷，不攒。
- 测试：一个每 100 ms 推一条 SSE 事件的服务，经分享号（分享方本机，和经访问方）收到的每条事件间隔不超过 200 ms；连接保持 5 分钟不断。
- rapp 和分享方之间的连接断了，长连接跟着断，要客户端自己重连（MCP 客户端、EventSource 都会）。这一点写进 `docs/` 的端口分享说明里。

## 4. 第二步：UDP（单独计划，单独发版）

- 分享方：`proto = udp` 时不探测（探不出来），在 `127.0.0.1`/`::1` 的分享号上开 UDP socket，收到的包转给本机 `<端口>`。
- 访问方：分享号上开 UDP socket。每个发来的源地址算一个"会话"，第一个包到时向分享方开一条 `forward`，请求里带 `udp: true`；包在这条流里按"2 字节长度 + 内容"传，两个方向都一样。会话 60 秒没包就关流。
- 分享方收到 `udp: true` 的 `forward`，开一个连本机 `<端口>` 的 UDP socket，按同样格式收发。
- 用一个新的 op（`forward_udp`），不在 `forward` 上加字段：`Op` 不拒绝不认识的字段，旧分享方会把带 `udp: true` 的 `forward` 当成普通 TCP 转发。旧分享方解析不了新 op，访问方把这种失败当成"对方不支持 UDP"，在面板写出来。
- 局域网直连、relay、复用通道都照现在的 `forward` 走，不新加 relay 功能。代价：UDP 包在流里传，丢包变成延迟。适合 DNS、游戏服务器调试这类用途，不适合要求实时的音视频。（我定的，说明里写清楚）
- 第二步的细节（单个包上限、会话数上限）放到它自己的计划里定。

## 5. 数据和兼容

### 5.1 `local/shares.json`

`Share` 加三个字段（`deny_unknown_fields` 照旧）：

```json
{"port": 8007, "note": "", "local": 28000, "proto": "http", "proto_auto": true}
```

- `local` 缺省：没有分享号（范围用完，或者是旧文件，见 §5.4）。
- `proto` 缺省：按旧规则补（22 → `ssh`，其余 → `http`），`proto_auto` 为 true，有服务在听时探测一次纠正。

### 5.2 设备之间（`Op::Shares` 的回复）

- `Op::Shares`（面板读别的设备）和 `Op::ListShares`（`rapp hosts`、`pipe::shares_of`，由 `forward::serve_list` 回）的回复，每项都加 `local`、`proto`。
- `Op::Share`（在面板或 `rapp share --to` 上改别的设备的分享）加可选的 `proto`；回复的每项加 `local`、`proto`，`rapp share --to X 8007` 能直接打印地址。旧分享方忽略 `proto`，所以对旧设备改协议不生效，面板在旧设备的分享上不显示协议选择。
- 只加字段和可选字段，不改版本号；旧的一方不认识的字段忽略。

### 5.3 本机 IPC（`shares`、`hosts`）

- 每项：`local`（这台上实际用的号）、`wanted`（分享号，只在退让时有）、`proto`、`proto_auto`、`addr`（带协议的地址）、`web`。
- `share` 请求加 `proto`（可选）。

### 5.4 升级到这一版

- 分享方：旧 `shares.json` 里的分享没有 `local`。服务启动后先读一遍在线设备的分享表（最多等 5 秒），再按 §3.1 逐个补上分享号并写回，这样少撞号；撞了由 §3.1.1 解开。（我定的）
- 访问方：`maps.json` 里旧的号和分享方新定的分享号不一样时，下一次读表就换成分享号。所以升级后访问方的地址会**变一次**。说明里写清楚，书签、MCP 配置要改一次。
- 两边版本不一样时：新访问方 + 旧分享方 → 访问方自己挑号（老行为）；旧访问方 + 新分享方 → 旧访问方仍然自己挑号，地址可能和别处不一样，升级后就一致了。

## 6. 用户看到的

**`rapp share 8007`**
```
已分享：8007 → http://localhost:28000（探测到 http）
在别的设备上也用这个地址
```
`--proto tcp` 时写 `tcp://localhost:28000`。`rapp share`（不带参数）的表加一列地址。

**`rapp hosts`**
```
MacBook-M4-Pro  297283213  8007  http://localhost:28000
Bruce-Macmini   343758121  5353  tcp://localhost:28001   这台上是 28002（28001 被占）
```
设备 ID 不再写 `.rapp`。（`.rapp` 已作废；`rapp pipe 123456789.rapp 22` 这种写法仍然接受，只是不再显示。）

**面板**
- 每一行（本机的分享，和在面板里管理的别的设备的分享，同一个控件）：地址、协议选择（http / https / tcp / ssh）、复制、http/https 时有"打开"。协议是探测出来的，旁边写小字"自动"。对方是旧版本时不显示协议选择。
- 访问方退让时地址下面写"这台上是 28005（28000 被占）"；分享方换号时写"28000 和 Mini 撞了，换成 28003"；分享号在分享方本机被占时写 §3.1 那句。

## 7. 怎么验

- 单元测试：挑号的四条规则；两台分享方撞号时 ID 大的换、小的不动；访问方两项映射互相占着对方的分享号时能解开；分享方本机分享号被占时号不变、监听之后补上；改备注/只给谁/协议号不变；退让与换回；旧文件补号、补协议；地址表（§3.3）；探测的四种服务（假的 sshd 横幅、TLS、HTTP、什么都不说）和没服务。
- testkit：两台设备 + 一台分享方，分享号在三台上一致；人为占住访问方的分享号 → 退让且回复带 `wanted`；占的程序退出 → 换回；旧分享方（不带 `local`）兼容。
- 长连接测试（§3.6）。
- GUI：协议选择、复制内容、"打开"按协议出现、退让提示。
- 真机（`tasks/todo.md` 加一节）：
  1. M5 分享 8007，M5 和另外两台都用同一个 `http://localhost:<分享号>` 打开。
  2. 一个 MCP 服务（SSE 或 Streamable HTTP）经分享号接入 Claude Code 之类的客户端，跑一个工具调用。
  3. 一个 tcp 服务（比如 Redis），`--proto tcp`，`redis-cli -p <分享号>` 能用。
  4. 访问方上先让别的程序占住分享号，看到退让提示；退出那个程序后地址换回。

## 8. 留给实现的

- "见过的号"的数据结构；分享方自己的监听放在 `maps.rs` 里还是新文件。
- 探测放在 `share` 请求的处理里同步做（最多约 1 s），还是先回复再补。倾向同步：`rapp share` 能直接打印探测结果。
- GUI 协议选择的控件样式，沿用面板现有的按钮/菜单。

## 9. 谁定的

- 用户：统一分享号、28000 段只给映射分配、撞号的处理、UDP 分两步、默认自动探测、复制带协议。
- 用户：两台分享方撞号时 ID 大的换号。
- 我定的：分享号在分享方本机被占时号不变（§3.1）；访问方挪走不在自己分享号上的映射（§3.2）；所有设备都记"见过的号"；升级补号前先读在线设备的表（§5.4）；`Op::Share` 加 `proto`，别的设备的分享也能改协议；UDP 用新 op；`proto` 和 `raw`/`open_web` 互不影响；§3.4 不落盘、不事先问所有设备；§3.5 探测顺序和 300 ms；UDP 用流承载；`rapp hosts` 不再显示 `.rapp`；分享方自己的监听不过授权检查点。
