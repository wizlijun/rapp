# 等候卡片（全局等待提示）设计

日期：2026-11-26　规模：小改动

## 为什么

在文本终端里按 ⌘T 后，被控 Mac 要跑 Terminal 脚本，可能要等好几秒到几十秒（hub 最多等 45 秒，GUI 最多等 50 秒）。这段时间界面上什么都不显示，只有失败时顶栏才出一行小字，所以用户会以为快捷键失效了。

我们要让用户一按下就看到"在等"，并且一直看到出结果：弹出授权框、新终端打开，或者失败。这个提示要做成全局功能，别的慢操作也用它。

## 目标

- 按下 ⌘T 后，舞台中央偏上浮出一张小卡片，内容是：转圈、在做什么（「正在新建终端…」）、设备名（⌘T 还写「在『某终端』旁边」；终端列表里没有目录，所以不显示目录，这是我的决定），以及已等的秒数。
- 连按 ⌘T 时，卡片显示「还有 N 个排队」。
- 结果出来时：
  - 成功：卡片消失。
  - 需要授权：卡片显示授权那句话，停 8 秒。同时照现有逻辑切到被控 Mac 的桌面。
  - 失败：卡片显示失败那句话，停 4 秒。
  - 不管哪种结果，顶栏提示和提示历史都照旧写入。
- 全局可用：一个入口 `waitFor`，同时只显示一张卡片；有几件事一起等时，显示最早开始的那件，并加一句「另有 N 件在等」。
- 首批接入的操作：
  - ⌘T（`newTermFrom`）；
  - 总览和常用里的「新建」（`_openTerms` 的 NewText 分支）；
  - 「恢复」（`restoreSaved`）；
  - 待机卡片的「启动」（`openStandby`）；
  - 设备页打开 shell（`devices_tab.dart` 调 `openText`）。

## 不做的事

- 不挡操作：卡片不是模态窗口，终端照常显示，键盘和鼠标照常可用。卡片本身也不接收点击，点击会穿透到下面。
- 没有「取消」按钮。被控 Mac 那边的脚本已经发出去了，GUI 这边取消也拦不住窗口开出来。
- 不改 hub 和协议，不改超时时间。

## 反目标

- 很快完成的操作也闪一下卡片，会显得很吵。所以卡片在开始 300 ms 后才出现，在此之前完成的操作不显示卡片。
- 卡片挡住终端里正在看的内容。所以卡片要小，放在舞台中央偏上，用 `t.float` 实底（盖在远端画面上时透明玻璃会看不清，这是我的决定）。

## 做法

考虑过三种：

1. **选用：MainState 管一份「正在等」的清单。**
   - 接口是 `Future<T> waitFor<T>(String what, Future<T> f, {String? detail})`。
   - 加上 `waits` 和 `waitOutcome` 两个只读状态，主窗口的舞台 Stack 里放一个 `WaitCard` 组件来显示。
   - 慢操作都从 MainState 发起，接入时只需包一行。一张卡片只有一处实现。
2. 在各个界面组件里各自弹 Overlay：MainState 里拿不到界面上下文，还会复制出好几份卡片。放弃。
3. 在顶栏提示上加"忙"标记：等待状态会和提示历史搅在一起，排队数和秒数也不好放。放弃。

## 细节

- **排队**：⌘T 的排队数，等于 `newTermFrom` 链上还没轮到的数量。排队中的那几个按下时就计入，所以按第二次时卡片立刻显示「还有 1 个排队」。
- **秒数**：卡片自己每秒刷新一次。MainState 不为秒数调用 `notifyListeners`。
- **结果文字**：直接用现有的 `newTermWords(e)`。
- **补上一个缺口**：⌘T 遇到授权时也要调 `_showConsentPrompt`。现在只有总览「新建」等路径会这样做，⌘T 只出一行文字。
- **放置**：卡片放在 `main_window.dart` 舞台 Stack 的最上层，水平居中，距离顶边约舞台高度的 1/4。窄屏和 iPad 也一样。

## 留给实现者的

- 卡片的具体尺寸、圆角、颜色：用 RappTokens，跟 composer 的毛玻璃一致。
- 测试：
  - MainState 单测：waitFor 的 300 ms 延迟、成功清除、失败停留、排队计数、多件同时等。
  - Widget 测：卡片的显示和消失。
  - 回归测试：⌘T 遇到授权时会切桌面。
