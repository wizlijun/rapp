## 1. 一句话和边界

**终端会话是 rapp 里的第二种会话：传的是字符网格，不是像素。它是核心功能。Unix 上会话的容器只有 tmux，rapp 从外面去看、去送输入；本机的 tmux 和 SSH 上去的 tmux 是同一套代码。**

目标：

- 在主界面里像看 app 窗口一样看终端会话：列得出、点得开、状态一眼看得到，文字能选中复制。
- 在输入区写一段发过去；一个键打断。
- 没有桌面的服务器，只要有 tmux 和 SSH 就能进主界面，服务器上不装任何 rapp 的东西。
- 以后换一种终端管理应用，只加一个后端，协议和主界面不动。

不做：

- 派任务、编排、替用户回复。rapp 没有任务模型（主界面规格 §1）；每一次发给对方的话都由用户触发（沟通机制 K3）。
- 判断“在等你”。照沟通机制 §2.3，状态用“未读”。按 app 的“在等你”规则是 app 配置的第二版。
- **Unix 上自带的伪终端和持有进程。** 那是在重写 tmux（评审 R1）。机器上没有 tmux 就提示装一个。
- **Linux 无界面的安装包。** 服务器上已经有 sshd，不再装一个能给出 shell 的新守护进程（评审 R2）。只有一种情况值得重新考虑：服务器在 NAT 后面，任何一台设备都 SSH 不到它。
- **插件系统。** 可换的地方是后端和 app 配置（§4）。
- 鼠标转发、终端里的图片、把记录写盘。
- Zellij、GNU screen、Herdr 的后端。
- 读 CLI 自己的文件、日志，或者装 hook。只看终端上显示的字（§18 第 1 条）。

第二版：Windows（§10）。

不能出现的结果（做成了也算失败）：

- rapp 接上去看的时候，改了别人正在用的那个终端的尺寸，或者把它挤掉。
- rapp 改了用户 tmux 的任何设置。
- rapp 的服务重启或升级，杀掉了正在跑的 Agent。
- 网络差时越用越慢（流畅串流 G1）。
- relay 的代码里出现“终端”这个概念（relay 规格 §1）。
- 线协议或主界面里出现 tmux 专有的东西。

## 2. 用户看到的

**设备面板**里，每台设备在 app 列表下面多一组“终端”。

```
bruce-mac                                    ● 在线 · 局域网
 App     Claude · Safari · Terminal …
 终端    ● work      claude   3 个面板   刚刚有输出      [打开]
         ○ build     cargo    1 个面板   12 分钟没动静   [打开]
         ● train @gpu1  python  1 个面板   未读            [打开]     ← 经 SSH 代管的主机
         [新开终端…]  [添加 SSH 主机…]
```

**舞台**里是等宽字体画出来的字符网格，文字始终是清楚的，可以拖选、复制到本机。顶栏、窗口标签、输入区、流量标签都是现有的；一个面板一个标签。

```
┌ 顶栏 ── ●claude / bruce-mac · work ─ [1 claude] [2 logs] ───── [需要你 1] [▂ 0.3 KB/s ▾] ┐
│ ● Update(src/relay.rs)                                                                    │
│   ⎿ 12 additions, 3 removals                                                              │
│ Do you want to proceed?                                                                   │
│ ❯ 1. Yes   2. No                                                                          │
│                                                        [Esc] [⌃C] [Tab] [↑] [↓] [⏎] [输入] │
└───────────────────────────────────────────────────────────────────────────────────────────┘
```

**全景**里，终端会话那一块的缩略图位置直接显示最后几行文字。

和 app 会话的差别，用户能感觉到的：

- 被控端不用亮着屏幕，也不要“屏幕录制”“辅助功能”权限（未实测）。
- 不会移动被控端的鼠标，不会把窗口切到最前；被控端的输入法不相干。
- 流量小一到两个量级（我的估计，未实测）。

## 3. 做法的选择

| 做法 | 是什么 | 取舍 |
|---|---|---|
| **A. 屏幕状态同步（已选）** | 被控端拿到字符网格，发整屏和变了的行；主控台画网格 | 只送最新状态，延迟不累积；被控端手里有文字，状态、缩略图、选中复制、以后的记录都从这一份来；主控台不用解码器，纯 Flutter。代价：不转发鼠标，少数全屏程序的细节不如 B |
| B. 字节流终端 | 主控台嵌一个完整的终端仿真器，原始字节原样传 | 保真度最高。但每个字节都要按序送到，弱网下越积越多；断线后要补状态 |
| C. 继续走像素 | 被控端开一个终端 app 的窗口，用现有串流 | 今天就能用。但没有桌面的服务器做不了，这正是 TR1 |

## 4. 核心功能，可换的在两处（TR11）

终端会话做在核心里，因为它是一种会话，不是会话旁边的东西：它要进设备面板、会话列表、项目、全景、未读和“需要你”；它给出的是一个 shell，这种权限要和设备互信、访问记录、每台设备的开关放在一起。

| 层 | 形式 | 怎么换 |
|---|---|---|
| 终端会话本身：线协议、舞台、未读 | 核心 | 不换 |
| `rapp-term` | 独立的 worker 进程，守现有的 worker 命令行约定，和 `rapp-host` 并列 | 每台设备一个“允许终端会话”的开关；关着就不起这个进程，界面上也没有“终端”一组 |
| 后端：tmux，以后的 Windows 伪终端、Zellij 等 | `rapp-term` 里的一道缝（§5） | 加一个后端 |
| 某个 CLI 的适配 | app 配置，是数据不是代码 | 照《app 配置编写规范》写一份 |

不做插件系统。worker 的命令行约定本身是一条进程边界，将来要让别人写自己的终端后端，从这里开口子。

## 5. 结构

新增一个 crate `rust/term`（包名 `rapp-term`），库加一个可执行文件。

```
┌ 对外：worker（给 rapp-service 用的命令行和线协议，§6、§7）                 ┐
├ 核心：会话表、行的比较、限速和“只留最新”、未读                            │  与工具无关
├ 后端：tmux（第一版只有这一个）                                             │
└ 执行器：本机进程 │ SSH 到某台主机                                          ┘  命令在哪里跑
```

- **核心只认后端的三样东西**：会话和面板的列表、某个面板现在的屏幕、把输入送进去。
- **后端的接口现在不定**（评审 R3）。第一版直接写 tmux 这一个；写 Windows 那一个时，把两边共同的部分提成接口。新开会话、往上翻、能力表这些，用到再加。
- **执行器第一版就有两个实现**：本机起进程；`ssh <目标> <命令>`。tmux 后端只通过执行器起进程，所以本机的 tmux 和 SSH 上去的 tmux 是同一份代码（§9）。

**会话的名字**【我定的】：终端会话用一个以 `term:` 开头的 app 标识，格式 `term:<后端>[@<主机>]:<会话名>`。例：`term:tmux:work`、`term:tmux@gpu1:train`。现有按（设备, app）存的东西都不用改格式：`workspace.json` 的常用和项目、hub 的会话表、S3 的重连。

- 这个字符串只在一个函数里解析，别处都当不透明的标识。
- tmux 会把会话名里的冒号和句点改成下划线，名字里也可能有空格。给 tmux 发命令时用它自己的会话编号和面板编号，不用名字。

## 6. 接进现有组件

| 组件 | 现在 | 要加的 |
|---|---|---|
| `rapp-relay` | 只搬流 | 不改。终端只是设备之间的又一条流（relay 规格 §5.1、§15） |
| `rapp-service`（`rust/service`） | 设备请求只有 `list_apps`、`ping`、`open`（`rust/net/src/msg.rs`）；每个 app 拉起一个 `rapp-host` | 新请求 `list_terms`、`watch_terms`；`open` 的 app 以 `term:` 开头时接到 `rapp-term` worker，不找 `rapp-host` |
| worker | `rapp-host serve --app … --json` | `rapp-term serve --bind 127.0.0.1 --port 0 --token-env RAPP_TOKEN --json`，守平台规格 §5 的通用约定。一台设备一个 |
| `rapp-hub`（`rust/hub`） | 命令 `apps`、`open`、`close`… | 新命令 `terms`；每台在线设备挂一条 `watch_terms`，把变化作为事件给 GUI。`open` 带 `embed:true` 的那条路原样复用 |
| GUI（`gui/lib/embed`） | `SessionPort` 抽象；macOS 由 runner 解码，Linux 由 `rapp-session` 解码 | 一个纯 Dart 的 `TermSessionPort`：连 hub 给的本机端口，说 §7 的线协议，发出现有的 `SessionEvent`（窗口表、流量、断开）。一个 `TermStage` 控件画网格、管选中。不需要原生代码 |
| 设备之间的连接 | 正在从旧的连接层换到 relay 规格的新连接层 | 不依赖哪一个。终端请求是 relay 规格说的 L4 设备请求 |

主控台这一侧不需要解码器，所以终端会话在 macOS、Linux、Windows 的主控台上是同一份代码；以后的 iPad、Android 主控台也是。

## 7. 线协议（`open` 之后的那条流）

沿用平台规格 §2.1：JSON 行，UTF-8，一行不超过 64 KiB。消息名和字段在实现计划里定；这里定有哪几种、守什么规则。

**屏幕的每一行是一个带标准颜色转义的文字串**（评审 R4），就是 `capture-pane -e` 吐出来的样子（实测 E4）。被控端不解析它，只比较两次的行是不是同一个字符串。主控台有一个只认颜色和字形转义的小解析器，不是完整的仿真器。

| 方向 | 消息 | 内容 |
|---|---|---|
| A→B | 开场 | 协议版本、后端名 |
| A→B | 面板表 | 这个会话的面板：编号、标题、当前命令、行列数、是否已退出。对应窗口标签 |
| A→B | 屏幕 | 某个面板的整屏，或只有变了的行（行号 + 文字串）；光标位置；版本号。一屏太大就分几条 |
| A→B | 历史 | 应答“往上翻”，一批行 |
| A→B | 已粘贴 | 应答一段文字：成功或原因。输入区据此清空或保留草稿 |
| B→A | 看哪个 | 当前标签是哪个面板，以及主控台舞台能放下多少行列（§8 的尺寸规则用）；没有就只收面板表 |
| B→A | 确认 | 收到并画完了哪个版本 |
| B→A | 文字 | 一段文字，作为一次粘贴送进去；可带“之后补一个回车” |
| B→A | 按键 | 具名的键（Esc、Tab、方向键、回车、⌃C…）或原始字节 |
| B→A | 往上翻 | 要哪个位置之前的多少行 |
| B→A | 按我的屏幕重排 | 用户明确点了才发 |

**规则（对应流畅串流规则一）**：A 对每个面板只留最新的一屏。上一条“屏幕”没被确认之前不发下一条；确认到了，发的是“B 已确认的那一版”和“现在”之间的差。网络慢时表现为刷新变慢，但每次都是最新的。

**设备级的监视流**（`watch_terms`）：会话的增减、每个会话的状态（§12）、最后几行文字（给全景用，变化后至少隔 2 秒才再发）。hub 只在 GUI 开着时挂它。

## 8. tmux 后端

### 8.1 rapp 可以对用户的 tmux 做什么（评审 R7）

只有四类命令：

1. 读：列会话和面板、取屏、查值。
2. 送输入：`send-keys`、`paste-buffer`。
3. 新开会话：用户点了才做。
4. 设尺寸：按 §8.3。

不执行 `set-option`，不改键位，不动用户的配置。粘贴用 rapp 自己命名的缓冲区，贴完就删。

### 8.2 看

- **没人在看的会话**：用一次性的命令每 2 秒问一次列表（最后输出时间、当前命令、是否退出）。实测每次约 3 毫秒（E7）。
- **有人在看的会话**：这时才接上一个控制模式的客户端（`tmux -C attach`），一直到没人看为止。这样 `tmux ls` 里的 “attached” 说的是真话。
  - 输出通知只当作“这个面板脏了”的信号。控制客户端只收得到它所接会话的通知（实测 E6），正好够用。
  - 合并限速后用 `capture-pane -e` 取整屏、查光标位置和是否备用屏幕。走这条控制连接每次约 0.7 毫秒（实测 E7）。
  - tmux 自己就是仿真器，屏幕以它为准，随时可以重取。
- 往上翻就是带范围的 `capture-pane`。

### 8.3 尺寸（评审 R5）

- 这个会话**没有别的客户端接着**：按主控台舞台的行列数设尺寸。没有人会受影响；rapp 离开后尺寸留着（实测 E8）。
- **有别的客户端接着**：不设，按面板原来的行列数缩放字号显示。控制模式的客户端不设尺寸时不影响别人（实测 E1）。用户点了“按我的屏幕重排”才改。
- 不用普通方式接上去看：那会直接改掉别人的尺寸（实测 E2）。

### 8.4 送输入

- 按键用 `send-keys`。
- 一段文字：放进 rapp 的缓冲区，`paste-buffer -p` 贴进去再删掉缓冲区。带换行的一段在 tmux 这一层是一次粘贴（实测 E5）；贴进 Claude Code、Codex 是不是一段，见 §17。

### 8.5 新开

- `new-session -d`，行列数取主控台舞台的。`rapp-term run -- claude` 是同一件事的命令行写法【我定的】。
- **如果这台机器上还没有 tmux 服务，不能让它成为 rapp 服务的子孙**（评审 R6）：systemd 停一个服务时默认杀掉它控制组里的全部进程。Linux 上经 `systemd-run --user --scope` 起（未实测）。macOS 的 launchd 怎么对待，见 §17。经 SSH 起的不受影响。
- 机器上没有 tmux：不新开，提示装一个。

### 8.6 范围

- 只看 rapp 服务所属用户的默认 tmux 服务。别的 socket 以后加配置项。
- tmux 的路径可以配（§9 的 SSH 主机尤其需要）。
- 版本下限暂定 tmux 3.2；实测用的是 3.4。

## 9. SSH 上去的主机（TR8）

tmux 后端配上 SSH 执行器。一台装了 rapp 的设备（下称“代管设备”）用系统自带的 `ssh` 连到远程主机，在那边执行 §8 的同一批 tmux 命令。远程主机上不装任何 rapp 的东西。

```
主控台 ══ rapp 连接 ══▶ 代管设备（rapp-service + rapp-term）── ssh ──▶ gpu1 上的 tmux
```

- 这些会话列在代管设备下面，名字带 `@主机`。
- **rapp 不保管 SSH 的凭据。** 它只存“目标”这一个字符串（就是平时 `ssh` 后面写的那个），密钥、跳板、端口都照代管设备上那个用户的 `~/.ssh/config`。rapp 以不交互的方式调用 `ssh`：要输密码或确认指纹的目标连不上，界面上写原因，不弹窗。
- 一条长开的 SSH 连接上复用，不为每次命令重新握手；断了自己重连，间隔照流畅串流规则二（1 秒起翻倍，15 秒封顶）。
- 每个目标可以写 tmux 的路径。不交互的 SSH 用的是精简的 PATH，远程主机是 Mac 而 tmux 装在 Homebrew 里时会找不到（评审 R9，未实测）。
- 目标的名单存在代管设备的 `$ROOT/local/term.json`。在那台设备上加，或者从主控台加，都可以（§15）。
- 自己这台主控台也是一台设备（平台规格 D1）。最简单的用法：在主控台上加 SSH 目标，本机的服务去连。平板当主控台时没有服务，要靠另一台设备代管。

**使用说明里的一条建议（不是功能）**：给 rapp 用的那把 SSH 密钥，在服务器的 `authorized_keys` 里限制成只能执行 tmux。即使这把密钥被拿走，对方得到的也只是 tmux 会话，不是任意命令。

## 10. Windows（第二版，TR4）

- Windows 没有 tmux，会话的容器由 rapp 自己做，用 hurryvc 的方法：伪终端（随包带新版 ConPTY）加 `alacritty_terminal`，把网格写成 §7 的那种文字行。
- 用法 `rapp-term run -- claude`。本地终端照常显示和操作，rapp 是第二个观众。
- 持有伪终端的是一个独立的小进程，rapp 的服务重启后重新接上它。
- 写这个后端时，把它和 tmux 后端共同的部分提成接口（§5）。
- **许可证**：hurryvc 仓库没有许可证文件，rapp 是 GPL-3.0（PD16），所以不搬它的代码，按它的方法重写【我定的】。`alacritty_terminal`（Apache-2.0）和 `portable-pty`（MIT）可以直接依赖（许可证用之前再核对）。动手做第二版之前，如果你想直接用它的代码，请作者加一个许可证。

## 11. 以后的后端

Zellij、GNU screen、Herdr 都有给外部程序用的接口（调研 §10.1），有人用再各写一个后端。只保活不存屏幕的工具（dtach、abduco、shpool）和后台运行的进程（nohup、systemd、docker）不接；使用说明里写：想让 rapp 看得到，就把命令放进 tmux。

## 12. 状态、未读、需要你

和已有规格对齐，不另起一套。

**会话的生命周期**照主界面规格 §4 和 S3：连接中、活动、空闲、已断开、已结束。

- “结束会话”只是不再看它；**不结束被控端的程序**【我定的】。
- 10 秒没有新的屏幕就是空闲（S3 §2.1）。

**被控端那一头的状态**（来自 §8.2 每 2 秒一次的列表，不用连着看也有）：有输出或多久没动静、当前命令、已退出。

**未读**照沟通机制 §2.2、§2.3：有动静，然后连续 3 秒安静下来，标为未读；用户在舞台上看过，或者回复了，未读清除。

- “看到哪了”记在被控端（worker 的内存里），几个主控台看到的未读是同一份【我定的】。
- 未读点亮主界面的“等你”灯（沟通机制 §2.3）。
- 守设计语言 §0 的三条检查：状态平时只改灯，不弹窗、不抢焦点；看过就自己退回去。

**和记录的关系**：终端会话的文字是现成的，不用识别。第一版不写盘；记录那份规格（路线图 D1）定下存哪里以后直接接上。

## 13. 输入和复制

| 入口 | 行为 |
|---|---|
| 输入区（主界面规格 §3.5） | 本机输入法写完一段，作为一次粘贴发过去，等“已粘贴”再清空。发送后补不补回车，照 app 配置的 `afterSend` |
| 按键排 | Esc、⌃C、Tab、方向键、回车。打断就是 Esc 或 ⌃C，两个都摆着 |
| 舞台有焦点时直接打字 | 逐键发过去 |
| **选中复制** | 在舞台上拖选文字，复制到本机剪贴板（评审 R9）。往上翻出来的历史同样可以选 |
| 附件（图片、文件） | 不支持，按钮灰着并说明 |

**app 配置**：终端会话按面板的当前命令去配 `ids`（比如给 `claude`、`codex` 各写一份），用到 `afterSend` 和 `composer` 两项。`stream` 对终端不适用。

**流量标签的菜单**在终端会话里是：字号（适应宽度 / 原样）、按我的屏幕重排、“会话”那一组【我定的】。

## 14. 配置、日志

## 15. 多个主控台、安全

- **多个主控台同时看同一个终端会话：允许，不接管**【我定的】。输入谁发都进去。
- **终端会话就是那台机器上那个用户的 shell。** 边界只有两道，都在别的规格里：relay 的 key（加上 relay 规格 §7.3 的两个开关），和每台设备的“允许终端会话”开关，默认开【我定的】。不另加密码。
- **不限制“谁能加 SSH 目标”**（评审 R8）：能打开终端会话的人已经有 shell，可以自己敲 `ssh`，限制这一项拦不住任何人。要收紧，就关那台设备的开关，或者照 §9 的建议限制密钥。

## 17. 先探查的（T0）

第 1 稿列的五项里，tmux 这一层的三项评审已经实测过（评审 §1、§4）。剩下：

1. 对着 Claude Code、Codex 的真实界面取屏：宽字符、颜色、光标对不对。
   - 结论（2026-11-14）：自动检查通过：每行不超过 120 列（按东亚宽度算），光标行就是输入框那一行。链接在 `capture-pane -e` 里是 OSC 8 序列，客户端要认得。画面和原界面是否一致，待用户对照保存下来的取屏文件。
2. 带换行的一段文字贴进 Claude Code、Codex，是不是一段。
   - 结论（2026-11-14）：通过。三行都在输入框里，没有提交，也没有新一轮回答。
3. SSH：从后台服务（LaunchAgent）里不交互地连得上吗（服务的环境里可能没有 ssh-agent）；远程主机上找不找得到 tmux；断了能不能干净地重来。
   - 结论（2026-11-14）：未测，执行时没有可用的主机。
4. rapp 的服务新起的 tmux，在 systemd 和 launchd 下活不活得过服务重启；`systemd-run --user --scope` 管不管用。
   - 结论（2026-11-14）：macOS 上 launchd 停掉服务后，tmux 会话仍在，不用额外处理。Linux 未测（没有 Linux 机器）。

## 18. 要你确认的

1. **只看终端上显示的字，算不算守住了“不侵入 app”（沟通机制 K2）。** 我的读法：算。终端的字符网格就是屏幕上显示的东西，rapp 不读 CLI 自己的文件，不装 hook。
2. **终端的未读算不算进顶栏“需要你”的数字。** 主界面规格 §3.6 把“Agent 等你”算在内。但 Agent 每停一次都算一件，数字可能一直不为 0，和“尽量减少提醒”（PD5）有点顶。两个走法：算进去；或者只亮灯、不进数字。

这两条不挡 T0 和 T1。
