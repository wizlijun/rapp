# 总览里显示版本号（短设计）

## 为什么

几台设备版本不一致时，要一眼看出谁没升级。例如 Duo 已经是协议 v14，Mac 主控还是 v13，连不上，却看不出原因。

## 要做的

- 总览每台设备那一列的最下面，用淡色小字显示那台设备的 rapp 版本号，例如 `0.14.7`。
- 「本机」列底部显示的就是这台客户端自己的版本号。总览别处不再另放（用户选定）。

## 不做的

- 不在设备页、日志、顶栏显示版本号。
- 不比较版本，也不提示"该升级了"。
- 不升协议版本。

## 做法

用户问到方案时只有一种合理做法，下面写明另外两种为什么不用。

- **远程设备**：A 回复 `list_apps` 时多带一个 `"version"`（A 的 `CARGO_PKG_VERSION`）。hub 的 `apps` 事件原样转出，GUI 的 `AppList` 增加 `version`。总览已经为每台设备拉取 app 列表（`DeviceProbe.apps`），所以不用多发请求。
- **本机**：hub 的 `hosts` 事件多带 hub 自己的 `"version"`。hub 和 GUI 来自同一个安装包，macOS 和 iPad 都适用，不用再分平台去读。
- 两处都只是多加一个字段，老设备照常能连。

### 没选的做法

- 版本放进连接握手（hello facts）：要动 `rapp-conn` 的握手格式，改动面大。
- GUI 自己去读本机服务状态（`update.current`）或 iOS 的 `CFBundleShortVersionString`：要分平台写两套代码，而 hub 一个字段就够了。

## 显示规则

- 位置是列内容（会话、常用、「打开 app」）之后，上边距 14。字号用 `bodySmall`，颜色用 `muted`。
- 不知道版本时不显示这一行，不写"未知"。这包括老设备，以及离线、还没拉到 app 列表的设备。
- 设备离线时，显示最后一次拿到的版本。现有的 probe 留着 `apps` 就沿用，没留就不显示。

## 留给实现者

- 字段名统一叫 `version`。Dart 侧是 `String?`，空字符串按没有处理。
- 测试：`deviceColumns`、overview widget 和 hub 各加一条，service 的 `list_apps` 回复也加一条。
