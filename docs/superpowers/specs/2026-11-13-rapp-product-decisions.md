日期：2026-11-13。状态：**待用户审阅**。本文不改代码。

这份文件把 2026-11-13 这一轮里用户说定的事整理成决定。每条决定都带出处；出处是需求反馈文档里的 U 号，原话在那里。

相关文档：

- 原话：`2026-11-12-rapp-requirements-feedback.md`（下称"反馈文档"）的 U45–U69。
- 逐条的问答和我查到的现状：`2026-11-13-rapp-builtin-apps-research.md`（下称"插件文档"）。
- 这些决定怎么拆成规格、分几个阶段做：`2026-11-13-rapp-spec-roadmap.md`。

## 1. 产品方向

| # | 决定 | 状态 | 出处 |
|---|---|---|---|
| PD1 | **工作台的设想。** 不同物理机、虚拟机、不同操作系统上开的 app，都能在一个平台上灵活切换，并按项目分类。人只需要切换项目，就切换到不同的工具，但还在同一个思维空间里；操作系统和电脑的细节可以忽略 | 已定（是设想，不是界面改动的决定） | U45 |
| PD2 | **增加七个内置插件**：备忘、便签、提醒、搜索、专注、快照、资源监控 | 已定 | U46、U47 |
| PD3 | **应用之间独立。** rapp 和 note.md 等别的应用互不依赖 | 已定 | U68 |
| PD4 | **能接已有工具的就接，不重做。** 备忘接 note.md 的 vault，任务状态接 NEXT，vault 搜索接 note.md 的搜索，便签接现有的便签服务。rapp 负责定接口和显示 | 我的归纳，每一项各有出处 | U48、U50、U54、U55 |
| PD5 | **尽量减少提醒。** | 已定 | U69 |

PD1 留下的待定：现在的界面是按设备组织的（设备、会话、项目是并列的几个标签）。要不要改成以项目为先，用户没有说。

## 2. 七个插件

### PD6 备忘

| 决定 | 状态 | 出处 |
|---|---|---|
| 用 note.md 管 vault。note.md 作为应用装在本机用 | 已定 | U48 |
| 其他设备通过"系统提供的资源共享机制"读写（我理解是指 rapp 自己的共享机制，用户没有细说是哪一种） | 已定 | U48 |
| vault 只配在少数必要的机器上，由用户选。用户主要在一台主 rapp 上用，偶尔在另一台电脑上用。别的设备上的项目有自己的 git，不需要整个 vault | 已定 | U49 |
| 文件存在 vault 里，多机可以同步 | 已定 | U51 |
| 编辑器独立成插件，用户按需选用哪种 | 已定 | U52 |
| note.md 的 Sumi（沉浸式书写，做了输入法适配）独立成原生体验的书写模块，作为全局的备忘编辑器 | 已定 | U51 |
| 沉浸式书写和语音输入是 rapp 的特色能力 | 已定 | U53 |

待定：Sumi 是否也用在主界面的输入区；语音输入什么时候做（用户说的是"将来"）。

| 数据上，"需要你"是提醒的一个子集 | 已定 | U66 |

### PD9 搜索

| 决定 | 状态 | 出处 |
|---|---|---|
| 要有全局搜索 | 已定 | U55 |
| 主要用来快速搜到资源和应用，然后快速启动 | 已定 | U55 |
| 剪贴板和文件的搜索也要做 | 已定 | U55 |
| note.md 的 vault 搜索集成进来，rapp 不自己做，以降低复杂度 | 已定 | U55 |
| rapp 自己只搜核心的关键对象；其他知识库工具通过接口整合，只需要把接口设计好 | 已定 | U55 |

待定："资源"具体包括哪些；接口的形式；搜索入口放在哪里。

### PD10 专注

| 决定 | 状态 | 出处 |
|---|---|---|
| 参考 macOS 的专注模式 | 已定 | U56 |
| 专注时不主动提醒、不打扰 | 已定 | U56 |
| 进入写作、进入 AI 对话时，自动进入专注 | 已定 | U56 |
| 专注要做到：沉浸的体验；原生的交互，流畅；给出的信息都是相关的（跟着项目切换） | 已定 | U56 |

待定：专注时"需要你"这一类还打不打断；怎么退出，退出后攒下的提醒怎么给；能不能手动开关；在远程窗口里用别的 app 算不算专注。

### PD11 快照和记录

| 决定 | 状态 | 出处 |
|---|---|---|
| 用 git 做归档，参考 note.md 里 vault 的归档 | 已定 | U57 |
| 画面转成文字以后，文字同步 | 已定 | U67 |
| 截图留在本机做归档，不同步 | 已定 | U67 |
| 截图可以设置定期删除 | 已定 | U67 |

待定：

- 现场快照（开着哪些员工、各在什么位置，换设备一键恢复）要不要。用户只回答了画面这一种。
- 同步的文字里会有屏幕上出现过的所有内容，包括恰好显示出来的密码、密钥。同步前要不要过滤。
- 截图默认多久删一次。

### PD12 资源监控

| 决定 | 状态 | 出处 |
|---|---|---|
| 除了硬件，各种 AI 订阅用量、流量也归到这里 | 已定 | U47 |
| 把用户需要关注的所有数值集中在一起 | 已定 | U58 |
| 设计成一份规范。以后要加新的资源预览，让 Agent 按规范快速生成 | 已定 | U58 |
| 资源可以显示在各台主机上，也可以有一个全局的 | 已定 | U58 |
| 可以作为插件，显示在总览（全景）的某个地方 | 已定 | U58 |
| 资源吃紧不产生提醒，在便签 app 里用颜色区分就够了 | 已定 | U69 |
| 资源的事不进"需要你" | 已定 | U69 |

待定：规范的具体内容；数值由谁采集；"Agent 生成"生成的是采集、显示，还是两者；便签里显示资源数值，和资源预览是一个东西的两个页面，还是两个插件共用一份数据。

## 3. 平台

### PD13 rapp 自己的数据目录

| 决定 | 状态 | 出处 |
|---|---|---|
| rapp 的关键配置等都放在一个目录下单独管理，用 git 同步 | 已定 | U57 |
| 默认目录是 `~/rapp`，是 rapp 独立的目录 | 已定 | U68 |
| 用户可以自己把它放到 note.md 的 `vault/rapp` 下，这是用户自己的选择 | 已定 | U68 |
| 每个终端都需要安装 git | 已定 | U57 |

这几条和已经确认的《数据目录》规格（`2026-11-13-rapp-data-dir-design.md`，由另一个会话写成并经用户确认）是同一件事，内容一致：根目录 `~/rapp`（它的 D1）、是一个 git 仓库且只有文字进 git（D2、D3）、机密放在不进 git 的 `local/` 里（D4）、根目录用户可以改（D12）。以那份规格为准。

待定：平板上没有系统自带的 git，平板算不算"每个终端"。

### PD14 数据服务跑在哪里

| 决定 | 状态 | 出处 |
|---|---|---|
| 只需要自己的 rapp 查看的数据服务，可以跑在本机 | 已定 | U59 |
| 也可以自己部署在某台服务器上，通过配置地址（IP、URL）来用 | 已定 | U59 |
| relay 可以做中转 | 已定 | U59 |
| 这类应用服务可以算作 rapp 核心的一部分 | 已定 | U59 |
| 目的：数据只在自己的安全环境里（局域网，或者经 relay 中转），把安全风险降到最小 | 已定 | U59 |
| 外部小屏可以访问到：接入 relay 的地址即可 | 已定 | U60 |
| USB 只是小屏联网的一种方式，不用特别处理 | 已定 | U61 |

待定："算作 rapp 核心的一部分"是把便签服务搬进 rapp，还是 rapp 把它当作一个受管的服务来启动和连接。

### PD15 relay

| 决定 | 状态 | 出处 |
|---|---|---|
| 经 relay 中转时，relay 不能看到任何内容 | 已定 | U62 |
| 能力上像 frp 一类的工具，但没有经过统一认证（设备注册或其他方式）的访问不到 | 已定 | U62 |
| 这是 relay 整体的设计规格，不只针对数据服务 | 已定 | U63 |
| 前提：不消耗额外资源，更流畅，轻量 | 已定 | U63 |
| 目标：保持必要的安全性，避免被攻破后数据被劫持 | 已定 | U63 |
| relay 的功能尽量与业务无关，是纯技术方案 | 已定 | U64 |
| 尽量选最成熟的做法 | 已定 | U64 |
| 首选做法：设备之间直接用 TLS 1.3 互相验证，配对时记住对方证书的指纹；加密在两台设备之间建立，relay 只转发 | 方向认可 | U65 |

待定：设备第一次怎么互相认识（要做到"relay 被攻破也不能冒充"，这一步不能靠 relay）；已经配好的设备怎么过渡；外部小屏怎么注册、它的固件能不能自己解密。

更新（U78，已定）：relay 要重构，不在以前的基础上修改。规格已整篇重写，待用户确认。

更新（U77，已定）：有了 key 就互相信任，不再要密码。设备密码取消。这改了平台规格的 D5（认证用 RustDesk 那种 ID + 密码）：现在是一个 key 加 ID。

更新（U74，已定）：参考 RustDesk，设备接入 relay 只需要一个接入点和一个 key；设备之间用 ID 互相访问。

更新（U75，已定）：relay 要留日志做审计用。

更新（U72，已定）：relay 发布为 Docker 部署，只发一个 Docker 镜像，基于最专业的轻量 Linux 发行版，尺寸越小越好。

更新（U71、U73）：relay 的设计规格已写并经用户确认，`2026-11-13-rapp-relay-design.md`。前两项待定按那份规格办（用密码配对；三步升级）；小屏那一项仍然待定。

## 6. 待定清单

按会牵动多少别的东西排。

1. 界面要不要从以设备为先改成以项目为先（PD1）。
2. 设备第一次怎么互相认识；已配好的设备怎么过渡（PD15）。
3. 外部小屏怎么注册，固件能不能自己解密（PD15）。
4. 平板上没有系统自带的 git 怎么办（PD13）。
5. 同步的文字里可能带有屏幕上出现过的密码、密钥，同步前要不要过滤（PD11）。
6. 便签服务是搬进 rapp，还是由 rapp 管着启动和连接（PD14）。
7. 数值规范的内容；数值谁采集；Agent 生成的是什么（PD12）。
8. 便签和资源预览是一个东西还是两个（PD12）。
9. 便签里的颜色守不守设计语言第 1 条（PD12）。
10. 专注时"需要你"还打不打断；怎么退出；能不能手动开关（PD10）。
11. 搜索的"资源"包括哪些；接口形式；入口位置（PD9）。
12. 现场快照要不要（PD11）。
13. Sumi 是否也用在输入区；语音输入什么时候做（PD6）。
14. 截图默认多久删一次（PD11）。
