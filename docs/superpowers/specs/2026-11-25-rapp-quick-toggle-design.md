# 快捷区开关：照 Claude 的布局，放进框下的工具行

2026-11-25。接 `2026-11-24-rapp-input-dock-design.md`。

## 为什么

快捷区收起后，块旁边剩一个 28 的小圆圈（⊙），和输入框、＋、发送的样式都不搭。用户的要求是把它和 ＋、发送放在一起，并参照 Claude 的布局：框里只放文字和发送，框外下方一条扁平的工具行，放 ＋ 和各种开关。

## 考虑过的方案

- **F 照 Claude 截图（选中）**：框里只有文字和发送。框下面一条细工具行，放 [＋] [⌨ 快捷区]。快捷区的按键排在工具行下面。框仍是一行高，文字几乎占满整个宽度。
- D 两行框：＋ 和开关放进框内的底栏。所有控件都在一个框里，但写一行字时框也要高出约 36。
- A 单行框加方键 [⌨][＋][发送]：框最矮，但开关没有文字说明，文字的宽度也被占去一些。
- B（⌨ 和 ＋ 合成一个胶囊）、C（开关只放在 ＋ 菜单里）、E（按键区也放进框里）：都放弃了，原因见对话记录。

## 设计

1. **框内**：只放文字和发送。发送键留在原位（框内右侧），样式不变。＋ 移出框外。
2. **工具行**：在框的正下方，属于文本区，跟着文本区一起开合。左边从左往右是：
   - **＋**：和今天的 ＋ 一样，菜单内容不变，菜单从这里弹出。
   - **⌨ 快捷区开关**：快捷区显示时，是一个亮起的小标签「⌨ 快捷区」；收起时，只剩一个 ⌨ 图标，样式和 ＋ 一样。点一下就切换（`setQuickHidden`），终端类和普通 App 仍然各记各的。
   - 工具行很矮（随放大档缩放）。因为它浮在远程画面上，所以垫一层淡淡的透明底，样式沿用 `seeThroughBox`，但比框更淡，保证图标在任何画面上都看得清。
3. **块从上到下**：框 → 工具行 → 快捷区（按键区和常用语条）。快捷区开合时，它上面的框和工具行不挪位置。块仍然站在原来的锚点上。
4. **去掉圆圈把手**：删掉 `QuickHandle`，删掉 `FloatingComposer` / `_Place` 里放把手的逻辑。
5. **去掉按键区行尾的 ⊙ 键**（`key_bar_keys` 的 `hide`）：开关只留工具行这一处，按键区空出一格。iOS 和 PC 都一样。
6. **文本区收起时**，工具行也跟着收起。这时按钮栈里在「输入」旁边多一个 ⌨，样式和「输入」一样，亮暗规则同上。只在能写字的会话（`composerAllowed`）里出现。按钮栈的高度和个数计算要算上它。
7. **不变的部分**：
   - 打字后自动收起；
   - ＋ 菜单「快捷区」一组；
   - 按住语音时快捷区不出现也不消失；
   - 语音键仍在按钮栈里，不搬进工具行；
   - 块的拖动和记位置。
8. **无障碍和悬停提示**：⌨ 的标签随状态变，显示时是「收起快捷区」，收起时是「显示快捷区」。

## 留给实现的

- 工具行的具体高度、两键之间的间距，以及 ⌨ 亮起时的颜色：照 ＋ 现有的样式定。
- 工具行左对齐框的左边。很窄的屏幕上标签「⌨ 快捷区」放不下时，只显示图标。
