# 快捷区开关：放进框里，和 ＋ 并排在左

2026-11-25。接 `2026-11-24-rapp-input-dock-design.md`。

## 为什么

快捷区收起后，块旁边剩一个 28 的小圆圈（⊙），和输入框、＋、发送的样式都不搭。用户要求把它放进输入板的框里，和 ＋、发送融合在一起，而且要紧凑：不能为它多占行高。

## 考虑过的方案

效果图见对话。最后两轮都按 westworld 主题、在模拟终端画面上出了图。

- **G（选中）**：一行框，从左到右是 [＋] [快捷区开关] 文字 [发送]。和 Claude 桌面版一样，＋ 放在框内左侧；开关挨着 ＋；发送单独在右边，不容易误点。
- A：一行框，三个键都挤在右边，从左到右是 [开关] [＋] [发送]。文字从最左边开始，但开关离发送太近。
- H：＋ 在左，开关挨着发送在右。开关常用，容易碰到发送。
- F（照 Claude 截图，框下另加一条工具行放 ＋ 和开关）：做了效果图，被否决，原因是太占行高。
- B（开关和 ＋ 合成一个胶囊）、C（开关只放在 ＋ 菜单里）、D（两行框）、E（按键区也放进框里）：都早已放弃。

## 设计

1. **框内布局**：一行框，高度和今天一样（放大档 1 时最低 50）。从左到右依次是：
   - **＋**：样式和菜单都不变，只是从右边搬到最左边。菜单从这里弹出。
   - **快捷区开关**：一个方键，样式和 ＋ 一样（`RappButton.secondary`，40·k 见方）。快捷区显示时，开关亮起（描边用 accent，和 ＋ 菜单打开时的亮法一样）；收起时不亮。点一下就切换（`setQuickHidden`），终端类和普通 App 仍然各记各的。
   - **文字**：占中间剩下的宽度。
   - **发送**：在最右边，样式不变。
2. **图标**：开关用「键格」图标（几个小方块），不用 ⌨。⌨ 已经是按钮栈里「输入」的图标，⌘ 是按键区里的一个键，都会认混。
3. **块从上到下**：框 → 间隔 8 → 快捷区（按键区和常用语条），和今天一样。快捷区开合时框不挪位置，块仍然站在原来的锚点上。
4. **去掉圆圈把手**：删掉 `QuickHandle`，删掉 `FloatingComposer` / `_Place` 里放把手的逻辑。
5. **去掉按键区行尾的 ⊙ 键**（`key_bar_keys` 的 `hide`）：开关只留框里这一处，按键区空出一格。iOS 和 PC 都一样。
6. **文本区收起时**，框连同里面的开关一起收起。这时按钮栈里在「输入」旁边多一个开关，样式和「输入」一样（56 见方），亮暗规则同上。它只在能写字的会话（`composerAllowed`）里出现。按钮栈的高度和个数计算要算上它。
7. **不变的部分**：
   - 打字后自动收起；
   - ＋ 菜单「快捷区」一组；
   - 按住语音时快捷区不出现也不消失；
   - 语音键仍在按钮栈里；
   - 块的拖动和记位置；
   - 放大档照常缩放三个键。
8. **无障碍和悬停提示**：开关的标签随状态变，显示时是「收起快捷区」，收起时是「显示快捷区」。

## 留给实现的

- 左边两键和文字之间的间距：照右边发送与文字之间的间距定。
- 多行文字时，三个键的竖直位置：照今天 ＋ 和发送的对齐方式（贴底）定。
- macOS 原生编辑框（`ComposerNative.m`）的文字左边距，要让出左侧两键的宽度。Flutter 编辑框（Linux/iOS）同理。
