# rapp 输入区：写作面板

状态：设计稿，待用户确认。用户 2026-11-14 看过效果图后说「可以先这么做」；这份文档把效果图和讨论写成可以照着排计划的样子。

效果图（三张画板，MATRIX 主题）：https://claude.ai/artifact/5zEiy8qEm5oVUyzWFX6NW8

标了【我定的】的是我做的决定，用户没有逐条确认过，可以否掉。

## 1. 为什么改

用户的话（2026-11-14）：

- 「一长条很占空间，且按钮都很大，输入框的空间压缩小了。」
- 「一长条会挡住串流窗口底部。」
- 「我期待这个输入框是整个产品输入体验最好的地方。」
- 「初始时只有一行高度，写多了就往上延伸。且这一块宽度最好保持不变；编辑框使用系统原生的控件，以保障流畅的书写体验。把书写体验当做第一公民来设计。」
- 「后续会改造输入法，让打字体验在文字的下一行，这样眼睛可以固定不动。减少输入法框飘来飘去的问题。」

现状（`gui/lib/embed/composer_bar.dart`）：打开后是横贯舞台的一条，`[远端输入法] [按键] [附件] [输入框] [复制] [发送] [收起]`，每个控件 48 高；输入框夹在中间，是 Flutter 的 `TextField`，最多 6 行。整条浮在画面底部，那里正好是远端 app 最新的输出和它自己的输入框。最近两次输入法的修复（字母重复、组字时点击移位）都出在这个 Flutter 输入框上。

## 2. 目标、不做的、不能出现的

目标：

- G1 书写第一。输入区里几乎全是编辑区，别的控件给它让位。
- G2 编辑区是系统原生的文本控件：输入法、文字快捷键、撤销、听写都是系统自带的行为。
- G3 一行起步，写多了往上长；宽度和底边不动。
- G4 平时回一句话时，不挡远端画面的底部。
- G5 不碰鼠标也能打开输入区、在画面和编辑区之间来回。

这次不做：

- 语音输入的专门优化；Sumi 接入（只留一道缝，见 §5）。
- 把输入法的组字和候选固定在文字下一行（用户说的是「后续」，见 §9）。
- 终端会话舞台上的按键排（终端会话规格 §13 另管）。
- A 侧和线路协议；发送、上传、粘贴的规则。
- 全屏模式和分离出去的独立窗口里加输入区（和现在一样没有）【我定的】。

不能出现的：

- 草稿丢失。
- 输入区的开合或增高让 A 上的窗口改尺寸。
- 输入法组字中途被 rapp 的快捷键或点击打断。

## 3. 用户看到的

**收起时**：和现在一样，舞台右下角一个「输入」按钮。

**打开时**（效果图 1）：一个 720 宽的框贴着舞台底部居中，一行高。框里从左到右是编辑区、「＋」、发送。画面整体上移一行的高度，远端最后一行和它自己的输入框都看得见。

**写长了**（效果图 2）：框往上长，底边和宽度不动。多出来的部分盖在画面上，画面不再移动。长到舞台一半高之后，在框内滚动。

**「＋」**（效果图 3）：点开是一个小浮层：附件、在远端复制、一组按键。粘贴或附加进来的图片、文件、长文字显示成编辑区上方的一排虚线小块。

**发送之后**：框留在原地，缩回一行，光标还在里面，等下一句。

## 4. 做法的选择

布局考虑过三种：

| 做法 | 是什么 | 取舍 |
|---|---|---|
| A 瘦身 | 原来的浮条只留 `[＋] [输入框] [发送]` | 改动最小；但还浮在画面上，最后一两行仍被挡 |
| B 让位 | 瘦身，并且打开时画面上移，输入框每长一行画面再让一行 | 什么都不挡；但写长文时画面一直在跳，顶部被推走很多 |
| C 写作面板 | 一个独立的、固定宽度的书写框，书写是主体 | 最适合书写；原提议是居中、发完消失，回短话不顺手 |

**用户选的是 C**，并且改成：一行起步、往上长、宽度不变、原生控件。在这个基础上取了 B 的一小部分（只上移一行，之后不再动）和 A 的精简（控件收进「＋」）【这两处是我的提议，用户看过效果图后接受】。

原生编辑区怎么进 Flutter 主窗口，考虑过三种：

| 做法 | 取舍 |
|---|---|
| 继续调 Flutter 的 `TextField` | 不是原生控件，不符合 G2；输入法的问题会继续一个个修 |
| Flutter 的平台视图 | macOS 上有；Linux、Windows 桌面上据我所知没有正式支持（没有核对），而 Linux 是首发平台 |
| **外壳自己把原生控件叠在 Flutter 视图上（已选）**【我定的】 | 每个平台各写一个；macOS 的外壳已经有「原生子窗口浮在主窗口上」的做法（`DetachedWindow.swift`），旧 `rapp-client` 里也有现成的原生编辑框（`Sources/rapp-client/Composer.swift`，NSTextView）可以参照 |

## 5. 结构

```
ComposerPanel（Dart）      框、块、「＋」浮层、发送、提示行、位置和画面上移
  └ ComposerEditor（接口） 编辑区
       ├ FlutterEditor     现在的 TextField；Linux、Windows 先用它
       └ NativeEditor      macOS：外壳里的原生文本控件，经 SessionPlugin 的通道和 Dart 说话
```

- **这道接口就是留给 Sumi 的缝**：以后 Sumi 独立出来，是第三种实现（PD6 的待定项「Sumi 是否也用在输入区」先按「不用，留缝」处理）【我定的】。
- 接口上要过的东西：
  - Dart → 编辑区：显示在哪个矩形（窗口坐标）、主题的字体字号和颜色、隐藏、取焦点、设置全文（切会话时换草稿、取回历史）、在光标处插入文字、取一份全文、取走全文并清空。
  - 编辑区 → Dart：内容变过了（不带全文）、想要的高度、按了 Enter（要发送）、按了 Esc、光标在第一行时按了 ↑、要粘贴（⌘V）、得到或失去焦点。
- **文字只有一个主人：编辑区**（评审 A1）。Dart 不跟着每次按键镜像全文，只在四个时刻向编辑区要一份：发送、切会话、存草稿（停笔 1 秒后）、收起。输入法正在组字时，Dart 不往编辑区里写任何东西。
- **发送是把内容整段取走**（评审 A2）【我定的，改了现状】：按下发送，编辑区立刻清空、缩回一行，取走的内容变成框上方的一条「发送中」；发完消失，没发出去就留在那里，带「重试」和「放回输入框」。现在的做法是发送期间文字留在输入框里、发完再删掉开头，用户这时继续打字就要合并两份文字，新做法没有这种情况。
- **行为规则只写一份**（评审 A4）：Enter、Esc、↑ 这些规则都在 `ComposerPanel` 里，两种编辑区只上报「发生了什么」，不各自实现规则。同一份行为测试两种编辑区都要通过。
- 块仍由 Dart 画在编辑区上方，发送顺序不变（块在前，文字在后）【我定的；旧 `rapp-client` 是块嵌在文字中间，这次不恢复】。
- `EmbeddedComposer`、`Sender`、`ComposerBlocks` 和粘贴规则都不动。
- 画面上移：把舞台里的画面整体平移，舞台的尺寸不变，所以不会给 A 发改尺寸。点击换算、弹出层的位置要跟着平移一起对（实现时核对）。

## 6. 规则

W1. 宽 720。舞台比 736 窄时，取舞台宽减 16。

W2. 一行高 48。字号 15，行高 22，字体和颜色跟主题。MATRIX 的文字光晕不加在编辑区里【我定的】。

W3. 最高到舞台高度的一半，之后在框内滚动。

W4. 打开时画面上移 64（一行 48，上下各留 8）；增高时不再移动；收起时移回。移动用不超过 0.15 秒的动画，系统开了「减少动态效果」时不用动画。

W5. Enter 发送；Shift+Enter 换行；输入法组字时 Enter 和 Esc 归输入法。空着按 Enter 给远端发一个回车（保留）。

W6. Esc 只收起，不清空文字【我定的，改了现状：现在是先清空、再按一次才收起，写长文时容易误删】。

W7. 发送之后：框留着，缩回一行，焦点留在编辑区【我的提议，用户说「可以先这么做」】。

W8. 快捷键 ⌃⌘I（macOS）/ Ctrl+I（其他）【我定的】：
  - 没打开：打开，光标进编辑区；
  - 打开着、焦点在画面：光标进编辑区；
  - 焦点在编辑区：焦点回画面，框不收起。

W9. 「＋」浮层：附件…；在远端复制；按键一组（Esc、Tab、⌘、⌥、删除、←、↓、↑、→、回车）；收起（给没有键盘的触屏）。⌘ 和 ⌥ 仍是粘住的。点按键不关浮层，可以连着按。

W10. 块：编辑区上方一排虚线小块，点一下移除。

W11. 提示行在框的正上方，和框同宽，只在有事时出现：上传进度和取消、出错的话、复制的结果、远端停在输入法上（强调色，点一下切到英文）。去掉「已发送…」「已给远端发回车」这类每次都出现的话。

W12. 编辑区空着时的灰字：「写给 <app 名>」。

W13. 「＋」和发送固定在框的右下角，写多行时留在底部；点按区域 48 高。

W15. 发送后 1 秒内的空 Enter 不算数（评审 U2）【我定的】：发送后光标留在框里，习惯性多按一下 Enter，会给远端补一个回车，可能替你确认了 Agent 正在问的事。

W16. 增高没有动画，立即到位；正在写的那一行始终在框的最底下，屏幕位置不变（评审 U5）。

W17. 编辑区空着时按 ↑ 取这个会话的上一条输入；「＋」里有「输入历史」。规则在《输入记录》（`2026-11-14-rapp-input-history-design.md`）§6。发送和草稿要交给输入记录的信息见那一份 §4。

W14. 不变的：草稿跟着会话走（R18）；app 配置里的开关、「这个窗口不要输入区」、发送后补回车、标记输入框位置；发送前把远端切到英文并点标记的位置；粘贴规则（不到 800 字且不到 10 行直接进文字，否则成块）；单块 256 MB 上限；Linux 主控台不支持文件附件。

## 7. 分步

每一步做完都能单独验收。

| 步 | 做什么 | 验收 |
|---|---|---|
| S0 探查（macOS，代码不留） | 把一个原生文本控件叠在 Flutter 视图上，看六件事：系统输入法的候选框位置对不对；编辑区有焦点时 ⌃⌘ 快捷键还到不到 rapp；点画面焦点回不回得去；窗口缩放、全屏切换时位置跟不跟得上；用子视图还是子窗口；**Flutter 画的浮层（左侧面板、串流菜单、「＋」浮层）滑到编辑区上面时，原生控件会不会从浮层里透出来，怎么办**（评审 A3） | 六件各有结论 |
| S1 新布局（全平台，仍用 Flutter 输入框） | `ComposerPanel`、「＋」浮层、提示行、画面上移、快捷键、Esc 的改动、`ComposerEditor` 接口和 `FlutterEditor` | 效果图的三个状态都能做出来；开合和增高时 A 的窗口尺寸不变（看 A 端日志没有 resize）；Esc 不丢字；现有的发送、块、草稿测试改写后通过 |
| S2 macOS 原生编辑区 | `NativeEditor` 和外壳里的那一半 | 用系统输入法打中文、日文：候选框跟着光标，不重复字母，组字时点击不出错；⌥←、⌃A、撤销、听写都是系统行为；切会话草稿各归各；主题切换后字体颜色跟着变 |
| S3 Linux 探查 | GTK 的文本控件叠在 Flutter 视图上，配 fcitx5 | 有结论后再定 Linux 的做法；在那之前 Linux 用 `FlutterEditor` |

Windows 放在 Linux 之后。

## 9. 以后：组字固定在文字下一行

用户的打算：改造输入法，让组字和候选出现在文字的下一行，眼睛不用跟着候选框移动。

这次不做，但现在的选择给它留了路【我的分析，没有验证】：

- 候选框出现在哪里，是系统输入法去问文本控件的。编辑区是 rapp 自己放进去的原生控件，这个问题由 rapp 来回答，所以以后可以让它固定在一处，不跟着光标走。Flutter 的输入框做不到这一点。
- 框贴着舞台底部，下面没有空间。要在文字下一行放组字区，框里得多留一行，或者整个框再上移一行。到时候再定。
- 如果「改造输入法」指的是换一个输入法或自己做一个，而不是改 rapp 这一侧，那么这里只需要保证编辑区是标准的系统文本控件，G2 已经保证了。

## 10. 留给实现的人

- 原生控件用子视图还是子窗口（S0 定）。
- 通道上消息的名字和格式。
- 画面平移用哪种 Flutter 写法；动画曲线。
- 「＋」浮层的具体尺寸和排法，照效果图 3 和设计语言 §8。
- Linux 上 Ctrl+I 在终端里等于 Tab，和现有的 Ctrl+[ 是同一类问题，排计划时一并看。

## 11. 我定的，一览

1. 原生控件由外壳叠在 Flutter 视图上，不用平台视图（§4）。
2. 先直接用系统控件，不等 Sumi；留接口（§5）。
3. 块画在编辑区上方，不嵌进文字（§5）。
4. 编辑区里不加 MATRIX 的文字光晕（W2）。
5. Esc 只收起，不清空（W6）。
6. 快捷键 ⌃⌘I / Ctrl+I（W8）。
7. 全屏和分离窗口里仍然没有输入区（§2）。
8. 先做 macOS，Linux 先探查，Windows 最后（§7）。
9. 发送是把内容整段取走，框上方显示「发送中」（§5）。
10. 发送后 1 秒内的空 Enter 不算数（W15）。

## 12. 评审（2026-11-14，用户要求以做文档编辑器的架构和体验负责人的眼光看一遍）

改进了文档的：

| 编号 | 发现 | 落在哪里 |
|---|---|---|
| A1 | 文字有两份（编辑区和 Dart 各一份、每次按键同步全文），之前的输入法问题就是两边抢同一段文字 | §5：只有一个主人，四个时刻取一份 |
| A2 | 发送期间文字留在框里，要处理「发送中又改了」 | §5：发送即取走 |
| A3 | 原生控件叠在 Flutter 上面，会盖住滑过来的 Flutter 浮层 | §7 S0 第六件 |
| A4 | 两种编辑区各写一遍规则，迟早一个平台对一个平台不对 | §5：规则只写一份 |
| U2 | 空 Enter 发回车，加上发送后焦点留在框里，容易误确认 | W15 |
| U5 | 增高时不能让正在写的那一行跳 | W16 |

没有改、留着观察的：

- U1 **顶部被裁掉 64 是长期的，不是一小会儿。** 框在发送后留着，所以对一直在对话的会话，画面是一直上移的。终端里最上面三行不要紧；浏览器这类 app 的顶部是标签栏和地址栏。S1 做完用真实 app 看一遍；如果确实碍事，备选是打开稳定之后让 A 的窗口改一次高度（只改一次，不是每次开合都改）。
- U3 写长文时半个舞台的高度可能不够。以后加「展开」，和 Sumi 一起考虑。
