## 1. 目标与非目标

目标：
- 所有会话的剪贴板条目和传输进一个列表，按时间排，标明来源。
- 想留着的条目点「固定」，会话结束、断开后还能复制到本机。

非目标：
- 协议改动。A 端记录规则不变（只记本会话 app 在前台时的复制，剪贴板规格 §3）。
- 跨重启保留（§6 第 3 条）。
- 搜索、分类筛选、把条目发到另一台 A。
- Windows、Linux 的独立 `rapp-client` 路径：它们仍是每窗口一份历史。

## 2. 用户看到的行为

### 2.1 一份列表

- GUI 收到任一嵌入会话的 `clipboard` 事件（S2 的 runner → Dart 事件）就在全局列表最前面加一条，带：种类（文字、图片、文件、数据、文件夹）、显示文字（沿用剪贴板规格 §4.5 的写法）、来源「<app> @ <设备>」、时间（`HH:mm`）、所属会话。
- 最多 100 条不固定的；超出时挤掉最旧的不固定条目。固定的不计数、不挤。
- 文字条目照旧自动写进本机剪贴板（剪贴板规格 §4.4，行为不变）。

### 2.2 串流菜单第 5 组

- 「A 的剪贴板」：当前会话来源的最近两条；点一下等同「复制到本机」。
- 「全部剪贴板」：打开左侧面板的资源标签。

### 2.3 资源标签（720px）

上半「剪贴板」，下半「文件」。

剪贴板每行：种类图标、显示文字、来源和时间、「固定 / 取消固定」、「复制到本机」。
- 「复制到本机」：文字直接写；图片、数据、文件按剪贴板规格 §4.5 下载后写进本机剪贴板（文件落到 `~/Downloads/rapp/`）。
- 来源会话已断开或已结束，且条目没有本机副本：按钮变灰，写「A 已断开，复制不到」。
- 文件夹条目照旧是灰的「不支持」。

文件分两块：
- 进行中：每个传输一行，方向（↓ 从 A、↑ 到 A）、名字、百分比、来源、「取消」。取消即停止这次下载或上传，`.rapp-part` 留着，下次同名续传（剪贴板规格的续传规则不变）。
- 传过的：本次启动以来完成的下载和上传，名字、大小、来源、时间、「显示位置」（下载：在 Finder 里选中本机文件；上传：只显示 A 上的路径文字，不能点）。最多 50 行。

面板底部总览、状态灯图例不变（S1）。

### 2.4 固定

- 点「固定」时：文字立即固定（文字已在内存）。图片、数据、文件要先拿到本机副本：会话在线就先下载（进度显示在"进行中"），下载完才标为固定；会话不在线时「固定」是灰的。
- 固定的条目在来源会话断开、结束后仍留在列表里，「复制到本机」用本机副本，不再找 A。
- 取消固定：变回普通条目；如果来源会话已结束，取消固定后它就删除（§2.5）。
- 图片、数据的本机副本放内存；文件的副本就是 `~/Downloads/rapp/` 里那个文件，不另存。

### 2.5 会话结束时

- 会话「结束」：它的不固定条目从列表删掉；进行中的传输取消。
- 会话「已断开」（S3）：条目留着，按钮按 §2.3 变灰；重连后新会话沿用同一条目上的来源，条目重新可用（剪贴板编号在 A 上仍有效时）。

## 3. 接口改动

- runner（`RappSession`）：`clipboard` 事件带 clip 编号、种类、显示文字（S2 已有，若字段不全在计划里补齐）；新增 `transfer` 事件 `{sid, id, dir, name, done, total, state}`（state：running / done / failed / cancelled）；Dart → runner 新增 `fetch_clip {sid, clip}`（复制到本机或固定前下载）、`cancel_transfer {sid, id}`。
- Dart：新文件 `resources_state.dart`（全局列表、固定、挤掉规则，纯逻辑可测）；资源标签页；串流菜单第 5 组改读全局列表。
- hub 不变。日志沿用可观测性规格：传输照旧由 host 记；GUI 不记剪贴板内容，固定、取消固定不记。

## 4. 拆分建议

1. `ResourcesState`：加条目、100 条挤掉、固定不计数、会话结束清理、断开置灰。
2. runner 事件与命令：`transfer`、`fetch_clip`、`cancel_transfer`。
3. 资源标签页：剪贴板列表和文件两块。
4. 串流菜单第 5 组改读全局列表；固定的下载流程。

## 5. 验收

- 两个会话里分别在 A 上复制文字：资源标签里两条，来源各自正确，最新在上。
- 固定一条文字，结束它的会话：条目还在，「复制到本机」可用。
- 不固定的条目在会话结束后消失。
- 复制一个文件，在资源标签点「复制到本机」：进行中出现进度，完成后进"传过的"，「显示位置」能在 Finder 里选中它。
- 下载中点「取消」：传输停止，`.rapp-part` 留着。
- 测试：纯逻辑用单元测试；实机只用自己起的 host、client 和自己拉起的 app，按 PID 操作；不碰真实系统剪贴板（用剪贴板规格里的测试替身），下载目录用临时目录。

## 6. 我做的假设（按默认执行，验收时可改）

1. **全局列表放在 GUI 进程里，不在 hub。** 主界面规格写的是"上移到 hub"；S2 之后所有嵌入会话、旁路连接和传输都已经在 GUI 进程里，放 hub 要给 hub 加协议、多一跳，换不来东西。意图（跨会话一份、固定后保留）不变。
2. **不固定的最多 100 条。**
3. **不跨重启保留**，固定的也不保留。
4. **固定图片、文件前先下载到本机**；会话不在线时不能固定。
5. **"传过的"只显示这次启动以来的**，最多 50 行。
