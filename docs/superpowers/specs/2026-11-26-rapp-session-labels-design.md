| # | 要求 |
|---|---|
| R1 | 「现在会话太多，看上去都差不多。我希望能自己修改各个会话卡片上的会话的标题或者备注。让我能持续的约定某一个会话长期是干什么的」 |
| R2 | 「并且能快速的在远程启动起这个会话」 |
| R3 | 「这个标记应该是持久化在 host 那一段，任何一个 client 打开他都能看到变化」 |
| R4 | 「都能看到自定义的内容，并且允许编辑修改」 |
| R5 | 「在服务终端那一侧的 rapp 的本机卡片中，也可以修改」 |
| R6 | 「如果用户不想再保留这种标注了，应该有一键 reset 的能力」 |
| R7 | 已停止的卡片放哪：「按最符合常规认知的来选择」 |
| R8 | 存在哪：选了 **A：被控端的 rapp 服务里统一存一份标注表，图形 App 和终端共用** |

为什么：同一台 Mac 上开着好几个文本终端，都在跑 claude/codex，卡片上全是「claude · zsh」，分不清哪个是干什么的。用户想给每个会话一个长期的身份（这个是「后端 API」，那个是「写作面板」），在哪台客户端上看都一样，终端关了这个身份也还在，点一下就能在原地重新拉起来。

## 1. 现状（main 65807ebe）

- **会话的键**：`<设备 id>/<app>`。图形 App 的 `app` 是 bundle id（一台设备上一个 App 一个会话）；文本终端的 `app` 是终端 id `term:pty:<key>`（`SessionEntry.key`，`session_model.dart`）。
- **标题**：`SessionEntry.title`。终端是 `termTitle(name, fg)` =「程序 · 名字」，图形 App 是 App 名。顶栏、总览、侧栏、窗口菜单、Dock 菜单等所有列出会话的地方都读它。
- **终端名**：已经能改（设备页 `_TermRow` 行内改名 → `rename_term`），名字存在 holder 进程里，进程没了名字就没了（终端恢复把它写进快照）。图形 App 的名字改不了。
- **项目成员的 `task`**：`workspace.json` 里项目成员有一个备注字段，存在客户端本机，别的客户端看不到。
- **协议**：没有版本号。新 Op 是加法：旧被控端回 `unknown op`，hub 把它记成 `Unsupported`，不再问（`hub/src/terms.rs:55,80`）。所以**加 Op 不会让新旧两端连不上**，只是旧端没有这个功能。
- **推送**：终端列表是长连接 `WatchTerms`：worker 每次列表变了就整份重发，服务转给 B，hub 每台 host 一个 watch（上线开、下线停、失败退避 30 s → 10 min），发 `terms` 事件给 GUI（`termLists[id]`）。
- **服务的小状态文件**：`state.home` 下的 `term.json`、`shares.json` 等；写法是 `rapp_net::config::write_json`（0600 临时文件 + fsync + rename），读改写外面套一个 `static EDIT: Mutex<()>`，改完 `state.notify()` 叫醒本机 IPC 的 `subscribe`。
- **本机 GUI 怎么找本机服务**：本机 IPC（127.0.0.1:22029，首行 token，`service_client.dart`），`subscribe` 后服务有变化就推 `{"event":"changed"}`。内嵌 hub **不连本机**：本机列只有「正在被接入」的卡片（`InboundGroup`，来自 `monitor.status.sessions`：sid、peer、name、app、path、since），能踢掉，不能打开。
- **权限**：认证过的对端可以用所有 Op（安全立场：relay 是唯一的门）。只给本机做的事放在 IPC 上，不进 Op。
- **终端恢复（未合入）**：快照在 `$ROOT/local/term/saved/<key>.json`；恢复出来的 holder 沿用旧 key，所以**终端 id 不变**；计划中的 `Op::RestoreTerms{keys, app}` / `Op::ForgetTerms{keys}`；可恢复列表随终端列表里本机那行 `HostRow.saved:[{key,name,prog,saved,boot}]` 推给客户端（不带目录和命令）。快照在 shell 退出或用户「结束终端」时删除，信号（关窗口、关机）保留；30 天或 50 个以上会被清掉。

## 2. 目标 / 非目标 / 反目标

**目标**
1. 任何会话卡片（总览、顶部下拉列表、侧栏会话页，以及被控端本机列的「正在被接入」卡片）都能改标题、写备注、一键还原（R1、R4、R5、R6）。
2. 标注存在被控端的 rapp 服务里；任何一端改了，所有连着的客户端和被控端自己几秒内都看到（R3）。
3. 有标注的文本终端结束以后，卡片还留着，标「已停止」，点「启动」就在被控端按原来的目录、环境把它拉起来，标注不变（R2）。
4. 标注过的会话，标题在所有列出它的地方都一样：读 `SessionEntry.title` 的（顶栏、窗口菜单、Dock 菜单）和读 `labelOf(AppRef)` 的（常用、项目成员）以及「打开应用」菜单（§7.6）。

**非目标**
- 不改 Terminal 标签页在被控端上显示的标题；终端自己的名字（`rename_term`）照旧，是标注的默认值。
- 不做标注历史、撤销、多人合并：后写的覆盖先写的。
- 不把项目成员的 `task` 备注搬到被控端（它属于项目，不属于会话）。
- 图形 App 没有「已停止」：没打开的 App 本来就在「打开应用」菜单和「常用」里，不额外出卡片。
- 不按客户端区分标注：一个会话只有一份。

**反目标（做成了也算失败）**
- 同一个会话在两个客户端上显示不同的标题或备注（超过推送延迟）。
- 标题或备注进了日志、进了 relay 的元数据（它们只在加密的会话流里走）。
- 有标注的终端结束以后卡片没了，或者 30 天清理把它的快照清了（用户说长期）。
- 还原以后留下痕迹：卡片还在、快照还被钉着、顶栏还显示旧标题。
- 为标注另写一套卡片：总览、顶栏、侧栏、本机列各一份（违反「一张卡片一个实现」）。
- 旧版被控端或旧版客户端因为这个功能连不上或报错。

## 3. 做法（Approaches）

| 做法 | 是什么 | 取舍 |
|---|---|---|
| **A. 被控端服务里一张标注表（已选，R8）** | 服务在 `state.home/labels.json` 存 `{app → {title, note}}`，三个新 Op：看（长连接推送）、改、还原；本机 GUI 走 IPC 改同一张表 | 图形 App 和终端一套；服务本来就是每台设备的常驻进程，掉线重连有现成的 watch 模式可抄。代价：新 Op 要走一遍服务、hub、GUI 三层 |
| B. 标注跟终端走，存在 `rapp-term` | 备注加进 `rename_term` 和终端列表 | 改动最小，但图形 App 不能标；以后要支持就得另做一份，两套实现 |
| C. 存在客户端的 `workspace.json`，靠某种同步 | 和「常用」「项目」放一起 | 不满足 R3（存在被控端），多客户端要自己做同步，排除 |

## 4. 设计

### 4.1 数据

被控端 `state.home/labels.json`【我定的】：

```json
{"version": 1, "rev": 17, "labels": {
  "term:pty:ab12": {"title": "后端 API", "note": "改 rust/hub，别碰 relay", "at": 1764100000},
  "com.apple.Safari": {"title": "", "note": "只开 rapphub 后台", "at": 1764100100}
}}
```

- 键是 `app`（不带设备 id：表本来就在那台设备上）。
- `title`、`note` 都可以是空串，但不能两个都空（两个都空 = 还原，条目删掉）。
- 标题：一行，去首尾空白，没有控制字符，最长 64 个字符（和终端名同一条规则，`cleanTermName`/`id.rs` 那条）。备注：一行，最长 200 个字符；换行折成空格【我定的】。服务端也校验，不合规回错误文本。
- `rev`：每次改动加 1，推送里带着，GUI 用它丢掉乱序的旧推送。`at`：最后一次修改时间（秒），只用于提示。
- 写法照 `term.json`：`EDIT` 锁里读改写，`write_json` 原子写；读不了的文件挪成 `labels.json.bad`，从空表开始并记一条日志（照 `shares.json`）。
- 最多 500 条【我定的】，超了拒绝新增（不是静默丢）。

### 4.2 协议（加法，不升版本）

新 Op（`rust/net/src/msg.rs`）【我定的命名】：

| Op | 参数 | 回答 |
|---|---|---|
| `watch_labels` | — | 长连接：先发一行整表 `{ok, rev, labels}`，以后每变一次发一行整表 |
| `set_label` | `app`, `title`, `note` | `{ok, rev}`；校验失败回 `err(<中文原因>)` |
| `reset_label` | `app` | `{ok, rev}`；没有这条也回 ok |

- 整表推送：表很小（≤500 条短文本），整份发比增量简单，和 `WatchTerms` 一个路子。
- `log_fields`：三个 Op 只记 op 名（`set_label` 不记 app、标题、备注；和 `rename_term_logs_neither_the_term_nor_the_name` 同一条规矩）。
- 旧被控端回 `unknown op` → hub 记成不支持，GUI 对这台设备的卡片**不显示**「改标题和备注…」和「还原」。旧客户端不发这些 Op，什么都不变。
- `set_label`/`reset_label` 可以重发（结果一样）；`watch_labels` 照 `WatchTerms` 的重连退避。

### 4.3 被控端服务

- 新模块 `service/src/labels.rs`：表在内存里一份（`Mutex<Table>`），启动时读文件；`watch_labels` 的订阅者用 `tokio::sync::watch` 拿到新 `rev` 就整表重发。
- `peer.rs` 的分发里加这三个 Op；它们**不受** `term.json` 的 `allow` 管（图形 App 也能标）。
- 本机 IPC 加 `labels`（取整表）、`set_label`、`reset_label`；改完 `state.notify()`，本机 GUI 收到 `changed` 后重新取 `labels`。
- 还原一个终端的标注时，同时告诉 `rapp-term serve` 解除钉住（4.5）。

### 4.4 hub 和 GUI 的数据层

- hub：每台 host 一个 `watch_labels`，和终端 watch 同时开同时停（`presence.rs` 上线 `ensure_watch` 那里），发 `{"event":"labels","id","rev","labels"}`；`set_label`/`reset_label` 是 GUI 命令，回 `label_set`/`label_reset`。
- GUI `hub_client.dart`：`labels[id] = LabelTable(rev, map)`，`rev` 比手上的小就丢；但每条 watch 的第一张表带 `first: true`，不管 rev 都收（设备可能换了新的 `labels.json`、rev 从 0 重来，presence 停掉 watch 时又不发事件）；`unsupported` 记下，菜单项据此隐藏。
- 本机：`service_client.dart` 加 `labels()`、`setLabel`、`resetLabel`；本机表放在 `MainState.localLabels`。
- `SessionEntry` 加 `label`（`Label?`：title、note），在 `_entryOf`/`_mapEntries` 里从 `labels[device][app]` 填。
- **`SessionEntry.title`**：有非空的标注标题就用它，否则照旧（`termTitle` / App 名）。这样所有读 `title` 的地方自动一致。
- 搜索、排序（`_byDeviceThenApp` 按 title）跟着变，这是对的：用户起了名就按名字找。

### 4.5 已停止的终端（需要终端恢复）

- **钉住**：一个终端有了标注，服务告诉 serve `{"op":"pin","key":…}`；serve 在快照里记 `pinned: true`。钉住的快照：shell 退出、「结束终端」时**不删**（改成标记 `ended`），也不参加 30 天/50 个的清理。还原标注 → `unpin`，快照回到普通规则（已 `ended` 的就删掉）。
- **列出来**：GUI 对每台设备，凡是标注表里的 `term:pty:<key>`，而终端列表里没有活着的这一行，就出一张「已停止」卡片。数据来自标注（标题、备注）加 `HostRow.saved` 里同 key 的那条（程序名、保存时间）；没有快照也照样出卡片。
- **卡片长相**：还是 `SessionBlock`，`Lamp.notOpened` 的样子（淡、虚线框，和设备页没打开的行一样），第二行「已停止」+ 程序名，右边「启动」。放在所属分组的末尾（R7【我定的】：按设备分组就在那台设备下面；按项目分组时，它属于哪些项目就在哪些项目下面；按 App 分组归到「终端」那组）。
- **启动**：有快照 → `RestoreTerms{keys:[key]}`（终端恢复的 Op），holder 沿用 key，终端 id 不变，标注自然接上；恢复出来就像点了「打开」一样进到这个会话。没有快照（比如钉住前就没了，或者被控端没开 shell 钩子）→ 在被控端家目录新开一个文本终端，**把标注搬到新终端 id 上**（服务端一步完成：`set_label` 新 id + `reset_label` 旧 id），提示「原来的目录没有记下，已在家目录新开」。
- **还原**已停止的卡片：标注删掉、`unpin`，卡片消失。
- 终端恢复没合入之前：已停止的卡片照样出，「启动」走「没有快照」那条路。

### 4.6 界面

- **入口**：卡片右键（触屏长按）菜单，所有地方是同一个菜单，放在 `session_block.dart` 里（`SessionBlock` 带它，不在各处另写）【我定的】：
  - 「改标题和备注…」→ 一个小对话框：标题一行、备注一行，下面一行灰字写默认标题（「留空用默认：claude · zsh」）；保存、取消。
  - 「还原」：没有标注时不出现；点了直接还原，hint 提示「已还原，标题回到 claude · zsh」，不再确认（一键）【我定的】。
  - 对端不支持时两项都不出现。
- **卡片三行**：有备注时卡片多一行灰色小字，单行截断，完整内容在 tooltip 里【我定的】。卡片因此有两种高度：`sessionBlockHeight`（56）和带备注的 72；同一个列表里各卡片按自己的内容取高度。
- **第一行**：有自定义标题时就是这个标题。文本终端第二行开头的「CLI」换成程序名（「claude · 活动」），让程序信息不丢【我定的】。
- **本机列（被控端，R5）**：「正在被接入」卡片用标注后的标题和备注，右键同样能改、能还原，走本机 IPC。本机列的被接入卡片仍然是 `InboundGroup` 里的那张；这一张也要换成 `SessionBlock` 的同一套标题/备注显示（只是动作是「踢掉」，不是「打开」），否则就是两套实现。具体：给 `SessionBlock` 加一个 inbound 的变体参数，或把共同的「标题 + 备注 + 菜单」抽成 `SessionBlock` 内部的一块，由两处共用——由实现者选，但只能有一份标题/备注/菜单代码。
- **冲突**：保存时如果别人刚改过（推送的 `rev` 比打开对话框时新），直接覆盖，不提示【我定的】（用户场景是一个人多台设备）。

### 4.7 失败

- 设备离线：菜单项变灰，提示「设备离线，连上后再改」。
- 保存失败（校验、写盘）：对话框不关，下面红字写服务回的原因。
- 标注表读不了：照常运行，表从空开始，日志一条；客户端看到的就是没有标注。

## 7. 审读后我定的（2026-11-26）

### 7.1 分两期，第一期不依赖终端恢复
终端恢复（`feat/term-restore`）只做了 holder 那一半，serve、协议、GUI 都没做，也不是这个 session 的分支。所以：
- **第一期（现在做，建在 main 上）**：标注表、三个 Op、IPC、hub、GUI 全部显示和编辑、已停止的卡片、「启动」走「没有快照」那条路（家目录新开 + 搬标注）、本机列。
- **第二期（终端恢复合入后做）**：钉住快照，「启动」优先用快照恢复。规则先定在 §7.2，写进 `tasks/todo.md`。
- 第一期的 GUI 判断「有没有快照」只看 `HostRow.saved` 里有没有同 key 的条目；main 上没有这个字段，就永远走家目录那条路。第二期只需补上钉住，GUI 的分支不用改。

### 7.2 钉住（第二期的规则）
- 快照只有 holder 写（`holder.rs` "The only writer of this terminal's snapshot"），所以钉住不写进快照。**钉住的集合就是标注表里的 `term:pty:<key>`**：服务把这组 key 交给 serve（启动时一次，之后每次标注变化一次），serve 再转给 holder 和清理逻辑。
- holder 在 shell 退出或「结束终端」时，key 被钉住的快照不删，改写一个 `ended` 标记（`saved.rs` 的 `Snapshot` 加 `ended: bool`）。
- `HostRow.saved` 每条加 `pinned`、`ended` 两个字段。**`ended` 的条目不进「恢复上次的终端」列表，也不计入开机后的「恢复」按钮**，免得踩终端恢复的反目标第 3 条。它们只给已停止的卡片用。
- 钉住的快照不按 30 天清理，也不计入 50 个的上限。`ForgetTerms` 和「全部清掉」跳过钉住的条目。要清掉，就还原标注。
- 还原标注后解除钉住：已经 `ended` 的快照删掉，其余回到普通规则。

### 7.3 有标注的会话，每台客户端上都常驻一张卡
否则会倒挂：终端死了，每台客户端都有「已停止」卡片；终端活着，没打开过它的客户端反而看不到。所以凡是标注表里有的会话，每台客户端都出一张卡（`SessionBlock`）：
- **已经打开**：照旧。
- **活着但这台客户端没打开**（终端在终端列表里，或者是图形 App）：`Lamp.notOpened` 的样子，右边写「打开」，点了等于 `openOrSwitch`。
- **终端已不在终端列表里**：「已停止」，右边写「启动」。
- 这些卡片排在所属分组的末尾。只在那台设备在线、标注表已经到了的时候出现；设备离线就收起。已经打开的会话不受影响，继续用最后收到的标注。

### 7.4 被控端本机列（R5）
内嵌 hub 不连本机，所以本机列的数据全部走本机 IPC：
- 「正在被接入」的卡片显示标注后的标题和备注，右键能改、能还原。
- 卡片下面再列出这台机器上**有标注、此刻没人接入**的会话，同一张卡片，菜单只有「改标题和备注…」和「还原」，没有打开或启动，因为被控端自己不通过 rApp 看自己。这样被控端能管这台机器上的全部标注。
- 本机列不显示终端在不在跑（被控端 GUI 没有本机终端列表），这一期不做。

### 7.5 「无快照启动」搬标注
`Op::OpenTerm` 加一个可选字段 `label_from: Option<String>`（旧的终端 id）。服务在 serve 回了新 id 之后，在同一把锁里把标注从旧 id 搬到新 id，然后推送。旧被控端不认这个字段，也没有标注，不受影响。GUI 不自己发两次请求。

### 7.6 不读 `SessionEntry.title` 的地方
- `MainState.labelOf(AppRef)`（常用、项目成员）：先查标注标题，没有再走原来的逻辑。
- 「打开应用」菜单（`open_apps_menu.dart`）：有标注的 App 显示标注标题，App 名放在小字里。
- 这三个地方共用一个 `titleOf(device, app, fallback)`，不各写一份。

### 7.7 「不支持」要发出来
hub 在对端回 `unknown op` 时发 `{"event":"labels","id","unsupported":true}`。GUI 据此隐藏菜单项。没收到任何 `labels` 事件之前，菜单项也不出现，所以「还没到」和「不支持」显示得一样。

### 7.8 本机被接入卡片并进同一张卡片
`inbound.dart` 的 `_InboundCard` 现在是自己写的（高度、样式都是独立的）。这次改成用 `session_block.dart` 里同一套卡片：外框、标题行、第二行、备注行、标注菜单都只有一份。被接入卡片只是右边的动作是「踢掉」。一个 App 被几台设备同时接入时，仍然一台一张卡，每张显示同一个标注。
