# 总览本机列显示「正在被接入」（短设计）

日期：2026-11-25 · 分支 `feat/overview-inbound`

## 为什么

总览里「本机」列通常只有一句「没有打开的 app」。可这台机器其实正在被别的设备看、开着终端，
这件事只在服务自动弹出的「rApp 连接管理」小窗口（`gui/lib/cm_page.dart`）里看得到，而这个小窗口还会挡在前面。
用户要的是：接入清单放进总览本机列，用同样的卡片；一眼看出这是「别人在用本机」、不是可点开的任务；
主窗口开着时小窗口不再弹。

## 目标

1. 本机列在会话卡片之后加一组「正在被接入 · N」，每个接入会话一张卡片。
2. 卡片和任务卡片明显不同：虚线边框、没有按下效果、点卡片本身没有反应；右侧一个小「断开」按钮。
3. macOS：主窗口在运行时，服务拉起的 `rapp --cm` 不显示窗口、直接退出；主窗口不在运行时照旧弹出。

## 非目标

- 不改网络协议（只给本机服务的 `status` 加可选字段）。
- 不改 Linux 行为：服务自动拉起的 `--cm` 在 Linux 上本来就不显示（`gui/linux/runner/my_application.cc` 的 `--background`）。
- 不处理「小窗口已弹出后才打开主窗口」：小窗口不自动关，照旧在会话结束 5 秒后关闭。
- iOS 没有服务，不显示这一组。
- 端口分享的转发不算接入会话（`status.sessions` 里没有），不显示。

## 反目标

- 接入卡片被当成任务：可以选中、点了切舞台、出现在会话计数或状态队列里——都不行。
- 小窗口隐藏后断不开接入的设备。

## 做法（已选 A）

- **A（选定）**：macOS 的 `--cm` 进程启动时，非阻塞地试一下主窗口单实例锁（`SingleInstance` 的 `com.rapp.rapp.gui.lock`）。
  锁被别的进程占着＝主窗口在运行 → 在创建 Flutter 引擎/窗口之前退出。只改 Swift，不动服务。
  代价：每次接入多起一个马上退出的进程。
- B（未选）：主窗口定期告诉服务「我在」，服务不拉起 `--cm`。要加新的本机通信操作和过期处理，收益只是省一次进程启动。

## 设计

**数据。** 主窗口已有的 `ServiceMonitor.status.sessions`。服务 `State::status()` 每个会话加可选字段：
`name`（对方自称的设备名，`Peer.name`）和 `side`（传文件的旁路连接）。GUI 的 `ServiceSession` 读这两个字段，缺了就是 null/false。

**显示名。** `hub.hosts` 里 id 相同的设备名 → 自称名 `name` → 设备 ID（`peer`）。

**卡片。** 高度同任务卡片（56）。第一行：接入图标 + app 名（终端显示成终端的样子，和其他地方一致）+ 右侧「断开」。
第二行：显示名 · 接入多久（由 `since`，Unix 秒，算出「12 秒 / 3 分钟 / 2 小时」）；传文件的连接加「· 传文件」。
虚线边框，无 InkWell。读屏：不是按钮，标签「正在被接入，<app>，<显示名>」，「断开」单独是按钮。
顺序同服务给的（最早接入在前）。没有接入会话或服务没在运行时，整组不出现。

**断开。** `monitor.kick(sid)`；失败时提示「断开失败：…」（同 `cm_page.dart`）。

**小窗口。** `MainFlutterWindow.awakeFromNib` / `AppDelegate`：`isConnectionManager` 且主锁被占 → 立刻 `exit(0)`。
显式手动 `rapp --cm` 也会被这条规则挡住——主窗口开着时总览里已经有同样的清单，可以接受。
