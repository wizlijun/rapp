# iOS 输入键开合 + 按键区（设计）

2026-11-21。依据：用户原话（§1），用户看过分帧图后的认可（「ok」），现有代码：`gui/lib/embed/composer_panel.dart`（`composerLayer`、`_IosStage`、`_VoiceAbovePanel`）、`stage_buttons.dart`（`StageButtons`）、`composer_float.dart`（`FloatingComposer`，拖动条和 ×）、`composer_plus.dart`（＋ 菜单「收起」）、`ui/stage.dart:52`（键盘高度）。

图：`2026-11-21-rapp-ios-input-toggle/1-now.png`（现在）、`2-new.png`（新方案）、`3-keys.png` 和 `4-keys-layout.png`（按键区，§5）。

## 1. 为什么做

用户原话：「现在键盘展开和收起的体验非常差：1. 操作不方便。2. 视觉上不流畅。3. 应该是点开之后就能直接折叠回去。」

按代码看，现在 iOS 上：

- 点「输入」后这颗键消失（`composer.open && button` 时整组只剩 `_VoiceAbovePanel` 里的语音键），拇指回原位按不到东西。
- 收起只有两条路：拖动条旁的 ×（先碰一下面板才出现，图标 14 点），或 ＋ 菜单 →「收起」（两下）。实体键盘还有 Esc。
- 面板是 `open() ? … : SizedBox.shrink()`，打开瞬间出现、收起瞬间消失；键盘自己滑。收起后按键组按 `keyboard + 12` 跟着键盘往下滑，键盘到底（`keyboard == 0`）再一下跳到 88。

## 2. 目标、不做的、不能出现的

**目标**

- G1 「输入」变成开关：打开后不消失，图标换成「键盘 + 向下箭头」、边框亮成强调色，读作「收起」；再点一下就收起，草稿留着（同 Esc）。
- G2 打开时，语音和收起这一组站在面板上方，还在原来那一侧（`stageSide`）、原来的顺序（语音最外）。即把现在的 `_VoiceAbovePanel` 扩成两颗键。
- G3 一起走：键盘、面板、按键组一起动。打开时面板随键盘上来、同时淡入；收起时面板跟着键盘一起滑下去，最后淡出，不再先消失。按键组从收着的位置（88）平滑走到面板上方，收起时平滑走回 88，中途不贴到底、不跳。
- G4 往下拉收起（用户 2026-11-21 选「贴底后再拉才收起」）：面板已经在最低处（贴着按键区或键盘）时，按住面板继续往下拉，面板（和按键组）跟着手指往下；松手时拉过 70 点或向下甩，就收起；不够就弹回去。面板不在最低处时，拖动照旧是挪位置；挪到底后手不松继续往下，超出最低处的部分才算往下拉。
- G5 没有软键盘时（接实体键盘，或用户用系统键收了软键盘）：面板在底部，按键组在面板上方，同一颗键收起。
- G6 去掉拖动条旁的小 ×（iOS）。

**不做的**

- 点 A 的画面不收起面板：那一下是点给 A 的，会误点。
- Esc 和 ＋ 菜单里的「收起」照旧保留。
- macOS / Linux 的输入行不改。
- 不改面板本身的大小、内容、发送逻辑。

**不能出现的**

- 收起或打开的过程中，任何一样东西先到位再跳一下。
- 收起键要先碰面板才出现、或比其它舞台按键小。
- 往下拉的手势抢掉编辑框里的选字、滚动。

## 3. 做法（用户已选）

考虑过三种：

| 做法 | 结果 |
|---|---|
| **A. 「输入」变开关，整组跟面板上去**（选这个） | 开和收是同一颗键，拇指从原位往上推就到；动起来是一条线 |
| B. 面板输入行最左边加一颗「收起」 | 改动小，但开在一处、收在另一处，还挤编辑框的宽度 |
| C. 点画面空白处收起 | 画面上的点击是给 A 的，会误点，不能用 |

用户看过分帧图（`2-new.png`）后说「ok」，选 A，以及图里的五帧行为。

## 4. 细节

- **时长和曲线**：键盘由系统驱动；面板、按键组的位置都从键盘高度（`stage.dart` 的 `keyboard`）算，所以天然跟着键盘走。键盘不动的情况（没有软键盘）用 340ms、`Curves.easeOutCubic` 一类的曲线自己动。图标换（旋转 + 淡入淡出）约 200ms。系统要求减少动态时（`disableAnimations`）全部不动画。
- **收起时面板留到键盘下去**：`composer.open = false` 之后，面板再挂一段，跟着键盘高度往下，最后约 100ms 淡出再拆掉。草稿照现在的规则在 `collapse` 时写回。
- **按键组的位置**：打开时用 `panelPlaceOf(session)` 的面板上沿（现在 `_VoiceAbovePanel` 就是这么算的），收起时是 `stageButtonsUp`（88）。两者之间做插值，不是两套布局来回切。横屏和 iPad（竖列）同理：整列跟面板上去，收起键在语音上面。
- **往下拉从哪里起手**：面板的拖动条那一排和面板边框空白处；编辑框里不起手（不抢选字和滚动）。拖动挪位置的手势不变（`FloatingComposer` 的 `_PanelPan`），只在面板已到最低处、还往下时转成「往下拉」（G4）。
- **长按语音**：打开状态下语音键行为不变（按住说话）。录音时按现在的 `hidden` 规则，收起键淡出、不能点。
- **终端会话**（`term != null`，面板在底部居中）：同一套规则；面板下面是按键区（§5），不再有六颗大键。

## 5. 按键区（用户 2026-11-21 追加）

用户原话：「考虑一下手机和 pad 上虚拟键盘没有常用控制键的问题……整理 claude code codex 这类 terminal 应用最常需要的操作键，如 tab、上下左右、复制粘贴等……专业的做排布，增加这种虚拟按键的操作区域。目前藏在 + 号按钮内不方便。请根据键盘交互调整一起修改掉。」

图：`3-keys.png`（iPhone 四帧）、`4-keys-layout.png`（排布、每颗键的用途、行为）。

**依据**（Claude Code / Codex 官方快捷键表；Termux、Blink、Termius、Agents Room 的按键条）：手机上用 agent CLI 最离不开的是 Esc（打断、拒绝、Esc Esc 回退）、↑↓（权限框选项、历史）、⏎、⇧Tab（Claude Code 切模式；GitHub issue #32676、#6383 点名手机打不出 Esc 和 ⇧Tab）、⌃C。面板自己能打的（字母、数字、`/ @ !`、换行）不占位子。

**K1 位置**
- 面板打开：所有会话都有，贴在软键盘上沿（全宽，0 间隙）。从下往上：键盘 → 按键区 → 面板（间隔 8）→ 语音/收起。四样一起上下（G3）。没有软键盘时，按键区在舞台底部，面板在它上方。
- 面板收着（用户选「终端会话和终端类 App」）：rapp 文字终端会话，和画面是终端类 App 的会话（`terms_entry.dart` 的 `terminalApps`）在舞台底部显示一排；其它 App 不显示。语音/输入键站在它上方（不低于 `stageButtonsUp`）。
- 画面上移：按键区占的高度从画面底下让出来（同现在 `pictureLift` 的做法），不盖住远端最底下几行。

**K2 排布**
- 窄（iPhone 竖屏、iPad 分屏窄栏）：第一排 10 颗 `Esc ⇧Tab Tab ⌃C ← ↑ ↓ → ⏎ ⋯`，等宽（约 35 点，同系统键盘字母键），高 42。`⋯` 长出第二排 `⌃ ⌥ ⌃R ⌃O ⌃T ⌃B ⌃D ⌫ 复制 粘贴`，再点收回；展开与否记在偏好里。
- 宽（够一排放下全部时：iPad、手机横屏）：一排，按组留空：`Esc ⇧Tab Tab` · `⌃ ⌥`（App 会话加 `⌘`）· `⌃C ⌃D ⌃R ⌃O ⌃T ⌃B` · `Home End PgUp PgDn` · `⌫ 复制 粘贴` · `← ↑ ↓ →` `⏎`。没有 `⋯`。Esc 永远最左，方向和 ⏎ 永远最右。
- 方向键上滑是备用键：← Home、↑ PgUp、↓ PgDn、→ End，键角写小字。
- App 会话窄排第二排多一颗 `⌘`（排不下时 `⌃D` 让位）。

**K3 行为**
- 按下就发给远端，不进编辑框、不动光标和草稿，键不可聚焦（不弹也不收软键盘）。连点两下 Esc 就是两个 Esc，不合并、不防抖。
- `⌃ ⌥ ⌘` 粘滞：点一下管下一个键（亮边框），点两下锁住（亮底），再点熄灭；沿用 `ModifierLatch` 的三态。⌃ 亮着时：按键区的键带 Ctrl 发；面板编辑框里打的下一个字母不进编辑框，以「⌃字母」发给远端，然后 ⌃ 熄灭（锁住的不熄）。
- `← ↑ ↓ → ⌫` 按住 0.4 秒后每 80 毫秒连发。
- 每次按下轻震一下（`selectionClick`）。
- 复制：文字终端复制选中的字（同现在的选区复制）；App 会话发 ⌘C 给远端（同 ＋ 菜单「在远端复制」）。粘贴：手机剪贴板的字直接发给远端；终端用 `TermSessionPort.paste`，App 会话用 `composerSend` 一段 text，不走面板发送后的处理（不回车、不收起、不清草稿）。
- 发送被冻结（`state.sendBlocked`）时键变灰、不发。
- 文字终端用线上的键名（`Esc`、`Shift-Tab`、`Ctrl-C`……）；App 会话用 macOS 键码 + 修饰位（同 `AppKeyRow`）。
- 实体键盘（用户选「照旧显示，可收成窄条」）：接了实体键盘（`hardwareKeyboard()`）时照旧显示；按键区右端多一颗小键，点了缩成只剩 `Esc ⇧Tab` 和展开键的窄条，再点展开；这个选择记在偏好里。

**K4 取代**
- iOS 上：终端的六颗大键（`TermKeyRow`、偏好「按键排」）、关着的 App 按键排（`AppKeyRow`、`showAppKeyRow`）、＋ 菜单里的「按键 · 直接发给远端」格子，都换成按键区。＋ 菜单的其它行（附件、在远端复制、输入历史、直接回车、缩放、收起）不变。
- macOS / Linux 不改。

## 6. 留给实现的

- 面板「收起时多挂一段」用 `AnimatedSwitcher` 还是自己的 `AnimationController`；以及键盘不动时的插值怎么和键盘高度合起来。
- 「收起」图标：Material 的 `Icons.keyboard_hide` 或自画，要和 56 点的舞台按键一致。
- Semantics：这颗键在两种状态下分别读「输入」「收起」；按键区每颗键读它的名字（Esc、Shift Tab、Control C、左……）。
- 「⌃ + 编辑框字母」截在哪一层（Flutter 编辑器的输入格式化 / 原生编辑器的回调），只要那个字母不留在草稿里。
- 上滑备用键的判定距离。

## 7. 实机检查（Duo 和 iPad 各一遍）

1. 点「输入」：键盘、按键区、面板、按键组一起上来，没有先出现再跳。
2. 打开后「输入」在面板上方变成「收起」，在原来那一侧；再点一下收起，草稿还在。
3. 收起时面板跟着键盘一起下去，按键组平滑回到原位，不贴底、不跳。
4. 面板在最低处时按住拖动条往下拉，面板跟着手指；拉够松手收起，不够弹回。面板在高处时往下拖是挪位置。编辑框里选字、滚动不受影响。
5. 接实体键盘：面板在底部，按键组在面板上方，同一颗键收起；按键区照旧在，能缩成窄条。
6. 横屏、iPad：竖列按键组跟着面板上去，收起键在语音上面；按键区并成一排。
7. 拖动条旁不再有小 ×；Esc 和 ＋ 菜单「收起」照常；＋ 菜单里不再有按键格子。
8. 开着面板按住语音说话：收起键淡出，松手后回来。
9. 远端 Claude Code 弹权限框：面板收着，↑↓ 选、⏎ 确认、Esc 拒绝都能用；⇧Tab 切模式；连点两下 Esc 打开回退菜单。
10. ⌃ 点亮后在键盘上打 r，远端收到 ⌃R，编辑框里没多出 r；双击 ⌃ 锁住后连发几次都带 Ctrl。
11. 按住 ← 或 ⌫ 连发；方向键上滑发 Home/End/PgUp/PgDn。
12. 粘贴：手机里复制一段字，点「粘贴」，远端收到，面板草稿不变。
13. 远端是 Safari 这类普通 App 时，面板收着没有按键区；打开面板才有。

实现时追加的检查：

14. 打开面板时，键盘还没开始升，面板先自己从按键区后面淡入上升，同时被键盘托起，两者在 0.34 秒会合。看着顺不顺。
15. 收起时如果键盘下落超过 0.34 秒，面板会不会在半空就淡没了。
16. 在终端类 App（如 Mac 终端）里开合面板：画面只让出按键区高度，不跟着上下跳；在 Safari 里打开面板，按键区盖住画面最下面一截，看会不会挡视线。
17. 软键盘上打字被 ⌃ 截住后，系统输入法的待选字被清空，不残留。内置 Rime（实体键盘）在拼音输入中按了按键区 ⌃ 再打字母，不会被截。
18. 方向键点按的延迟（为了支持上滑，在手指抬起时才发）能不能接受。
19. 在编辑框文字上开始往下拉：选字还正常；长按文字后往下拉会收起，这样是否合意。终端面板上从按钮处往下拉也会收起，是否合意。
20. 下拉终端面板的过程中刚好来了发送回执或状态更新，面板不会被弹回。
21. ⌘ 锁住时切换会话，新会话不会收到 ⌘。
22. 有 AI 整理卡片时开合面板，卡片会跳一下（已知，暂不改）。
