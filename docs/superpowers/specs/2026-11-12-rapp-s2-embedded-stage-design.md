## 1. 目标与非目标

目标：
- 打开一个 app，画面直接出现在舞台上，在舞台里点、拖、滚、打字，和今天在独立窗口里一样。
- 用户想要时，把当前会话"分离"成独立窗口（今天的样子）；也能"放回"舞台。
- 串流菜单和输入区搬进主窗口，行为沿用 `rapp-client`。

非目标（不在 S2）：
- 断开后保留条目、重连、斜条纹最后一帧、需要你（S3）。
- 全景、缩略图（S4）。
- 跨会话的全局剪贴板（S6）。S2 里剪贴板历史仍然每个会话一份。
- 平板（S7）。
- Windows、Linux 上的嵌入。S2 只做 macOS；另外两个平台继续用独立窗口，舞台显示 S1 的占位。

## 2. 用户看到的行为

### 2.1 打开即嵌入

- 在设备面板或会话列表里打开一个 app：舞台先显示"正在连接"，连上后显示画面。面板自动收起（主界面规格 §5 第 3 条）。
- 切到另一个会话：舞台换成那个会话的画面。没选中的会话继续连着，但不在舞台上。
- 没在舞台上的嵌入会话把帧率降到 1 fps，切回来时恢复原来的帧率。这样十个会话同时开着也不费流量。

### 2.2 舞台里的画面

- 画面按比例缩放放进舞台，不拉伸；多余的地方用主题底色。
- 舞台大小变了（改主窗口大小、进出全屏）：停 0.3 秒后，把 A 上当前窗口的尺寸改成舞台的尺寸，沿用今天 `rapp-client` 的规则（`WindowCoordinator.sendResize`）。A 拒绝改尺寸时（有最小、最大尺寸）就按比例缩放。
- 浮层（左侧面板、串流菜单、输入区）开合时不改 A 的尺寸（R1）。
- 只有当前窗口跟着舞台改尺寸。其他窗口（见 2.3）切到时才改。
- A 上的菜单、弹出框、sheet 这些附属窗口画在它所属窗口的上面，位置按 A 上的相对位置换算，不单独成为标签。

### 2.3 多窗口标签

- 当前 app 在 A 上有两个以上普通窗口时，顶栏出现窗口标签（主界面规格 §3.1），一个窗口一个，写窗口标题，太长省略。
- 点标签：舞台换成那个窗口，同时让 A 把那个窗口提到最前（沿用今天的 raise）。
- A 上新开的窗口自动成为当前标签；A 上关掉当前窗口时，换到最近用过的另一个。

### 2.4 指针和键盘

- 指针：点、拖、滚、右键都在画面坐标里换算后发给 A，和今天一样（落点前的最上层窗口检查在 A 端，已实现）。
- 键盘焦点只有一个归属，点画面后键盘给 A，点画面外（顶栏、浮层）后键盘给 rapp。焦点在画面上时，画面四周一圈 1px `--on` 色的边。
- 焦点在画面上时，**按住 ⌃⌘ 的组合键归 rapp，其余全部发给 A**，包括 Esc、⌘W、⌘[：
  - ⌃⌘F 全屏；⌃⌘[ 和 ⌃⌘] 上一个、下一个会话；⌃⌘D 分离或放回（2.7）。
  - ⌘Q 仍然退出 rapp（macOS 标准，今天的 `rapp-client` 也是这样）。
  - 这会改掉 S1 的 ⌘[ ⌘]（Safari 等 app 在 A 上要用它们后退前进）。
- 本机输入法：直接在画面上打字时不经过输入法，按键原样发给 A；要用中文输入法，用输入区（2.5）。这和今天一致。
- 滚动：触控板的双指滚动和鼠标滚轮都要发给 A，方向和今天的独立窗口一致（S0：Flutter 收到的滚动方向和 AppKit 相反，触控板走另一类事件，见 §3）。

### 2.5 输入区

按主界面规格 §3.5，搬自 `rapp-client` 的 `ComposerBar` / `Composer`：

- 平时是舞台右下角一个「输入」按钮；点开后从底部浮出一条，盖在画面上，不改 A 的尺寸（主界面规格 §8 第 5 条的默认）。
- `[按键] [附件] [多行输入框 + 块] [复制] [发送] [收起]`。
- 输入框有焦点时，键盘给输入框，按键不发给 A；⌃⌘ 组合仍归 rapp。
- 附件、贴大块文字、复制、发送、剪贴板历史的行为和限制都不变（`2026-11-11-rapp-clipboard-composer-design.md`）。

### 2.6 串流菜单

按主界面规格 §3.4，顶栏右端的流量标签点一下打开，右键也打开。第 6 组"会话"在 S2 里是：路径、「分离成独立窗口」或「放回主窗口」、「结束会话」（点两次）。"断开"等 S3。

### 2.7 分离和放回（detach / attach）

- **分离**：串流菜单「分离成独立窗口」或 ⌃⌘D。当前会话的画面离开舞台，变成一个独立窗口，放在主窗口旁边。独立窗口里只有画面：点、拖、滚、打字照常发给 A，⌃⌘D 放回。流量标签、串流菜单、输入区留在主窗口里，舞台换成占位：「<app> 在单独的窗口里 · <设备> · <路径>」、「切到窗口」、「放回主窗口」、「结束会话」，占位上仍有「输入」按钮，顶栏流量标签仍对这个会话有效。见 §6 第 8 条。
- **放回**：占位上的「放回主窗口」、主窗口串流菜单里的「放回主窗口」、或在任一窗口按 ⌃⌘D。画面回到舞台，独立窗口消失。
- 分离和放回都**不断开连接**，不重新协商，画面不黑。目标：从点下到画面出现在新位置 ≤ 200ms。
- 分离以会话为单位：一个 app 的所有窗口一起出去，在外面各自成窗（今天的多窗口行为）。
- **关掉独立窗口 = 结束会话**，和今天一样（之前用户定的"关闭按钮断开会话"）。想回到舞台用「放回」。见 §6 第 2 条。
- 分离状态记在会话上，不记到下次启动。新开的会话总是嵌入。

### 2.8 连接中和结束

- 连接中：舞台居中旋转的连接中灯和"正在连接"（S1 已有）。
- 会话结束（用户点了结束、A 端关了 app、网络断了）：S2 里条目直接消失，舞台换回"没有选中的会话"，提示栏写结束原因，例如「Safari 已结束：A 端关闭了 app」。最后一帧加斜条纹和「重连」等 S3。

## 3. 怎么把画面送进 GUI（S0 结论）

**选定：纹理（B）+ 把连接和解码链进 GUI（i）。**

- 显示：runner 里注册 `FlutterTexture`，背后是 IOSurface 的 CVPixelBuffer 池；Flutter 用 `Texture` 显示，指针用 `Listener` 收，键盘用 `Focus`。
- 帧从哪来：`rapp-client` 的连接和解码代码做成 Swift 库，链进 GUI 的 runner，在 GUI 进程里直接解码到 CVPixelBuffer。macOS 上 GUI 不再为嵌入会话拉起 `rapp-client` 进程。
- 分离：runner 开一个原生 NSWindow，里面的 NSView 直接显示同一组 IOSurface，事件走 AppKit。

S0 量到的（Flutter 3.44.1 release、arm64、1194×778、30 fps，显示器 30 Hz；单次 15 秒，误差约 ±2 点）：

| | A 原生视图（今天的做法，每帧 CGImage） | A′ 原生视图，IOSurface 做内容 | B 纹理 |
|---|---|---|---|
| 浮层盖在画面上、帧在更新 | 可以 | 可以 | 可以 |
| 圆角裁剪、半透明、旋转 | 可以，但画面会漏到标题栏后面一点 | 同 A | 干净 |
| 显示的 CPU（30 fps） | 约 19 点 | 约 1.5 点 | 约 5–7 点 |
| 1 fps | 1.8% | 没量 | 0.5% |
| 帧到屏幕 | 下一次刷新 | 同 A | 比 A 晚 0.5–1 次刷新（30 Hz 屏上平均 19 ms） |
| 点击、滚动坐标 | 准 | 准 | 准；滚动方向相反 |
| 键盘、输入法 | 画面可以拿焦点，有 macOS keyCode | 同 A | 焦点在 Flutter 上，没有 macOS keyCode，输入法只能走输入框 |
| 分离 / 放回 | 约 9 ms / 70 ms，要绕开引擎回收视图的问题 | 同 A | 8.6 ms / 下一帧 |

为什么选 B：
- 画面就是普通 widget，浮层、裁剪、命中测试都和别的 widget 一样，正合 R1。原生视图在 Flutter 里位置一变就重建、带变换时会漏出界、引擎释放时会把视图拿走（S0 都碰到了）。
- 分离简单：同一组 IOSurface 交给一个 NSView 就行。
- 窗口标签、S4 的缩略图都只是多几个 `Texture`；舞台和输入的 Dart 代码以后能带到平板（S7）和 Linux、Windows。
- 代价：比原生视图晚 0.5–1 次刷新；比 A′ 多约 5 点 CPU。

为什么选 (i)：
- `RappCore` 已经是库，`Connection.swift` 原样能搬；要从 `main.swift` 搬约 60 行。
- (ii) 要跨进程传 IOSurface，而 `rapp-client` 是 Rust hub 的子进程，没有现成的 XPC 通道：只能用 launchd mach 服务、已废弃的全局 IOSurface ID，或者每帧多拷一次的共享内存；输入还要再开一条通道。界面反正都要用 Flutter 重写，(ii) 多了管道，没省下什么。
- 代价：失去进程隔离，解码里的 `precondition`/`fatalError` 会带倒 GUI。S2 要把解码路径上的这些改成返回错误、结束这一个会话（§6 第 7 条）。

不管选哪种都要做的：**直接解码进 IOSurface 像素缓冲池**，不再每帧做 CGImage。S0 量到单这一项省约 17 点 CPU，今天的独立 `rapp-client` 也受益。

后备：S2 里如果觉得延迟明显，换 A′（复用 `RemoteView`，用一个容器视图绕开引擎回收）。所以帧的产生和显示分开写，可以互换。

S0 没量的：WindowServer 和 GPU 的开销；真实的帧到屏延迟（要摄像机）；真实的输入法、触控板和键盘；重复测量。

## 4. 接口改动

- `Package.swift` 加一个库 target（暂名 `RappSession`）：连接、解码到像素缓冲池、窗口表、焦点和尺寸逻辑（从 `WindowCoordinator` 拆出的非界面部分），加上 `SideConnection`、`Transfers`、`ClipHistory`、`LocalPasteboard`、`Sender`。`rapp-client` 改为依赖这个库，Windows、Linux 和分离以外的老路径不变。
- GUI runner 链这个库；`MACOSX_DEPLOYMENT_TARGET` 从 12.0 提到 14（和 package 一致）。
- runner 和 Dart 之间一个 method channel + 每个会话一个纹理 id：
  - runner → Dart：`frame`（只通知纹理有新帧）、`windows`（窗口表：id、标题、尺寸、是否附属窗口）、`traffic`、`clipboard`、`closed`（原因）。
  - Dart → runner：`pointer`、`scroll`、`key`、`resize`（舞台尺寸）、`select_window`、`detach`、`attach`、`set_stream`（档位、密度、帧率）、输入区相关命令、`close`。
- hub：`open` 加一个"嵌入"选项，不拉起 `rapp-client`，而是像今天一样开好到 A 的流和本机 `127.0.0.1:0` 监听，把 `{port, token}` 回给 GUI；这条 TCP 断开就算会话结束，`closed` 事件照发。非嵌入（Windows、Linux）照旧拉起 `rapp-client`。
- 键盘：Flutter 按键到 macOS keyCode 要一张映射表；或者 runner 里用 `addLocalMonitorForEvents`（今天 `rapp-client` 的做法）在画面有焦点时直接取 NSEvent。计划阶段二选一，倾向后者（keyCode 原样，不用维护表）。
- 滚动：Dart 侧把方向翻过来；触控板的 `PointerPanZoom*` 事件也换成滚动发给 A；悬停用 `onPointerHover`。
- `MirroredMenu`（把 A 的菜单栏镜像到 B）今天占的是 `rapp-client` 自己的菜单栏。嵌入后放进串流菜单的一组，不占 GUI 的菜单栏（§6 第 9 条）。
- 日志沿用可观测性规格：不记按键、粘贴、剪贴板内容。嵌入会话的连接事件由 hub 记（它仍然开流、仍然看到结束）；分离、放回各记一行。

## 5. 拆分建议（写计划时细化）

0. 库 target + 直接解码进 IOSurface 像素缓冲池；`rapp-client` 改用它（单独可测，独立窗口先省 CPU）。
1. 画面：一个会话嵌入显示 + 舞台尺寸驱动 A 尺寸；hub 的"嵌入"选项。
2. 指针和键盘：焦点规则、⌃⌘ 保留键、S1 快捷键改成 ⌃⌘、滚动方向和触控板。
3. 多窗口标签和附属窗口。
4. 串流菜单搬进顶栏（含镜像菜单）。
5. 输入区搬进舞台。
6. 分离和放回。
7. 未在舞台上的会话降到 1 fps。

## 6. 我做的假设（请确认或改）

1. **"面板"= 舞台。** U1 的"嵌入到面板内"理解为嵌进主窗口的舞台，而不是左侧面板。
2. **关掉独立窗口 = 结束会话**（沿用已定的关闭按钮规则）。另一种是"关掉 = 放回舞台"，像画中画那样；那样结束会话只能从菜单或占位上点。
3. **焦点在画面上时只有 ⌃⌘ 组合归 rapp**，S1 的 ⌘[ ⌘] 改成 ⌃⌘[ ⌃⌘]。
4. **不在舞台上的会话降到 1 fps**。另一种是保持原帧率（切回来更快，但费流量）。
5. **Windows、Linux 不嵌入**，继续用独立窗口。
6. **附属窗口（菜单、弹框、sheet）不成标签**，画在主窗口上面。
7. **选 B + (i)**（§3）：接受比原生视图晚 0.5–1 次刷新，接受 GUI 和会话同一个进程（一个会话的解码出错要改成只结束这个会话，不带倒 GUI）。S0 前我倾向 (ii)，数据推翻了它。
8. **分离出去的窗口只有画面**，流量标签、串流菜单、输入区留在主窗口。另一种是在独立窗口里再做一套原生的（今天的样子），那等于两套界面。
9. **A 的镜像菜单放进串流菜单**，不占 GUI 自己的菜单栏。

## 7. 验收

- 打开一个 app，画面出现在舞台上，没有出现独立窗口。
- 在画面里点、拖、滚、右键、打字，A 上的 app 收到；Esc、⌘W 发到 A；⌃⌘F 进出全屏。
- 开合左侧面板、串流菜单、输入区，A 上窗口尺寸不变（看 A 端日志里没有 resize）。
- 改主窗口大小，停下后 A 上窗口改成舞台尺寸，一次。
- 两个以上窗口时出现标签，点标签切窗口。
- 分离：独立窗口出现、舞台变占位、画面不黑；放回：画面回舞台、独立窗口消失；两次都不重连（A 端日志里没有新会话）。
- 关掉独立窗口，会话结束。
- 不在舞台上的会话流量降到 1 fps 的水平。
- 30 fps 时 GUI 进程的 CPU 不高于今天独立 `rapp-client` 的水平（S0 参考：显示约 5–7 点）。
- 让一个会话的解码出错（测试里喂坏数据）：只有这个会话结束，提示原因，GUI 不退出。
- 测试只用自己起的 host、client 和自己拉起的 app，按 PID 操作。
