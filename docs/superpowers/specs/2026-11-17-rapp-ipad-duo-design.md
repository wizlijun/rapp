## 1. 为什么做，做成什么

rapp 的定位是"更多 Agent，一个 Pad"。现在控制端只有 macOS 和 Omarchy；真正随身带的那块 Pad（iPad）还不能用。

做成之后：

- **iPad 上是完整的主控台。** 和桌面同一个主界面：顶栏、舞台、全景、左侧面板、输入板、终端。接键盘和触控板时和桌面一样用；只用手指也能完成全部操作。
- **Duo 展开是一块小平板，合上是巡检器。** 展开时和 iPad 同一套界面。合上时（以及普通 iPhone 上）只做三件事：看谁需要我、进去看一眼、回一句话。
- **一份代码，按窗口大小排版。** 不按机型分支。iPad 分屏、窗口缩放、Duo 开合，都只是窗口大小变了。

## 2. 目标、不做、不能出现

**目标**

1. iPad（iPadOS 17 及以上）上能接入、列出设备和 app、打开 app 和终端会话、在嵌入舞台里操作、用输入板打字发送、切换会话、看全景。
2. 触控、触控板或鼠标、外接键盘、Apple Pencil 都能操作远程画面。
3. Duo 内屏铺满显示；开合不换会话、不丢草稿；外屏和普通 iPhone 上用紧凑布局。
4. 切到别的 App 再回来，画面自己恢复，不用手动重连（§9）。
5. 弱网下行为和桌面一致：冻结画面、输入板照常能写（断网冻结规格）。
6. 能通过 TestFlight 装到自己的设备上；最后能上 App Store。

**不做**

- iPad / iPhone 当被控端。没有 `rapp-service`，没有"本机"的密码、权限、服务这几块。
- 后台保活、推送通知、锁屏小组件、实时活动。切到后台就断，回来再连（原因见 §9.4）。
- git 同步（数据目录规格 PD13 的待定项）。iPad 上的数据只在本机，见 §6.5。
- 单独窗口（detach）、多窗口（多个 scene）。第一版只有一个窗口。
- 在线更新。更新走 TestFlight 和 App Store。
- Android。但本文的分层要让 Android 以后能接上（§5.2）。
- Duo 半折姿态和它要的原生桥（折痕、铰链、姿态），见 §7.6。
- 改线路协议、改 relay、改 A 端（§9.3 的锁屏宽限已定为不加，Q1）。

**不能出现**（技术上能跑，但出现了就算失败）

- 为 iPad 另写一套界面，或者在 Dart 里出现按机型（"是不是 Duo""是不是 iPad"）分支的排版代码。
- 软键盘弹出、浮层开合让舞台改尺寸，进而让 A 上的窗口跟着改（主界面规格 §5 第 1 条在 iPad 上照样成立）。
- Duo 开合、iPad 拖动分屏分隔条的过程中，A 上的窗口被连续改尺寸。
- 回到前台后，往已经断开的会话里发输入或尺寸（断网冻结规格的"不能出现"照样成立）。
- key、设备私钥、记住的 Mac 密码出现在"文件"App 看得到的目录里，或者进了 iCloud 备份。
- 桌面三个平台的行为因为这次改动而变化。

## 3. 平台事实

下面这些事实决定了方案。标"实测"的是第三方资料或我的记忆，P0 探查时要在真机或模拟器上核对。

| # | 事实 | 对 rapp 的影响 |
|---|---|---|
| F1 | iOS 上的 App 不能启动子进程 | hub 不能再是子进程；Linux 那种"每个会话一个 `rapp-session` 进程"的做法也不能用（§5） |
| F2 | App 进后台后几秒到几十秒内被挂起，线程全停，网络连接随后失效；没有给这类 App 的常驻后台权限 | §9 |
| F3 | Duo 外屏 5.4 寸、内屏 7.6 寸，两块屏比例相同 [S3] | 外屏就是一块偏小的 iPhone 屏 |
| F4 | 外屏竖持是紧凑宽度；内屏横竖两个方向都是常规 [S1] | 内屏按平板排版，外屏按手机排版 |
| F5 | 内屏不遵守 App 声明的支持方向，Apple 要求按尺寸排版 [S2] | 不能靠锁横屏保证舞台形状 |
| F6 | Duo 上可以两个 App 并排 [S3]；iPad 上窗口可以任意缩放、分屏 | 窗口宽度随时会变，会跨过紧凑和常规的分界 |
| F7 | 用 iOS 27.1 SDK 构建才能铺满内屏；更旧的 SDK 构建出来只是内屏里一块手机大小的画面 [S1] | 构建机要 Xcode 27.1 |
| F8 | 铰链角度、姿态、折痕区域的接口在 iOS 27.1 SDK 里 [S1][S5] | 只有半折姿态用得上，本期不做（§7.6） |
| F9 | Flutter 3.41 及以上配 Xcode 27.1 构建能铺满内屏，窗口大小和安全区随开合上报；但折痕和铰链在 iOS 上 Flutter 不上报（`MediaQuery.displayFeatures` 是空的），要自己写一小段原生桥 [S4][S5]（P0 在 iPad 模拟器和 iPhone 真机上核对过 `displayFeatures` 为空；开合没量到，等 Duo 真机） | 排版只靠窗口大小就够；不写原生桥 |
| F10 | 用 iOS 27 SDK 构建的 Flutter App 必须用 UIScene 生命周期，否则起不来 [S6]（实测） | 新建 iOS 工程时就按 UIScene 建 |
| F11 | 程序去读系统剪贴板，系统会弹"允许粘贴"；用户在文本框里自己粘贴不弹 | §8.6 |
| F12 | 连局域网地址要用户同意"本地网络"权限 | §10 |
| F13 | App Store 没有办法把 iPhone App 限定到某一款机型（据我所知） | 兼容 Duo = 发布一个 iPhone App，所有 iPhone 都能装，所以紧凑布局必须完整可用 |
| F14 | 一部分键盘快捷键系统自己留着，App 收不到（⌘Tab、⌘空格、⌘H、地球键组合等） | §8.3 |
| F15 | 国行 iPhone / iPad 上，App 在用户回答"无线数据"弹框之前没有网络；只有系统网络（`URLSession`、Network 框架）会让这个框弹出来，Rust 自己的 UDP 套接字不会，只会一直超时（P0 实测） | §10：hub 拨号前先发一个系统请求 |
| F16 | iOS 上 Dart 的 `Platform.environment` 里没有 `HOME`（P0 实测） | 数据根由原生传进来（§6.5） |

## 4. 现状（代码里和本文有关的）

- `gui/`：Flutter，只有 `macos`、`linux`、`windows` 三个目标。`lib/` 约三万行，界面状态集中在 `ui/main_state.dart`。
- **hub**：`gui/lib/hub_client.dart` 的 `ProcessHubTransport` 把 `rapp-hub` 当子进程拉起，stdin/stdout 上走 JSON 行。传输已经抽象成 `HubTransport`（测试里用假的）。Rust 侧 `rapp_hub::run(opts, input, output)` 对输入输出是泛型的，`main.rs` 只是把 stdin/stdout 交给它。
- **嵌入会话的接法**：`open` 带 `embed` 时，hub 在 `127.0.0.1:0` 上开一个端口，把端口和令牌放进 `opened` 事件；界面这边连上去、第一行送令牌。终端会话走同一条路（`gui/lib/term/term_link.dart`）。
- **画面层有两套**：
  - macOS：`gui/macos/Runner/SessionPlugin.swift`（505 行）用 Swift 包 `RappSession`（3003 行）解码，直接写进 IOSurface 像素缓冲池，注册成 `FlutterTexture`；Dart 侧是 `ChannelSessionPort`（`rapp/session` 通道）。
  - Linux：`LinuxSessionPort` 每个会话拉起一个 `rapp-session` 进程（`rust/client-core`），Dart 用 `ui.Image` 画。
- **Swift 包**：`RappCore`（5214 行）只依赖 Foundation、CoreGraphics、zlib。`RappSession` 有 6 个文件用了 AppKit：`Detach`、`KeyRouting`、`LocalPasteboard`、`PopupPanel`、`RemoteView`、`Sender`（共 733 行）。`Package.swift` 只声明了 `.macOS(.v14)`。
- **输入板**：macOS 用原生 `NSTextView`（`ComposerPlugin.swift`、`ComposerNative.m`，Dart 侧 `native_editor.dart`）；别的平台用 `flutter_editor.dart`。
- **接入设置**：接入点和 key 存在 `<home>/service.json`，由 `rapp-service` 写，hub 只读（`rust/conn/src/settings.rs`）。设备私钥由 hub 自己建（`Identity::load_or_create(home, "device")`）。
- **只有桌面才有的依赖**：`tray_manager`、`window_manager`；`service_client.dart`（连 `127.0.0.1:22029` 的 `rapp-service`）；`gui/lib` 里 16 处 `Platform.is…` 判断（`main.dart` 里 3 处）有一部分是为了拉起子进程、打开文件夹。`gui/lib/paths.dart` 等处读环境变量 `HOME`，iOS 上没有（F16）。
- **hub 依赖 `rapp-term`**，后者带 `portable-pty` 和 `alacritty_terminal`。
- **触摸**：`gui/lib/embed/picture.dart` 已经按触摸滚动规格实现了单指点按、拖动和双指滚动；真机检查还没做（那份规格写着"需要触摸屏 B"）。
- **自动锁屏**：A 上最后一个看得到屏幕的会话结束 10 秒后锁屏；B 端记住的 Mac 密码存在 Keychain（`UnlockStore`）。

## 5. 办法

### 5.1 三条路

| | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A（选用）** | 现有 Flutter 界面加 iOS 目标；Rust 的 hub 编成静态库在进程内跑；苹果平台共用 Swift 的 `RappSession` 和纹理通道 | 界面三万行原样带过去；画面走的是 macOS 上量过、最省 CPU 的那条路（直接解码进像素缓冲池）；macOS 和 iOS 共用一份原生代码 | 要把 `RappSession` 里的 AppKit 部分拆出平台层；hub 要多一个库入口 |
| B | 走 Linux 那条路：Rust `client-core` 解码，Dart 用 `ui.Image` 画 | 以后 Android 能直接用 | iPad 上每帧多一次拷贝和上传，更费电；`rapp-session` 是进程，要先改成库；苹果平台从此有两套画面代码 |
| C | 用 SwiftUI 重写 iPad 界面 | 最"原生" | 丢掉全部 Dart 界面和设计语言的实现；和 I2 相反；以后每个功能做两遍 |

选 A。B 留给 Android：到那时把 `client-core` 做成库，接在同一个 `SessionPort` 接口后面。A 和 B 在 Dart 这一层是同一个接口，所以现在选 A 不挡 Android 的路。

### 5.2 分层

```
┌──────────────────────────── Flutter（Dart，各平台同一份）────────────────────────────┐
│ 界面：顶栏 / 舞台 / 全景 / 面板 / 输入板 / 终端      排版：按窗口大小分档（§7）        │
│ MainState ── HubClient ── HubTransport        SessionPort        ComposerEditor     │
└────────────────┬───────────────────────────────┬────────────────────┬───────────────┘
        桌面：子进程 │ iOS：进程内（FFI）   macOS/iOS：rapp/session 通道 │       macOS：NSTextView
                 │                               │                    │       iOS：先 Flutter，后 UITextView
┌────────────────▼──────────────┐   ┌────────────▼─────────────────┐  │
│ rapp-hub（Rust）               │   │ SessionPlugin（Swift，共用）   │  │
│ 选路、relay、端到端加密、设备表  │   │ RappSession：连接、解码、纹理   │  │
│ 嵌入会话：127.0.0.1 上的端口 ───┼──▶│ RappCore：协议、编解码、几何    │  │
└────────────────────────────────┘   └──────────────────────────────┘  │
                                      平台层：AppKit（macOS）/ UIKit（iOS）：按键、剪贴板、文件
```

原则：**iOS 上不新增协议，不新增界面，只换"底下那一层怎么接"。** hub 的 JSON 行协议、`rapp/session` 通道的方法和事件、嵌入会话的本地端口加令牌，全部原样。

## 6. 架构细节

### 6.1 hub 在进程内运行

- 新 crate `rust/hub-ffi`（`staticlib`，目标 `aarch64-apple-ios`、`aarch64-apple-ios-sim`），导出四个 C 函数（P0 定的，见 `probe/ipad-p0` 的 `rust/hub-ffi/include/rapp_hub.h`）：

  ```c
  // 起一个 tokio 运行时，在它上面跑 rapp_hub::run。on_line 在 hub 的线程上被调用，每次一行（不带换行）。
  // 这一行归接收方：可以在回调返回后再读，读完用 rapp_hub_free_line 释放。
  int32_t rapp_hub_start(const char *home, const char *log_dir, void (*on_line)(const char *line));
  void    rapp_hub_free_line(char *line);
  // 送一行命令给 hub。可以在任何线程调用。
  int32_t rapp_hub_send(const char *line);
  // 等同于关 stdin：hub 关掉全部会话后结束。
  void rapp_hub_stop(void);
  ```

  第四个函数是 P0 加的：`NativeCallable.listener` 在回调返回之后才在 Dart 里读那一行，借用的指针那时已经释放了（模拟器上 MTE 检查直接崩）。
- **链接**（P0 实测，Release 才暴露）：Swift 里没人调这几个函数，死代码剥离会去掉它们，要用 `-Wl,-u,_rapp_hub_start` 等把四个都列成链接根；Release 默认剥掉全局符号，要 `STRIP_STYLE = non-global`，否则 Dart 的 `dlsym` 找不到。另外链接 `-lc++`、`Security`、`SystemConfiguration`。

- 库里用一对内存管道接 `rapp_hub::run(opts, input, output)`，hub 本身的代码不改。
- Dart 侧新增 `FfiHubTransport implements HubTransport`：用 `dart:ffi` 直接调上面三个函数，回调用 `NativeCallable.listener`（可以从别的线程回到 Dart）。不经过 Swift。
- `Opts`：`home` 是 §6.5 的本机目录；`bin_dir` 为空；`presence_every` 同桌面。
- iOS 上不带 `embed` 的 `open`（要拉起 `rapp-client`）直接回错误；界面本来就只发带 `embed` 的。
- **编译**：hub 连同 `rapp-term`、`portable-pty` 在两个 iOS 目标上原样编过（P0），不需要分 feature。
- **子进程**：编得过不等于能用。hub 里起子进程的地方在 iOS 上都会失败：`rapp_net::config::hostname()` 调 `hostname` 命令，失败退回 `"rapp"`（所以 A 上这台设备叫"rapp"，见 §6.2）；不带 `embed` 的 `open`（见上）。
- 嵌入会话仍然是 hub 在 `127.0.0.1` 上开端口、`RappSession` 用 `NWConnection` 连过去。同一个进程里走回环是允许的，不需要"本地网络"权限。

### 6.2 接入设置和身份

iPad 上没有 `rapp-service`，所以 `service.json` 没人写。做法（我定的）：

- hub 加两条命令：`access`（读：接入点、有没有 key、设备名）和 `set_access {relay, key}`（写 `service.json` 的 `relay` 和 `key` 两个字段，写法和 service 一致）。只在 iOS 的构建里打开；桌面上这个文件仍然只归 service 写。
- 界面上"本机"那一页在 iPad 上换成精简版：接入点、key（默认遮住）、这台设备的名字、数据占用、版本。没有密码、权限、服务、更新、自动锁屏这几块。
- 第一次启动没有 key 时，全景的位置显示接入引导：两个输入框（接入点、key）加一个"接入"按钮；key 支持粘贴和扫码（扫码放 P3）。
- **P0 核对过**：只往外拨不用登记。hub 从不调 relay 的 `register`，拨号走 `dial → relay_to_at → enroll`，真机上 `add_host` 经 relay 710 ms 成功。A 上这台设备显示成"rapp"（`hostname()` 起不了子进程时的默认值），路径 relay。所以 hub 要一个由入口传进来的设备名（`Opts` 加一个字段，或 `set_access` 带上）；iOS 16 起 `UIDevice.name` 默认只给"iPad"、"iPhone"，要么用户在"本机"页里改，要么申请读真实名字的授权。

### 6.3 画面层：共用 Swift

- `Package.swift`：`platforms` 加 `.iOS(.v17)`；`RappCore`、`RappSession` 两个库在 iOS 上也产出。`rapp-host`、`rapp-client`、`rapp-testpage` 仍然只在 macOS。
- `RappCore` 改得很少（P0）：`DataPaths` 取家目录分平台（iOS 用 `NSHomeDirectory()`），`Windows.swift` 的 `classifyWindow` 和它的两个测试只在 macOS 编。单元测试在 iOS 模拟器上 476 个通过、1 个跳过。`xcodebuild test -scheme RappCore` 没有测试动作，`rapp-Package` 又带进 macOS 专有的可执行目标，P1 要提交一个能在 iOS 模拟器上跑测试的 scheme 或测试计划。
- `RappSession` 的 6 个 AppKit 文件这样处理：

  | 文件 | iOS 上 |
  |---|---|
  | `Detach`、`RemoteView`、`PopupPanel` | 不编（`#if canImport(AppKit)`）。iPad 第一版没有单独窗口 |
  | `KeyRouting`、`Sender` | 把"平台按键事件 → 线路上的按键消息"这一步拆成协议；AppKit 一份实现，UIKit 一份实现（§8.3） |
  | `LocalPasteboard` | 同上，UIKit 用 `UIPasteboard`（§8.6） |

- `WindowSurfaces`（像素缓冲池）用的是 CoreVideo，iOS 上照用；缓冲要带 Metal 兼容属性，Flutter 的 iOS 引擎才能直接当纹理。P0 核对。
- `SessionPlugin.swift` 改成 macOS、iOS 两个 Runner 共用的一份：`import FlutterMacOS` 和 `import Flutter` 用条件编译分开；单独窗口、按键监视器、`NSView` 相关的部分留在 macOS 专有的扩展里。通道名、方法、事件一个不改，Dart 侧的 `ChannelSessionPort` 不用动。
- `UnlockPlugin`（记住的 Mac 密码）在 iOS 上照搬：底下的 `UnlockStore` 用的是 Security 框架，iOS 有。`SecureInputPlugin` 是给 macOS 输入法用的，iOS 上密码框用系统的安全输入，不需要它。

### 6.4 Dart 侧要动的

- 加 `gui/ios/`（Flutter 的 iOS 工程，UIScene 生命周期，F10）。
- `main.dart` 按"这个平台有什么能力"分开，不在界面代码里到处判断平台。加一个小的能力表（我定的），由入口填好交给 `MainState`：

  | 能力 | macOS | Linux | iOS |
  |---|---|---|---|
  | hub 传输 | 子进程 | 子进程 | 进程内 |
  | 会话端口 | 通道 | `rapp-session` | 通道 |
  | 本机服务（`rapp-service`） | 有 | 有（只控制端） | 无 |
  | 托盘、窗口管理 | 有 | 有 | 无 |
  | 单独窗口 | 有 | 无 | 无 |
  | 在线更新 | 有 | 有 | 无 |
  | 打开文件夹、打开链接 | `open` | `xdg-open` | 系统接口（§8.7） |
  | 记住 Mac 密码 | Keychain | 只在内存 | Keychain |

- `tray_manager`、`window_manager` 是桌面插件。iOS 的入口不引用它们；如果它们让 iOS 构建失败，把桌面外壳（`_Shell`、托盘菜单、全屏）移到单独的文件里，用条件导入。
- `service_client.dart`、`service_control.dart`、`linux_*.dart` 在 iOS 上不被引用。
- 排版分档（§7）是给所有平台的：桌面窗口拖窄了也走同一套规则。这样紧凑布局在 Mac 上就能开发和跑 widget 测试，不用每次上真机。

### 6.5 数据放在哪

| 内容 | 位置 | "文件"App 可见 | 备份 |
|---|---|---|---|
| `service.json`（接入点、key）、设备私钥、设备表、日志 | `Library/Application Support/rapp/` | 否 | 排除在备份之外；文件保护等级为"首次解锁后可读" |
| 记住的 Mac 密码 | Keychain，仅本设备 | 否 | 不随备份迁移 |
| 界面偏好、app 配置、项目和常用 | 同第一行的目录下，沿用数据目录规格的子目录 | 否 | 可备份 |
| 输入历史 | 同上 | 否 | 可备份 |
| 传过来的文件 | `Documents/传输/` | 是 | 可备份 |

- `RAPP_HOME` 这一套环境变量在 iOS 上不存在；数据根由入口算好传给 hub 和 `DataDir`。没有"搬数据目录"的功能。
- **git**：iPad 上不做。输入历史"已发送记录要 git 同步"在 iPad 上暂时只存本机。这延续数据目录规格 PD13 那条待定（"平板上没有 git 怎么办"），不在本文里解决。

### 6.6 不带到 iPad 的

`rapp-service` 及其全部界面、`--cm` 连接管理、托盘、单独窗口、在线更新、Linux 防火墙和输入法候选、Fcitx5 / Sumi 的桌面集成、`rapp-cli`。

## 7. 排版：按窗口大小分档

### 7.1 分档

只看 rapp 自己这个窗口的大小（逻辑点），不看机型、不看方向。

| 档 | 条件 | 出现在 | 界面 |
|---|---|---|---|
| **常规** | 宽 ≥ 600 | iPad 全屏和较宽的分屏、Duo 展开、iPhone 横持、桌面 | 现有主界面（§7.2） |
| **紧凑** | 宽 < 600 | Duo 合上、iPhone 竖持、iPad 窄分屏、Duo 上并排两个 App | 列表 → 舞台（§7.3） |

另有一个修饰：**矮窗**（高 < 480，比如 iPhone 横持）。排版仍按宽度走常规档，但窗口模式下顶栏自动收起，变成舞台左上角一个带状态灯的小按钮，点一下顶栏滑出、3 秒不动收回。原因：56 的顶栏在 390 高的窗口里占掉七分之一。

600 是一个常量。P0 量出 Duo 内屏竖持的宽度后，如果它落在 600 以下，就把常量调到让内屏两个方向都是常规档（和 F4 一致）。

### 7.2 常规档

结构不改，就是主界面规格 §3。只补窗口比基准（1194×834）小的时候怎么办：

- **顶栏放不下时按这个顺序让位**：提示区先缩成一个图标（点开看提示历史）→「本机」收进菜单 → 网络标记并进流量标签 → 窗口标签变成一个下拉。**永远留着**：会话切换、需要你、流量标签。任何时候控件不小于 48。
- **左侧面板**：四个标签一样宽，都是窗口宽的一半（2026-11-17 起，见主界面规格 §3.7），但不窄于四个标签加收起按钮排一行的宽度。
- **全景**：设备墙一行放不下就换行，整页上下滚动。
- **安全区**：顶栏避开状态栏、灵动岛和内屏的摄像头区域（用 Flutter 报的四边内边距，Duo 内屏上四边可以不一样）。远程画面只画在安全区里，安全区外是主题底色。
- **屏幕边缘手势**：舞台上有活动会话时，四条边都让系统手势"第一下只出横条、第二下才生效"，底部横条自动隐藏。否则在远程画面底部拖动（比如 A 上 app 的底部工具栏）会直接回到主屏。这要在原生的视图控制器里设。

### 7.3 紧凑档

把左侧面板的四个标签变成四个整页，放在底部标签栏上；选中一个会话就进入整屏的舞台。

```
 根：四个标签页                      选中一个会话后
┌──────────────────────────┐      ┌──────────────────────────┐
│ rapp      活动3 等你1  ⋯  │      │ ‹ ● Claude·mac1  [2] ▂▃▅ │ 细顶栏 48
├──────────────────────────┤      ├──────────────────────────┤
│ 需要你                    │      │                          │
│ ◆ Claude @mac1 等你 [查看]│      │                          │
│ ▨ 终端 @gpu1 断开  [重连] │      │        远程画面           │
│ 会话     [设备|App|项目]  │      │     （缩放、平移，§7.5）   │
│ ● Claude       mac1  48K │      │                          │
│ ● 终端 build   gpu1      │      │                          │
│ ○ Chrome       mac2 空闲 │      │                  [看|点]  │
│ 常用                      │      │                   [输入] │
│ ＋ ChatGPT     mac1      │      └──────────────────────────┘
├──────────────────────────┤
│  会话   设备   项目   资源 │
└──────────────────────────┘
```

- **根**：「会话」页最上面是"需要你"（紧凑档里全部列出，不限 3 条），下面是会话列表和常用，用的是现有的 `sessions_tab`、`needs_you`、`session_row`。另外三页用现有的 `devices_tab`、`projects_tab`、`resources_tab`。标题栏右边一行状态计数（活动、等你、已断开），代替全景的第一层。
- **没有单独的全景模式**。紧凑档里"会话"页就是全景。
- **舞台页**：细顶栏从左到右是返回、状态灯加 app 名和设备、窗口数（两个以上才有，点开是窗口列表）、流量标签。没有上一个、下一个按钮：左右切换会话用返回再选。
- **浮层**：串流菜单、需要你、窗口列表在紧凑档里都从底部升起，占下半屏。"同时只开一个"不变。
- **主题、图例、本机设置**：收在根标题栏的「⋯」里。
- **系统的边缘右滑返回**在舞台页上关掉（它会和在远程画面左边缘的拖动抢），只用返回按钮。
- 点两次确认、选了就收、控件不小于 48，这几条规则不变。

### 7.4 窗口大小变化时的规则

舞台大小一变，A 上的窗口就要跟着改尺寸（现有规则）。iPad 和 Duo 上窗口大小变得比桌面频繁得多，所以要收紧：

- **Z1 盖，不挤。** 软键盘、输入板、底部升起的浮层都盖在舞台上面，舞台大小不变。（界面骨架不随键盘让位。）
- **Z2 稳了再改，只改一次。** 旋转、开合、拖分屏分隔条、缩放窗口的过程中不发改尺寸。舞台大小连续 400 毫秒不变之后发一次。过程中画面按原来的远程尺寸等比缩放显示。
- **Z3 进紧凑档不改 A。** 从常规档变到紧凑档（比如合上 Duo），不发改尺寸，画面改用 §7.5 的方式显示。从紧凑档回到常规档时，按 Z2 发一次（尺寸和 A 现在的一样就不发）。
- **Z4 冻结时不改。** 断开、冻结、在后台时不发（现有规则）。
- **Z5 不换会话，不丢东西。** 换档前后选中的是同一个会话；输入板里的草稿、光标、终端滚动位置都在。对应关系：

  | 换档前 | 换档后 |
  |---|---|
  | 常规档，窗口模式，会话 X | 紧凑档，X 的舞台页 |
  | 常规档，全景 | 紧凑档，根（会话页） |
  | 紧凑档，X 的舞台页 | 常规档，窗口模式，会话 X |
  | 紧凑档，根 | 常规档，全景 |

  实现上舞台和输入板在两档里必须是同一个组件实例，不能换档时销毁重建。

### 7.5 紧凑档里的远程画面

问题：A 上的窗口是按电脑的尺寸开的（比如 1194 宽），手机竖持只有 390 宽。

做法（我定的）：**A 上的窗口保持原来的大小，B 这边缩放和平移。** 不把 A 的窗口改成手机大小，原因：桌面 app 大多有最小宽度；每次开合都让 Agent 的界面和终端的历史重排；回到主控台时希望布局还是离开时的样子。

- **初始取景**：A 端按焦点区域规则（`2026-11-16-rapp-focus-pane-rules.md`）报了主内容区时，让主内容区的宽度铺满屏幕；没有就让整个窗口的宽度铺满。
- **两种手势模式**，画面右下角一个切换钮，默认「看」：

  | 手势 | 「看」（默认） | 「点」 |
  |---|---|---|
  | 单指轻点 | A 上点击 | A 上点击 |
  | 单指拖 | 平移取景 | A 上拖动（选字、拖滑块），即常规档的规则 |
  | 双指上下滑 | A 上滚动 | A 上滚动 |
  | 双指捏合 | 缩放取景（从"整窗铺满"到 4 倍） | 缩放取景 |
  | 双击 | 在"主内容区铺满"和"整窗铺满"之间切换 | A 上双击 |

- **输入板打开时**：可见区域是输入板和键盘上面那一块，取景自动上移，让主内容区的底边留在可见区域里。
- **可选项**：串流菜单里一个开关「窗口跟随屏幕」，紧凑档里默认关。打开后紧凑档也按 Z2 改 A 的窗口。

### 7.6 Duo 专有

- **开合**：就是 Z2、Z3、Z5，没有专门的代码。
- **外屏**：紧凑档。
- **并排两个 App**：rapp 那一半多半是紧凑档，照 §7.3。
- **半折姿态**（像小笔记本那样立着）：**先不做**（用户 2026-11-17 定）。它要自己写原生桥报折痕和姿态（F9），不在 P0–P3 里。半折时就是普通的常规档。

### 7.7 iPad 专有

- **分屏、窗口缩放、台前调度**：照 §7.1–7.4，没有专门的代码。iPad 要声明支持全部四个方向、不要求全屏，否则不能分屏。
- **外接显示器**：第一版不做专门处理，系统怎么摆窗口就怎么显示。
- **指针悬停**：有触控板或鼠标时，悬停提示和桌面一样；没有时界面不依赖它（I6）。
- **菜单栏、按住 ⌘ 的快捷键列表**：P3 再看。

## 8. 输入

### 8.1 触摸（常规档）

沿用触摸滚动规格的 T1–T7，不改。加一条（我定的）：

- **T8 双指轻点 = 右键。** 两根手指都落下又都抬起，全程不超过 250 毫秒、谁也没移动超过 8 逻辑像素：在两指中点发一次右键点击。超时或移动了就照 T3 当滚动。

常规档里远程画面和舞台一样大，不做捏合缩放。真机检查（那份规格里欠着的）并进 P1 的验收。

### 8.2 触控板、鼠标

iPad 接触控板或鼠标后，Flutter 报的是鼠标类指针：移动、左右键、滚动都走桌面已有的路。触控板的双指滚动在 iPadOS 上可能以"平移缩放"事件而不是滚轮事件到达，`picture.dart` 要两种都认。P1 核对。

### 8.3 外接键盘

- **按键从哪来**：iOS 给的是 HID 用法码，线路上用的是 macOS 虚拟键码（终端那边的映射表也是 macOS 键码）。在 `RappCore` 里加一张纯数据的表"HID 用法码 → macOS 虚拟键码"和修饰键的换算，写单元测试。
- **谁来收**：iOS Runner 的视图控制器重写按键的按下、抬起、取消三个回调。画面有键盘焦点时（Dart 的 `picture_focus`）按键交给会话、不再给 Flutter；否则照常给 Flutter。和 macOS 上按键监视器的分工一样。焦点离开时补发抬起（现有的 `KeyTracker`）。
- **系统留着的键**（F14）收不到。按键排上的修饰键做成**粘滞**的：点一下 ⌘ 亮起，再按实体键盘上的 Tab，A 收到的就是 ⌘Tab；发出后自动熄灭，双击锁定。
- **输入法切换、大写锁定**留在本机，不发给 A（文字本来就在本机组好再发）。
- 在画面上直接打字唤出输入板（type-to-compose）和 macOS 一样。

### 8.4 软键盘和输入板

- **没有实体键盘时，所有文字都从输入板走。** 点远程画面不会弹出软键盘。点「输入」打开输入板，软键盘跟着出来。
- **按键排**（现有的按键一排）在输入板打开时贴在软键盘上沿：Esc、Tab、⌘、⌥、⌃、⇧、四个方向、删除、回车。修饰键粘滞（§8.3）。
- **编辑框**（我定的分两步）：P1 用现有的 `FlutterEditor`，系统输入法和听写都能用；P2 换成原生 `UITextView`，实现和 macOS `ComposerPlugin` 同一份通道约定（`focus`、`unfocus`、`set`、`insert`、`read`、`take`、`style`、`chips` 和回来的事件），Dart 侧的 `NativeEditor` 不用改。这样 I7"系统原生控件"在 P2 兑现，P1 先把串流和操作跑通。
- **回车**：有实体键盘时和桌面一样（回车发送，Shift+回车换行，组字时回车归输入法）。只有软键盘时回车是换行，发送用「发送」按钮（我定的）。
- **语音**：第一版就是系统键盘上的听写键。专门的按住说话不在本文范围。

### 8.5 Apple Pencil

当作单指触摸；支持悬停的 iPad 上，悬停当作鼠标移动。Duo 上 Pencil 的支持 Apple 说晚些时候到 [S3]，到时不需要额外代码。手写转文字只在 P2 的原生编辑框里由系统提供。

### 8.6 剪贴板

- **A → 本机**（「复制到本机」）：写系统剪贴板，不弹框。
- **本机 → A**：用户在输入板里自己粘贴，不弹框。
- **程序主动读本机剪贴板**（比如"＋"里的"贴图片"）会弹系统的"允许粘贴"（F11）。可以接受；P2 换成系统提供的粘贴按钮就不弹。
- **不能有**：回到前台时自动读本机剪贴板。现有代码里如果有轮询本机剪贴板的逻辑（`LocalPasteboard`），iOS 上要关掉。

### 8.7 文件和链接

- **上传**（附件）：系统的文件选择器和照片选择器。从别的 App 拖进输入板放 P3。
- **下载**：存到 `Documents/传输/`，在"文件"App 里能看到（Info.plist 打开文件共享和就地打开）。「显示位置」在 iOS 上改成打开系统的分享菜单（我定的）。
- **链接**：交给系统打开。

## 9. 前台、后台和恢复

### 9.1 进后台

系统通知"进入后台"时（不是"不活动"；下拉控制中心、开合 Duo 的过程只是不活动，什么也不做）：

1. 界面把所有活动会话标成冻结。显示上沿用断网冻结规格：停在最后一帧，终端停在最后的内容，输入板照常能写。
2. 向系统申请一小段后台时间，让 hub 主动关掉各会话的连接，原因写「切到后台」。这样 A 立刻停止采集，而不是等超时。
3. hub 停掉定时探测。

「切到后台」算一种会自动重连的原因（`autoReconnects`），但重试只在回到前台后开始。

### 9.2 回前台

1. 给 hub 发现有的 `net_suspect`，让它重新探路。
2. 重连进后台前活动的会话：当前会话先连，其余的错开。走现有的重连路径，草稿照现有办法搬到新会话。
3. 舞台一直是最后一帧加顶部细提示「正在重连…」，新画面到了再换。

目标：Wi-Fi 下，回到 rapp 后 2 秒内当前会话的画面恢复（P1 实测；A 锁屏的情况另算，见下）。

### 9.3 和自动锁屏的关系（已定：甲，Q1）

自动锁屏规格：A 上最后一个看得到屏幕的会话结束 10 秒后锁屏。在 iPad 上这意味着**切出去超过十来秒，A 就锁了**；回来要先解锁。

- 记住了密码并勾了自动输入：回来时自动解锁，多等一小会儿。iOS 上有 Keychain，`UnlockStore` 能用。
- 没记住密码：每次回来都要输一遍 Mac 的密码。

两个办法：

| | 做法 | 影响 |
|---|---|---|
| 甲（**已定**，用户 2026-11-17） | A 端不改。iPad 上引导用户记住密码并自动输入；P1 量回来到画面恢复的时间 | 最安全；不动已批准的自动锁屏规格 |
| 乙 | A 的「本机」里把那 10 秒做成可调的宽限（比如 5 分钟） | 回来更快；但宽限期内 A 是解锁着没人看的，和 AL1 的本意有出入 |

不管选哪个，有一件事要做：自动锁屏规格的目标是"从 B 打开 app 或桌面时，A 锁着就自动解锁或弹密码框"，它的实现还在进行中，写规格时的现状是自动输入只在桌面会话新连上时触发。在桌面端"连上时 A 锁着"是少数情况，在 iPad 上是每次回来的常态，而且走的是**重连**而不是首次打开。所以 P1 要确认：app 会话重连时遇到 A 锁着，也能不经手动操作走完解锁。缺的部分在自动锁屏的实现里补。

### 9.4 为什么不做后台保活和推送

- iOS 给后台常驻的几种权限（播放音频、网络电话、定位等）都不是给这种用途的，借用了过不了审核。
- 推送要有一台服务器知道"哪个会话在等你"并能向 Apple 发推送。那就要 relay 懂业务，或者另起一个服务，和 I9 相反。
- "需要你"在 iPad 上的含义因此是：**打开 rapp 那一刻能看到谁需要我**，不是"它来叫我"。以后做助理时再考虑。

### 9.5 其他

- **屏幕常亮**：前台、舞台上有活动会话时不让屏幕自动熄灭（设置里可关，默认开；我定的）。
- **内存和耗电**：非当前会话是否继续收帧，沿用桌面的行为。P0 量 6 个会话同时开着时的内存和每小时耗电；超出预算（我定的：内存 500 MB；单个前台会话占不到一个核的 30%）就让非当前会话降到最低一档。收到系统的内存警告时，丢掉剪贴板缩略图和非当前会话的缓冲，只留最后一帧。
- **App 切换器里的快照**：见 §13。

## 10. 网络和权限

- **无线数据**（F15，国行设备）：hub 起来之前，原生一侧先用 `URLSession` 发一个请求（探查用的是 `https://captive.apple.com/hotspot-detect.html`），让系统弹出"无线数据"的框；请求通了再让 hub 拨号。用户拒绝时请求失败（`NSURLErrorNotConnectedToInternet`，路径 `Denied over Wi-Fi interface`），界面提示去"设置 → 无线数据"打开，带去设置的按钮。P0 实测：弹框 0.65 s 出现，允许后 6.4 s 网络通。
- **本地网络**（F12）：Info.plist 里写用途说明（"连接同一网络里你自己的电脑"）。第一次走局域网直连时系统弹框。用户拒绝后局域网那条路不通，自动走中继；界面提示一次"没有本地网络权限，只能走中继"，带去系统设置的按钮。
- **P0 核对过**：hub 没有用广播或组播，只连已保存的地址，不需要组播授权。
- **只有 IPv6 的网络**：Apple 审核时会在这种网络下测。接入点写成域名时要经系统解析拿到合成的 IPv6 地址；写成 IPv4 数字地址在这种网络下连不上。hub 的拨号要支持 IPv6 套接字，并在说明里建议接入点用域名。待办里记着"只测了 IPv4"，P1 要在这种网络下实测（Mac 的互联网共享可以建一个）。
- **网络切换**（Wi-Fi 和蜂窝之间，I5 的地铁、高铁场景）：原生一侧监听系统的网络路径变化，一变就给 hub 发 `net_suspect`，走现有的重连。P2 探查能不能让 QUIC 连接直接换到新网络上而不重连。
- **蜂窝和低数据模式**（我定的）：当前网络是按流量计费或用户开了低数据模式时，新开的会话默认用「智能」档；流量标签上加一个蜂窝标记（用形状，不用颜色）。不自动改已经开着的会话。
- **相机**：只在 P3 扫码接入时用，到时再加用途说明。照片走系统选择器，不需要权限。听写是系统键盘的功能，rapp 不要麦克风权限。

## 11. 终端会话

- 界面是纯 Dart（`term_stage`、`term_painter`、`term_model`），连接走 hub 的嵌入端口（`term_link.dart` 连 `127.0.0.1`），所以 hub 在进程内跑起来之后终端会话不需要原生代码。
- **字体**：iOS 上没有桌面那种"读系统设置里的等宽字体"。用系统自带的等宽字体，中文回落到系统中文字体；具体字体名留给实施者，要求是中英文混排时列对得齐（和桌面的验收一样）。
- **按键排**：现有的 `term_key_row.dart`，修饰键按 §8.3 做成粘滞。
- **选中和复制**：有鼠标或触控板时沿用现有的选中；纯触摸下的长按选中放 P2。
- **紧凑档**：终端是文字不是图像，不用 §7.5 的缩放和「看 / 点」。A 端的终端尺寸照 Z3 不改；本机窗口比 A 的终端窄时怎么显示，先看现有代码有没有这种情况的处理，有就沿用，没有就横向滚动（留给实施者）。

## 12. 端口共享和内置浏览器（只留位置）

- 桌面上"别的设备分享给我的端口"是本机的 `rapp-service` 在 `localhost` 上开端口。iPad 上没有 service；就算在 rapp 进程里开了端口，rapp 一进后台就停，Safari 用不了。所以只能是 I8 说的内置浏览器。
- 这一块轮到时单独写规格（端口共享主规格第 7 步）。范围大致是：把"映射到本机端口"那部分做成 hub 能带的库；一个内置浏览器页（系统的网页视图），地址栏只列已分享的端口；Info.plist 里允许访问本机的明文地址。
- 在那之前，资源里的端口面板在 iOS 上不显示。

## 13. 安全

relay 规格已经写明：key 是所有设备的总钥匙（T5）。iPad 和手机比台式机容易丢，所以：

| 项 | 做法 |
|---|---|
| key、设备私钥 | 放在"文件"App 看不到的目录，排除在备份之外，设文件保护（§6.5）。P2 评估把 key 挪进 Keychain（要给 hub 加一个"从外面拿 key"的入口） |
| 记住的 Mac 密码 | Keychain，仅本设备、解锁时可读 |
| 回到 rapp 时验证（我定的） | 设置里一个开关：离开超过 5 分钟再回来，要过一次面容、指纹或设备密码。默认关，接入引导的最后一步问一次要不要开（Q4 已定）。放 P2 |
| App 切换器里的快照 | 进入不活动状态时，用主题底色加标志盖住远程画面，防止切换器里露出 A 的屏幕。默认开，放 P2 |
| 丢了设备 | 照 relay 规格：先吊销，再换 key。使用说明里加一段"iPad / 手机丢了怎么办" |
| 数据收集 | 没有。不带统计、崩溃上报之类的第三方组件。App Store 的隐私标签填"不收集数据" |

- 终端的字体名；紧凑档里终端比 A 窄时的显示（§11）。
- §6.2、§10 里标了"留给实施者核对"的三件事（P0 已核对，结论写在原处）。
