## 1. 现状

来自平台规格 §2、`rust/relay/src/`、`rust/net/src/quic.rs` 和 `scripts/rapp-relay.service`。

| 方面 | 现在怎么做 |
|---|---|
| 暴露面 | 只开一个端口 `21116/udp` |
| 传输 | QUIC，自带加密。证书是自签的，客户端不校验，所以设备没法确认对面是不是真的 relay |
| relay key | 一个共享口令，登记、连接、中继三种请求都要带。启动时从命令行 `--key` 传入 |
| 设备密码 | 存的是 `SHA-256(salt ‖ password)`，比对用常量时间比较。B 发起连接时把明文密码发给 relay |
| 失败限速 | 按 ID 和来源 IP 分别计数，连续失败 5 次后指数退避，最长 300 秒。计数只在内存里，最多记 10 万个键 |
| 令牌 | 32 位十六进制随机数，有效 24 小时 |
| 输入上限 | 一行最长 64 KiB；保活 10 秒，空闲 30 秒超时；每条连接最多 1024 条并发流 |
| 存储 | `relay.json`，内容一变就整个重写。文件权限和写入方式我没有核对 |
| 运行 | Linux 有静态链接的 x86_64 二进制和 systemd 示例（非 root 的 DynamicUser、崩溃重启）。没有 Docker 相关文件 |

## 2. 对照"最常用的防护"还差什么（我的建议）

按要紧程度排。每条都只动 relay 和设备连 relay 的那一段，不动设备之间的连接（D8）。

### 先做

1. **设备要能确认 relay 的身份。**
   现在不校验证书。有人在网络中间冒充 relay，就能拿到 relay key 和设备密码。
   最常用的做法：relay 持有一对固定的密钥，设备上配置 relay 的公钥指纹，连接时核对。RustDesk 的 key 就是这个做法，平台规格 D2 本来就是照它划分组件的。
2. **relay key 不从命令行传。**
   命令行参数会出现在进程列表里，同一台机器上的其他用户看得到。systemd 示例虽然把 key 放在环境文件里，启动时还是展开进了命令行。
   改成从环境变量或文件读；Docker 下对应 secrets。
3. **设备密码换成慢哈希。**
   单次 SHA-256 算得太快，`relay.json` 一旦泄露，可以离线快速穷举。常用的是 Argon2id，scrypt、bcrypt 也行。
4. **给没通过认证的连接设资源上限。**
   现在只对"认证失败"限速。还缺：每个来源 IP 的连接数和新建速率、没认证的连接多久没动静就断开、每条连接的并发流上限（1024 偏大）、同一个 relay key 能登记多少个 ID、中继的流量上限。
   另外打开 QUIC 的地址验证，防止有人伪造来源地址拿 relay 去放大攻击别人。

### 接着做

5. **最小权限运行。**
   非 root、根文件系统只读、去掉全部 capability、禁止提权、只挂载放 `relay.json` 的那一个卷、限制内存和进程数。镜像里只放那个静态二进制。
6. **审计日志。**
   登记、连接、失败、锁定、中继的开始和结束都记一行，带来源地址；key、密码、令牌不进日志。统一日志格式已有（可观测性规格）。
7. **`relay.json` 的权限和写入方式。**
   权限 0600；写入时先写临时文件再改名，避免写到一半断电留下坏文件。现状要先核对。
8. **依赖和发布。**
   依赖版本已经锁定（`Cargo.lock`）。加上定期的漏洞扫描；镜像用固定的版本标签。
9. **令牌作废。**
   改了密码或重新登记时，旧令牌应当立刻失效。现状要先核对。

### 不在 relay 自身，但要说清楚

10. **D8 里接受的那条代价仍然在。**
    平台规格写着："拿到 VPS 的人能冒充任何设备，也能看到中继流量。"
    上面九条降低的是 VPS 被拿到的可能性，不改变被拿到之后的后果。这条要不要动，由用户定；我不在这里提方案。

## 3. 平台和部署（R4、R5）

- **Linux 优先。** 静态二进制和 systemd 示例已有。要新增的是 Dockerfile 和一份 compose 示例。
- **Docker 上有一处要小心。** relay 靠"它看到的对端地址"做两件事：按来源 IP 限速；把 A 的公网地址告诉 B，用来打洞。有些容器网络方式会改写来源地址，这两件事就都坏了。
  Linux 上最省事的是用主机网络模式。据我所知，RustDesk 的 Docker 部署也是这么建议的（没有核对）。这一点要实测确认。
- **macOS。** 最精简的做法是同一个二进制加一份 launchd 示例，直接运行，不走 Docker。Mac 上的 Docker 跑在虚拟机里，容器看不到真实的来源地址。
- 现在只有 x86_64 的 Linux 二进制。要不要 arm64 的 Linux（不少便宜的云主机是这个架构），见 §5。

## 4. 不做的

TCP 备用中继、网页管理界面、账号和多租户、Windows 版 relay。

## 5. 待用户定
