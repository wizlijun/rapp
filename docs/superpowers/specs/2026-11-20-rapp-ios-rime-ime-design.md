# iOS / iPadOS 内置输入法（Rime）设计

日期：2026-11-20。状态：设计，待用户批准。

标了【我定的】的是我做的决定，用户没有逐条确认过，可以否掉。没标的，是用户在 2026-11-20 的对话里选定的。

## 1. 为什么

用户的话：

- 2026-11-14：「后续会改造输入法，让打字体验在文字的下一行，这样眼睛可以固定不动。减少输入法框飘来飘去的问题。」
- 2026-11-19：「我们的输入板这一块自己去实现一个输入法。一个轻量的输入法，不知道要消耗多少的代价。」
- 2026-11-20，在 Duo 上用过探查版之后：「整体体验可行。」「请把 ios、ipados 上的这种方式的输入法，单独放在一个子目录下，长期维护内嵌输入法。」

背景：

- iOS 上第三方输入法以键盘扩展的形式存在，接了实体键盘后按键不经过它们。所以 iPad 或 iPhone 配实体键盘时，只能用系统拼音，系统候选条跟着光标飘。
- 探查（规格 `2026-11-19-rapp-ios-rime-panel-probe.md`；分支 `probe/ios-rime-panel`，提交 `40bdec88`；测量文档 `docs/superpowers/measurements/2026-11-19-rapp-ios-rime-panel.md` 只在那条分支上）已经做了这些：
  - 把 librime 放进 app，实体键盘的按键在 `pressesBegan` 里交给引擎，然后吞掉。
  - 候选固定在文字下一行。
  - 模拟器上 R2、R3、R4、R8 都成立。
  - Duo 上实测：13 次按键全部由引擎接管，系统输入法没有插手；每次按键中位 0.69 ms，最大 5.44 ms。
  - 安装包增量：引擎代码 +1.27 MB，雾凇词库压缩后 +16.5 MB。
- 探查代码不原样搬：里面有调试日志、对 `UIApplication.sendEvent` 的方法替换和测量面板。正式版按产品要求重写，探查分支留作参照。

## 2. 目标、不做的、不能出现的

目标：

1. iPhone 和 iPad 接实体键盘时，输入板（iOS 上 `ComposerPanel` 里的 `FlutterEditor`）可以用内置的 Rime 打字：
   - 组字显示在光标处，带下划线；
   - 候选固定在文字的下一行。
2. 输入法单独放在一个子目录里，长期维护：
   - 升级 librime 或雾凇时只动这个目录；
   - app 一侧只有很少的接线。
3. 自带雾凇拼音；也能用用户自己放进「文件」app 的 Rime 目录。
4. 设置里有总开关，默认关；打开后，输入板上有一个「内 / 系」小按钮，随时在内置和系统输入法之间切，记住上次的选择。

不做（这一轮）：

- 自己的软键盘。
- macOS、Linux、Android、Windows 上的内置输入法。
- 用户词库在设备之间同步。
- 在 app 里编辑方案或词库。
- 从源码编 librime。
- 输入板关着时直接打进远端会话的按键：这条路径和现在一样，内置输入法只管输入板的编辑区。

不能出现：

- 总开关关着时，行为和现在完全一样，包括 type-to-compose、语音、chips、远端按键。
- 没接实体键盘时一切照旧，走系统软键盘和系统输入法。
- 首次部署（编词库）期间不能卡住打字：引擎就绪前，按键照常交给系统输入法。
- 不丢键、不乱序：打开输入板之前暂存的那几下，也要按顺序进引擎。
- 不改协议，不改 A 侧，只用公开 API。

## 3. 约束

- **引擎包**：固定用 LibrimeKit-iOS v0.2.2（librime 1.16.1，带 librime-lua，雾凇要用）。
  - 构建时由脚本下载，核对 sha256。
  - 不进仓库（约 68 MB 的 xcframework，链进 app 后约 +1.3 MB）。
  - 换版本时改脚本里的地址和校验和。
- **词库**：雾凇拼音固定在一个提交上，同样由脚本下载、核对、打进 app 包。
- **许可证**：
  - librime BSD-3；依赖库见探查测量文档的库表。
  - 雾凇 GPL-3.0（里面有 lua 脚本）。rapp 本身是 GPL-3.0，自己设备上安装和 TestFlight 内部测试都没问题；README 里列出各库和数据的许可证。
  - **和上架的冲突（用户 2026-11-20 知情后定的：照旧打进包）**：iPad 规格（`2026-11-17-rapp-ipad-duo-design.md` G1/Q2）定过，公开分发（TestFlight 外部测试、App Store）要靠 GPLv3 第 7 条的 App Store 附加许可，前提是 iOS 包里没有别人的 GPL 代码。雾凇打进包后，这个前提不再成立。所以公开分发之前，要重新处理词库：改成首次启用时下载、换词库，或者取得许可。这一轮不处理。
- **只在 iOS 上**：插件只声明 iOS 平台，macOS、Linux、Windows 构建不链接它。Dart 一侧在别的平台上不调它。
- **共用的文件**：`SessionPlugin.swift` 由 macOS 和 iOS 共用，iOS 工程按路径引用 `../macos/Runner/SessionPlugin.swift`。动它的地方用 `#if os(iOS)` 隔开，macOS 照常编译。
- **Flutter 的 SwiftPM 插件通道**：iOS 工程里已经接好了（`FlutterGeneratedPluginSwiftPackage`），目前一个插件都没有。这会是第一个。

## 4. 做法

| 做法 | 取舍 |
|---|---|
| **A 本地 Flutter 插件 `gui/packages/rapp_rime/`（用户选的）** | 一个目录装下 Swift 引擎桥、按键换算、Dart 一侧的组字和候选、脚本、测试和说明。app 按路径依赖它，只留少量接线。边界清楚，可以单独升级。代价是第一次要在插件的 Package.swift 里接通十个预编译库 |
| B 原生和 Dart 各放一处（`gui/ios/Runner/Rime/`、`gui/lib/rime/`、`scripts/rime/`） | 照 macOS 上 Sumi 的放法，构建最简单；但输入法分在三处，不是「单独一个子目录」 |
| C 引擎放进 Rust crate | 为以后 macOS、Linux 共用一个引擎层做准备；这一轮只做 iOS，多一层 Rust 和 C++ 的链接，眼下用不上 |

用户选 A。

## 6. 设计

### 6.1 目录

【我定的】的布局，文件名留给执行的人：

```
gui/packages/rapp_rime/
  README.md            它是什么、怎么升级 librime 和雾凇、各库和数据的版本和许可证
  pubspec.yaml         Flutter 插件，只有 ios 平台
  lib/                 Dart：引擎状态、组字、候选快照、候选行组件、开关状态
  ios/rapp_rime/       SwiftPM 包：引擎封装、UIKey → Rime 键码、自己做的连发、通道
  scripts/fetch.sh     下载 LibrimeKit 和雾凇，核对 sha256，放进 gitignore 掉的 vendor/
  test/                Dart 测试
```

app 一侧只改这几处：

- `gui/pubspec.yaml`：按路径依赖。
- `RappViewController`：按键接线。
- `FlutterEditor`：显示组字，并且在内置输入法开着时由它接管按键。
- `ComposerPanel`：在文字下一行放候选行。
- `UiPrefs` 和设置页：两个开关。
- `scripts/build-ios.sh`：构建前先跑 fetch。

### 6.2 按键怎么走

1. `RappViewController.pressHandler` 先交给 `SessionPlugin`，和现在一样：送远端、type-to-compose 的暂存，都由它决定。
2. `SessionPlugin` 不要的按键（留在本地），满足下面全部条件时交给 Rime：
   - 总开关开着，小按钮在「内」；
   - 输入板的编辑区有焦点；
   - 接着实体键盘；
   - 引擎已就绪。
3. Rime 把 `UIKey` 的键位和修饰键换成 X11 keysym 和 Rime 的修饰位，交给引擎：
   - 引擎收下的就吞掉。
   - 引擎没在组字、又不要的键（方向键、⌘ 组合键、组字为空时的退格、Tab 等），照常交给 Flutter。
   - 引擎不要的可打印字符，由编辑区插入。
   - Shift 的按下和抬起都发给引擎，Rime 靠 Shift 抬起切中英。
4. 连发：`pressesBegan` 每次物理按下只来一次（探查在模拟器上看到的，真机待确认），所以要自己做。探查的做法是按住 0.4 s 后每 40 ms 一次，可以沿用。【我定的】如果真机上系统自己会重复送 `pressesBegan`，那就不再自己连发，免得一次按住出两份；用探查里「系统连发」那个计数来判断。
5. type-to-compose：输入板关着时按下一个字母，`SessionPlugin` 先把它暂存，等输入板拿到光标后再把暂存的按键补进编辑区（iOS 上的 `replay`）。
   - 内置输入法生效时，这些暂存的按键要按顺序送进 Rime，不能直接 `insertText`；否则第一个字母会以英文上屏。
   - 这是 `SessionPlugin.swift` 里唯一要改的地方，放在 `#if os(iOS)` 里。

### 6.3 编辑区

- 组字（preedit）不进编辑区的文字，只在显示时插在光标处，带细下划线（探查就是这么做的）。所以系统那一侧的文字输入连接看不到它，chips、撤销和现有的组字规则都不受影响。
- `FlutterEditor` 的约定是：`read`、`take`、`setText`、`insert` 在组字时要等上屏。Rime 的组字不会自己结束，所以不能等。【我定的】规则只有一条：**按键以外的东西碰到文字时，先把组字按原文上屏（和回车一样），再照常执行。**
  - 适用于：`take`、`setText`、`insert`（语音的结果、chips、从画面插入的东西）、交接时的 `read`。
  - 平常的 `read` 返回的文字不含组字。
  - 编辑区失去焦点时也按原文上屏，不丢用户打的字母。失去焦点包括：点画面、关闭或隐藏输入板、交给原生窗口、app 进后台。
  - 组字时点编辑区不能挪光标，和系统输入法组字时一样（现有的 `AbsorbPointer`）。
  - 切到「系」时清掉组字，不上屏（§6.4）。
- 总开关关着时，`FlutterEditor` 走的代码路径和现在一样。

### 6.4 候选行和小按钮

- 位置：输入板编辑区文字的下一行，从文字左缘开始。打字时不跟着光标横移，一行。
- 【我定的】只要总开关开着、并且接着实体键盘，这一行就一直占着位置：
  - 不组字时，这一行是空的，只有右端的小按钮。
  - 这样候选出现、消失时，输入板不会跳。这也是用户要「眼睛固定不动」的本意。
  - 代价是多占一行高。
- 内容：序号、候选字、当前高亮、‹ › 翻页。点候选上屏，点 ‹ › 翻页。
- 【我定的】小按钮左边有一个「中 / 英」标记，显示 Rime 现在的状态。不组字时也在，免得误按 Shift 后打成英文却看不出来。只显示，不能点；Shift 才是切换方法。
- 样式：沿用现有的候选画法（`linux_candidates.dart` 的 `LinuxCandidatesSurface`，也就是 Sumi 的样子）。拷一份精简版到插件里，还是把它挪进插件、app 改用插件里的那份，留给执行的人。
- 小按钮「内 / 系」：
  - 在候选行右端，点一下就切；选择记进 `UiPrefs`。
  - 切到「系」时，引擎里的组字清掉，之后按键交给系统输入法。
- 引擎部署中：候选行显示「部署中…」，这时按键走系统输入法。

### 6.5 设置

- 「本机」一节（`IosLocalSection`）加一个开关：「实体键盘用内置输入法（Rime）」，默认关。
- 【我定的】开关下面再放三样：
  - 当前词库：自带雾凇，或「我的目录」；
  - 「重新部署」按钮：用户改了自己的目录后要点它；
  - 一行状态：就绪 / 部署中 / 出错和原因。
- 关掉总开关时，引擎释放（`finalize`），候选行和小按钮都不出现。

### 6.6 词库和部署

- 自带：
  - 雾凇的共享数据打在 app 包里，作为共享目录。
  - 用户目录放在 app 的 Application Support 下，存编译结果和用户词库（leveldb，用户打的词会记住）。
  - 不同步，删 app 就没了。
- 「我的目录」：
  - 「文件」app → rapp → `Rime` 里有用户自己的 Rime 目录时，可以选用它。【我定的】判断条件：里面有 `default.yaml`。
  - 这个目录同时当共享目录和用户目录。探查里发现，如果共享目录指向自带数据，自带数据里的 `default.custom.yaml` 会盖掉用户的 `schema_list`。
- 部署：
  - 首次启用、升级了自带雾凇、或者点了「重新部署」时，在后台线程做（`start_maintenance`），期间有状态提示。
  - 模拟器上雾凇首次部署 7–10 s；真机还没量。
  - 【留给执行的人，按数字定】真机首次部署如果超过 5 s，在构建时把编译好的词库一起打进包里，省掉设备上的编译。这样包会更大，大多少要量出来。
- 引擎什么时候加载：【主控定的，2026-11-20 终审改，原来是「编辑区第一次拿到焦点才加载」】总开关开着、并且接着实体键盘时就在后台加载（app 启动时的 `configure`、打开总开关、或者键盘接上的时候），不等编辑区拿到焦点；之后只要总开关开着就常驻，键盘断开也不释放；输入板开关不重新加载；关总开关就释放。原来等第一次拿到焦点才加载，结果每次启动后的第一次「打字即输入」补发时引擎还在加载（约 0.34 s），字母交给了系统，上屏成英文，加载期间现打的键也走系统输入法。代价：接着键盘、开着总开关、却没在打字时，也占着引擎的内存（参考线 100 MB，见 §7 第 2 条）；不用的人不打开总开关，就不付这份内存。探查里加载（不含首次部署）只要几毫秒的主线程时间，Duo 上从启动到就绪 0.34 s，加载期间按键仍走系统输入法。

### 6.7 构建

- `scripts/build-ios.sh` 在 flutter 构建之前跑插件的 `fetch.sh`：已下载并且校验和对得上就跳过。
- 缺文件或校验和不对时，构建停下，提示跑哪个命令。
- 不改 macOS、Linux、Windows 的构建脚本。
- 探查里的条件构建（`RAPP_RIME`、`--dart-define=RAPP_PROBE`）不带过来：这是正式功能，随 iOS 版一起构建，靠总开关控制。
