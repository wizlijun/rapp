# 总览本机列：连上的服务 + PC 默认折叠

- 日期：2026-11-27
- 相关：总览本机列折叠（iPad/Duo，`gui/lib/ui/overview.dart` 的 `_LocalFold`）、正在被接入卡片（`InboundGroup`）、中心服务（`2026-11-27-rapp-center-design.md`）、LLM 接入点（`gui/lib/llm_api.dart`）

## 1. 为什么

在 Duo 上分不清中心服务有没有生效：后台自动连接一直在工作，但界面上看不出来。用户要的是在总览上一眼看出本机连着 rapp 自己的哪些服务，以及它们通不通。另外，PC 上本机列平时只有一句「没有打开的 app」，白白占着 220px，所以和 iPad/Duo 一样默认折起来。

## 2. 要做的

### 2.1 连上的服务（所有平台的本机列）

本机列展开时，在会话和「正在被接入」卡片下面、版本号上面，加一组「连上的服务」，每个服务一行：

```
连上的服务
● 中心服务   Mac mini · :28003
● LLM 网关   localhost:28001
```

| 行 | 灯和右边的字 | 数据从哪来 |
|---|---|---|
| 中心服务 | 绿 = 已连上，右边写它在哪台设备（自己这台写「本机」）和端口；灰 = 连接中… / 没找到 / 已关；红 = 连不上 | `StateSync.status`、`StateSync.url`；在哪台设备用 `stateHost()`（PC 上由服务给，iOS 上由 hub 的分享给），设备名用 `state.deviceName` |
| LLM 网关 | 绿 = 通（`LlmApi.probe` 成功），右边写地址；红 = 连不上或 key 不对，右边写探测失败的那一行字；灰 = 没设置（`LlmEndpoint.configured` 为假） | `local/llm.json`，探测复用 `LlmApi.probe`（带 key 的 `GET /v1/apps`，地址和 key 一起验） |

- 只列 rapp 自己的服务（用户选的）。别的设备分享过来的端口不列，以后加了网盘、笔记这类服务再加行。
- LLM 网关只在这一组显示在屏幕上时才探测：显示出来时探一次，之后每 60 秒一次；本机列折起来、离开总览时停。没设置就不探。
- 两行都只用来看，点了没有反应。要改设置，到原来的地方：中心服务在 全局设置 / 本机页，LLM 在 LLM 接入点。

### 2.2 PC 上本机列默认折叠

- 现在只有没有本机服务的设备（iPad/Duo）会折。改成：PC 上本机列没有「正在被接入」卡片时，也折成 56px 竖条，样子和 iPad 的一样：系统标、灯、名字。
- 有人接入时自己展开，接入全部断开后再折回去。
- 用户手动点开或用 ‹ 折起以后，就按用户的来，接入有没有都不再自动改，直到 app 退出。和 iPad 一样只记在内存里。
- 竖条上不放服务的灯（用户选的）：折着就什么都不显示，点开才看到「连上的服务」。
- iPad/Duo 的折叠行为不变：默认折，点开以后在这次运行里一直开着。
- 远程设备的列一律不折（用户之前就定过）。

## 3. 不做

- 不列端口分享、不做点击打开。
- 不加新的设置项，也不改协议、服务和中心服务。

## 4. 做法

只有一种合理的做法：把它当作总览本机列里的一个新小部件，数据全部来自 app 里已有的对象（`StateSync`、`LlmEndpoint`/`LlmApi`、服务或 hub 的 `stateHost`）。另外考虑过两种，都不合适：
- 把服务状态放进顶上的计数行：离本机太远，用户要的是本机那一块。
- 让服务把这些状态汇报上来：服务本来就不知道 LLM 网关，为此加接口不值得。

留给实现的：灯用现有的 `StatusLamp`；文案和间距跟着本机列现有的小字样式；60 秒探测的计时器放在小部件里（显示时起、消失时停），这样测试可以注入假的 `LlmApi` 和时钟。
