## 1. 目标与非目标

目标：一个主窗口里完成"看全局、选一个、在里面干活"三件事，并且远程 app 的画面始终占最大面积。

非目标（本规格不做）：
- rapp 自己的任务模型。任务、放行、注意力编排归 Tower.md；rapp 只把 Agent 任务当作会话上的一个标签。
- 多个远程窗口同屏平铺。一次只嵌一个窗口，靠切换。
- 改 relay、service、worker CLI 的协议（生命周期和全局资源需要的 hub 改动见 §7）。

## 2. 对象模型

所有视图都是下面五种对象的不同分组方式。

| 对象 | 是什么 | 界面上要看到的 |
|---|---|---|
| 设备 | 一台独立 OS 的机器。本机也是设备表里的一行，不再是单独的区块 | 在线或离线、路径（局域网、直连、中继）、ID；本机另有密码、Relay、权限、服务 |
| App | 某台设备上的一个 app | 状态（未打开、活动……）、是否常用 |
| 会话 | 一次到（设备, app）的连接，含它的一个或多个窗口 | 生命周期状态、流量、串流设置、所属项目、关联的 Agent 任务 |
| 项目 | 一组（设备, app），可带 Agent 任务标签 | 每个资源一盏灯；全部打开、全部结束 |
| 资源 | 剪贴板条目、共享文件、进行中的传输 | 类型、来源（哪个 app @ 哪台设备）、时间 |

同一（设备, app）最多一个会话：再次"打开"是切到它，已断开则重连。

## 3. 界面结构

基准尺寸是 11 寸平板横屏 1194×834。常驻的只有顶栏；其余都是浮层。

```
┌ 顶栏 56px ──────────────────────────────────────────────────────────┐
│ [面板] [全景] [‹] ●App 名 / 设备·项目·任务 [›] [窗口标签…]  提示  [需要你 3] [▂▃▅ 48 KB/s ▾] │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│              舞台：嵌入的远程窗口（窗口模式）                         │
│              或 全景（全景模式）                                      │
│                                                           [输入]     │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.1 顶栏（常驻）

从左到右：

| 控件 | 行为 |
|---|---|
| 面板按钮 | 展开或收起左侧面板 |
| 全景按钮 | 在窗口模式和全景模式之间切换 |
| 上一个、下一个 | 按会话顺序循环切换，不用开面板 |
| 当前会话 | 状态灯、app 名；第二行是设备、项目、Agent 任务 |
| 窗口标签 | 当前 app 有两个以上窗口时才出现，点一下切窗口 |
| 提示 | 最近一次操作的结果，一行，溢出省略 |
| 需要你 | 一盏灯加一个数字；点开是"需要你"浮层（§3.6） |
| 流量标签 | 五格电平、数字、下箭头；点一下或右键打开串流菜单（§3.4）。没有选中会话时不显示 |

顶栏在两种模式下都不变。

### 3.2 窗口模式（默认）

舞台整块给一个远程窗口。在基准尺寸下约 1194×778，占整屏约 93%。

- 画面区域直接接受点、拖、滚。
- 区域大小变化时，A 上的窗口按现有规则跟着改尺寸。
- 连接中：居中显示旋转的灯和"正在连接"。
- 已断开：画面停在最后一帧，上面盖斜条纹，居中一个「重连」按钮。
- Agent 等你：左上角浮一条提示，带「已处理」按钮。
- 没有选会话：居中提示去打开面板。

### 3.3 全景模式

舞台换成一屏总览，从上到下三层：

1. **状态计数**：活动、空闲、连接中、已断开、等你、设备在线、总流量。已断开和等你不为 0 时整格用强调色加底纹；其余为 0 时数字变暗。
2. **设备墙**：每台设备一栏（含本机、离线设备）。栏里每个会话一块：状态灯、app 名、缩略图位置、流量电平或状态文字。点一块就进入该会话并退出全景。
3. **项目和资源**：每个项目一格（一盏灯一个资源），点开进项目面板；最右一格是剪贴板条数和传输进度，点开进资源面板。

分工：全景用来看全局、决定去哪；窗口模式用来干活。

### 3.4 串流菜单（流量标签）

从右上角浮出，自上而下：

1. 一键：最省流（双色·灰度 + 自适应 + 1 fps）、最清晰（高彩 + 原画 + 15 fps）
2. 档位：双色·灰度、双色·彩色、高彩
3. 采集密度：省流 1x、自适应、原画
4. 帧率：1、5、15、30
5. A 的剪贴板：最近两条，点一下写进本机剪贴板；另有「全部剪贴板」进资源面板
6. 会话：路径和状态；断开；结束会话

内容沿用现有 `rapp-client` 流量标签右键菜单的项目，多了最后的"会话"一组。

### 3.5 输入区

平时只是舞台右下角一个「输入」按钮。点开后从底部浮出一条：

`[按键] [附件] [多行输入框 + 块] [复制] [发送] [收起]`

- 输入框：用本机输入法打字，回车发送，Shift+回车换行，输入法组字时回车归输入法。
- 块：附件、长文字、图片在输入框上方显示成虚线框的小块，点一下移除。
- 发送：文字和块按顺序贴到 A 上当前的 app。输入区为空时点发送只提示"按键直接发给 A"。
- 复制：在 A 上按一次 ⌘C，结果进剪贴板。
- 按键：展开一排 Esc、Tab、⌘、⌥、方向键、删除、回车，给没有实体键盘的平板用。

行为沿用现有 `rapp-client` 底部编辑器，多了"按键"一排和"收起"。

### 3.6 需要你

顶栏上的数字是所有需要人处理的事的总数，点开最多列 3 件，每件带一个直接动作：

| 事 | 动作 |
|---|---|
| 某会话的 Agent 等你 | 查看：切到那个会话 |
| 某会话已断开 | 重连 |
| 某设备离线 | 查看：打开设备面板 |

没有时显示一盏活动灯和"没有需要你处理的事"。

### 3.7 左侧面板

从左边滑出，盖在舞台上。顶部四个标签，右端一个收起按钮；底部固定是主题下拉、状态灯图例、总览数字（在线设备数、会话数、总流量）。

| 标签 | 宽度 | 内容 |
|---|---|---|
| 会话 | 330px | 分组切换（设备、App、项目）；每个会话一条：状态灯、app 名、所属和流量或状态；最后一组"常用"是还没打开的常用 app，点一下打开。选中一条后面板自动收起 |
| 设备 | 720px | 设备标签（含本机）；远程设备列出它的 app，每行有状态、「设为常用」、「打开 / 切到 / 重连」；本机显示密码、Relay、权限、服务和重启；底部是添加设备（ID 或 ID@IP，加密码） |
| 项目 | 720px | 每个项目一张卡：一排灯、「全部打开」、「全部结束」；成员逐行列出 app @ 设备、Agent 任务、状态 |
| 资源 | 720px | 剪贴板：类型、内容、来源和时间、「固定」、「复制到本机」；文件：进行中的传输（进度、取消）和传过的文件（显示位置） |

## 4. 会话生命周期

| 状态 | 含义 | 进入 | 可做的事 |
|---|---|---|---|
| 连接中 | 正在选路、拉起窗口 | 打开、重连 | 等 |
| 活动 | 正在串流 | 连上 | 断开、结束、改串流设置 |
| 空闲 | 画面不变，不发数据，窗口还开着 | 一段时间没有画面变化 | 同活动 |
| 已断开 | 连接没了，条目和设置都留着 | 手动断开、网络断、A 端结束 | 重连、结束 |
| 已结束 | 从所有列表里消失 | 结束会话 | 无 |

- "断开"保留条目，"结束"才消失。两者在界面上是两个按钮。
- "等你"不是生命周期状态，是叠在活动或空闲会话上的一个标记，显示时优先于状态灯。
- "离线"是设备的状态，"未打开"是 app 的状态，不属于会话。

## 5. 交互规则

1. **浮层只盖不挤**。面板、串流菜单、需要你、输入区都盖在舞台上面，不改变舞台大小。原因：舞台大小一变，A 上的窗口就要跟着改尺寸，反复开合浮层会让 A 上的 app 反复重排。
2. **同时只开一个右上角浮层**。串流菜单和需要你互斥。
3. **选了就收**。在面板里选会话、在设备面板里打开 app、在全景里点会话，都会收起面板或退出全景，直接回到窗口。
4. **不可撤销的操作点两次**。「结束会话」「全部结束」第一次点变成强调色的"再点一次确认"，3 秒不点自动复原。不用弹窗。
5. **不依赖悬停和右键**。平板上流量标签点一下就开；桌面上右键等效。
6. **触控尺寸**见设计语言文档。

## 6. 与现有实现的差距

现状（来自代码）：

- GUI 是 Flutter 桌面程序，`gui/` 下只有 macos、linux、windows 三个目标，没有平板目标。
- 远程窗口由 `rapp-client`（Swift，AppKit）以独立的原生窗口显示；底部编辑器和流量标签右键菜单都在它里面。
- hub 只有 `hosts`、`add_host`、`remove_host`、`apps`、`open`、`close`，事件只有 `opened`、`closed`、`error`；不转发流量和窗口事件。
- 没有重连；会话一关就没有了。
- 剪贴板历史在每个 `rapp-client` 进程里，每个连接一份，最多 20 条，会话结束清空。
- 没有项目、常用 app 的概念和存储。

所以本设计需要的新能力是：嵌入式画面和输入（D10）、会话状态和流量上报、断开后保留条目并重连、全局剪贴板和文件、项目与常用的存储、平板目标（D8）。

## 8. 我做的假设（实施前请确认）

这些是设计过程中用户没有明确回答、我按默认处理的地方。

1. **平板的角色**。默认：dashboard 本身显示在平板上，点一下把对应的远程窗口切到最前。另一种理解是平板当遥控器，切换另一块屏幕上的内容；那样架构不同。并且现有 GUI 没有平板目标，要在 S7 决定是加 iPadOS / Android 目标，还是把平板当作 Mac 的副屏来用。
2. **"Agent 等你"的来源**。默认：这个状态保留在设计语言里，但信号要等 S8 才有；S3 的"需要你"只含断开和离线。
3. **批量操作**。默认：不做多选；批量只有项目里的"全部打开""全部结束"。用户早先提过要批量管理，需要的话加一个多选模式。
4. **实时缩略图**。默认：不做，全景里只写窗口数。
5. **浮层盖住画面**。默认：输入区展开时盖在窗口底部。如果要窗口让位，输入区单独改成"挤"的方式，代价是每次展开 A 上的窗口都改一次尺寸。

## 9. 验收

每个子项目的计划里各自写验证步骤。整体上以原型为准，逐项对照：

- 窗口模式下，除顶栏外没有常驻的界面元素。
- 打开或收起任何浮层，舞台大小不变。
- 七种状态在四套主题下都能只凭形状分辨（把屏幕转成灰度后仍能分清）。
- 所有可点的控件高度不小于 48px。
- 「结束会话」「全部结束」单击一次不会执行。
- 全景里点任一会话，一次点击进入该会话。
