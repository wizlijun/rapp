# Congestion control on the weak link: cubic vs newreno vs bbr (Task 17)

Test: `rust/testkit/tests/cc_compare.rs` (`cc_table`, `#[ignore]`), quinn 0.11.19 controllers set through
`TransportConfig::congestion_controller_factory` on both ends (keep-alive 10 s, idle 30 s like production), over
`rapp-weaknet` profiles s0, n2, n3 with the outage list cleared and the profile's own fixed seed. 20 s per cell, one run
per cell, loopback. One uni stream sends as fast as it can (throughput = bytes received by the server / 20 s); every
200 ms a bi stream round-trips 1 KB (100 pings per cell; a ping still unfinished at 20 s counts as its age so far).

**Verdict rule (fixed before the run):** BBR replaces the default (cubic) in both `transport()` fns only if its throughput
is >= 1.2x cubic on n3 and >= 1.0x cubic on s0 and n2, and its ping p95 is not more than 20% worse than cubic's on all
three profiles. Otherwise nothing changes.

## Results

| profile | controller | throughput kbit/s | ping p50 ms | ping p95 ms |
|---|---|---:|---:|---:|
| s0 | cubic | 99.7 | 572 | 1366 |
| s0 | newreno | 86.0 | 608 | 1457 |
| s0 | bbr | 19.0 | 2684 | 12573 |
| n2 | cubic | 8.0 | 3422 | 7282 |
| n2 | newreno | 5.4 | 6577 | 13377 |
| n2 | bbr | 3.8 | 5818 | 18576 |
| n3 | cubic | 12.5 | 3377 | 10595 |
| n3 | newreno | 8.8 | 4583 | 12383 |
| n3 | bbr | 1524.5 | 1027 | 3955 |

BBR / cubic: throughput s0 0.19, n2 0.48, n3 122; p95 s0 9.2x, n2 2.55x, n3 0.37x.

## Verdict: do not switch

BBR fails on s0 (throughput 0.19x, needs >= 1.0x; p95 9.2x, limit 1.2x) and n2 (0.48x; p95 2.55x). It only wins on n3
(30% random loss, 2 Mbit/s), where cubic and newreno collapse because they treat every loss as congestion; BBR does not.
Both `transport()` fns stay on quinn's default (cubic). No code change outside the test.

Caveats: single run per cell with a fixed seed, so the s0/n2 numbers are noisy (n2 is 50 kbit/s, a few KB per second);
the direction on s0 and n2 is large enough that it is unlikely to flip. Pings are queued behind the bulk stream on the
same connection, so ping latency here includes bufferbloat from the saturating stream. BBR in quinn 0.11 is experimental;
it did not panic.
