# Baseline on the current version (v6), before step 1

Taken on commit 082a7d7 (feat/smooth-step1, before any step-1 change; measure-video.py is added by the commit that adds this file), 2026-11-14.
Machine: MacBook Pro, Apple M5, lid closed, external 4K display, UI looks like 1920x1080 at **30 Hz** (so the test clip draws about 30 fps, not 60; capture is 30 fps). A and B run on the same Mac over loopback (A's service, rapp-weaknet, B's hub + rapp-session). One rig at a time, test page window visible and frontmost.
Commands (each writes one table below): `scripts/measure-video.py --profile lan --mode color16 --density original --fps 30 --minutes 5`; `scripts/measure-weak.py --profile lan|s0|n1..n4 --path direct|relay --minutes 5|10`, seed 1.

Caveat for every row that depends on frames per second (all latency rows, the video table): Task 4 found that on this machine the rate at which the capture delivers frames to B falls sharply with the display/window state (RustDesk holds the display, the window server). During these runs the clip drew ~30 fps (marks file) but B received only a few frames per minute in the video run. Read the sample counts (n) next to each median. The video table below is therefore a statement about this machine's state at the time as much as about v6, and is not a usable v6 frame-rate baseline; re-take it on a quiet display before comparing.

## 5. Weak-network run: n1, direct, 10 min (exit 1, no table)

The rig could not start: `rig.RigError: connect 127.0.0.1:<proxy port>: timed out` while B's hub added the host (`add_host`). v6's hub dials a direct address with a fixed 0.5 s handshake wait (LAN_WAIT in rust/hub/src/link.rs), and n1 has 100-400 ms delay and 10% loss, so the connection is not established. Re-run with seed 2 (1 min): same error. Result: v6 cannot connect on n1 at all, which fails every §4.3 n1 row (open <= 8 s, flip <= 3 s, text identical, recovery <= 5 s). No numbers.
