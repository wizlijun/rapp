# iPad / Duo P0 探查的结论

规格：`docs/superpowers/specs/2026-11-17-rapp-ipad-duo-design.md` §15 P0。计划：`docs/superpowers/plans/2026-11-17-rapp-ipad-p0-probe.md`。
探查代码在分支 `probe/ipad-p0`（不合入，留给 P1 取用），最后一个提交 82e620e。

## 机器和版本

| 项 | 值 |
|---|---|
| A（被连的 Mac） | MacBook Pro，Apple M5，rapp 0.13.x 已安装，经自建 relay |
| 模拟器 | iPad Pro 11-inch (M5)，iOS 26.5 运行时，Debug 构建 |
| 真机 | iPhone 12 mini（A14），iOS 27.2，Release 构建；**没有 iPad 真机，也没有 Duo 真机** |
| 工具 | Xcode 27.2（27B52），Flutter 3.44.1，Dart 3.12.1，Rust 目标 `aarch64-apple-ios`、`aarch64-apple-ios-sim` |

规格说"真机 iPad"的地方都用 iPhone 12 mini 代替：hub、会话、画面层在两种设备上是同一份代码，差别在窗口大小和芯片。

## Q1 hub 能不能编到 iOS

**能，原样编过，hub 不用改。** `rapp-term` 带的 `portable-pty`（连同 `rustix-openpty`）在两个 iOS 目标上都编得过，没有警告；不需要分出不带伪终端的 feature。

| 项 | 结果 |
|---|---|
| `cargo build -p rapp-hub-ffi --release --target aarch64-apple-ios` | 通过，18 s |
| 同上，`aarch64-apple-ios-sim` | 通过，16 s |
| 静态库大小 | 每个约 103 MB（未剥离的静态库；链接进 App 后小得多） |
| `cargo test -p rapp-hub-ffi -p rapp-hub`（macOS） | 通过 |

C 接口是**四个**函数，不是规格写的三个：`rapp_hub_start`、`rapp_hub_send`、`rapp_hub_stop`，加 `rapp_hub_free_line`。原因：`on_line` 交出去的那一行，Dart 的 `NativeCallable.listener` 要在回调返回**之后**才读；按"借用指针、回调返回就释放"的写法，模拟器在 M5 上直接崩（`EXC_ARM_MTE_TAGCHECK_FAIL`）。现在这一行归接收方，读完调 `rapp_hub_free_line` 释放。

链接时还要两样（Release 才会暴露）：

- Swift 里没人调这四个函数，Release 的死代码剥离会把它们去掉，Dart 的 `dlsym` 就找不到。要在链接参数里把它们列成根：`-Wl,-u,_rapp_hub_start` 等四个。
- Release 默认剥掉全局符号，同样让 `dlsym` 失败。要 `STRIP_STYLE = non-global`。
- 还要链接 `-lc++`、`Security`、`SystemConfiguration`（见 `probes/ios/ios/Flutter/Probe.xcconfig`）。

iOS 上**起不了子进程**（F1），而 hub 里有几处会起：`rapp_net::config::hostname()` 调 `hostname` 命令，失败就退回 `"rapp"`——所以 A 上这台手机的名字就叫"rapp"（Q6）；`datadir.rs` 调 `git`；不带 `embed` 的 `open` 拉起 `rapp-client`。前两个在 P1 要换成由入口传进来的值或直接关掉。

## Q2 经 FfiHubTransport 发 hosts 能不能收到回答

**能。** Flutter App 里用 `dart:ffi` 直接调 hub，不经 Swift。

| 项 | 模拟器（iPad Pro 11） | 真机（iPhone 12 mini） |
|---|---|---|
| `hub_start` | 9 ms | 1–4 ms |
| 第一次 `hosts` 回答 | 13 ms | 7–22 ms |
| 20 个 `hosts` 并发 | 2 ms | 2 ms |
| `add_host`（加这台 Mac） | 128 ms，走局域网 | 710 ms，走 relay |
| `apps` | — | 754 ms |
| `open`（嵌入）到 `opened` | — | 207 ms |

hub.log 里没有 panic。

**真机上先要拿到网络（新发现，规格没写）**：国行 iPhone 上，App 在用户回答"无线数据"弹框之前没有网络。hub 用的是 Rust 自己的 UDP 套接字，**这种套接字不会让系统弹这个框**，于是拨 relay 一直超时（两次、共约 15 分钟，"relay unreachable: timed out"，屏幕上什么也没出现）。用系统网络（`URLSession`）发一个请求，0.65 s 弹框，用户点允许后 6.4 s 网络通了，之后一切正常。产品里要在 hub 拨号前先发一个系统请求，并处理用户拒绝的情况（规格 §10 已补）。

## Q3 RappSession 在 iOS 上出一路纹理

**能。** `RappCore`、`RappSession` 改了几行就在 iOS 上编过，嵌入会话经 `FlutterTexture` 把 A 上的测试页画到了手机屏幕上（截图核对过：标题栏、帧标记、移动的线）。

`RappCore` 不是"一行不改"：`DataPaths` 取家目录要分平台（iOS 用 `NSHomeDirectory()`），`Windows.swift` 的 `classifyWindow` 和它的两个测试只在 macOS 编。`RappSession` 的 AppKit 文件按规格处理，`LocalPasteboard` 有了 UIKit 版。

| 测试 | 结果 |
|---|---|
| `RappCoreTests`，iOS 模拟器 | 476 个，1 个跳过（`ScrollCopyPerfTests` 要 `RAPP_PERF=1`），0 失败 |
| 同上，macOS `swift test` | 478 个，1 个跳过 |

`xcodebuild test -scheme RappCore` 没有测试动作，而 `rapp-Package` 会带进只有 macOS 才有的可执行目标；这次是用一个临时 scheme 跑的。P1 要提交一个正式的办法（测试计划或 scheme），§14.1 的检查才能落地。

性能（真机 Release，color16，请求 30 fps，`original`）：

| 状态 | 帧/秒 | CPU（一个核的百分比） | 内存 |
|---|---|---|---|
| 会话开着、没有帧 | 0 | 0.4–1 % | 150–165 MB |
| 有帧的那几秒 | 17–25 | 13–47 % | 最高 218 MB |

**和 macOS 的对比没量成**，过关条件里的"CPU 不超过 macOS 同档的两倍"留到 P1。原因是 A 那边持续给不出 30 帧，见下一段。

**A 没锁屏时几乎不发帧（新发现，和手机无关）**：

- **现象：** A 没锁屏时，给任何客户端都几乎不发帧，手机、Mac 上的 rapp-client、直接跑的 rapp-host 都一样。rapp-host 自己统计是 0 fps、在途 0/2，所以不是限速。
- **测试页确实在画：** marks 文件每秒多 30 条记录，隔 0.7 秒的两张截图也不同。
- **挪窗口也没用：** 窗口原来有 313 点伸出屏幕右边，挪回屏幕内之后，手机连窗口移动这一帧都没收到。
- **没人碰 Mac 时也一样：** 08:23–08:28Z 这段 Mac 没人碰，手机照样是 0 帧，只有两小段 2–7 帧/秒，每帧约 300 字节。
- **锁屏后正常：** 同一个会话在 A 锁屏的那一刻就到了 29–30 fps。看起来是 A 没锁屏时走的窗口抓取在这台 Mac（macOS 27）上不出帧，锁屏时走的另一条路正常。这个要在 host 上查。

**锁屏测量为什么做不成：** 本来改成锁屏后再量，但量的时候另一台设备正通过 rapp 用着 A，A 每次锁上约 30 秒就被解开。

**两条量的时候要注意的：**

- **HID 空闲时间不能用来判断"有没有人在 Mac 前"：** 会话开着时，rapp-host 会声明 UserIsActive，并且会碰 IOHIDSystem。
- **只能轮流量：** A 上同一个 app 同一时间只能有一个客户端，后开的会顶掉先开的，所以手机和 Mac 只能轮流量。

## Q4 窗口大小、开合

**Flutter 3.44 够用；开合没量到。**

| 设备 | 竖 | 横 | 安全区 | 转向到窗口更新 |
|---|---|---|---|---|
| iPad Pro 11 模拟器 | 834×1210 | 1210×834 | 上 32、下 25（不要全屏标记时下 20） | 240–310 ms |
| iPhone 12 mini 真机 | 375×812，[左0 上50 右0 下34] | 812×375，[左50 上0 右50 下20] | | 200–260 ms |

两处 `displayFeatures` 都是空的（和 F9 一致）。转向是 App 自己请求的（`SystemChrome`），因为 Xcode 27.2 没有 Simulator 的图形界面可点；iPad 上要 Info.plist 带 `UIRequiresFullScreen` 才理会这个请求，这只是探查用的，产品不能要求全屏。

Duo 模拟器没跑：设备类型"iPhone Duo"有，但要 27.1 运行时（只装了 26.5，约 8 GB），而且没有图形界面来开合。开合序列、开合时 App 是否一直活动、外屏的窗口大小，记进 `tasks/todo.md`，等 Duo 真机。

## Q5 进后台

**切走就被挂起；回来走现有重连路径就行，hub 不报错。** 真机（Release），探查 App 播着画面时切到"设置"，10 / 30 / 120 秒后切回：

| 项 | 10 秒 | 30 秒 | 120 秒 |
|---|---|---|---|
| `tick` 断档（被挂起的时长） | 10.6 s | 30.3 s | 120.2 s |
| 回来后 `apps` | 280 ms | 200 ms | 89 ms |
| `open(reconnect)` 到 `opened` | 249 ms | 20 ms | 53 ms |
| 回来到会话就绪 | 678 ms | 323 ms | 353 ms |
| 回来到第一帧 | 1565 ms | 1223 ms | 21147 ms |
| A 的状态 | 没锁 | 没锁 | 已锁（自动锁屏），20 s 后在 Mac 上被解开 |

- 切走时 0.8 秒内 inactive → hidden → paused，探查在 hidden 时关会话；回来 0.45 秒内 hidden → inactive → resumed。
- 回来先发 `net_suspect`，再 `open(..., reconnect: true)`：三轮都直接成功，hub 没有报超时或错误。旧连接在挂起期间怎么断的（超时还是立刻报错）看不到，因为探查进后台时主动关了会话（规格 §9.1 的做法）。
- 120 秒那轮正是 §9.3 说的情形：切走超过 10 秒，A 自动锁屏；新会话报"A 锁着，等解锁"，画面等到 A 解锁才来。没有记住密码时，回来到画面恢复的时间就是用户去解锁的时间。§9.2 的"2 秒内恢复"只在 A 没锁时成立（这里 1.2–1.6 秒）。

模拟器（Debug）：切走 10 / 30 / 120 秒，`tick` 断档 7.8 / 29.3 / 119.8 秒，即模拟器也会挂起；回来到会话就绪 309 / 147 / 254 ms，到第一帧 1485 / 1204 / 1335 ms（帧按秒统计，是上限）。生命周期：走时 inactive → hidden → paused，回来 hidden → inactive → resumed。

## Q6 权限、登记、组播

| 问题 | 结论 |
|---|---|
| "本地网络"弹框 | 先走 relay 时没出现。后来某次重连时弹出，用户允许后，重连直接走局域网（A 的日志：`path lan`）。具体在哪一步弹出的没有记下来。嵌入会话本身走 `127.0.0.1`，不需要这个权限 |
| "无线数据"弹框（国行） | 见 Q2：只有系统网络会触发；hub 拨号前要先发一个系统请求 |
| 只往外拨要不要先登记 | 不要。hub 从不调 relay 的 `register`（`relay.rs:216`），拨号走 `dial → relay_to_at → enroll`，`add_host` 710 ms 就成功了 |
| A 上这台手机叫什么 | "rapp"：`hostname()` 起子进程失败后的默认值。路径 relay，对端是手机的公网地址。P1 要给 hub 传一个设备名 |
| hub 用没用组播 | 没有 |

## 过关判定

| 条件 | 结果 |
|---|---|
| 1 hub 编到 iOS | 通过 |
| 2 `hosts` 有回答 | 通过（模拟器 iPad、真机 iPhone） |
| 3 出一路纹理 | 通过 |
| 3 的 CPU 不比 macOS 同档高出一倍以上 | **没量到**：A 没锁屏时给不出持续的帧（见 Q3），留到 P1 |

## P1 要带上的

1. C 接口四个函数；链接根 `-Wl,-u,…` 和 `STRIP_STYLE = non-global`；`-lc++`、`Security`、`SystemConfiguration`。
2. hub 拨号前先用系统网络发一个请求，拿到"无线数据"授权；被拒绝时提示去设置里开。
3. 设备名由入口传给 hub（`hostname()` 在 iOS 上起不了子进程）；`datadir.rs` 的 `git` 在 iOS 上关掉。
4. Dart 在 iOS 上 `Platform.environment` 里没有 `HOME`：`gui/lib/paths.dart` 等读 `HOME` 的地方会退成 `.`。数据根用 `path_provider` 或原生传进来的 `NSHomeDirectory()`。
5. `IPHONEOS_DEPLOYMENT_TARGET` 要 17.0（Xcode 27.2 不接受 13）；模拟器只有 arm64（Flutter 3.44 的模拟器引擎只有 arm64）。
6. 签名：这台 Mac 的 Xcode 没登录账号，自动签名找不到描述文件，Xcode 也不肯手动用它自己管理的通配描述文件；探查是 `flutter build --no-codesign` 后由脚本 `codesign`。产品要么 Xcode 登录账号，要么准备 CI 签名。
7. RappCore 的 iOS 测试要一个提交进仓库的 scheme 或测试计划。
8. 量性能时 A 要没人用，也不能有别的设备连着；同一个 app 同时只能一个客户端；HID 空闲时间不能用来判断有没有人。
9. 查 A 没锁屏时窗口抓取不出帧的问题（macOS 27，Q3）；查清以后再做手机和 macOS 的 CPU 对比。

## 没量到的

| 项 | 原因 |
|---|---|
| iPad 真机上的任何数 | 没有 iPad 真机；用 iPhone 12 mini 代替 |
| Duo 开合序列、外屏、开合时的生命周期 | 没有 Duo 真机；Duo 模拟器要 27.1 运行时，也没有图形界面开合 |
| 点一下到画面变化的延迟 | 探查 App 不发输入；P1 用触摸规格的真机检查一起量 |
| 6 个会话同时开着的内存和每小时耗电（§9.5） | 只开了一个会话；手机一直插着电（电量 1.0、状态 full），耗电读不出来 |
| "本地网络"弹框的时机 | 弹过，也允许了，但具体在哪一步弹出的没有记下来 |
| 手机和 macOS 的 CPU 对比、长时间运行的趋势 | A 没锁屏时不出帧；锁屏后又被另一台设备的会话解开（Q3） |
